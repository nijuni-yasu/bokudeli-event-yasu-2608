# shokujii base

shokujii サイト(hosting)共通で使用するコンポーネント等をまとめたディレクトリです。
当初は npm パッケージにするなどして再利用性を高める予定でしたが、[Materio](https://store.vuetifyjs.com/products/materio-vuetify-vuejs-admin-template) が依存関係の動的解決に向いていない構造なので、 ひとまずシンボリックリンクを用いて各アプリに共通項目を提供するものとします。
`common` は hosting, functions 共通で使用されるモジュールライブラリで、 `base` とは明確に区別すべきです。

## Materio の扱い

基本的には編集しないでください。
ただし、Materio 自体が「タイプチェックが通らない」、「最新のライブラリ(Vuetify 等)に対応していない」など、環境依存のバグを抱えていることがあります。
その際は、変更が最小限になるよう留意しながら修正してください。

不要な依存関係を排除するため、Theme と Layout に関係するモジュールのみ移植しました。今後、必要になった時に持ってくる方針です。
なお、 `@layouts` の中で [casl](https://casl.js.org/v6/en/) への依存関係が直接書き込まれており、これを削除するために [src/@layouts/plugins/casl.ts](./src/@layouts/plugins/casl.ts) を修正しています。このファイルを含む casl に依存する箇所を最新の Materio に更新する際は十分気をつけてください。

## `@/utils/router` の扱い

現在、各コンポーネントで `@/utils/router` を参照してしまっています。
これは依存関係の逆転を意味し、 `base` 単体でのビルドを困難にしています。また、各 UI プロジェクトが互いに影響し合う問題も発生させています。
今後、新規で作成するコンポーネントに関しては、適切に `props`, `emits`, `slot` 等を用いて、 上位プロジェクトの依存を持ち込まないようにしてください。
既に作成されてしまっているコンポーネントに関しては、変更を加える際に順次変更していくものとします。

## コンポーネントの設計方針

基本原則としては、各コンポーネント内で `useXXXStore` を呼び出すのではなく、 `props` で受け取るようにしてください。
しかし、トップレベルコンポーネントで `useXXXStore` を呼び出すのは許容されます。
トップレベルコンポーネントとは、pages とほぼ同等のビジネスロジックまでを含むコンポーネントを指します。
なお、既に実装済みのコンポーネントでは、この原則に反しているものもあります。今後の修正時に対応するものとします。
