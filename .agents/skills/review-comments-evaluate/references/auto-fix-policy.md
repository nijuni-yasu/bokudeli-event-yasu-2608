# レビュー自動修正ポリシー（共通）

[/shokujii-code-review](../../shokujii-code-review/SKILL.md) 手順 3a・3b と [/review-comments-evaluate](../SKILL.md) 手順 4a の正本。

## 実行順・周回

1. **🚨 必須修正**を先に自動修正する
2. 続けて **条件を満たす 🟡 修正提案**を自動修正する
3. 手順 1（レビュー / 再評価）から**再実行**する（同一タスク内・**最大 2 周**・🚨 と 🟡 **合算**）
4. 2 周後も自動修正できない指摘は完了報告に列挙する
5. **評価**（🚨 / 🟡）は変更しない。**ステータス**のみ ✅ 対応済み に更新する

ユーザーが「修正しない」「自動修正しない」と明示した場合はスキップしてよい。

## 共通の自動修正対象外

次のいずれかに該当する指摘は **🚨 / 🟡 問わず**自動修正しない（一覧を報告し、人間判断を待つ）:

- 仕様判断が必要（仕様書に無い挙動・要件の解釈）
- スコープ外の設計変更（本 PR / Issue の範囲を超える改修）
- セキュリティで影響範囲の確認が必要

## 🚨 必須修正（自動修正対象）

**すべて**満たす:

| 条件 | 値 |
|------|-----|
| **評価** | 🚨 必須修正 |
| **PRスコープ** | 📌 スコープ内（セルフレビューでは本タスク / Issue 範囲内） |
| **ステータス** | 未着手 |
| 共通対象外 | 該当しない |

evaluate では上記に加え、手順 2 で RC 化済みであること。

## 🟡 修正提案（条件付き自動修正対象）

**すべて**満たす:

| 条件 | 値 |
|------|-----|
| **評価** | 🟡 修正提案 |
| **PRスコープ** | 📌 スコープ内 |
| **ステータス** | 未着手 |
| **想定工数** | **S** |
| **変更種別** | **🔧 微修正** または **📄 ドキュメントのみ** |
| **ラベル** | **📑 仕様書** / **💰 金銭** / **🔒 セキュリティ** / **👤 UX** を**含まない** |
| 共通対象外 | 該当しない |
| 実装方針 | コメント・指摘文から**修正方針が一意**（複数案の併記なし） |

### 🟡 で自動修正しない（いずれかで除外）

| 除外理由 | 例 |
|----------|-----|
| **変更種別** | 📋 仕様追加 / 🆕 新機能 / 📐 リファクタ |
| **PRスコープ** | 📤 スコープ外 / ❓ 要確認 |
| **想定工数** | M / L |
| **ラベル** | 📑 仕様書 / 💰 金銭 / 🔒 セキュリティ / 👤 UX |
| **文言** | 原文・判断理由に「検討」「方針」「要確認」「別 Issue」「スコープ外」等 |
| **既存** | **ステータス** が ✅ 対応済み / 📤 別Issue化、**評価** が 👌 修正不要 |

セルフレビュー（shokujii）で種別・工数タグを省略した 🟡 は、記録時に付与する。タグ未付与で上記 S + 🔧/📄 と判断できる場合のみ 3b 対象とする。

## 完了報告

- 自動修正した 🚨 / 🟡 を件数・RC 番号で列挙する
- 自動修正しなかった 🟡（対象外・M 以上・曖昧等）を列挙する
- evaluate auto ではメタデータに `手順 4a 自動修正: RC-x〜y（🚨 n件 / 🟡 m件）` を記載してよい

## lint

ソースコードを変更した場合は [`/lint-and-format`](../../lint-and-format/SKILL.md) を実行する（push 前の PR verify 相当）。
