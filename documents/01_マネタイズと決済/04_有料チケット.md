# 有料チケット機能

## 1. 概要

### 1.1 機能の目的
イベント主催者が有料チケットを複数種設定し、参加者が前払いでイベントに申し込める機能を提供する。

### 1.2 主要な機能
- 複数種の有料チケット設定（価格・枠数）
- 食事代のインクルード設定s
- システム利用料の自動計算
- チケット購入制御（食事個数との連動）
- 販売代金の自動計算表示

### 1.3 対象ユーザー
- **主催者**: イベント作成・管理を行うコミュニティ管理者
- **参加者**: 有料チケットを購入するイベント参加者

## 2. ねらい

### 2.1 ビジネス目標
- 主催者の収益化支援
- システム利用料による収益確保
- イベント参加者の事前決済によるキャッシュフロー改善

### 2.2 ユーザー価値
- **主催者**: イベント収益の事前確保、参加者数の確定
- **参加者**: 事前決済による安心感、確実な参加権確保

### 2.3 成功指標（KPI）
- 有料チケット機能の利用率
- システム利用料収益
- チケット購入完了率

## 3. 前提条件

### 3.1 技術的前提条件
- 既存のイベント管理システム
- Stripe決済システム
- Firestoreデータベース
- 既存の注文管理機能

### 3.2 ビジネス的前提条件
- イベントが「注文受付中」ステータスであること
- 主催者がコミュニティ管理者権限を持つこと
- 参加者が認証済みユーザーであること

### 3.3 依存関係
- イベント作成・管理機能
- 決済システム（Stripe）
- 注文管理機能
- ユーザー認証システム

## 4. 画面仕様

### 4.1 主催者画面：チケット設定
#### 4.1.1 チケット設定画面
- **チケット項目**
  - チケット名入力フィールド（必須、最大50文字）
  - 金額入力フィールド（必須、数値のみ）
  - 販売予定数入力フィールド（必須、数値のみ）
- **補助表示**
  - 販売代金お振込合計（システム手数料控除後）
- **操作ボタン**
  - 「＋有料チケット」ボタン（複数チケット追加）
  - 「削除」ボタン（各チケット項目）
- **食事代インクルード設定**
  - チェックボックス（ON/OFF切り替え）

#### 4.1.2 インクルードON時のUI制御
- 食事金額：非表示
- 食事個数：「1個固定」、選択不可
- チケット購入数：「1枚固定」、変更不可

#### 4.1.3 インクルードOFF時のUI制御
- 食事金額：表示
- 食事個数：選択可能
- 注文制限：食事個数 = チケット購入数

### 4.2 参加者画面：チケット購入
#### 4.2.1 インクルードONの表示例
```
食事代：非表示
チケット代：¥3,000（食事込み）
システム利用料：¥150
合計：¥3,150
```

#### 4.2.2 インクルードOFFの表示例
```
食事代：¥1,200 × 2 = ¥2,400
チケット代：¥3,000
システム利用料：¥150
合計：¥5,550
```

## 5. 技術仕様・データ構造設計

### 5.1 Firestoreスキーマ

#### 5.1.1 Firestoreドキュメント構造
```
/communities/{communityId}
  /events/{eventId}
    /tickets/{ticketId}  ← 新規追加：チケット情報
    /orders/{orderId}    ← 既存：注文情報（チケット関連フィールド追加）
```

#### 5.1.2 イベントチケットスキーマ
**ドキュメントパス**: `/communities/{communityId}/events/{eventId}/tickets/{ticketId}`

```typescript
// common/src/schemas/EventTicket.ts
import { z } from 'zod'

const EventTicketDbSchema = z.object({
  // 基本情報
  ticket_id: z.string(),
  event_id: z.string(),
  community_id: z.string(),  // コミュニティID（セキュリティルール用）
  
  // チケット情報
  ticket_name: z.string().min(1).max(50),
  ticket_price: z.number().min(0),
  ticket_quantity: z.number().min(1),
  sold_quantity: z.number().min(0),
  
  // 食事代インクルード設定
  is_meal_included: z.boolean(),
  
  // タイムスタンプ
  created_at: z.date(),
  updated_at: z.date(),
})

export class EventTicket {
  ticket_id: string = ''
  event_id: string = ''
  community_id: string = ''
  ticket_name: string = ''
  ticket_price: number = 0
  ticket_quantity: number = 0
  sold_quantity: number = 0
  is_meal_included: boolean = false
  created_at: Date = new Date()
  updated_at: Date = new Date()
  
  // 在庫チェック
  isAvailable(): boolean {
    return this.sold_quantity < this.ticket_quantity
  }
  
  // 残り数量
  getRemainingQuantity(): number {
    return this.ticket_quantity - this.sold_quantity
  }
  
  // ファクトリメソッド
  static fromDb(data: any): EventTicket {
    const ticket = new EventTicket()
    ticket.ticket_id = data.ticket_id
    ticket.event_id = data.event_id
    ticket.community_id = data.community_id
    ticket.ticket_name = data.ticket_name
    ticket.ticket_price = data.ticket_price
    ticket.ticket_quantity = data.ticket_quantity
    ticket.sold_quantity = data.sold_quantity || 0
    ticket.is_meal_included = data.is_meal_included
    ticket.created_at = data.created_at.toDate()
    ticket.updated_at = data.updated_at.toDate()
    return ticket
  }
}
```

#### 5.2.2 データ更新処理

### 5.4 Functions設計

#### 5.4.1 Callable Functions（フロントエンドから呼び出し）
- `createEventTicket`: チケット作成
  - **引数**: `eventId: string`, `ticketData: EventTicketData`
  - **戻り値**: `{ success: boolean, ticket_id: string }`
  - **認証**: コミュニティ管理者のみ

- `updateEventTicket`: チケット更新
  - **引数**: `ticketId: string`, `ticketData: EventTicketData`
  - **戻り値**: `{ success: boolean }`
  - **認証**: コミュニティ管理者のみ

- `deleteEventTicket`: チケット削除
  - **引数**: `ticketId: string`
  - **戻り値**: `{ success: boolean }`
  - **認証**: コミュニティ管理者のみ

- `purchaseTicket`: チケット購入
  - **引数**: `eventId: string`, `ticketId: string`, `quantity: number`
  - **戻り値**: `{ success: boolean, order_id: string }`
  - **認証**: 認証済みユーザー

#### 5.4.2 Trigger Functions（自動実行）
- `onTicketPurchased`: チケット購入時の在庫更新
  - **トリガー**: チケット購入完了時
  - **処理内容**: 在庫数量の自動減算
  - **権限**: システム権限

- `onTicketSoldOut`: チケット売り切れ時の処理
  - **トリガー**: 在庫が0になった時
  - **処理内容**: 売り切れ通知、関連処理
  - **権限**: システム権限

### 5.5 処理フロー

#### 5.5.1 チケット作成フロー
1. 主催者がチケット設定画面で情報を入力
2. フロントエンドでバリデーション（必須項目、数値チェック）
3. Callable Function `createEventTicket`を呼び出し
4. Firebase Functionで認証・権限チェック
5. チケットデータをFirestoreに保存
6. レスポンスをフロントエンドに返却
7. チケット一覧を更新表示

#### 5.5.2 チケット購入フロー
1. 参加者がチケット選択画面でチケットを選択
2. フロントエンドで在庫チェック
3. 食事代インクルード設定に応じたUI制御
4. Callable Function `purchaseTicket`を呼び出し
5. Firebase Functionで認証チェック
6. 在庫の再確認（同時購入対策）
7. 決済処理実行（Stripe）
8. 注文データをFirestoreに保存
9. Trigger Function `onTicketPurchased`が自動実行
10. 在庫数量を更新
11. レスポンスをフロントエンドに返却
12. 購入完了画面を表示

## 7. 注意事項

### 7.1 既存システムへの影響
- **データベース**: 新しいコレクション`/communities/{communityId}/events/{eventId}/tickets/{ticketId}`を追加
- **注文システム**: 既存の注文スキーマ（`/communities/{communityId}/events/{eventId}/orders/{orderId}`）にチケット関連フィールドを追加
- **決済システム**: 既存のStripe決済システムを利用
- **UI**: 既存のイベント作成・編集画面にチケット設定機能を追加
- **セキュリティルール**: チケットコレクション用の新しいセキュリティルールを追加

### 7.2 セキュリティ考慮事項
- **認証**: すべてのFunctionsで認証チェックを必須とする
- **権限**: チケット作成・編集・削除はコミュニティ管理者のみ許可
- **在庫管理**: 同時購入による在庫の不整合を防ぐ排他制御
- **決済**: Stripeのセキュア決済システムを利用
- **入力値検証**: すべての入力値に対して適切なバリデーションを実装

### 7.3 運用考慮事項
- **在庫管理**: リアルタイムでの在庫状況監視
- **決済管理**: 決済失敗時の適切なロールバック処理
- **通知**: チケット売り切れ時の自動通知
- **パフォーマンス**: 大量のチケット購入時の処理性能
- **拡張性**: 将来的なチケット種別追加に対応できる設計

### 7.4 制約事項
- **インクルードON時**: チケットは1枚固定購入、食事個数は1個固定
- **インクルードOFF時**: 食事注文数とチケット購入数が一致する必要
- **無料チケット**: 実装対象外（有料チケットのみ）
- **システム利用料**: 一律¥150/件（変更不可）
