# ユーザー決済手数料機能

## 1. 概要
### 1.1 機能の目的
決済処理のコストをカバーするため、ユーザー決済手数料を動的に計算してクレジットカード決済に上乗せする機能を提供する。

### 1.2 主要な機能
- 注文金額に応じた動的手数料計算
- 手数料を含む決済金額の表示
- 返金時の手数料除外処理
- 店舗向け表示での手数料除外

### 1.3 対象ユーザー
- イベント参加者（決済手数料を支払う側）
- イベント主催者・店舗（手数料を受け取らない側）

## 1.4 手数料
### 1.4.1 手数料計算式
- **計算式**: `ユーザー手数料 = MAX(110, FLOOR(注文金額 × 0.1, 100) × 1.1)`
- **計算手順**:
  1. 注文金額に10%をかける
  2. 100の位で切り捨てる
  3. 1.1（消費税）をかける
  4. 最低でも110円とする
- **適用条件**: すべてのクレジットカード決済

### 1.4.2 手数料計算例
| 注文金額 | 計算過程 | 手数料 |
|---------|---------|--------|
| 1,000円 | MAX(110, FLOOR(1000×0.1, 100)×1.1) = MAX(110, 100×1.1) = 110円 | 110円 |
| 2,000円 | MAX(110, FLOOR(2000×0.1, 100)×1.1) = MAX(110, 200×1.1) = 220円 | 220円 |
| 3,500円 | MAX(110, FLOOR(3500×0.1, 100)×1.1) = MAX(110, 300×1.1) = 330円 | 330円 |
| 10,000円 | MAX(110, FLOOR(10000×0.1, 100)×1.1) = MAX(110, 1000×1.1) = 1,100円 | 1,100円 |

### 1.4.3 手数料の変動要因
- 注文金額に応じて手数料が変動
- 将来的な手数料変更に対応するため、設定可能な仕組みを構築
- イベント単位での手数料設定は現時点では対応しない

## 4. 画面仕様
### 4.1 画面遷移
```
カート画面 → 決済確認画面 → Stripe決済画面 → 完了画面
     ↓
マイページ（注文履歴）
```

### 4.2 UI要素
#### 4.2.1 カート画面
- **表示内容**:
  - 商品小計: 1,000円
  - 決済手数料: 110円
  - 合計金額: 1,110円
- **表示位置**: 小計の下、合計金額の上
- **デザイン**: 手数料項目は明確に区別して表示

#### 4.2.2 Stripe決済画面
- **表示内容**: カート画面と同様の内訳表示
- **決済金額**: 合計金額（商品小計 + 手数料）で決済
- **手数料の明示**: 決済前に手数料を含むことを明確に表示

#### 4.2.3 マイページ（注文履歴）
- **表示内容**:
  - 商品金額: 1,000円
  - 決済手数料: 110円
  - 合計金額: 1,110円
- **表示形式**: 内訳を明確に分けて表示
- **注文詳細**: 各注文の詳細画面でも同様の表示

#### 4.2.4 店舗管理画面
- **表示制限**: 手数料を含まない商品金額のみ表示
- **店舗メール**: 手数料を含まない商品金額で通知
- **店舗支払い金額**: 手数料を除いた商品金額のみ

#### 4.2.5 イベントページ
- **キャンセルポリシー**: 手数料の返金不可を明記
- **表示例**: 「決済手数料は返金されません」

#### 4.2.6 返金・キャンセル仕様

##### 4.2.6.1 返金ルール
- **返金対象**: 商品金額のみ
- **返金対象外**: 決済手数料
- **返金計算**: 合計金額 - 決済手数料 = 返金金額

##### 4.2.6.2 キャンセル時の表示
- **マイページ**: キャンセル実行時に手数料返金不可を明記
- **確認ダイアログ**: 「決済手数料は返金されません」を表示
- **キャンセルポリシー**: イベントページに事前に明記

##### 4.2.6.3 部分キャンセル
- **対応**: 部分キャンセルは現時点では対応しない
- **理由**: 手数料の按分計算が複雑になるため

## 5. 技術仕様・データ構造設計
### 5.1 Firestoreスキーマ

```typescript
// common/src/schemas/order.ts
import { z } from 'zod';

export const OrderMenuSchema = z.object({
  menu_id: z.string(),
  name: z.string(),
  price: z.number().positive(),
  count: z.number().int().positive(),
});

export const OrderSchema = z.object({
  orderId: z.string(),
  eventId: z.string(),
  userId: z.string(),
  
  // 注文されたメニュー（複数対応）
  menus: z.array(OrderMenuSchema),
  
  // 金額関連フィールド
  payment_user_fee_amount: z.number().min(110), // ユーザー決済手数料（動的計算）
  payment_user_total_amount: z.number().positive(), // 小計 + 手数料 = 合計金額
  payment_user_refund_amount: z.number().optional(), // 返金金額（合計金額 - 手数料）
  
  // 注文ステータス
  status: z.enum(['ordered', 'in_cart', 'canceled']),
  
  // タイムスタンプ
  canceled_at: z.date().optional(), // キャンセル日時
  ordered_at: z.date(),
  created_at: z.date(),
  updated_at: z.date(),
});

export type Order = z.infer<typeof OrderSchema>;
```

### 5.2 Functions設計
#### 5.2.1 Callable Functions（フロントエンドから呼び出し）
- `createOrderWithFee`: 手数料を含む注文作成
  - **引数**: `orderData: Partial<Order>`（注文データ）
  - **戻り値**: `{ orderId: string, paymentIntent: any }`（注文IDとStripe決済意図）
  - **認証**: 認証済みユーザーのみ
  - **処理内容**: 
    1. 商品小計から手数料を計算
    2. 手数料を含む注文データをFirestoreに保存
    3. Stripe決済意図を作成
    4. 決済情報をフロントエンドに返却

#### 5.2.2 Trigger Functions（自動実行）
- `onOrderCanceled`: 注文キャンセル時の返金処理
  - **トリガー**: Firestore `orders` ドキュメント更新時（status: 'canceled'）
  - **処理内容**: 
    1. 注文データから手数料を除外した返金金額を計算
    2. Stripe返金処理を実行
    3. 返金金額を注文データに記録
  - **権限**: システム権限

### 5.3 処理フロー

#### 5.3.1 手数料計算フロー（フロントエンド）
1. 商品小計を取得
2. 手数料計算式を適用：`MAX(110, FLOOR(注文金額 × 0.1, 100) × 1.1)`
3. 合計金額を計算：`商品小計 + 手数料`
4. 画面に表示

#### 5.3.2 注文作成フロー
1. フロントエンドでカート情報から商品小計を計算
2. 手数料計算ロジックで手数料と合計金額を算出
3. `createOrderWithFee` Functionを呼び出し
4. Function内で手数料を含む注文データをFirestoreに保存
5. Stripe決済意図を作成
6. フロントエンドに決済情報を返却

#### 5.3.3 返金処理フロー
1. ユーザーがキャンセルを実行
2. 注文ステータスを'canceled'に更新
3. `onOrderCanceled` Trigger Functionが自動実行
4. Function内で手数料を除外した返金金額を計算
5. Stripe返金処理を実行
6. 返金金額を注文データに記録

### 5.4 計算ロジック実装

```typescript
// フロントエンド用の手数料計算ロジック
// utils/calculateUserFee.ts
export const calculateUserFee = (subtotal: number): { fee: number, total: number } => {
  // 手数料計算: MAX(110, FLOOR(注文金額 × 0.1, 100) × 1.1)
  const feeBase = Math.floor(subtotal * 0.1 / 100) * 100; // 100の位で切り捨て
  const feeWithTax = feeBase * 1.1; // 消費税をかける
  const fee = Math.max(110, feeWithTax); // 最低110円
  
  const total = subtotal + fee;
  
  return { fee, total };
};

// Functions用の返金金額計算
// functions/default/src/orders/refund.ts
export const calculateRefundAmount = (total: number, fee: number): number => {
  return total - fee; // 手数料を除いた金額
};
```

## 7. 注意事項
### 7.1 既存システムへの影響
- 既存の注文データには手数料フィールドが存在しないため、マイグレーション処理が必要
- 表示時は手数料0円として扱い、新規注文から手数料を適用
- 既存の決済フローとの互換性を保つ必要がある

### 7.2 セキュリティ考慮事項
- 手数料計算ロジックはサーバーサイドで実行し、改ざんを防ぐ
- 決済金額の整合性チェックを実装
- 返金処理時の権限チェックを強化

### 7.3 運用考慮事項
- 手数料計算エラー時の適切な処理とログ記録
- 決済失敗時の手数料扱いの明確化
- 手数料に関する問い合わせ対応体制の整備
- 手数料変更時の既存注文への影響検討

### 7.4 パフォーマンス考慮事項
- 手数料計算のキャッシュ機能
- 大量注文時の処理性能確保
- データベースクエリの最適化

### 7.5 将来の拡張性
- 手数料計算式の設定可能化
- イベント別・店舗別の手数料設定
- 手数料の段階的変更機能
