# 無料参加・割引参加 — 請求書仕様

主催者請求書払い（`event_payment: 'community_bill'`）かつ `community_bill_settings` による無料参加・割引参加が有効なイベント向けの、**請求書 PDF のレイアウト・金額の定義**をまとめる。

割引・注文データモデル・ Callable の詳細は [03_無料参加・割引参加・クーポン.md](./03_無料参加・割引参加・クーポン.md) を参照する。

---

## 1. 適用範囲

| 条件 | 請求書の扱い |
|------|----------------|
| `event_payment !== 'community_bill'` | 本仕様の対象外（別フロー） |
| `community_bill` かつ **割引設定なし**（従来どおり） | **§3.1 従来型（メニュー明細）** と同一 |
| `community_bill` かつ `community_bill_settings.type === 'free'` | **§3.2 無料参加（メニュー明細）** |
| `community_bill` かつ `community_bill_settings.type === 'discount'` | **§3.3 割引参加（割引集計明細）** |
| Phase 2 以降 `type === 'coupon'` | **§3.4**（本書では概要のみ。明細はクーポン単位で複数行になり得る） |

**割引設定なし（上表の §3.1 行）の判定**

- [03_無料参加・割引参加・クーポン.md](./03_無料参加・割引参加・クーポン.md) **3.5** に合わせ、`community_bill_settings` が **`undefined` / `null` / 空オブジェクト `{}`** のいずれかのときは **割引設定なし**とみなし、**§3.1（従来型）** とする（`type` を解釈しない）。

## 2. 共通ルール

### 2.1 集計対象となる注文

- `status === 'ordered'` の注文のみを集計する。
- `canceled` は集計に含めない（ドキュメント上フィールドは残り得るが、金額に加算しない）。

### 2.2 手数料のカットオフ（売上・割引の両方で共通）

既存の請求書払い手数料（売上ベース）と同様、**イベント開始日時**が **2025-11-01 00:00 JST 以降**のイベントに限り、各節で定める「10% 相当の手数料」を**請求書に計上する**。それより前のイベントでは、当該手数料は **0 円**（明細行も出さない）。

- 実装上の基準時刻は [common/src/utils/invoice.ts](../../common/src/utils/invoice.ts) の `isEventAfterInvoiceFeeCutoff` と一致させる。

### 2.3 端数

- 手数料はいずれも **小数点以下切り捨て**（`Math.floor(基礎金額 × 0.1)`）。

### 2.4 Firestore に保存しない値

次の値は請求書生成時に都度算出し、**イベントドキュメント等へは永続化しない**（[03_無料参加・割引参加・クーポン.md](./03_無料参加・割引参加・クーポン.md) 5.1.2 の方針と同じ）。

- 割引総額（§3.3）、売上合計に対する手数料、割引に対する手数料、請求書合計 など

### 2.5 データソース

- **メニュー別集計**: 対象注文の `menus`（既存どおり）。
- **割引関連**: 対象注文の `pay_community_bill_off_amount`（フィールドが無い注文は **0** として扱い、行の「適用件数」には含めない。`0` の注文も同様）。

## 3. 請求書レイアウトと合計の定義

### 3.1 従来型（`community_bill`・割引設定なし）

**明細**

- メニュー名称（集計後）｜単価｜個数｜小計（※ 既存の請求書 PDF と同様）
- カットオフ後のみ：**請求書払い手数料**（売上合計に対する 10%、税区分は既存実装に従う）

**合計金額**

- メニュー小計の合計 ＋（カットオフ後）売上に対する手数料  
- 税の内訳（8% 対象・10% 対象）は既存の `calculateInvoiceTaxBreakdown` の定義に従う。

---

### 3.2 無料参加（`type: 'free'`）

**方針**: 主催者への請求の見せ方は **従来と同じくメニュー明細を主とする**。

**明細**

- メニュー名称｜金額｜個数｜小計（`ordered` の `menus` をメニュー単位に集計）
- カットオフ後のみ：**請求書払い手数料**（上記メニュー小計の合計＝売上に対する 10%）

**合計金額**

- **§3.1 と同じ式**（メニュー計 ＋ 売上に対する手数料）。

**補足**

- 無料参加では注文ごとの `pay_community_bill_off_amount` がメニュー全額相当となる想定のため、**数値上は「割引総額の合計」と「メニュー集計の合計」が一致し得る**。請求書では **メニュー行で表現**し、§3.3 のような割引表形式は用いない。

---

### 3.3 割引参加（`type: 'discount'`）

**方針**: 主催者への請求の見せ方は **「主催者負担の割引（補填）」の集計**を主とする。**メニュー行は載せない**（飲食の売上と割引補填の二重表現を避ける）。

**明細（イメージ）**

| 割引名称 | 割引金額（1 注文あたり） | 適用件数 | 小計 |
|----------|---------------------------|----------|------|
| 表示用ラベル（例:「割引参加」） | グループ共通の `pay_community_bill_off_amount`（**注文に保存された実額**） | 当該金額の `ordered` 注文件数 | グループ内の `pay_community_bill_off_amount` の合計 |

**行の分割（グルーピング）**

- 対象は `status === 'ordered'` かつ `pay_community_bill_off_amount` が **存在し、整数として 0 より大きい**注文のみとする（未設定・`null`・`0` は集計にも行の適用件数にも含めない）。
- **1 注文あたりの実額**（`pay_community_bill_off_amount` の値）が同一の注文をまとめ、**実額ごとに 1 行**とする。実額のパターンが複数あれば **明細は複数行**になる。
- イベント設定の `off_amount` は請求書の数値表示に**用いない**（設定値とメニュー合計の切り詰め等で注文ごとの実額が変わるため）。**請求・表示のソース・オブ・トゥルースは Order 上の `pay_community_bill_off_amount`** とする。
- **割引名称**: Phase 1 は固定ラベル「割引参加」等（プロダクト文言で統一）でよい。同一ラベルで複数行になる場合は、**実額が異なる行**として区別される。

**Phase 1（単一の `discount` 設定）**

- 全注文の実額が同じであれば **明細は 1 行**。メニュー合計による切り詰め等で実額にばらつきがあれば **その分だけ行が増える**。

**Phase 2 以降（クーポン等）**

- 注文ごとに割引額・種別が異なり得る。グルーピングキーを **クーポンコード・クーポン ID 等**に拡張し、§3.4 のとおり行を分ける（実額が同じでもクーポン別に分けたい場合はキーを複合する）。

**割引総額**

- 全明細行の「小計」の合計（= 対象 `ordered` 注文の `pay_community_bill_off_amount` の総和）。

**割引総額が 0 の場合（実額 > 0 の対象注文が 0 件）**

- **異常系・移行データ**を含み得る前提で仕様化する（例: `type: 'discount'` だが `ordered` に実額 > 0 の注文がない）。
- **請求書 PDF は生成してよい**（既存どおりイベント終了後のフロー）。**割引に関する明細行は 0 行**（表は空、テンプレート上はパディングのみでよい）。
- **割引総額 = 0**、**手数料 = 0**（カットオフ後でも `Math.floor(0 × 0.1) = 0`）。**合計金額 = 0**。
- 税額内訳（§3.3 の合成ルール）は **8%・10% とも実質 0** とする。

**手数料行**

- カットオフ後のみ：**請求書払い手数料**（**割引総額**に対する 10%、切り捨て）
- PDF 上のラベルは既存の「請求書払い手数料」と同じでもよいが、**売上ベースの手数料ではない**ため、誤解を避けるなら「割引補填に対する手数料」等に分けることも可（実装・デザインの判断）。

**合計金額**

- **割引総額 ＋（カットオフ後）割引総額に対する手数料**

**税区分（実装方針）**

- **割引補填本体**（上記「小計」の合計＝割引総額）は、**標準税率 10%** の課税取引として整理する。PDF の 8% / 10% 内訳では、**補填本体を 10% 側**に載せる想定で実装する（税込金額の分解は既存の「請求書払い手数料」と同様の扱い）。`calculateInvoiceTaxBreakdown` の拡張、または割引ブロック専用の税込分解とする。
- 本書の**ビジネス上の合計**は引き続き「割引総額 ＋（カットオフ後）手数料」で定義する。

**税額内訳の合成（§3.3・参考数式）**

補填と手数料を **それぞれ税込 10% の取引**として分解し、§3.1 と同様の PDF 用フィールド（`subTotal` / `tax` / `tax8*` / `tax10*` / `total` 等）へ載せる。**8% 対象はない**（メニュー行がないため）。

記号:

- **S** = **割引総額**（税込・補填本体の合計）
- **F** = **割引に対する手数料**（カットオフ後は `F = floor(S * 0.1)`、カットオフ前は `F = 0`）。これも **税込 10%** として内訳に含める。

各ブロックを **税込 → 税抜・税額**へ分ける（既存の手数料 1 行と同様、税抜は `floor(税込 / 1.1)`、税額は残り）:

- 補填: `subsidyEx = floor(S / 1.1)`，`subsidyTax = S - subsidyEx`
- 手数料: `feeEx = floor(F / 1.1)`，`feeTax = F - feeEx`（`F = 0` なら両方 0）

**PDF 内訳への対応（§3.1 のキーに合わせる想定）**

- **8% 対象**: `tax8Inclusive = 0`，`tax8SubTotal = 0`，`tax8 = 0`
- **10% 対象**: 税抜・税額は **上記 2 ブロックの和**でよい  
  - `tax10SubTotal = subsidyEx + feeEx`  
  - `tax10 = subsidyTax + feeTax`  
  - 検算: **税込合計** `tax10Inclusive` を 1 本だけテンプレに渡す場合は `S + F` と一致させる必要がある（テンプレが「10% 税込合計」を 1 フィールドのみ持つ場合は、内訳行との整合をテンプレ側で確認する）
- **合計（税込）**: `total = S + F`
- **全体の税額**: `tax = tax8 + tax10`（§3.3 では `tax = tax10`）
- **全体の税抜小計**: `subTotal = tax8SubTotal + tax10SubTotal`（§3.3 では `subTotal = tax10SubTotal`）

**補足: 割引補填を 10% とする理由（要約）**

金額の**性格の定義**で税率が分かれ得るが、Shokujii の運営事務としては **一部補填（`discount`）は 10% で揃える**方針とする。

| パターン | 主催者負担の内容のイメージ | 本書での整理 |
|----------|----------------------------|--------------|
| **全額負担（`free`）** | 参加者が払うはずの飲食代金を、そのまま肩代わり。対価は飲食（軽減税率）そのもの。 | **§3.2** のとおり **メニュー明細**で表し、**8%** を適用（既存どおり）。 |
| **一部補填（`discount`）** | 残額は参加者が支払い、主催者分は「特定の食事代の一部」というより **販売促進・サービス支援・協賛金・補填金**に近い性格が付きやすい。 | **割引集計明細**とし、**補填本体は 10%**。 |

- **一部補填でも 8% とする**整理は、運営が「当該金額は飲食代金の一部である」と明確に区分し、**立替・仮受払**として税理と説明できる場合に論理的には可能。その場合は請求書明細に **「飲食代金（一部負担分）」** 等と明記し、税理と合意したうえで実装・区分を変える。
- **プラットフォーム実装の観点**: メニューごとに 8% / 10% を突き合わせると複雑になる。**`discount` の補填は 10% 一律**にすると、実装が単純になり、**税率を低く取り過ぎる**疑義を避けやすい。

---

### 3.4 クーポン（Phase 2 以降・概要）

- `type: 'coupon'` では、**クーポン（または適用パターン）ごと**に行を分け、各グループについて「名称・1 注文あたり実額・適用件数・小計」を集計する。§3.3 と同様、**表示金額は Order の `pay_community_bill_off_amount`（実額）**をソースとし、同一クーポン内で実額が複数パターンあれば **さらに行を分割**してよい。
- 手数料・合計は **§3.3 と同様**（**全行の小計の合計**＝割引総額を基礎に、カットオフ後はその 10% を加算）。
- **割引補填本体の税区分**も **§3.3 と同じく 10%** とする。

## 4. 一覧画面・実装との対応

- コミュニティ管理の請求書一覧で表示する「金額」は、**PDF の合計金額と同一の式**とする。
- **分岐（必須）**:
  - **§3.1 / §3.2** および **§1 の「割引設定なし」**（`undefined` / `null` / `{}` を含む）: **メニュー計 ＋（カットオフ後）売上に対する手数料**（現行の [common/src/utils/invoice.ts](../../common/src/utils/invoice.ts) `calculateInvoiceTotal` と同じ考え方）。
  - **§3.3 / §3.4**（`type: 'discount'` および将来の `coupon`）: **割引総額 ＋（カットオフ後）割引総額に対する手数料**（§3.3 の合計定義）。メニュー計ベースの `calculateOrdersTotal` のみでは一致しない。
- 実装では [user/src/components/manage/community/invoice.vue](../../user/src/components/manage/community/invoice.vue) の表示ロジックを、`community_bill_settings`（§1 の判定を含む）に応じて上記のいずれかを呼ぶ、または [common/src/utils/invoice.ts](../../common/src/utils/invoice.ts) に **PDF と共有の合計関数**を置き、一覧・PDF の双方から利用する。
- PDF 生成: [functions/default/src/eventBillInvoice.ts](../../functions/default/src/eventBillInvoice.ts)  
- 共通計算: [common/src/utils/invoice.ts](../../common/src/utils/invoice.ts)

## 6. PDF テンプレート・明細行数（実装タスク）

- 現行 [functions/default/src/eventBillInvoice.ts](../../functions/default/src/eventBillInvoice.ts) は `INVOICE_ITEMS_PADDING` により、明細枠が **おおよそ固定行数**（現状 12）で設計されている。
- **§3.3** では **実額グループごとの行数 ＋（カットオフ後）手数料行** が明細に載るため、**グループ数が多いと 1 ページの行上限を超えうる**。
- 実装時は次のいずれか（または併用）を **Issue / タスクとして切る**こと。
  - **複数ページ**用テンプレート、または明細超過時の **ページ分割**。
  - テンプレートの **可変行**対応（Adobe Document Merge の制約に依存）。
  - **明細行の上限**を仕様化し、超過分は **集約行**（例:「その他」）にまとめる（要プロダクト判断）。
