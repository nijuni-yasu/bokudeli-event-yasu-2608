# 注文期限超過時の注文期限メール

## 1. 概要

### 1.1 機能の目的

注文期限を過ぎた後に決済が完了した場合、お店に追加で注文締切メールを送信し、注文を取りこぼさないようにする。

### 1.2 背景・課題

現状、以下の問題が発生しうる。

1. 注文期限直前（5〜15分前など）に決済を開始し、決済完了が注文期限を超過するケースがある
2. 注文期限到来時に `pollingTask` がお店に注文締切メールを送信するが、この時点ではまだ `in_cart` 状態の注文は含まれない
3. その後 Webhook で `ordered` に遷移しても、お店には伝わらない

### 1.3 対応方針

- **返金は行わない**: 注文期限後の注文はレアケースのため、返金処理は行わず注文をそのまま受け入れる
- **お店に追加メールを送信**: `onOrderChanged` トリガーで期限超過を検知し、既存の注文締切メールと同じテンプレートでお店に再送信する
- **テンプレートは共通化**: 既存の `ORDER_DEADLINE_TEMPLATE_ID` をそのまま使用し、`late_order_notice` フラグで追記文面を表示する
- **Checkout Session の有効期限**: `expires_at` を 30 分に設定し、決済画面の有効期限を短くする

### 1.4 対象ユーザー

- イベント参加者（決済を行うユーザー）
- お店（追加メールの受信者）

## 2. 処理フロー

### 2.1 正常フロー（注文期限内に決済完了）

```
ユーザーが「決済する」ボタンを押す
  → [stripe.ts] 注文期限チェック ✓
  → [stripe.ts] Stripe Checkout Session 作成（expires_at: 30分後）
  → Stripe 決済画面に遷移
  → ユーザーが決済完了
  → [stripeWebhook.ts] checkout.session.completed 受信
  → order.status を 'ordered' に更新、saveOrder
  → コミュニティにメンバー追加
  → [onOrderChanged] Firestore 更新を検知してトリガー
  → [onOrderChanged] 注文期限チェック ✓（期限内）
  → [onOrderChanged] 注文完了メールを送信
  → 通常の success_url リダイレクト、成功モーダル表示
```

※ お店への注文締切メールは `pollingTask` で送信済みのため、`onOrderChanged` では送信しない。

### 2.2 拒否フロー（注文期限を過ぎた後にセッション作成を試行）

```
ユーザーが「決済する」ボタンを押す
  → [stripe.ts] 注文期限チェック ✗（期限超過）
  → HttpsError('failed-precondition', '注文期限を過ぎています') をスロー
  → フロントでエラーメッセージを表示
```

### 2.3 追加メール送信フロー（決済中に注文期限を超過）

```
ユーザーが「決済する」ボタンを押す（注文期限の数分前）
  → [stripe.ts] 注文期限チェック ✓（この時点ではまだ期限内）
  → [stripe.ts] Stripe Checkout Session 作成（expires_at: 30分後）
  → Stripe 決済画面に遷移
  → ★ 注文期限到来（決済操作中）
  → ★ pollingTask: お店に注文締切メール送信（この注文は含まれない）
  → ユーザーが決済完了
  → [stripeWebhook.ts] checkout.session.completed 受信
  → order.status を 'ordered' に更新、saveOrder
  → コミュニティにメンバー追加
  → [onOrderChanged] Firestore 更新を検知してトリガー
  → [onOrderChanged] 注文期限チェック ✗（ordered_at > event_deadline_datetime）
  → [onOrderChanged] お店に追加メール送信（late_order_notice 付き）
  → [onOrderChanged] 注文完了メールを送信
  → 通常の success_url リダイレクト、成功モーダル表示
```

## 3. 変更対象ファイルと実装内容

### 3.1 `functions/default/src/stripe.ts`（セッション作成時チェック・expires_at）

- イベント取得後に `event_deadline_datetime` と現在時刻を比較
- 注文期限を過ぎていた場合は `HttpsError('failed-precondition', '注文期限を過ぎています')` をスロー
- Stripe Checkout Session 作成時に `expires_at` を 30 分後に設定
  - Stripe の制約により最短 30 分〜最長 24 時間
  - `expires_at: Math.floor(Date.now() / 1000) + 30 * 60`（Unix 秒）

### 3.2 `functions/default/src/orderCompletionMail.ts`（onOrderChanged の拡張）

#### 処理の挿入位置

既存の `status === 'ordered'` の分岐内、注文完了メール送信と並列で実行する。

```
if (before?.get('status') !== after?.get('status') && after?.get('status') === 'ordered') {
  // ...既存: 注文完了メール、主催者メール、新着イベント通知...

  // ★ 追加: 注文期限超過チェック
  const orderedAt = after.get('ordered_at')
  if (orderedAt != null && afterEvent.event_deadline_datetime < orderedAt) {
    promises.push(sendLateOrderNotificationToShop(afterEvent))
  }
}
```

#### 期限超過の判定条件

- `ordered_at` が存在し、かつ `event_deadline_datetime < ordered_at` の場合に期限超過とみなす
- `ordered_at` は `saveOrder` で設定されるため、`onOrderChanged` 発火時点で存在する

#### 依存の追加

- `sendLateOrderNotificationToShop` を `./orderDeadlineMail.js` から import

※ `onOrderChanged` は既に `secrets: ['SENDGRID_API_KEY']` を指定しているため、追加不要。

### 3.3 `functions/default/src/orderDeadlineMail.ts`（追加メール送信関数）

#### 型定義の拡張

`TemplateDataForOrderDeadline` に `late_order_notice?: string` を追加する。

```typescript
interface TemplateDataForOrderDeadline {
  // ...既存フィールド
  is_reminder?: boolean
  late_order_notice?: string  // 追加: 注文期限後の追加注文時に設定
}
```

#### 新規関数 `sendLateOrderNotificationToShop`

- 引数: `event: ShokujiiEvent`
- 処理内容:
  1. `createTemplateDataForOrderDeadline(event)` でテンプレートデータを取得（同ファイル内の private 関数を利用）
  2. `late_order_notice` に以下の文言を設定
  3. `getEventPartnerShop(event)` でショップ情報を取得
  4. `ORDER_DEADLINE_TEMPLATE_ID` を使って `sgMail.send` で送信（`cc: SUPPORT_MAIL` を含む）
- エラーハンドリング: `sendOrderDeadlineMailToShop` と同様に `logger.warn` でログ出力し、例外は握りつぶす

#### `late_order_notice` の文言（最終案）

```
【追加注文のご連絡】
注文期限後に決済を完了したご注文が発生したため、追加注文をご連絡いたします。
※決済はStripeという外部システムに依存しており、決済セッションの有効期限の関係上、注文期限から最大30分の間は追加注文が発生する場合がございます。
今回、該当する追加注文がございました。誠に恐れ入りますがご確認の上、ご対応をお願いいたします。
```

※ 改行は `\n` で表現する。SendGrid テンプレートで `{{late_order_notice}}` を表示する際、改行が反映されるようテンプレート側で設定する。

#### `createTemplateDataForOrderDeadline` について

- 既存の private 関数をそのまま利用
- `createOrdersForOrderDeadline` は `event.getOrders('ordered')` で注文を取得するため、`onOrderChanged` 発火時点では既に `saveOrder` 済みの今回の注文が含まれる

### 3.4 SendGrid テンプレート（`ORDER_DEADLINE_TEMPLATE_ID`）

- テンプレートIDは変更しない
- Handlebars の条件分岐で `late_order_notice` がある場合に追記文面を表示する
- 表示位置: メール冒頭または注文一覧の直前

```
{{#if late_order_notice}}
{{late_order_notice}}
{{/if}}

（以下、既存の注文一覧等）
```

※ 既存の `is_reminder` と同様のパターンで実装する。

## 4. 注意事項

### 4.1 stripeWebhook は変更しない

追加メール送信のトリガーは `onOrderChanged` に集約する。`stripeWebhook` は注文の更新とコミュニティメンバー追加のみ行い、メール送信ロジックは含めない。

### 4.2 注文は通常どおり受け入れる

返金は行わず、`order.status` は `'ordered'` のまま。`onOrderChanged` による注文完了メールも通常どおり送信される。フロントの成功モーダルも変更不要。

### 4.3 スキーマ・フロント変更なし

- 新ステータス（`deadline_refunded` 等）の追加は不要
- フロントエンドの変更は不要

### 4.4 expires_at について

Stripe Checkout Session の `expires_at` は最短 30 分〜最長 24 時間の制約がある。30 分に設定することで、セッション作成から 30 分経過すると決済画面が無効化される。注文期限の数分前に決済を開始した場合、期限超過後に決済を完了する可能性は残るが、30 分を超えて放置されたセッションは自動的に無効化される。

### 4.5 お店への影響

お店は注文締切メールを既に受け取っている可能性がある。追加メールには `late_order_notice` の文言（3.3 参照）で、注文期限後の注文であること・決済システムの仕様によるものであることを伝える。

### 4.6 冪等性

`onOrderChanged` は Firestore の document write で 1 回だけトリガーされる。同一注文に対する重複送信は発生しない。

### 4.7 開発工数

変更ファイルは `stripe.ts`、`orderCompletionMail.ts`、`orderDeadlineMail.ts` の 3 ファイル + SendGrid テンプレートの編集のみ。工数は低い。
