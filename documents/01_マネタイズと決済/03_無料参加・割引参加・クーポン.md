# 無料参加・割引参加・クーポン機能

## 1. 概要

### 1.1 機能の目的
イベント主催者が参加者に対して「無料参加」「割引参加」「クーポン参加」のいずれかの割引設定を行える機能を提供し、参加者の参加障壁を下げてイベントの集客を促進する。

### 1.2 主要な機能
- 無料参加設定：参加費を全額主催者が負担し、参加者は¥0で参加可能
- 割引参加設定：一部金額を主催者が負担し、残額を参加者が支払う
- クーポン設定：条件を満たす参加者に対してクーポン割引を適用（コード入力式）
- 割引タイプ別の表示制御：イベントカードや、イベントページでのラベル表示、決済画面での価格表示
- 主催者への請求書：無料参加、割引参加、クーポンで割引いた金額は、主催者請求書機能において請求する。

### 1.3 対象ユーザー
- イベント主催者：割引設定を行う側
- イベント参加者：割引を利用する側

## 2. ねらい

### 2.1 ビジネス目標
- イベント参加率の向上
- 新規参加者の獲得促進
- 主催者のイベント運営コスト最適化

### 2.2 ユーザー価値
- 主催者：参加者の参加障壁を下げて集客効果を向上
- 参加者：経済的負担を軽減してイベント参加を促進
- 学生や経済的制約のある参加者への配慮

### 2.3 成功指標（KPI）
- 割引設定イベントの参加率向上率
- クーポン利用率
- 新規参加者の獲得数
- 主催者の満足度（アンケート）

## 3. 前提条件

### 3.1 技術的前提条件
- 既存の決済システムとの連携
- Firestoreでのデータ管理
- フロントエンドでの表示制御
- バリデーション機能

### 3.2 ビジネス的前提条件
- 主催者が割引費用を負担する仕組み
- クーポンの不正利用防止

### 3.3 依存関係
- イベント作成・編集機能
- 決済システム（Stripe）
- 請求書機能

### 3.4 `event_payment` との関係

本機能（`community_bill_settings`）は、イベントの `event_payment` が `'community_bill'`（主催者 請求書払い）の場合にのみ設定可能。

| `event_payment` | `community_bill_settings` | Stripe決済 |
|---|---|---|
| `user_advance`（クレカ前払い） | 設定不可 | 全額Stripe決済 |
| `community_bill` + 割引設定なし | なし | 決済なし（全額・主催者請求書払い） |
| `community_bill` + `free`（無料参加） | `{ type: 'free' }` | 決済なし（全額・主催者請求書払い） |
| `community_bill` + `discount`（割引参加） | `{ type: 'discount', off_amount }` | 差額が ¥0 より大きい場合は Stripe 決済、¥0 の場合は決済なし（5.3.2）。主催者負担は請求書で算定 |
| `community_bill` + `coupon`（Phase 2以降） | `{ type: 'coupon', coupons }` | 同上（5.3.2） |

### 3.5 `community_bill_settings` の未設定・空

- `event_payment` が `'community_bill'` であっても、`community_bill_settings` が**未設定**、または**空オブジェクト**のときは、**3.4 の「`community_bill` + 割引設定なし」と同一**として扱う（割引なし。Order の `payment_community_bill_off_amount` は付けない）。
- 既存の過去データで表現が揺れている場合は、**`bokudeli-event-batch` リポジトリの `tasks` でマイグレーション**し、正規化する（Firestore の一括更新の正本は batch。手順は `documents/デプロイ手順/デプロイ手順.md`、必須化まわりの詳細は `03_無料参加・割引参加_EventMemberOrder対応.md` の **5.1.3**）。

### 3.6 割引設定の変更（運用前提）

- **イベント公開後、または参加者がカート・注文に関与しうるタイミング以降、割引設定（`community_bill_settings`）を変更することは想定しない**（変更不可とする）。そのため、主催者のみが設定を書き換えた結果、参加者のカートに古い `payment_community_bill_off_amount` が残るケースは**仕様上起きない**前提とする。
- **注文確定時のサーバー側再計算・整合検証は最終の正**（5.3.2・5.3.3）。

## 5. 技術仕様・データ構造設計

### 5.1 Firestoreスキーマ

本機能で新規に定義するフィールド名（クーポン設定・クーポン使用履歴を含む）は **snake_case** とする。

#### 5.1.1 コレクション構成

```
communities/{communityId}/events/
├── {eventId}/
│   ├── community_bill_settings (フィールド)
│   ├── orders/ (サブコレクション)
│   │   └── {orderId}/
│   │       ├── ... (既存フィールド)
│   │       └── payment_community_bill_off_amount (フィールド)
│   └── coupon_usage/ (サブコレクション・Phase 2以降)
│       └── {couponUsageId}/
│           ├── coupon_code
│           ├── user_id
│           ├── used_at
│           └── discount_amount
```

#### 5.1.2 イベントドキュメント拡張
```typescript
// 既存のイベントドキュメントに追加
interface EventDocument {
  // ... 既存フィールド ...

  // 割引設定（event_payment が 'community_bill' の場合にのみ設定可能）
  // Phase 1: type は 'free' | 'discount' のみ
  // Phase 2: type に 'coupon' を追加
  community_bill_settings?: {
    type: 'free' | 'discount';           // Phase 1
    // type: 'free' | 'discount' | 'coupon'; // Phase 2で拡張
    off_amount?: number;       // 割引金額（discount時のみ）
    // coupons?: CouponConfig[];  // クーポン設定（coupon時・Phase 2以降）
  };

  // ※ 請求関連の以下の値はFirestoreに保持しない（都度算出する）
  //   - 割引総額: 全注文(ordered)の payment_community_bill_off_amount の合計
  //   - 手数料率: 10%固定
  //   - 手数料: 割引総額 × 0.1
  //   - 請求合計: 割引総額 × 1.1
}

// Phase 2以降（Firestore 保存時は snake_case）
interface CouponConfig {
  name: string;         // クーポン名称

  quantity: number;     // 発行数（枠数）
  code: string;         // クーポンコード
  redeemed: number;     // 使用済数（サーバー管理）
  created_at: Timestamp; // 作成日時
  updated_at: Timestamp; // 更新日時
}
```

#### 5.1.5 注文ドキュメント（Order）

```typescript
  // in_cart から保持する。カート更新用 Callable がイベントの community_bill_settings とメニュー合計から算出し同一トランザクションで更新する（5.1.5 参照）。クライアントからの任意書き込みは不可（5.2.1・7.2）。

```

##### `payment_community_bill_off_amount` の値の決まり方

請求書では「全注文の本フィールドの合計」を割引総額として用いる（5.3.4）。そのため、**イベント設定の生の値をそのまま保存するのではなく、当該注文に実際に適用された主催者負担額**を保存する。これにより、設定の `off_amount` がメニュー合計を超えるケースでも請求側で再度 `min` 計算する必要がない。

| 割引タイプ | 値 | 例 |
|---|---|---|
| 無料参加 (`free`) | メニュー合計金額（= 全額負担） | メニュー合計 ¥1,200 → `1200` |
| 割引参加 (`discount`) | `min(community_bill_settings.off_amount, メニュー合計金額)` | 設定 ¥500・メニュー合計 ¥1,200 → `500`／設定 ¥500・メニュー合計 ¥300 → `300`（切り詰めと同じ値） |
| クーポン (`coupon`) | Phase 2以降: `min(クーポン割引額, メニュー合計金額)` を同様に保存 | — |
| 割引なし | **フィールドなし**（`undefined`。`0` は保存しない） | — |

##### カート中の `payment_community_bill_off_amount` の更新

- **`status` が `in_cart` の段階から** Order に `payment_community_bill_off_amount` を持てる（割引が適用される場合）。**割引なし**のときは**フィールドを付けない**（`undefined`。`0` は保存しない）。
- **カート更新用 Callable**（メニュー追加・数量変更・削除など）内で、イベントドキュメントの `community_bill_settings` と当該 Order の `menus` から **5.1.5 の表どおり**算出し、**`menus` の更新と同一トランザクション**で `payment_community_bill_off_amount` を書き込むか、該当しない場合はフィールドを削除する（追加ボタン連打などへの対策）。
- 算出は **Firebase Functions 上のみ**行い、**クライアントがこのフィールドを任意の値で更新できない**こと（Firestore ルールまたは Callable 経由のみ）。
- 以前の草案では「カート中はフロントのみ算出」としていたが、**改ざん防止と表示の単一ソース化**のため、本仕様ではサーバー算出・Order 保存に変更した。

##### 参加者の支払額の算出

```
支払額 = menus の合計金額 - (payment_community_bill_off_amount ?? 0)
```

`payment_community_bill_off_amount` は上表どおり実適用額であるため、無料参加・割引後が ¥0（`off_amount` がメニュー合計以上で切り詰めた場合を含む）では支払額が `0` になる。

##### Stripe 決済金額の保持

- Order に **Stripe の請求額だけを重複保存するフィールドは新設しない**（決済金額専用の冗長フィールドは持たない）。
- 決済処理・払い戻しで用いる参加者負担額は、**メニュー合計**と **`payment_community_bill_off_amount`** から、上記「参加者の支払額の算出」と**同一の式で都度算出**する。
- 将来、ユーザー向けのシステム利用料などを加算する場合は、**`payment_user_fee_amount` など内訳用のフィールド**を注文に追加し、合計額は `メニュー合計 − payment_community_bill_off_amount + （利用料等）` のように**部品の和差で算出**する方針とする（それでも Stripe 請求額専用フィールドは新設しない）。
- 実際に Stripe に課金された金額の突合・返金上限の確認が必要な場合は、既存の **`payment_intent`** により Stripe API から取得する。

##### Stripe 連携（`community_bill` で差額が発生する場合）

- 参加者が支払う**差額**は **Stripe Checkout Session** で課金する（既存が PaymentIntent / Elements の経路でも、**差額分は Checkout で行う想定**）。
- **通貨は JPY**。金額は**円の整数**。海外展開・多通貨は現時点では対象外とする。
- Order と Stripe の紐づけは、既存の **`user_advance`（クレカ前払い）の Stripe 決済と同様に**、Order の **`payment_intent`**（Stripe PaymentIntent ID）で行う。
- **決済成功の確定**、失敗・タイムアウト・ユーザー離脱時の **`in_cart` のまま／再試行**、**冪等性**（同一注文の二重決済・二重 `ordered` 防止）は、**`user_advance` の Stripe 決済と同じ**運用・実装に準拠する。

### 5.2 Functions設計

#### 5.2.1 Callable Functions（フロントエンドから呼び出し）
- **カート更新**（メニュー追加・数量変更・削除など）: Order の `menus` を更新すると同時に、`community_bill_settings` とメニュー合計から `payment_community_bill_off_amount` を算出し、**同一トランザクション**で更新する（5.1.5「カート中の `payment_community_bill_off_amount` の更新」参照）。割引が適用されない場合は**フィールドを付けない**（`0` は保存しない）。具体的な関数名は実装に委ねる。
- `updateEventDiscountSettings`: イベントの割引設定を更新
  - **引数**: `eventId: string`, `settings: DiscountSettings`
  - **戻り値**: `{ success: boolean, message: string }`
  - **認証**: イベント主催者のみ

- `validateCoupon`（Phase 2以降）: クーポンの有効性を検証
  - **引数**: `event_id: string`, `coupon_code: string`
  - **戻り値**: `{ valid: boolean, discount_amount: number, message: string }`
  - **認証**: 認証済みユーザー

- `applyCoupon`（Phase 2以降）: クーポンを適用
  - **引数**: `event_id: string`, `coupon_code: string`, `user_id: string`
  - **戻り値**: `{ success: boolean, discount_amount: number, message: string }`
  - **認証**: 認証済みユーザー

#### 5.2.2 Trigger Functions（自動実行）
- `onCouponUsage`（Phase 2以降）: クーポン使用時の処理
  - **トリガー**: `communities/{communityId}/events/{eventId}/coupon_usage`サブコレクションの作成
  - **処理内容**: イベントのクーポン使用済数を更新
  - **権限**: システム権限

### 5.3 処理フロー

#### 5.3.1 割引設定の更新
1. 主催者がイベント編集画面で `event_payment` に `'community_bill'` を選択
2. 割引タイプ選択欄が表示される（`event_payment` が `'community_bill'` の場合のみ）
3. 選択したタイプに応じて詳細設定を入力
4. バリデーション実行（5.3.3 参照）
5. Firestoreのイベントドキュメントを更新
6. 成功メッセージを表示

#### 5.3.2 注文確定時の決済フロー（支払い方法別）

注文確定処理では、**当該時点の**イベント `community_bill_settings` と Order の `menus` から `payment_community_bill_off_amount` を **サーバー側で再計算し、Order に保存済みの値と整合するか検証**する（クライアントの改ざん防止）。カート更新時に既に同一の式で保存されている想定（5.1.5）。

##### `community_bill` + `free`（無料参加）
1. カート画面で割引後価格 ¥0 を表示（Order の `payment_community_bill_off_amount` および `menus` に基づく）
2. 注文確定ボタン押下
3. サーバーで `payment_community_bill_off_amount` がメニュー合計と一致することを確認する
4. Stripe決済なし。直接 `status: 'ordered'` に変更
5. `payment_community_bill_off_amount` はカート時点で既にメニュー合計相当が入っているため、**新規に別値を書き換える必要はない**（整合確認のみ）

##### `community_bill` + `discount`（割引参加）
1. カート画面で割引後価格を表示（同上）
2. 注文確定ボタン押下
3. サーバーで実効の主催者負担額 `min(off_amount, メニュー合計)` と Order の `payment_community_bill_off_amount` が一致することを確認する
4. 支払額 = メニュー合計 − 実効負担額 とする
5. **支払額が ¥0 の場合**（無料参加と同様）: Stripe 決済は行わず、直接 `status: 'ordered'` に変更する
6. **支払額が ¥0 より大きい場合**: その支払額を Stripe Checkout Session で決済し（5.1.5「Stripe 連携」）、決済成功後に `status: 'ordered'` に変更する。Order には **`payment_intent` を保存**する（`user_advance` と同様）
7. `payment_community_bill_off_amount` はカート更新時に既に実効負担額が入っているため、**確定時は整合確認が主**（不整合時はエラー）

##### `community_bill` + 割引設定なし
1. 既存の `community_bill` フローと同じ（Stripe決済なし）
2. `payment_community_bill_off_amount` は保存しない

##### `community_bill` + `coupon`（Phase 2以降）
1. カート画面でクーポンコードを入力し割引適用
2. 実効の主催者負担額を `min(クーポン割引額, メニュー合計)` とし、支払額 = メニュー合計 − 実効負担額 とする（クーポン適用時もカート更新 Callable で `payment_community_bill_off_amount` を更新）
3. **支払額が ¥0 の場合**: Stripe 決済は行わず、直接 `status: 'ordered'` に変更する
4. **支払額が ¥0 より大きい場合**: その支払額を Stripe Checkout Session で決済し、決済成功後に `status: 'ordered'` に変更する。`payment_intent` を保存
5. 注文確定時はサーバーで `payment_community_bill_off_amount` の整合を確認する（割引参加と同様）

##### `user_advance`（クレカ前払い）
- 割引設定不可。全額Stripe決済（既存フローのまま）

#### 5.3.3 バリデーション処理

##### イベント設定時（主催者側）
1. `community_bill_settings` は `event_payment` が `'community_bill'` の場合のみ設定可能
2. `discount` の場合: `off_amount` が 0 より大きい整数であることを確認

##### 注文確定時（参加者側）
1. **サーバー側**で、イベントの `community_bill_settings` と Order の `menus` から `payment_community_bill_off_amount` を再計算し、Order に保存されている値と一致すること（Callable 等）。一致しない場合はエラーとする。
2. `discount` の場合: `off_amount` がメニュー合計金額を超えていないことを確認
   - 超える場合はメニュー合計金額に切り詰める（支払額 ¥0）
   - 切り詰めの結果、支払額が ¥0 になる場合は、**無料参加（5.3.2 の `free`）と同様に Stripe 決済を行わず**、直接 `status: 'ordered'` とする（Phase 1.3）

##### Phase 2以降（クーポン関連）
1. クーポンコードが一意であることを確認
2. クーポン枠数が正の整数であることを確認
3. 使用済数が発行枠を超えていないことを確認

#### 5.3.4 請求処理
1. `payment_community_bill_off_amount` はカート更新時から Order に保存され、注文確定時にサーバーで整合確認される（5.1.5）。請求集計では **確定済み注文**の当該フィールドを用いる。
2. 請求書作成時に、対象イベントの全注文（`status: 'ordered'`）の `payment_community_bill_off_amount` を集計
   - キャンセルされた注文（`status: 'canceled'`）は集計対象外。フィールドはそのまま残る
   - 割引なしの注文はフィールドがないため **合計に加算しない**（5.1.5）
3. 請求額の算出:
   - 割引総額 = 全注文（`status: 'ordered'`）の `payment_community_bill_off_amount` の合計
   - 手数料 = 割引総額 × 0.1（10%固定）
   - 請求合計 = 割引総額 + 手数料
4. クーポン使用時は、使用履歴を `coupon_usage` サブコレクションに記録（Phase 2以降）

#### 5.3.5 キャンセル・払い戻し（Phase 1.3）

- **Stripe で差額を支払った注文**（`payment_intent` がある場合）: 既存の **`user_advance`（クレカ前払い）と同様**に、**Stripe へ支払った金額の全額払い戻し**を行う。
- **支払額 ¥0**（無料参加、割引後 ¥0 で Stripe 未使用）: **Stripe の払い戻し処理は不要**。
- **`community_bill` かつ割引設定なし**（従来どおり Stripe なし）: **払い戻し不要**。キャンセルフローは上記と同様に、**Stripe を使っていない注文には返金処理をかけない**。

#### 5.3.6 領収書（`receipt_number`）

- **無料参加**および **割引後 ¥0 で Stripe 決済がない注文**では、**領収書を発行しない**（`receipt_number` を付与しない）。
