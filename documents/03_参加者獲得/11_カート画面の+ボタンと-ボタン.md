# カート画面の+ボタンと-ボタン

## 1. 概要
### 1.1 機能の目的
カート画面でメニューの個数を直感的に調整できるようにするため、「+ボタン」と「-ボタン」を実装する。現状のゴミ箱アイコンによる削除機能を置き換え、ユーザビリティを向上させる。

### 1.2 主要な機能
- メニュー個数の増減機能（+ボタン/-ボタン）
- 個数が1個の時のゴミ箱ボタン表示（削除確認ダイアログ付き）
- 個数更新時のトランザクション処理
- `delete_order`機能の`functions/default`への移行

### 1.3 対象ユーザー
- イベント参加者（カートに商品を追加したユーザー）

## 2. ねらい
### 2.1 ビジネス目標
- カート操作のユーザビリティ向上による注文離脱率の削減
- 個数調整の容易さによる注文数の増加

### 2.2 ユーザー価値
- メニュー個数の調整が直感的に操作できる
- 削除操作の誤操作を防ぐ（1個の時のみ確認ダイアログ表示）

### 2.3 成功指標（KPI）
- カート画面での操作完了率
- カート画面からの離脱率の改善

## 3. 前提条件
### 3.1 技術的前提条件
- Firebase Functions v2（`functions/default`）を使用
- TypeScriptで実装
- Firestoreトランザクションを使用したデータ整合性の保証
- 型定義による型安全性の保証

### 3.2 ビジネス的前提条件
- 注文ステータスが`in_cart`の注文のみ操作可能
- 認証済みユーザーのみ操作可能
- 自分の注文のみ操作可能

### 3.3 依存関係
- `EventOrder`スキーマ（`common/src/schemas/EventOrder.ts`）
- `stores/order.ts`（`functions/default/src/stores/order.ts`）
- 既存の`delete_order`機能（`functions/legacy/src/orders.js`）
- カート画面コンポーネント（`base/src/components/pages/cart.vue`）

## 4. 画面仕様
### 4.1 画面遷移
カート画面内での操作のみ（画面遷移なし）

### 4.2 UI要素
#### 4.2.1 ボタン・アクション
- **+ボタン**
  - カラー: 既存のゴミ箱ボタンと同じ（デフォルト）
  - アクション: メニュー個数を1増やす（確認ダイアログなし）
  - アイコン: テキスト「+」

- **-ボタン（個数が2個以上の場合）**
  - カラー: 既存のゴミ箱ボタンと同じ（デフォルト）
  - 状態: 個数が2個以上の時有効
  - アクション: メニュー個数を1減らす（確認ダイアログなし）
  - アイコン: テキスト「-」

- **ゴミ箱ボタン（個数が1個の場合）**
  - カラー: 既存のゴミ箱ボタンと同じ（デフォルト）
  - 状態: 個数が1個の時のみ表示
  - アクション: 削除確認ダイアログを表示
  - アイコン: `mdiTrashCan`

#### 4.2.2 表示要素
- **個数表示**
  - 表示内容: 現在のメニュー個数
  - 条件: 常に表示
  - 配置: 「-」ボタンと「+」ボタンの間

- **削除確認ダイアログ**
  - 表示内容: 「商品を削除しますか？」
  - ボタン: 「削除」「キャンセル」
  - 条件: ゴミ箱ボタンクリック時のみ表示

#### 4.2.3 UIレイアウト
- 表示形式: 「- 個数 +」（個数が2個以上の場合）
- 表示形式: 「🗑️ 個数 +」（個数が1個の場合）
- 例: 「- 2 +」「- 3 +」「🗑️ 1 +」

#### 5.6.1 Callable Functions（フロントエンドから呼び出し）

##### updateMenuCountInCart
```typescript
// functions/default/src/orders.ts（新規作成）
import { onCall, HttpsError } from 'firebase-functions/https'
import { getFirestore } from 'firebase-admin/firestore'
import { UpdateMenuCountInCartRequest } from '@shokujii/common/apis/order.js'
import { getOrder, saveOrder, deleteOrder } from './stores/order.js'

const db = getFirestore()

export const updateMenuCountInCart = onCall<UpdateMenuCountInCartRequest, Promise<void>>(
  async (request) => {
    // 認証チェック
    const uid = request.auth?.uid
    if (uid == null) {
      throw new HttpsError('unauthenticated', '認証が必要です')
    }
    
    // 引数の取得
    const { community_id, event_id, order_id, menu_id, count } = request.data
    
    // 基本的なバリデーション
    if (count == null || !Number.isInteger(count) || count < 1) {
      throw new HttpsError('invalid-argument', 'count は1以上の整数である必要があります')
    }
    
    return db.runTransaction(async (transaction) => {
      // stores を使用して注文を取得
      const order = await getOrder(community_id, event_id, order_id, transaction)
      
      // 注文存在チェック
      if (order == null) {
        throw new HttpsError('not-found', `注文が見つかりません`)
      }
      
      // 権限チェック
      if (order.user_id !== uid) {
        throw new HttpsError('permission-denied', `権限がありません: ${uid}`)
      }
      
      // ステータスチェック
      if (order.status !== 'in_cart') {
        throw new HttpsError('invalid-argument', `カート内の注文ではありません`)
      }
      
      const menuIndex = order.menus.findIndex((m) => m.menu_id === menu_id)
      
      // メニュー存在チェック
      if (menuIndex === -1) {
        throw new HttpsError('not-found', `メニューが見つかりません: ${menu_id}`)
      }
      
      // 個数更新
      const updatedMenus = [...order.menus]
      updatedMenus[menuIndex] = {
        ...updatedMenus[menuIndex],
        count: count,
      }
      
      // 個数が0になった場合はメニューを削除（deleteMenuInCartと同じ動作）
      const filteredMenus = updatedMenus.filter((m) => m.count > 0)
      
      if (filteredMenus.length === 0) {
        // メニューが0個になった場合は注文を削除
        await deleteOrder(community_id, event_id, order_id, transaction)
      } else {
        // メニューを更新
        order.menus = filteredMenus
        await saveOrder(community_id, event_id, order, transaction)
      }
    })
  }
)
```

### 5.7 処理フロー
#### 5.7.1 個数増加（+ボタン）の処理フロー
1. ユーザーがカート画面で「+ボタン」をクリック
2. フロントエンドでバリデーション
3. Callable Function `updateMenuCountInCart`を呼び出し（`count: 現在の個数 + 1`）
4. Firebase Functionで認証チェック
   - 失敗時: 認証エラーを返却
5. 引数の基本的なバリデーション（count が1以上の整数であることをチェック）
   - 失敗時: バリデーションエラーを返却
6. トランザクション内で以下を実行:
   - stores を使用して注文を取得
   - 注文存在チェック
   - 権限チェック（ユーザーID一致）
   - ステータスチェック（`in_cart`）
   - メニュー存在チェック
   - 個数を更新（`updated_at`は`toFirestore()`内で自動更新）
   - stores を使用して注文を保存
7. レスポンスをフロントエンドに返却
8. フロントエンドでカート情報を再取得・表示

#### 5.7.2 個数減少（-ボタン）の処理フロー
1. ユーザーがカート画面で「-ボタン」をクリック（個数が2個以上の場合）
2. フロントエンドでバリデーション（個数が2以上であることをチェック）
3. Callable Function `updateMenuCountInCart`を呼び出し（`count: 現在の個数 - 1`）
4. Firebase Functionで認証チェック
   - 失敗時: 認証エラーを返却
5. 引数の基本的なバリデーション（count が1以上の整数であることをチェック）
   - 失敗時: バリデーションエラーを返却
6. トランザクション内で以下を実行:
   - stores を使用して注文を取得
   - 注文存在チェック
   - 権限チェック（ユーザーID一致）
   - ステータスチェック（`in_cart`）
   - メニュー存在チェック
   - 個数を更新（`updated_at`は`toFirestore()`内で自動更新）
   - 個数が0になった場合はメニューを配列から削除
   - メニューが0個になった場合は stores を使用して注文を削除
   - それ以外の場合は stores を使用して注文を保存
7. レスポンスをフロントエンドに返却
8. フロントエンドでカート情報を再取得・表示

#### 5.7.3 削除（ゴミ箱ボタン）の処理フロー
1. ユーザーがカート画面で「ゴミ箱ボタン」をクリック（個数が1個の場合）
2. フロントエンドで削除確認ダイアログを表示
3. ユーザーが「削除」をクリック
4. Callable Function `deleteMenuInCart`を呼び出し
5. Firebase Functionで認証チェック
   - 失敗時: 認証エラーを返却
6. 引数の基本的なバリデーション（型安全性による保証）
7. トランザクション内で以下を実行:
   - stores を使用して注文を取得
   - 注文存在チェック
   - 権限チェック（ユーザーID一致）
   - ステータスチェック（`in_cart`）
   - メニューを配列から削除
   - メニューが0個になった場合は stores を使用して注文を削除
   - それ以外の場合は`updated_at`は`toFirestore()`内で自動更新され、stores を使用して注文を保存
8. レスポンスをフロントエンドに返却
9. フロントエンドでカート情報を再取得・表示
10. 成功メッセージ「カートから削除しました」を表示
