# イベントタグ機能

> **関連**: [04_プロフィールタグ機能.md](./04_プロフィールタグ機能.md)（参加者タグ・取り込み・Trigger）。**Phase 1 はプロフィールタグと同時リリース**。

## 1. 概要
### 1.1 機能の目的
主催者がイベントのテーマ・内容を表すタグを設定することで、参加者がイベントの内容を把握しやすくし、自分の興味・関心に合ったイベントを発見しやすくする機能

### 1.2 プロフィールタグとの関係
- 「プロフィールタグ」（参加者設定）と「イベントタグ」（主催者設定）は**別フィールドで共存**する
- **同じタグマスタ定数**（`common/src/constants/tags.ts`）を共有する → 表記揺れを防ぎ、マッチングに活用できる
- イベントページでは「イベントタグ」と「参加者タグ集計」をセクション分けして表示する
- イベント詳細の参加者プレビューには**個別プロフィールタグを出さない**（集計のみ。個別表示は `/members` → [04 §4.2.2・§4.2.3](./04_プロフィールタグ機能.md)）

| | イベントタグ | プロフィールタグ |
|---|---|---|
| 設定者 | 主催者 | 参加者（ユーザー） |
| 目的 | イベントの内容・テーマを表現 | 自分の興味・関心を表明 |
| 上限 | 5個 | 10個 |
| 入力方式 | マスタタグのみ | マスタタグ＋フリー入力 |
| 表示場所 | イベントカード・イベント詳細 | プロフィール・参加者一覧（`/members`） |
| マスタ管理 | 共通（`common/src/constants/tags.ts`） | 共通（`common/src/constants/tags.ts`） |

### 1.3 リリース方針（確定）

- [04_プロフィールタグ機能.md](./04_プロフィールタグ機能.md) と **同一リリース（Phase 1）で同時公開** する
- 主催者の「設定」と参加者の「閲覧・取り込み」を初回からセットで提供する
- **タグ検索**（`array-contains-any` 等）は Phase 1 対象外 → [06_イベント検索（タグ検索・日付検索・場所検索）.md](./06_イベント検索（タグ検索・日付検索・場所検索）.md) で Phase 2 以降に実装

### 1.4 スコープ外（確定・Phase 1 では実装しない）

| 項目 | 理由 |
| --- | --- |
| **イベントタグのフリー入力** | 主催者間の表記揺れで検索・マッチングが機能しなくなる。マスタタグのみ |
| **イベントカードへの参加者タグ表示** | ノイズ。カードは `event_setting_tags` のみ |
| **want / give** | [04_プロフィールタグ機能.md §1.5](./04_プロフィールタグ機能.md) と同様に Phase 1 対象外 |
| **質問形式の誘導** | 同上 |
| **カートでのタグ必須** | 同上 |

## 2. 画面仕様
### 2.1 イベント作成・編集画面
- ジャンル別マスタタグ選択UI（`TAG_GENRES` 定数から生成・Firestore fetch 不要）
- 最大5個まで選択可能
- **マスタタグのみ**（フリー入力は不可）
- 保存時は `TAG_GENRES` 内の値のみ許可（マスタ外の文字列は拒否）
- UI コンポーネントはプロフィール用 `TagInput` とは分離し、**フリー入力を持たない EventTagInput**（名称は実装時に確定）を用いる

### 2.2 イベント一覧（カード表示）
- **`event_setting_tags` のみ**表示する（参加者タグ・プロフィールタグは表示しない）
- `event_setting_tags` が空の場合は**タグ表示欄自体を非表示**にする（「タグ未設定」はカードには表示しない）
- **表示数**: 最大 **3個**（はみ出し分は `+N` 等で省略可）。カードの主役は日時・場所・タイトルであり、タグはテーマの一行サマリ程度に留める
- ログインユーザーのプロフィールタグ（`user_tags`）と一致するタグをハイライト表示
- タグクリック時の挙動は [04_プロフィールタグ機能.md §4.2.5](./04_プロフィールタグ機能.md) と同一（`toggleTagOnMyProfile`）

### 2.3 イベント詳細ページ
```
■ イベントタグ（主催者設定）
  [スタートアップ] [AI] [地方創生]   ← event_setting_tags
  ※ 空の場合は「タグ未設定」と表示

■ （概要・日時・場所…）

■ 参加者タグ（集計）
  [スタートアップ] ×12人  [フットサル] ×5人 ...  ← event_members_tags（使用人数の多い順、全件表示）

■ 参加者プレビュー（アバター・名前・注文・個別タグ）
  ※ `/members` への導線は既存の「参加者プロフィール」リンク
```
- 参加者プレビュー（`EventMemberList`）に**個別タグ**を表示する（集計タグと併存）
- イベントタグ（主催者設定）が概要付近の**上部**に表示され、参加者タグ集計とは**明確に区別**する
- イベントタグ・参加者タグのいずれも、自分の `user_tags` と一致するタグをハイライト表示
- タグクリック時の挙動は [04_プロフィールタグ機能.md §4.2.5](./04_プロフィールタグ機能.md) と同一

## 3. 技術仕様
### 3.1 Firestoreスキーマ
```typescript
// communities/{communityId}/events/{eventId} ドキュメントに追加
interface EventDocument {
  // 既存フィールド...

  event_setting_tags: string[];      // 主催者が設定したイベントタグ（マスタのみ・最大5個）
                                     // 例: ["スタートアップ", "AI", "地方創生"]

  event_members_tags?: {             // 参加者タグの集計（Trigger Function が自動更新）
    [tag: string]: number;
  };
}
```

### 3.2 イベント検索・フィルタリング（Phase 2）

> Phase 1 同時リリースには**含めない**。Phase 2 で [06_イベント検索（タグ検索・日付検索・場所検索）.md](./06_イベント検索（タグ検索・日付検索・場所検索）.md) と合わせて実装する。

Firestore の `array-contains-any` を使用してイベント検索を行う。

**検索パターン**

| パターン | クエリ | 備考 |
|---|---|---|
| 特定タグでイベント検索 | `where('event_setting_tags', 'array-contains', tag)` | タグを1つ指定して検索 |
| プロフィールタグに合うイベントを検索 | `where('event_setting_tags', 'array-contains-any', userTags)` | ユーザーのタグ（最大10個）のいずれかに一致するイベントを返す |

**Firestore クエリ制約**

- `array-contains-any` に渡せる値は最大10個（ユーザータグ上限の10個とちょうど一致）
- `array-contains-any` はクエリ1回につき1つのみ使用可能
- イベントタグ検索と参加者タグ検索の**同時クエリは不可**（クライアントで並列実行しマージする）

### 3.3 セキュリティルール
```javascript
// イベントドキュメントの event_setting_tags 書き込みルール
// イベントの主催者（managers に含まれるユーザー）のみ更新可能
match /communities/{communityId}/events/{eventId} {
  allow update: if request.auth != null
    && request.auth.uid in resource.data.managers
    && request.resource.data.event_setting_tags.size() <= 5;
}
```

## 5. 注意事項
- イベントタグと参加者タグは表示上明確に区別する（ユーザーが混同しないように）
- タグマスタは `common/src/constants/tags.ts` で一元管理する。変更時はデプロイが必要。**マスタタグ廃止（フリーのみ）は行わない**
- イベント終了後もイベントタグは変更可能だが、`event_members_tags` は終了後に更新されない（プロフィールタグ仕様に準拠）
- イベントカードに参加者タグを載せない（[04 §1.5](./04_プロフィールタグ機能.md)）
