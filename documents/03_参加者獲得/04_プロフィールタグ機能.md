# プロフィールタグ機能

## 1. 概要
### 1.1 機能の目的
ユーザーが自身の興味・関心をタグとして設定し、イベント参加者間での共通点を可視化することで、コミュニティ形成とユーザーエンゲージメントを促進する機能

### 1.2 主要な機能
- ユーザープロフィールでのタグ設定・管理（マスタタグ選択 + フリー入力の併用）
- イベント詳細・参加者一覧での**個別プロフィールタグ**表示とタグ取り込み
- 共通タグのハイライト表示
- 他ユーザーのタグを自分のタグに取り込み機能（イベントページ・参加者一覧画面・プロフィールページ）
- **参加者一覧画面**（`/members`）での参加者個別タグ表示

### 1.3 対象ユーザー
- イベント参加者
- イベント主催者
- コミュニティ管理者

### 1.4 リリース方針（確定）

- **Phase 1（本 PR）** は **プロフィールタグ**（参加者設定・個別タグ表示・取り込み）のみを公開する
- **イベントタグ**（主催者設定の `event_setting_tags`）は [05_イベントタグ機能.md](./05_イベントタグ機能.md) を参照し、**別 PR / 別リリース**で提供する（仕様書はリポジトリに残す）
- タグ検索・フィルタ（[06_イベント検索（タグ検索・日付検索・場所検索）.md](./06_イベント検索（タグ検索・日付検索・場所検索）.md)）は **Phase 1 同時リリースの対象外**（Phase 2 以降）

### 1.5 スコープ外（確定・Phase 1 では実装しない）

| 項目 | 理由 |
| --- | --- |
| **want / give**（探している人・できることの2軸） | 食事コミュニティのトーンと合わず、入力・マッチングの複雑さが増す。単一の興味タグリストで十分 |
| **質問形式の誘導**（「好きなスポーツは？」等の必須／構造化フォーム） | 出会い系アプリに見えやすく、Shokujii の主目的（食事イベント参加）からズレる。フリー入力の placeholder とマスタタグ選択・タグ取り込みで誘導する |
| **カート画面でのタグ必須設定**（主催者が「最低 N 個設定してね」を指定） | 参加 CVR を下げる。Phase 2 以降、タグ設定率の計測後にソフト誘導から検討 |
| **参加者一覧の「フード／共通／全て」タブ切り替え** | Phase 1 では `/members` で全件表示 + 共通タグ優先ソートで十分 |
| **イベントカードへの参加者タグ・プロフィールタグ表示** | ノイズになる。一覧カードにはタグを載せない |
| **イベントタグ（主催者設定）の UI・保存** | Phase 1 はプロフィールタグのみ。[05_イベントタグ機能.md](./05_イベントタグ機能.md) を別 PR で提供 |
| **イベント詳細の「参加者別のタグを見る」専用導線** | 既存の「参加者プロフィール」→ `/members` で十分。集計見出し横の追加リンクは設けない |
| **マスタタグ廃止（フリータグのみ）** | 表記揺れでマッチング・集計が機能しなくなる。**マスタタグ + フリー入力の併用を維持** |

## 4. 画面仕様
### 4.1 画面遷移
1. ユーザープロフィール設定画面 → タグ設定・編集（マスタタグ選択 or フリー入力）
2. イベント詳細画面 → 参加者プレビュー（`EventMemberList`）で **「タグを表示」操作時のみ** 個別タグを表示 → タグクリックで自分のタグに追加／解除
3. 参加者一覧画面（`/members`）→ 各参加者カードに個別タグを表示 → タグクリックで自分のタグに追加／解除（既存の「参加者プロフィール」リンクから遷移）
4. 他ユーザーのプロフィールページ → タグ一覧表示 → タグクリックで自分のタグに追加／解除

**タグ表示の役割分担（確定）**

### 4.2 UI要素
#### 4.2.1 プロフィール設定画面（タグ追加モーダル）

`TagAddChip` から開くモーダル（`TagSettingsDialog`）の UI 仕様:

- タイトル: **プロフィールタグを追加**
- 冒頭にタグの説明文（例: 「興味や関心をタグとしてプロフィールに設定できます。…最大10個まで設定できます。」）
- **設定中のタグ**を primary（緑）のチップで表示（モーダル内で最大サイズ）。件数は `{count}/10` 形式

- フリー入力ブロック（任意のタグを追加。設定中タグと同系の枠付きカード）
  - 見出し **自由に入力**（`text-subtitle-1`・primary）、サブコピー「リストにないタグも追加できます」
  - **placeholder** で入力例（例: `スタートアップ、音楽フェス、タコス`）、hint「入力して Enter で追加」。追加ボタンは設けない
- **または** の区切り線の後に **おすすめのタグ（ジャンル別）**（旧: マスタタグ）の選択 UI
  - サブコピー「タップして追加・解除できます」
  - 後述のタグジャンル一覧から選択（アコーディオン）。未選択タグは compact サイズ
- 10 個到達時は未選択タグを disabled にし、上限メッセージを表示
- タグ上限：最大10個（マスタタグ＋フリー入力の合計）
- **want / give の区分は設けない**（単一の `user_tags` 配列）

#### 4.2.2 イベント詳細画面（参加者セクション）

**参加者プレビュー（`EventMemberList`）**

- 参加者のアバター・名前（コミュニティ設定で許可時）・注文メニューを表示する
- **個別プロフィールタグはデフォルト非表示**。参加者セクション見出し行の **「タグを表示」**（`EventDetailsCard`・`mdiTagOutline`・outlined pill）で ON/OFF する。ON 時は **「タグを隠す」** に切り替わる（`variant="flat"`）。状態はページ内のみ（再訪問のたび OFF。session 等には保存しない）
- `is_show_member === false` のときはタグ切り替えボタンも出さない（氏名非公開と同様）
- 参加者セクション上部の **「参加者プロフィール」** リンク（既存）は `/members` への導線として維持する（`/members` ではタグを常時表示）
- 各参加者のタグは `users/{userId}.user_tags` をリアルタイム参照する（イベント側への冗長化は行わない）

#### 4.2.3 参加者一覧画面（`/members`）

- ルート: `/c/{communityAccount}/e/{eventId}/members`（`base/src/components/pages/c/[communityAccount]/e/[eventId]/members.vue`）
- コミュニティの `is_show_member === false` の場合は既存どおり **404**（氏名非公開設定）
- 各参加者カード（`EventMemberCard`）内に**個別のプロフィールタグをすべて表示**する
  - **カード内の表示順**: アバター → 名前 → SNS → 自己紹介 → タグ。`UserBioPanel` と同順
  - **ゾーン開始位置の揃え**: 同行カード間で名前・SNS・自己紹介・タグ各行の**上端**が揃うよう固定スロットとする（`mt-auto` による下端吸着は使わない）
  - 名前欄は1行表示（`line-clamp: 1`）・固定 `min-height` を確保する（省略時は `title` で全文表示）
  - SNS 未設定時もレイアウトずれを防ぐため SNS 行の高さ（`48px`）を常に確保する
  - 自己紹介欄は最大3行表示・固定高。未設定時も同高さのスロットを確保する
  - タグ欄は自己紹介直下に配置し、先頭行の開始位置を揃えるため `min-height: 48px`（compact チップ2行分）のスロットを**常に**確保する。3行目以降はカード高が伸びてよい
  - **タグの表示順**: 自分との**共通タグを先頭**（`orderTagsWithHighlightFirst`）
  - タグが0件の参加者はチップを表示しない（レイアウト用スロットは空のまま確保）
- 自分と共通のタグをハイライト表示
- タグクリック時の挙動は §4.2.5 に準拠
- イベント詳細の参加者プレビューとは異なり、**誰がどのタグを持っているか**をカード単位で詳しく確認する専用画面とする

#### 4.2.4 他ユーザーのプロフィールページ
- タグ一覧を表示
- 自分と共通のタグをハイライト表示（色分け）
- タグクリック時の挙動は 4.2.5 に準拠

#### 4.2.5 タグクリック時の取り込み（参加者タグ・プロフィールタグ共通）

表示上のタグ種別にかかわらず、**同じ操作・同じ API** で自分の `user_tags` を更新する。

| 操作 | 挙動 |
| --- | --- |
| クリック（未所持） | 自分の `user_tags` に追加（`addTagToMyProfile` Callable） |
| クリック（所持済み） | 自分の `user_tags` から解除（`updateUserTags` Callable） |
| フロントエンド | `toggleTagOnMyProfile`（`base/src/apis/userTags.ts`）で上記を切り替え |

- 重複チェック・上限チェック（10個）・正規化は Callable 側で実施
- 成功後は Pinia store を直接更新し、ページリロードなしでリアクティブに反映する
- 未ログイン時はエラートーストを表示し、取り込み不可

## 5. 技術仕様・データ構造設計
### 5.1 タグマスタの管理方針
タグマスタは **Firestore ではなくソースコード（定数ファイル）で管理する**。

- タグの追加・変更頻度が低く、デプロイで十分対応できる
- Firestore への fetch・セキュリティルール設定が不要になり実装がシンプル
- TypeScript の `as const` により型安全に使用できる
- Phase 2 以降で管理画面からの動的変更が必要になった場合に Firestore 移行を検討する

```typescript
// common/src/constants/tags.ts
export const TAG_GENRES = [
  {
    genre: "コミュニティ／イベント",
    tags: ["コミュニティ", "食事会", "ランチ会", "交流会", "勉強会", "サークル" /* ... */],
  },
  {
    genre: "経営／マネジメント",
    tags: ["DX", "経営戦略", "財務", "不動産", "農業", "モビリティ", "物流" /* ... */],
  },
  {
    genre: "テクノロジー／サイエンス",
    tags: ["AI", "生成AI", "エンジニア", "IoT", "ブロックチェーン", "VR", "AR" /* ... */],
  },
  // ... 全25ジャンル
] as const;

// マスタタグの Union 型（型チェックに活用）
export type MasterTag = (typeof TAG_GENRES)[number]["tags"][number];
```

### 5.2 Firestoreスキーマ
```typescript
// ユーザープロフィールスキーマ（既存スキーマに追加）
// `users/{userId}` ドキュメントに追加
interface UserProfile {
  // 既存フィールド...
  user_tags: string[]; // ユーザーが設定したタグ配列（最大10個、マスタ＋フリーの混在可）
  updated_at: Timestamp;
}
// ※ Zod スキーマでは `user_tags: z.array(z.string()).optional().default([])` として定義する
//   （既存ユーザーのドキュメントに user_tags フィールドが存在しない場合を考慮）

// ※ event_setting_tags（主催者設定）は [05_イベントタグ機能.md](./05_イベントタグ機能.md) を別 PR で追加
// ※ event_members_tags / member_tags サブコレクションは採用しない（users.user_tags を正本とし、イベント画面は参加者 User を参照）
```

### 5.3 タグの種類
| 種類 | 説明 | 管理場所 |
|---|---|---|
| **マスタタグ** | 運営がソースコードで定義するタグ | `common/src/constants/tags.ts` |
| **フリータグ** | ユーザーが自由に入力したタグ | Firestore の `user_tags` に文字列として保存 |

- `user_tags` フィールドにはマスタタグ・フリータグを区別せず文字列配列で保存する
- フロントエンドで `TAG_GENRES` 定数と突合し、マスタタグかどうかを判定して表示を制御する（例：バッジの色分け等）

### 5.4 Firestoreフロントエンド処理
- **データ取得処理**:
  - タグ設定画面では `TAG_GENRES` 定数を使用してマスタタグ一覧を表示（Firestore fetch 不要）
  - ユーザープロフィール取得時にタグ情報も取得
  - イベント参加者一覧取得時に各参加者の `users/{userId}` を購読し `user_tags` を表示
- **データ更新処理**:
  - タグ設定時はユーザープロフィールを更新（`updateUserTags` Callable）
  - タグ取り込み時は既存タグに追加（重複チェック・上限チェック）
- **リアルタイム監視**:
  - 参加者の `users/{userId}` 変更を監視（タグ更新は即座にイベント画面へ反映）
- **エラーハンドリング**:
  - タグ数上限エラー（10個超過）
  - 重複タグエラー
  - ネットワークエラー

### 5.5 Firestoreセキュリティルール
```javascript
// ユーザープロフィールのタグ更新ルール
match /users/{userId} {
  allow update: if request.auth != null
    && request.auth.uid == userId
    && request.resource.data.user_tags.size() <= 10;
}
```

### 5.6 Functions設計
#### 5.6.1 Callable Functions（フロントエンドから呼び出し）
- `updateUserTags`: ユーザータグ更新
  - **引数**: `tags: string[]`
  - **戻り値**: `{ success: boolean, message: string }`
  - **認証**: ログインユーザーのみ（自分のタグのみ更新可）
  - **バリデーション**:
    - タグ数：10個以下（超過時はエラートーストを表示）
    - 各タグ文字数：最大20文字
    - 正規化処理：フリー入力フィールドでは**入力中にリアルタイム**で以下を適用し、保存前にも再適用する
      - 全角英数字 → 半角に変換（大文字小文字はマスタタグ定数の表記を維持）
      - 前後の空白をトリム
      - 正規化後に重複チェック（同一タグとみなす）
  - **成功後**: Pinia store を直接更新してリアクティブに反映する

- `addTagToMyProfile`: 他ユーザーのタグ / イベントタグ / 参加者タグから自分のタグに**1件追加**
  - **引数**: `tag: string`
  - **戻り値**: `{ success: boolean, message: string }`
  - **認証**: ログインユーザーのみ
  - **処理**: `updateUserTags` と同じ正規化処理（全角→半角・trim。大文字小文字は維持）を適用した上で、重複チェック・上限チェックを行い、自分の `user_tags` に追加
  - **成功後**: Callable Function の戻り値を受け取った後、フロントエンドで Pinia store を直接更新してページリロードなしでリアクティブに反映する
  - **上限超過時**: エラートーストを表示する（10個を超える場合）
  - **UI からの呼び出し**: クリック時はフロントエンドの `toggleTagOnMyProfile` が「未所持 → 追加」「所持済み → 解除」を切り替える（プロフィールタグ・イベントページ上の個別タグで共通）

### 5.7 処理フロー
1. ユーザーがプロフィール設定画面でタグを設定（マスタ選択 or フリー入力）
   - フリー入力中にリアルタイム正規化（全角→半角・trim。大文字小文字は維持）を適用
   - 10個超過時はエラートーストを表示
2. `updateUserTags` を呼び出し、正規化処理を経てユーザープロフィールの `user_tags` を更新
   - 成功後、フロントエンドで Pinia store を直接更新してリアクティブに反映
3. イベント詳細画面の参加者プレビュー（`EventMemberList`）で、ユーザーが **「タグを表示」** を押したときのみ個別タグを表示
4. 閲覧ユーザーと共通のタグをハイライト表示
5. プレビュー内個別タグクリックで `toggleTagOnMyProfile` を呼び出し、未所持なら `addTagToMyProfile`、所持済みなら `updateUserTags` で自分の `user_tags` を更新
   - 成功後、Pinia store を直接更新してリアクティブに反映（ページリロード不要）
   - 10個超過時はエラートーストを表示
6. 参加者一覧画面（`/members`）では個別参加者のタグを全件表示（共通タグ優先）。遷移は既存の「参加者プロフィール」リンクを使用

### 7.3 運用考慮事項
- マスタタグの追加・編集は `common/src/constants/tags.ts` を変更してデプロイする
- フリータグはマスタ登録しない（表記揺れを許容する）
- イベント詳細では参加者プレビューの個別タグは **デフォルト非表示**（「タグを表示」で ON）。`/members` では常時表示。詳細から `/members` への導線は既存の「参加者プロフィール」リンクのみとする
- 既存 Firestore の `member_tags` サブコレクション・`event_members_tags` フィールドはアプリから参照しない（物理削除は `bokudeli-event-batch` で任意）
- 廃止した Trigger（`syncMemberTagOnOrderChanged` / `updateEventMemberTags` / `syncUserTagsToEvent`）は deploy リストから外すだけでは GCP 上に残る。本番反映時は [デプロイ手順](../デプロイ手順/デプロイ手順_v2.12_260719.md) に従い `firebase functions:delete --region asia-northeast1 --force` で明示削除する
