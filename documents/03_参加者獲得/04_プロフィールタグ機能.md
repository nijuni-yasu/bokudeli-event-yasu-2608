# プロフィールタグ機能

## 1. 概要
### 1.1 機能の目的
ユーザーが自身の興味・関心をタグとして設定し、イベント参加者間での共通点を可視化することで、コミュニティ形成とユーザーエンゲージメントを促進する機能

### 1.2 主要な機能
- ユーザープロフィールでのタグ設定・管理
- イベント参加者全体のタグ表示（参加者タグ）
- 共通タグのハイライト表示
- 他ユーザーのタグを自分のタグに取り込み機能
- イベント参加者個別のタグ表示

### 1.3 対象ユーザー
- イベント参加者
- イベント主催者
- コミュニティ管理者

## 2. ねらい
### 2.1 ビジネス目標
- ユーザーエンゲージメント率の向上（目標：20%向上）
- イベント参加率の向上（目標：15%向上）
- コミュニティ内でのユーザー間交流促進

### 2.2 ユーザー価値
- 共通の興味・関心を持つ参加者との出会い促進
- イベント参加の動機付け強化
- コミュニティへの帰属意識向上

### 2.3 成功指標（KPI）
- タグ設定率（目標：登録ユーザーの60%以上）
- タグ取り込み機能の利用率（目標：月間10%以上）
- 共通タグを持つユーザー間の交流頻度

## 5. 技術仕様・データ構造設計
### 5.1 Firestoreスキーマ
```typescript
// ユーザープロフィールスキーマ（既存スキーマに追加）
// `users/{userId}` ドキュメントに追加
interface UserProfile {
  // 既存フィールド...
  user_tags: string[]; // ユーザーが設定したタグ配列（最大10個）
  updated_at: Timestamp;
}

// イベント参加者タグ集計スキーマ（新規）
// `communities/{communityId}/events/{eventId}` ドキュメントに追加
interface EventDocument {
  // 既存フィールド...
  // 連想配列
  participant_tags_summary?: {
    [tag: string]: number; // タグ名: 使用人数
  };
  updated_at: Timestamp;
}

// イベント参加者タグ詳細スキーマ（新規）
// `communities/{communityId}/events/{eventId}/participant_tags/{userId}` ドキュメント
interface EventParticipantTagDetail {
  user_id: string;
  user_tags: string[]; // そのユーザーのタグ
  created_at: Timestamp;
  updated_at: Timestamp;
}
```

### 5.2 Firestoreフロントエンド処理
- **データ取得処理**: 
  - ユーザープロフィール取得時にタグ情報も取得
  - イベント参加者一覧取得時に各参加者のタグ情報を取得
  - イベント参加者タグ詳細コレクションから個別タグ情報を取得
  - イベントドキュメントの `participant_tags_summary` をリアルタイム監視
- **データ更新処理**: 
  - タグ設定時はユーザープロフィールを更新
  - タグ取り込み時は既存タグに追加（重複チェック）
  - イベント参加時に参加者タグ詳細ドキュメントを作成
  - イベント退出時に参加者タグ詳細ドキュメントを削除
- **リアルタイム監視**: 
  - イベント参加者タグ集計の変更を監視
  - 参加者一覧のタグ変更を監視
- **エラーハンドリング**: 
  - タグ数制限エラー
  - 重複タグエラー
  - ネットワークエラー

### 5.3 Firestoreセキュリティルール
```javascript
// ユーザープロフィールのタグ更新ルール
match /users/{userId} {
  allow update: if request.auth != null 
    && request.auth.uid == userId
    && request.resource.data.user_tags.size() <= 10;
}

// イベント参加者タグ詳細の読み取り・書き込みルール
match /communities/{communityId}/events/{eventId}/participant_tags/{userId} {
  allow read: if request.auth != null;
  allow write: if request.auth != null 
    && request.auth.uid == userId;
}

// イベントドキュメントのタグ集計読み取りルール
match /communities/{communityId}/events/{eventId} {
  allow read: if request.auth != null;
}
```

### 5.4 Functions設計
#### 5.4.1 Callable Functions（フロントエンドから呼び出し）
- `updateUserTags`: ユーザータグ更新
  - **引数**: `userId: string`, `tags: string[]`
  - **戻り値**: `{ success: boolean, message: string }`
  - **認証**: ログインユーザーのみ

- `addTagFromParticipant`: 他参加者のタグを自分のタグに追加
  - **引数**: `sourceUserId: string`, `tag: string`
  - **戻り値**: `{ success: boolean, message: string }`
  - **認証**: ログインユーザーのみ

#### 5.4.2 Trigger Functions（自動実行）
- `updateEventParticipantTags`: イベント参加者タグ集計更新
  - **トリガー**: イベント参加者タグ詳細ドキュメントの作成・更新・削除時
  - **処理内容**: 該当イベントの `participant_tags_summary` を再計算・更新
  - **権限**: システム権限

- `syncUserTagsToEvent`: ユーザータグ変更時の同期
  - **トリガー**: ユーザープロフィールの `user_tags` 更新時
  - **処理内容**: 該当ユーザーが参加している全イベントの参加者タグ詳細を更新
  - **権限**: システム権限

### 5.5 処理フロー
1. ユーザーがプロフィール設定画面でタグを設定
2. ユーザープロフィールの `user_tags` を更新
3. Trigger Function `syncUserTagsToEvent` が実行され、参加中の全イベントの参加者タグ詳細を更新
4. イベント参加時に参加者タグ詳細ドキュメントを作成
5. Trigger Function `updateEventParticipantTags` が実行され、イベントの `participant_tags_summary` を更新
6. イベント画面で参加者全体のタグを集計表示
7. 閲覧ユーザーと共通のタグをハイライト表示
8. タグ取り込みボタン押下で他ユーザーのタグを自分のタグに追加
9. 参加者一覧画面で個別参加者のタグを表示

## データ更新の流れ

### 1. **イベント参加時**
```typescript
// ユーザーがイベントに参加した時
// `communities/{communityId}/events/{eventId}/participant_tags/{userId}` を作成
{
  user_id: "user123",
  user_tags: ["#スタートアップ", "#コミュニティ"], // その時点のユーザータグ
  created_at: Timestamp,
  updated_at: Timestamp
}
```

### 2. **プロフィール更新時**
```typescript
<code_block_to_apply_changes_from>
```

### 3. **自動集計更新**
```typescript
// Trigger Function `updateEventParticipantTags` が実行される
// イベントドキュメントの `participant_tags_summary` を再計算
{
  participant_tags_summary: {
    "#スタートアップ": 5,
    "#コミュニティ": 12,
    "#フットサル": 3
  }
}
```

## この設計の利点

1. **リアルタイム同期**: ユーザーがタグを変更すると、参加中の全イベントに即座に反映
2. **履歴保持**: `created_at` と `updated_at` でタグの変更履歴を追跡可能
3. **効率的な表示**: イベント画面では集計データを表示、参加者一覧では個別データを表示
4. **データ整合性**: ユーザーの現在のタグとイベント参加時のタグが常に同期

つまり、この `EventParticipantTagDetail` ドキュメントは「そのユーザーがそのイベントに参加している時点での最新のタグ情報」を保持する役割を果たします。
