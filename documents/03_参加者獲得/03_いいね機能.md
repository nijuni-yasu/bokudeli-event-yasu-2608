# いいね機能

## 1. 概要
### 1.1 機能の目的
ユーザーがイベントに対して「いいね（いくかも）」を押すことで、参加検討中のイベントを管理し、主催者に興味を示すユーザーの存在を伝える機能

### 1.2 主要な機能
- イベントカードでの「いいね（いくかも）」ボタン操作
- イベントページでの「いいね（いくかも）」ボタン操作
- マイページでの「いいね（いくかも）」したイベント一覧表示
- 主催者画面での「いいね（いくかも）」したユーザー一覧表示
- カウントダウンメールでの「いいね（いくかも）」したユーザー一覧表示
- 「いいね（いくかも）」したユーザーへの注文締切3日前メール通知

### 1.3 対象ユーザー
- イベント参加を検討している一般ユーザー
- イベント主催者
- システム管理者

## 2. ねらい
### 2.1 ビジネス目標
- イベント参加率の向上（目標：いいねしたユーザーの20%以上が実際に参加）
- ユーザーエンゲージメントの向上
- 主催者への興味ユーザー情報提供

### 2.2 ユーザー価値
- 参加検討中のイベントを簡単に管理できる
- 注文締切のリマインダー機能
- 主催者に興味を示すことで、イベントの認知度向上に貢献

### 2.3 成功指標（KPI）
- いいねボタンのクリック率（目標：イベント閲覧者の5%以上）
- いいねしたユーザーの実際の参加率（目標：20%以上）
- いいね機能利用後のイベント参加率向上

## 3. 前提条件
### 3.1 技術的前提条件
- ユーザー認証システムが実装済み
- Firestoreデータベースが利用可能
- メール送信機能が実装済み
- イベント管理システムが実装済み

### 3.2 ビジネス的前提条件
- イベントが作成・公開されている
- ユーザーがログインしている
- 主催者がイベント管理権限を持っている

### 3.3 依存関係
- ユーザー認証機能
- イベント管理機能

- 主催者管理画面

## 4. 画面仕様
### 4.1 画面遷移
1. TOP画面 → イベントカードの「いいね」ボタン → いいね状態更新
2. イベントページ → 「いいね」ボタン → いいね状態更新
3. マイページ → 「いいねしたイベント」タブ → いいねしたイベント一覧
4. 主催者画面 → 参加者一覧 → いいねしたユーザー一覧
5. カウントダウンメール → いいねしたユーザー一覧

### 4.2 UI要素
#### 4.2.1 ボタン・アクション
- **いいねボタン**
  - カラー: プライマリ（いいね済み時）、セカンダリ（未いいね時）
  - アイコン: ハートアイコン（いいね済み時は塗りつぶし、未いいね時は白抜き）
  - テキスト: 「いくかも」
  - 状態: ログイン済みユーザーのみ有効
  - アクション: いいね状態の切り替え

#### 4.2.2 表示要素
- **いいね数表示**
  - 表示内容: イベントに対するいいねの総数
  - 条件: イベントカード・イベントページに常時表示
  - フォーマット: 「いくかも: {数}人」

- **いいねしたユーザー一覧**
  - 表示内容: ユーザー名、いいね日時
  - 条件: 主催者画面でのみ表示
  - フォーマット: リスト形式でユーザー名と日時を表示

// common/src/schemas/eventFavorite.ts
import { z } from 'zod';

export const EventFavoriteDbSchema = z.object({
  // データベーススキーマ（Firestoreから取得したデータの型定義）
  id: z.string(),
  event_id: z.string().min(1),
  user_id: z.string().min(1),
  is_favorite: z.boolean(),
  created_at: z.date(),
  updated_at: z.date(),
});

// クラス定義
export class EventFavorite {
  id: string = '';
  event_id: string = '';
  user_id: string = '';
  is_favorite: boolean = false;
  created_at: Date = new Date();
  updated_at: Date = new Date();
  
  // バリデーション
  validate(): boolean {
    return this.event_id.length > 0 && this.user_id.length > 0;
  }
  
  // ファクトリメソッド
  static fromDb(data: any): EventFavorite {
    const item = new EventFavorite();
    item.id = data.id;
    item.event_id = data.event_id;
    item.user_id = data.user_id;
    item.is_favorite = data.is_favorite;
    item.created_at = data.created_at.toDate();
    item.updated_at = data.updated_at.toDate();
    return item;
  }
}

### 5.6 Functions設計

#### 5.6.1 Trigger Functions（自動実行）
```typescript
// functions/default/src/triggers/onFavoriteCreated.ts
export const onFavoriteCreated = onDocumentCreated(
  'communities/{communityId}/events/{eventId}/favorites/{userId}',
  async (event) => {
    const data = event.data?.data();
    if (!data) return;
    
    try {
      // いいね数カウントの更新
      await updateFavoriteCount(event.params.communityId, data.event_id);
      
      // 主催者への通知（オプション）
      await notifyOrganizer(event.params.communityId, data.event_id, data.user_id);
      
      console.log(`Favorite created for event: ${data.event_id}, user: ${data.user_id}`);
    } catch (error) {
      console.error('onFavoriteCreated failed:', error);
    }
  }
);

// いいね数カウント更新関数
const updateFavoriteCount = async (eventId: string) => {
  const favoritesRef = collection(db, 'events', eventId, 'favorites');
  const q = query(favoritesRef, where('is_favorite', '==', true));
  const snapshot = await getCountFromServer(q);
  
  const eventRef = doc(db, 'events', eventId);
  await updateDoc(eventRef, {
    favorite_count: snapshot.data().count,
    updated_at: serverTimestamp()
  });
};
```

### 5.7 処理フロー
#### 5.7.1 いいね機能の処理フロー
1. ユーザーがイベントカードまたはイベントページでいいねボタンをクリック
2. フロントエンドでログイン状態をチェック
   - 未ログイン時: ログイン画面にリダイレクト
3. 現在のいいね状態を取得
4. Firestoreの`communities/{communityId}/events/{eventId}/favorites/{userId}`ドキュメントを直接操作
   - いいね追加: `setDoc()` で `is_favorite: true`
   - いいね削除: `setDoc()` で `is_favorite: false`
5. `onFavoriteCreated` Triggerが実行され、いいね数カウントを更新
6. フロントエンドでいいね状態を更新表示
7. 定期実行でリマインダーメールを送信

#### 5.7.2 エラーハンドリングを含む処理フロー
1. ユーザーがいいねボタンをクリック
2. フロントエンドでログイン状態をチェック
   - 失敗時: ログイン画面にリダイレクト
3. 現在のいいね状態を取得
   - 失敗時: エラーメッセージを表示して処理を停止
4. Firestoreのドキュメントを操作
   - 成功: 処理を継続
   - 失敗: ネットワークエラーメッセージを表示
5. Trigger Functionが自動実行
   - 失敗時: ログに記録（ユーザー処理には影響しない）
6. フロントエンドで結果表示
   - 成功: いいね状態を更新表示
   - 失敗: エラー状態を表示

## 7. 注意事項
### 7.1 既存システムへの影響
#### 7.1.1 データベース構造への影響
- **新規サブコレクション**: `communities/{communityId}/events/{eventId}/favorites/{userId}` を追加
- **既存コレクションの変更**: `events` コレクションのドキュメントに `favorite_count` フィールドを追加
- **インデックス追加**: いいね数カウント用の複合インデックスを追加

#### 7.1.2 アプリケーションへの影響
- **フロントエンド**: イベントカード、イベントページ、マイページ、主催者画面のUI変更
- **バックエンド**: 新しいTrigger FunctionとScheduled Functionの追加
- **既存機能**: イベント一覧表示、イベント詳細表示の拡張

#### 7.1.3 運用への影響
- **パフォーマンス**: いいね数カウントのリアルタイム更新による軽微な負荷増加
- **ストレージ**: いいね情報の保存によるストレージ使用量の増加
- **セキュリティ**: 新しいセキュリティルールの追加

### 7.2 セキュリティ考慮事項
- Firestore Security Rulesでいいね操作はログインユーザーのみ許可
- いいね情報の読み取り権限は適切に制限
- 主催者は自分のイベントのいいね情報のみ閲覧可能
- フロントエンドからの直接操作のため、適切なバリデーションを実装

### 7.3 運用考慮事項
- **ログ**: いいね操作のログ記録、Trigger Functionの実行ログ
- **バックアップ**: いいねデータの定期バックアップ
- **監視**: いいね数カウントの整合性監視、メール送信の成功/失敗監視
- **パフォーマンス**: 大量のいいねがある場合のクエリ最適化
- **拡張性**: 将来的ないいね機能の拡張（コメント、評価等）への対応

### 7.4 実装しないこと
- 「いいね（いくかも）」した人をイベントページやイベントカードに表示する機能
- いいねしたユーザー同士の相互表示機能
- いいねの取り消し履歴表示機能
