# いいね機能

## 1. 概要
### 1.1 機能の目的
ユーザーがイベントに対して「いいね（いくかも）」を押すことで、参加検討中のイベントを管理し、主催者に興味を示すユーザーの存在を伝える機能

### 1.2 主要な機能
- イベントカードでの「いいね（いくかも）」ボタン操作
- イベントページでの「いいね（いくかも）」ボタン操作
- マイページでの「いいね（いくかも）」したイベント一覧表示
- 主催者画面での「いいね（いくかも）」したユーザー一覧表示
- カウントダウンメールでの「いいね（いくかも）」したユーザー一覧表示
- 「いいね（いくかも）」したユーザーへの注文締切3日前メール通知

### 1.3 対象ユーザー
- イベント参加を検討している一般ユーザー
- イベント主催者
- システム管理者

## 2. ねらい
### 2.1 ビジネス目標
- イベント参加率の向上（目標：いいねしたユーザーの20%以上が実際に参加）
- ユーザーエンゲージメントの向上
- 主催者への興味ユーザー情報提供

### 2.2 ユーザー価値
- 参加検討中のイベントを簡単に管理できる
- 注文締切のリマインダー機能
- 主催者に興味を示すことで、イベントの認知度向上に貢献

### 2.3 成功指標（KPI）
- いいねボタンのクリック率（目標：イベント閲覧者の5%以上）
- いいねしたユーザーの実際の参加率（目標：20%以上）
- いいね機能利用後のイベント参加率向上

## 4. 画面仕様
### 4.1 画面遷移
1. TOP画面 → イベントカードの「いいね」ボタン → いいね状態更新
2. イベントページ → 「いいね」ボタン → いいね状態更新
3. マイページ → 「いいねしたイベント」タブ → いいねしたイベント一覧
4. 主催者画面 → 参加者一覧 → いいねしたユーザー一覧
5. カウントダウンメール → いいねしたユーザー一覧

### 4.2 UI要素
- **いいねボタン**: ハートアイコン + 「いくかも」テキスト
- **いいね状態表示**: いいね済みの場合は塗りつぶしハート、未いいねの場合は白抜きハート
- **いいね数表示**: イベントカード・イベントページにいいね数を表示
- **いいねしたユーザー一覧**: 主催者画面でユーザー名・いいね日時を表示

## 5. 技術仕様・データ構造設計
### 5.1 Firestoreスキーマ
```typescript
// イベントのいいね情報
interface EventFavorite {
  eventId: string;           // イベントID
  userId: string;            // ユーザーID
  isFavorite: boolean;       // いいね状態
  createdAt: Timestamp;      // 作成日時
  updatedAt: Timestamp;      // 更新日時
}

// コレクション構造
// events/{eventId}/favorites/{userId}
```

### 5.2 フロントエンド処理
#### 5.2.1 いいね状態の切り替え
- **処理**: フロントエンドから直接Firestoreを操作
- **操作**: `events/{eventId}/favorites/{userId}` ドキュメントの作成・更新・削除
- **認証**: Firestore Security Rulesでログインユーザーのみ許可
- **処理内容**: 
  - いいね追加: `setDoc()` で `isFavorite: true`
  - いいね削除: `setDoc()` で `isFavorite: false`

### 5.3 Functions設計
#### 5.3.1 Trigger Functions（自動実行）
- `onFavoriteCreated`: いいね作成時の処理
  - **トリガー**: `events/{eventId}/favorites/{userId}` 作成時
  - **処理内容**: いいね数カウント更新、主催者への通知
  - **権限**: システム権限

#### 5.3.2 Scheduled Functions（定期実行）
- `sendFavoriteReminderEmail`: いいねしたユーザーへのリマインダーメール
  - **スケジュール**: 毎日午前9時に実行
  - **処理内容**: 注文締切3日前のイベントをいいねしたユーザーにメール送信

### 5.4 処理フロー
1. ユーザーがいいねボタンをクリック
2. フロントエンドでログイン状態をチェック
3. Firestoreの`events/{eventId}/favorites/{userId}`ドキュメントを直接操作
4. `onFavoriteCreated` Triggerが実行され、いいね数カウントを更新
5. フロントエンドでいいね状態を更新表示
6. 定期実行でリマインダーメールを送信

## 7. 注意事項
### 7.1 既存システムへの影響
- イベントカード・イベントページのUI変更が必要
- マイページ・主催者画面の拡張が必要
- メール送信機能の拡張が必要

### 7.2 セキュリティ考慮事項
- Firestore Security Rulesでいいね操作はログインユーザーのみ許可
- いいね情報の読み取り権限は適切に制限
- 主催者は自分のイベントのいいね情報のみ閲覧可能
- フロントエンドからの直接操作のため、適切なバリデーションを実装

### 7.3 運用考慮事項
- いいねデータの定期バックアップ
- いいね数カウントの整合性監視
- メール送信の失敗時のリトライ処理
- いいね機能の利用統計収集

### 7.4 実装しないこと
- 「いいね（いくかも）」した人をイベントページやイベントカードに表示する機能
- いいねしたユーザー同士の相互表示機能
- いいねの取り消し履歴表示機能
