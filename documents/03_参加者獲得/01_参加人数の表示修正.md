# 参加人数の表示修正

## 1. 概要

### 1.1 機能の目的
注文個数を参加人数として扱い、イベントの参加人数表示を正確に反映する機能の修正。`event_num_members`フィールドを注文個数ベースでリアルタイム更新することで、パフォーマンスとデータ整合性を向上させる。

### 1.2 主要な機能
- イベントカードでの参加人数表示の修正（「人」表記の削除）
- イベントページでの参加人数表示の修正
- `event_num_members`の注文個数ベースリアルタイム更新
- 満席判定ロジックの注文個数ベースへの変更
- TOP画面表示での注文個数ベース判定

### 1.3 対象ユーザー
- イベント参加者（ユーザー）
- イベント主催者（コミュニティ管理者）
- システム管理者

### 5.2 Trigger Functionsによる自動更新
```typescript
// functions/default/src/triggers/eventOrder.ts
import { onDocumentCreated, onDocumentUpdated, onDocumentDeleted } from 'firebase-functions/firestore'

// 注文作成時の自動処理
export const onEventOrderCreated = onDocumentCreated(
  'communities/{communityId}/events/{eventId}/orders/{orderId}',
  async (event) => {
    const orderData = event.data?.data()
    if (!orderData || orderData.status !== 'ordered') return
    
    const eventId = event.params.eventId
    await updateEventParticipantCount(eventId)
  }
)

// 注文更新時の自動処理
export const onEventOrderUpdated = onDocumentUpdated(
  'communities/{communityId}/events/{eventId}/orders/{orderId}',
  async (event) => {
    const beforeData = event.data?.before.data()
    const afterData = event.data?.after.data()
    
    // 注文ステータスが変更された場合のみ更新
    if (beforeData?.status !== afterData?.status) {
      const eventId = event.params.eventId
      await updateEventParticipantCount(eventId)
    }
  }
)

// 注文削除時の自動処理
export const onEventOrderDeleted = onDocumentDeleted(
  'communities/{communityId}/events/{eventId}/orders/{orderId}',
  async (event) => {
    const orderData = event.data?.data()
    if (!orderData || orderData.status !== 'ordered') return
    
    const eventId = event.params.eventId
    await updateEventParticipantCount(eventId)
  }
)
```

### 5.3 参加人数更新ロジック
```typescript
// 参加人数計算・更新関数
async function updateEventParticipantCount(eventId: string): Promise<void> {
  const orders = await getEventOrders(eventId)
  const participantCount = calculateParticipantCount(orders)
  
  await updateEvent(eventId, {
    event_num_members: participantCount
  })
}

// 参加人数計算関数
function calculateParticipantCount(orders: EventOrder[]): number {
  return orders
    .filter(order => order.status === 'ordered')
    .reduce((total, order) => {
      return total + order.menus.reduce((menuTotal, menu) => {
        return menuTotal + menu.count
      }, 0)
    }, 0)
}

// フロントエンドでの参加人数取得（簡素化）
function getParticipantCount(event: Event): number {
  return event.event_num_members  // 直接取得
}

// 満席判定関数（簡素化）
function isEventFull(event: Event): boolean {
  return event.event_num_members >= event.event_max_people
}

// 表示形式の統一
function formatParticipantCount(event: Event): string {
  return `${event.event_num_members}/${event.event_max_people}`
}
```

### 5.4 データ整合性の確保
```typescript
// データ整合性チェック関数
async function validateEventParticipantCount(eventId: string): Promise<boolean> {
  const event = await getEvent(eventId)
  const orders = await getEventOrders(eventId)
  const calculatedCount = calculateParticipantCount(orders)
  
  if (event.event_num_members !== calculatedCount) {
    console.warn(`Event ${eventId}: Count mismatch. Stored: ${event.event_num_members}, Calculated: ${calculatedCount}`)
    // 自動修正
    await updateEvent(eventId, { event_num_members: calculatedCount })
    return false
  }
  
  return true
}

// 定期実行による整合性チェック
export const scheduledParticipantCountValidation = onSchedule(
  '0 */6 * * *', // 6時間ごとに実行
  async () => {
    const events = await getAllActiveEvents()
    
    for (const event of events) {
      await validateEventParticipantCount(event.event_id)
    }
  }
)
```

## 7. 注意事項

### 7.1 既存システムへの影響
- **データベース**: `event_num_members`フィールドの意味が注文個数ベースに変更
- **表示機能**: フロントエンドでの計算処理が不要になり、`event_num_members`を直接使用
- **満席判定**: リアルタイム更新された`event_num_members`を使用
- **過去データ**: 既存データの一括移行が必要

### 7.2 セキュリティ考慮事項
- **データ整合性**: Trigger Functionsによる自動更新で整合性を保証
- **権限管理**: 既存の権限管理システムを維持
- **入力値検証**: 注文個数の妥当性チェック
- **エラーハンドリング**: Trigger Functionsの失敗時の適切な処理

### 7.3 運用考慮事項
- **過去イベント**: 満席を超えていた場合「20/15」などの表示も許容
- **データ移行**: 既存データの一括更新スクリプト実行
- **監視**: Trigger Functionsの実行状況監視
- **バックアップ**: 更新前のデータバックアップ

### 7.4 パフォーマンス考慮事項
- **同時更新**: 大量の注文がある場合の処理時間
- **競合状態**: 同時更新時の競合状態の回避
- **キャッシュ**: フロントエンドでのキャッシュ戦略
- **スケーラビリティ**: 大量イベント・大量注文への対応

### 7.5 今後の対応方針
- **オプションメニュー実装**: 1人で実際に複数個注文する可能性への対応
- **店舗協力**: セットメニュー化による1人1個前提への移行
- **システム拡張**: 将来的な複数個注文対応の検討
- **監視強化**: データ整合性の継続的監視
