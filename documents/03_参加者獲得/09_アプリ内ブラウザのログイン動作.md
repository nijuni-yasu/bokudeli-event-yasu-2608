# アプリ内ブラウザのログイン動作

# 課題
- アプリ内ブラウザでログイン画面に遷移し、ログインした場合、アプリ内ブラウザではログインできない
- アプリ内ブラウザとは、Facebookメッセンジャー、LINE、Xなどのアプリを指す。
- 通常のブラウザとは、Chrome、Safari、Firefoxなどのブラウザを指す。
- アプリ内ブラウザでログインしようとした場合、通常のブラウザに遷移して欲しい。
- URLをコピーするボタンを表示することで、通常のブラウザに遷移してログインするように促す。

# 動作仕様
- アプリ内ブラウザでログインしようとした場合、ログインボタンを表示しない。
- 代わりに、URLをコピーするボタンを表示する。
- このボタンをクリックすると、URLをコピーし「URLをコピーしました」と表示する。
- コピーしたURLを通常のブラウザに貼り付けてログインする。

---

## 詳細仕様

### 対象
- 対象画面: `user/src/pages/login.vue`

### 目的
- Facebook/LINE/X などのアプリ内ブラウザ(WebView)からアクセスした場合、SNSログインやメールログインを抑止し、通常ブラウザでのログインに誘導する。

### 判定方法（アプリ内ブラウザ検出）
- `navigator.userAgent` を用いて以下のいずれかを含む場合はアプリ内ブラウザと判定する。
  - `Line/`（LINE）
  - `FBAN` / `FBAV` / `Facebook` / `Messenger`（Facebook/Messenger）
  - `Instagram`（Instagram）
  - `Twitter`（X/Twitter）
  - `; wv` / ` wv;`（Android WebViewの一般的指標）

### 表示仕様
- アプリ内ブラウザの場合
  - 既存の「Google/Facebook/X ログインボタン」「メールアドレス入力＋続ける」UIを非表示。
  - 代替UIを表示する:
    - 注意タイトル: 「アプリ内ブラウザではログインできません」
    - 注意文: 「ChromeやSafariなど通常のブラウザで開いてログインしてください」
    - 現在ページURLをコピーする大ボタン: 「このページのURLをコピー」
    - 押下時の動作: クリップボードへ `location.href` をコピーし、成功時にトースト「URLをコピーしました」を表示。
    - クリップボードAPI非対応時は `document.execCommand('copy')` にフォールバック。失敗時は「コピーに失敗しました。手動でURLを選択してコピーしてください」を表示。
- 通常ブラウザの場合
  - 既存のログインUI（SNSログイン、メールログインフォーム）をそのまま表示。

### 国際化（i18n）
- `user/src/locales/messages/ja.ts` の `login` セクションに以下のキーを追加する。
  - `login.inapp.notice_title`: 「アプリ内ブラウザではログインできません」
  - `login.inapp.notice_body`: 「ChromeやSafariなど通常のブラウザで開いてログインしてください」
  - `login.inapp.copy_url`: 「このページのURLをコピー」
  - `login.inapp.copied`: 「URLをコピーしました」
  - `login.inapp.copy_failed`: 「コピーに失敗しました。手動でURLを選択してコピーしてください」

### エラーハンドリング
- コピー成功/失敗に応じて既存の `useNotification` によるトーストを表示する。

### アクセシビリティ/UX
- 注意文は視認性の高いスタイル（カード内の強調テキスト）。
- URLコピー導線は1アクションで完了する大ボタンを設置。

### テスト観点
- 既知の UA 文字列でアプリ内ブラウザ判定が `true` になること。
- クリップボードAPI対応/非対応端末での成功/フォールバック動作の確認。
- 通常ブラウザでは既存ログインUIが表示されること。

### 制限事項
- 一部のアプリ内ブラウザではクリップボードAPIや `execCommand('copy')` が動作しない可能性がある。その場合はエラートーストで手動コピーを促す。

## 実装仕様（login.vue）

### 追加ロジック（script）
- 状態
  - `isInAppBrowser: boolean`（アプリ内ブラウザ判定結果）
- 関数
  - `detectInAppBrowser()`: 上記 UA パターンで判定して `isInAppBrowser` を設定。
  - `copyCurrentUrl()`: `location.href` をクリップボードへコピー。成功/失敗でトースト出し分け。
- ライフサイクル
  - `onMounted` で `detectInAppBrowser()` を実行。

### 外部関数の配置方針（共通化）
- 判定ロジックは共通化のため外部ファイルへ切り出す。
- 配置先: `base/src/utils/browser.ts`
  - エクスポート関数: `isInAppBrowser(userAgent: string): boolean`
  - 役割: UA 文字列を受け取りアプリ内ブラウザかを判定する純粋関数。

#### 実装例（utils）
```ts
// base/src/utils/browser.ts
export function isInAppBrowser(userAgent: string): boolean {
  const ua = userAgent || ''
  const patterns = [
    /Line\//i,
    /FBAN|FBAV|Facebook/i,
    /Messenger/i,
    /Instagram/i,
    /Twitter/i,
    /; wv| wv;/i,
  ]
  return patterns.some(p => p.test(ua))
}
```

#### login.vue での利用例
```ts
// 直接 util を使う場合
import { onMounted } from 'vue'
import { isInAppBrowser as detectInApp } from '@shokujii/base/utils/browser'

const isInAppBrowser = ref(false)
onMounted(() => {
  isInAppBrowser.value = detectInApp(navigator.userAgent)
})
```

### テンプレート（template）
- `isInAppBrowser === true` の場合
  - 注意タイトル/注意文/URLコピー大ボタンのみ表示。
  - パートナーサイト/アカウント情報へのリンク（既存の下部リンク類）は残す。
- `isInAppBrowser === false` の場合
  - 既存のログインUI（SNSログイン/メールフォーム）をそのまま表示。

### 既存コードとの整合性
- `handleLogin`/SNSボタン/メールフォームは `isInAppBrowser` が `false` のときのみ表示されるため、アプリ内ブラウザでは操作できない。
- 通知は既存の `useNotification` を使用し統一する。
- `base/src/components/LoginDialog.vue` の注意文と内容が重複するが、本仕様によりページ側で抑止するためユーザー体験は一貫する。
