# メール_主催者_イベント未注文放置

## 1. 概要
### 1.1 機能の目的
主催者がイベントを予約申請し、店舗が予約承認した後に、主催者がなかなか注文したり告知しない場合のリマインド機能を提供する。

### 1.2 主要な機能
- イベント予約承認後の注文促進リマインドメール送信
- 3日間隔での自動リマインド送信
- 注文完了までの継続的なリマインド機能
- コミュニティ管理者全員への一括送信

### 1.3 対象ユーザー
- コミュニティ管理者（主催者）
- イベント予約承認済みの主催者

## 2. ねらい
### 2.1 ビジネス目標
- イベント予約承認後の注文率向上
- 主催者のアクション促進

### 2.2 ユーザー価値
- 注文忘れの防止
- イベント進行の促進
- 参加者への適切な告知タイミングの確保

### 2.3 成功指標（KPI）
- リマインドメール送信後の注文率
- イベント予約から注文までの平均日数短縮
- 注文キャンセル率の低下

## 3. 前提条件

### 3.3 依存関係

### 5.3 Functions設計
#### 5.3.1 Scheduled Functions（定期実行）
```typescript
// functions/default/src/scheduled/remindUnorderedEvents.ts
export const remindUnorderedEvents = onSchedule(
  '0 10 * * *', // 毎日午前10時に実行
  async () => {
    console.log('Starting remindUnorderedEvents...');
    
    try {
      const result = await processUnorderedEvents();
      console.log(`remindUnorderedEvents completed: ${result.sent_count} emails sent`);
    } catch (error) {
      console.error('remindUnorderedEvents failed:', error);
    }
  }
);

async function processUnorderedEvents() {
  const now = new Date();
  const threeDaysAgo = new Date(now.getTime() - (3 * 24 * 60 * 60 * 1000));
  
  // 注文受付中で3日以上経過したイベントを取得
  const eventsSnapshot = await db
    .collectionGroup('events')
    .where('event_status', '==', 'accepting_order')
    .where('updated_at', '<', threeDaysAgo)
    .where('event_deadline_datetime', '>', now)
    .get();
  
  let sentCount = 0;
  
  for (const eventDoc of eventsSnapshot.docs) {
    const eventData = eventDoc.data();
    const communityId = eventDoc.ref.parent.parent?.id;
    
    if (!communityId) continue;
    
    // 注文状況を確認
    const ordersSnapshot = await db
      .collection('communities')
      .doc(communityId)
      .collection('events')
      .doc(eventDoc.id)
      .collection('orders')
      .where('status', '==', 'ordered')
      .get();
    
    // 注文がない場合のみリマインド送信
    if (ordersSnapshot.empty) {
      await sendReminderEmail(communityId, eventData);
      sentCount++;
    }
  }
  
  return { sent_count: sentCount };
}

async function sendReminderEmail(communityId: string, eventData: any) {
  // コミュニティ管理者を取得
  const managersSnapshot = await db
    .collection('communities')
    .doc(communityId)
    .collection('members')
    .where('roles', 'array-contains', 'manager')
    .get();
  
  const managers = managersSnapshot.docs.map(doc => doc.data());
  
  // メール送信
  for (const manager of managers) {
    const emailData = {
      to: manager.user_email,
      subject: `【shokujii】イベント「${eventData.event_name}」の注文をお忘れではありませんか？`,
      template: 'reminder_unordered_event',
      dynamic_template_data: {
        community_manager_fullname: manager.user_fullname,
        event_name: eventData.event_name,
        event_start_datetime: eventData.event_start_datetime.toDate().toLocaleString('ja-JP'),
        event_place: eventData.event_place,
        shop_name: eventData.shop_name,
        event_url: `${process.env.FRONTEND_URL}/communities/${communityId}/events/${eventData.id}`
      }
    };
    
    await sendEmail(emailData);
  }
}
```

### 5.4 処理フロー
#### 5.4.1 リマインドメール送信フロー
```markdown
### リマインドメール送信の処理フロー
1. Scheduled Functionが毎日午前10時に自動実行
2. 注文受付中（accepting_order）のイベントを取得
3. 各イベントについて以下を確認：
   - 注文期限が未来であること
   - 最後の更新から3日以上経過していること
   - 注文が1件も存在しないこと
4. 条件に合致するイベントのコミュニティ管理者を取得
5. 各管理者にリマインドメールを送信
6. 送信結果をログに記録
```

#### 5.4.2 エラーハンドリングを含む処理フロー
```markdown
### リマインドメール送信の処理フロー（エラーハンドリング含む）
1. Scheduled Functionが毎日午前10時に自動実行
2. 注文受付中（accepting_order）のイベントを取得
   - 失敗時: エラーログを記録して処理を停止
3. 各イベントについて以下を確認：
   - 注文期限が未来であること
   - 最後の更新から3日以上経過していること
   - 注文が1件も存在しないこと
4. 条件に合致するイベントのコミュニティ管理者を取得
   - 失敗時: 該当イベントをスキップして次のイベントを処理
5. 各管理者にリマインドメールを送信
   - 失敗時: 該当管理者をスキップして次の管理者を処理
6. 送信結果をログに記録
   - 成功: 送信数を記録
   - 失敗: エラー内容を記録
```

## 7. 注意事項
### 7.1 既存システムへの影響
#### 7.1.1 データベース構造への影響
- **新規コレクション**: なし（既存コレクションを活用）
- **既存コレクションの変更**: なし
- **インデックス追加**: eventsコレクションの複合インデックス追加

#### 7.1.2 アプリケーションへの影響
- **フロントエンド**: 影響なし（自動実行機能）
- **バックエンド**: Scheduled Functionsの追加
- **既存機能**: 影響なし

#### 7.1.3 運用への影響
- **パフォーマンス**: 毎日の定期実行による軽微な負荷増加
- **ストレージ**: 影響なし
- **セキュリティ**: 既存のセキュリティルールを活用
