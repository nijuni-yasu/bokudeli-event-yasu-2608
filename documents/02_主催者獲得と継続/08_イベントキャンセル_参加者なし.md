# イベントキャンセル_参加者なし

## 1. 概要

### 1.1 機能の目的
主催者がイベントをキャンセルできる機能を提供する。Phase 1 として参加者がいない場合（返金不要）を対象とする。

### 1.2 主要な機能
- 主催者によるイベントキャンセル（予約申請中・注文受付中）
- キャンセル理由の選択（定型ラジオ）または「その他」＋自由記述（必須・文字数上限なし）
- キャンセル確定前の確認ダイアログ
- 飲食店への予約キャンセルメール送信（SendGrid）
- イベントステータスの更新

### 1.3 対象ユーザー
- **主催者**: イベントをキャンセルする権限を持つユーザー
- **飲食店**: イベントに関連する店舗

## 2. 画面仕様

### 2.1 画面遷移
```
イベント管理画面 概要タブ
└── 「イベントをキャンセルする」ボタン → キャンセル理由入力ダイアログ
    └── 「イベントをキャンセルする」ボタン → 確認ダイアログ
        ├── はい → キャンセル処理実行 → 完了表示
        └── いいえ → キャンセル理由入力ダイアログに戻る
```

### 2.2 ステータスごとのボタン表示

判定は `Event.calculatedEventStatus` を基準とし、`accepting_order` から時間・参加者数で派生する `order_closed` / `finished` / `full` も明示的に列挙する。

| ステータス | 「イベントをキャンセルする」ボタン | 「イベント削除」ボタン |
|---|---|---|
| 下書き中 (`in_draft`) | 非表示 | 表示 |
| 予約申請中 (`applying_reservation`) | 表示 | 非表示 |
| 店舗承認待ち (`applying_to_admin`) | 非表示 | 非表示 |
| 注文受付中 (`accepting_order`) | 表示 | 非表示 |
| 満員 (`full`) | 非表示 | 非表示 |
| 注文締切済み (`order_closed`) | 非表示 | 非表示 |
| イベント終了 (`finished`) | 非表示 | 非表示 |
| キャンセル済み (`event_canceled`) | 非表示 | 非表示 |

### 2.3 UI要素

#### イベントキャンセルボタン
- 警告色（赤系）で表示
- 概要タブに設置

#### キャンセル理由入力ダイアログ
- ラジオボタンで定型理由を 1 つ選択（文言は `common/src/constants/eventCancellationReasons.ts` の `EVENT_CANCEL_PRESET_REASONS` と一致させる）
- 「その他」を選んだ場合のみテキストエリアを表示し、**必須**（前後空白は保存時にトリム。**文字数上限は設けない**）
- 確認ダイアログへ進むボタンは、未選択または「その他」で未入力（空白のみ含む）のときは無効化

#### 確認ダイアログ
- モーダル形式
- 警告メッセージ: "イベントのキャンセル処理は戻すことができません。本当にキャンセルしますか？"
- 「はい」ボタン（赤系）/ 「いいえ」ボタン（グレー系）

### 2.4 参加者あり時の UI（Phase 1 暫定対応）
- 「イベントをキャンセルする」ボタンは表示する（**常にテーマ色 `grey-400` のアウトライン**で、赤の error 色は使わない）
- 押下時は処理を実行せず、ダイアログで案内する
  - **タイトル**: 「イベントのキャンセル」
  - **本文**: 参加者ありのため当画面からはキャンセル不可であること、参加者がいない場合は同一ボタンから手続きできること、返金が必要な場合はサポートへ問い合わせること（文言は `user` ローカライズ `manage.event.cancel_support_dialog` に合わせる）
- サポート連絡先を表示する（実装に応じて）

## 3. 技術仕様・データ構造設計

### 3.1 設計方針
- 新規フィールドは最小限に抑える
- キャンセル理由（`cancel_reason`）は `event_status` オブジェクトに追加する
- キャンセル日時・キャンセル実行者（`canceled_at`, `canceled_by`）は `updated_at` / `updated_by` と同列のトップレベルフィールドとする
- 将来の参加者ありキャンセル（返金あり）・最小催行人数による自動キャンセルにも同じデータ構造で対応する

### 3.2 イベントステータスの拡張

`RAW_EVENT_STATUS_VALUES` に `'event_canceled'` を追加する。

```typescript
// common/src/schemas/Event.ts

export const RAW_EVENT_STATUS_VALUES = [
  'in_draft',
  'applying_reservation',
  'applying_to_admin',
  'accepting_order',
  'event_canceled', // 新規追加
] as const

export const EVENT_STATUS_VALUES = [
  ...RAW_EVENT_STATUS_VALUES,
  'order_closed',
  'finished',
  'full',
] as const
```

`event_canceled` は時間で算出されるステータス（`order_closed`, `finished`, `full`）とは異なり、DB に直接保存されるため `RAW_EVENT_STATUS_VALUES` に追加する。

### 3.3 スキーマの拡張

#### event_status に `cancel_reason` を追加

```typescript
// EventDbSchema
event_status: z.object({
  value: z.enum(RAW_EVENT_STATUS_VALUES),
  shop_comment: NonEmptyStringSchema.optional(),
  cancel_reason: z.string().min(1).optional(), // event_canceled 時のみ。上限なし（Firestore ドキュメント上限内）
}),

// EventAppSchema
event_status: z.object({
  value: z.enum(RAW_EVENT_STATUS_VALUES).default('in_draft'),
  shop_comment: z.string().default(''),
  cancel_reason: z.string().min(1).optional(),
}).default({
  value: 'in_draft',
  shop_comment: '',
}),
```

#### トップレベルに `canceled_at`, `canceled_by` を追加

`updated_at` / `updated_by` と同列のフィールドとして配置する。

```typescript
// EventDbSchema
canceled_at: TimestampSchema.optional(),
canceled_by: z.string().nonempty().optional(), // userId or "system"（自動キャンセル時）

// EventAppSchema
canceled_at: EpochMillisSchema.optional(),
canceled_by: z.string().nonempty().optional(),
```

#### 追加フィールド一覧

| フィールド | 型 | 説明 |
|---|---|---|
| `event_status.cancel_reason` | `string`（非空） | キャンセル理由（定型の文言 or 「その他」の自由記述。文字数上限はスキーマでは設けない） |
| `canceled_at` | `Timestamp` / `EpochMillis` | キャンセル日時（`updated_at` と同列） |
| `canceled_by` | `string` | キャンセル実行者の userId（`updated_by` と同列、自動キャンセル時は `"system"`） |

### 3.4 Event クラスの拡張

```typescript
export class Event {
  // 既存フィールド ...
  event_status!: {
    value: RawEventStatusType
    shop_comment: string
    cancel_reason?: string
  }
  canceled_at?: number
  canceled_by?: string

  // calculatedEventStatus の修正
  get calculatedEventStatus(): EventStatusType {
    const rawStatus = this.event_status.value
    // event_canceled は時間計算をスキップ
    if (rawStatus === 'event_canceled') {
      return 'event_canceled'
    }
    if (rawStatus === 'accepting_order') {
      const now = Date.now()
      if (this.event_end_datetime < now) return 'finished'
      if (this.event_deadline_datetime < now) return 'order_closed'
      if (this.members.length >= this.event_max_people) return 'full'
    }
    return rawStatus
  }

  isCanceled(): boolean {
    return this.event_status.value === 'event_canceled'
  }
}
```

### 3.5 `event_canceled` ステータスの影響範囲

#### 操作制限（`finished` と同等）

| 操作 | `event_canceled` | 備考 |
|---|---|---|
| カート注文 | ❌ 不可 | メッセージ表示が必要 |
| イベント編集 | ❌ 不可 | ホワイトリスト方式のため自動で除外 |
| イベント削除 | ❌ 不可 | `in_draft` のみ許可のため自動で除外 |
| 予約申請 | ❌ 不可 | `in_draft` のみ許可のため自動で除外 |
| メニュー更新 | ❌ 不可 | Functions 側にガード追加が必要 |
| 注文追加（API） | ❌ 不可 | Functions 側にガード追加が必要 |
| イベントコピー | ✅ 可能 | 新規イベントは `in_draft` で作成 |
| イベント一覧表示 | ✅ 表示 | EventStatusChip で「キャンセル」と明示 |

### 3.6 EventOrder スキーマ（Phase 1 では変更なし）

Phase 1 は参加者なしが前提のため、注文スキーマの変更は不要。
将来の Phase 2（参加者ありキャンセル）では、既存フィールドで対応可能:

- `status: 'canceled'` — 既存の値を使用
- `canceled_at` — 既存フィールド
- `refund_id` — 既存フィールド（Stripe Refund ID の記録で返金済みを判定）

### 3.7 Functions 設計

#### Callable Function: `cancelEvent`
- **引数**: `{ communityId: string, eventId: string, cancelReason: string }`
- **戻り値**: `{ success: boolean, event_id: string }`
- **認証**: イベント主催者（members に含まれるユーザー）のみ

**処理フロー:**
1. 認証チェック（呼び出しユーザーが members に含まれるか）
2. ステータスチェック（`applying_reservation` or `accepting_order` であること）
3. 参加者チェック（`event_num_members === 0`）
   - 参加者がいる場合はエラーを返す（Phase 1）
4. イベントドキュメント更新
   - `event_status.value` → `'event_canceled'`
   - `event_status.cancel_reason` → 入力されたキャンセル理由
   - `canceled_at` → 現在時刻
   - `canceled_by` → 呼び出しユーザーの userId
5. SendGrid で飲食店に予約キャンセルメール送信

## 4. 予約キャンセルメール（飲食店向け）

- SendGrid の新規テンプレートを作成する
- 送信タイミング: 主催者がイベントキャンセルを確定した直後
- 送信先: 店舗メールアドレス（既存の飲食店向けメールと同様）
- テンプレート内容:
  - イベント名・日時・場所
  - 主催者名・連絡先
  - キャンセル理由（定型選択または「その他」時の主催者入力テキスト）
  - 管理画面へのリンク
