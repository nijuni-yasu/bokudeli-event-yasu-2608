# レター送信エラー時のリカバリー対応

## 1. 概要

### 1.1 目的
レター送信処理中にエラーやプロセス停止が発生した場合のリカバリー仕様を定義する。送信フローに中間状態 `sending` を導入し、二重送信防止と送信失敗時の整合性を両立させる。

### 1.2 対象範囲
- **individual（個別送信）**: 1件宛のメール送信
- **community / event（一括送信）**: コミュニティメンバー・イベント参加者への一括メール送信

## 2. 送信フローとステータス遷移

### 2.1 ステータス定義
| ステータス | 説明 |
|-----------|------|
| draft | 下書き（未送信） |
| timed | 予約済み（community/event の一括送信のみ） |
| sending | 送信処理中（排他ロックとして使用） |
| sent | 送信完了 |

### 2.2 送信フロー（sending 導入後）

#### individual
1. `draft` → `sending`（トランザクションで排他）
2. メール送信実行
3. 成功時: `sending` → `sent`
4. 失敗時: `sending` → `draft`（ロールバック）

#### community / event
1. `timed` → `sending`（トランザクションで排他）
2. 各ユーザーへメール送信（送信結果を `deliveries` サブコレクションに記録）
3. 全件完了時: `sending` → `sent`
4. 途中失敗時: `sending` のまま（リカバリー対象）

## 3. individual（1件送信）のリカバリー

### 3.1 想定シナリオ
- `sending` に更新した後、メール送信前にプロセスが停止
- メール送信中にネットワークエラー等でプロセスが停止

### 3.2 リカバリー方式
- **タイムアウト**: `sending` 状態が一定時間（例: 5分）以上経過したレターを検出
- **復旧処理**: `sending` → `draft` に戻す
- **再送**: ユーザーがレター一覧の「再送」ボタンで再度送信可能

### 3.3 実装方針
- 定期的な Cloud Function（例: 5分ごとのスケジュール）で `status === 'sending'` かつ `updated_at` が N 分以上前のレターを検索
- 該当レターのステータスを `draft` に更新
- individual のみ対象（`letter_type === 'individual'`）

### 3.4 再送導線
- **draft の individual をレター一覧に表示する**: 送信失敗時にリカバリー可能なよう、draft 状態の individual レターも一覧に表示する
- **再送ボタン**: レター一覧で draft の individual に「再送」ボタンを表示し、クリックで `sendIndividualLetter` を呼び出す

## 4. community / event（一括送信）のリカバリー

### 4.1 想定シナリオ
- `sending` に更新した後、`Promise.allSettled` による一括送信中にプロセスが停止
- 一部のユーザーには送信済み、一部は未送信の状態で停止

### 4.2 送信履歴の記録（letters のサブコレクション）

各ユーザーへの送信結果を `letters` のサブコレクション `deliveries` に記録する。

#### 4.2.1 コレクション構造
```
/communities/{communityId}
  /letters/{letterId}
    /deliveries/{userId}   ← 送信結果を記録（user_id をドキュメントIDに使用）
```

**注意**: SUPPORT_MAIL（サポートアカウント）は `user_id` を持たないため、`deliveries` には記録しない。送信対象には含めるが、リカバリー時の未送信者判定からは除外する。

#### 4.2.2 ドキュメントスキーマ（deliveries）
```typescript
interface LetterDelivery {
  user_id: string        // 受信者のユーザーID（ドキュメントIDと同一）
  status: 'sent' | 'failed'
  sent_at?: Timestamp    // 送信成功時のみ設定。失敗時は設定しない
  error_message?: string // 失敗時のエラーメッセージ
}
```

#### 4.2.3 記録タイミング
- 送信時に `user_id` と `email` の対応を保持し、`Promise.allSettled` の結果と `user_id` を紐付けて記録する
- 送信成功時: `deliveries/{userId}` に `{ user_id, status: 'sent', sent_at }` を `set` または `merge`（失敗時は `sent_at` を設定しない）
- 送信失敗時: `deliveries/{userId}` に `{ user_id, status: 'failed', error_message }` を記録（リカバリー時に未送信者として識別するため）

### 4.3 送信フロー（履歴記録付き）
1. `timed` → `sending`（排他）
2. 各ユーザーへ送信し、`Promise.allSettled` の結果を `deliveries` に逐次記録
3. 全件完了後: `sending` → `sent`
4. 途中失敗時: `sending` のまま（リカバリー対象）

### 4.4 リカバリー方式
- **検出**: `status === 'sending'` かつ `updated_at` が N 分以上前のレター（`letter_type` が `community` / `event_participant` / `event_non_participant`）
- **送信対象**: リカバリー時点のメンバーで再送する（`getUserIdsByLetterType` で取得したユーザーリストを使用）
- **復旧処理**:
  1. `letters/{letterId}/deliveries` を取得
  2. `status !== 'sent'` のユーザー（または `deliveries` に存在しないユーザー）を未送信者として特定
  3. 未送信者のみに再送
  4. 再送成功後、該当ユーザーの `deliveries` を更新
  5. 全ユーザー送信完了後: `sending` → `sent`

### 4.5 実装方針
- 送信処理中に `Promise.allSettled` の結果を `deliveries` に逐次記録
- リカバリー用 Cloud Function で `sending` のレターを検出し、`deliveries` を参照して未送信者にのみ再送

## 5. 技術仕様・データ構造設計

### 5.1 Firestore スキーマ設計

#### 5.1.1 コレクション構造（変更後）
```
/communities/{communityId}
  /letters/{letterId}
    /deliveries/{userId}   ← 新規追加（community/event の一括送信時のみ使用）
```

#### 5.1.2 deliveries の Zod スキーマ（案）
```typescript
// common/src/schemas/LetterDelivery.ts（新規）

const LetterDeliveryDbSchema = z.object({
  user_id: z.string().nonempty(),
  status: z.enum(['sent', 'failed']),
  sent_at: TimestampSchema.optional(),
  error_message: z.string().optional(),
})
```

### 5.2 スキーマ変更
- `common/src/schemas/CommunityLetter.ts`: `LETTER_STATUSES` に `'sending'` を追加

### 5.3 変更対象
- `functions/default/src/letter.ts`: 送信フローに `sending` 導入、`deliveries` への記録（community/event）
- 新規: リカバリー用 Cloud Function（individual のタイムアウト復旧）
- 新規: リカバリー用 Cloud Function（community/event の未送信者再送）
- `base/src/components/LetterTable.vue`: `sending` 状態の表示（「送信処理中」）、draft の individual の表示と再送ボタン

## 6. UI 表示仕様

### 6.1 レター一覧でのステータス表示
| ステータス | 表示文言 |
|-----------|----------|
| draft | 下書き |
| timed | 予約済み |
| sending | 送信処理中 |
| sent | 送信済み |

レター一覧（LetterTable）で `sending` のときは「送信処理中」と表示する。

### 6.2 individual の再送 UI
- draft の individual をレター一覧に表示する
- 操作列に「再送」ボタンを表示し、クリックで `sendIndividualLetter` を呼び出す

## 7. Firestore セキュリティルール
`deliveries` サブコレクションは Cloud Function からのみ書き込みを行うため、クライアントからの直接アクセスは不要。既存の `letters` ルールに従い、必要に応じて `deliveries` の読み取りを制限する。

## 8. 今後の検討事項
- タイムアウト時間（5分）の妥当性
- リカバリー Function の実行頻度
- `deliveries` の保持期間（送信完了後のクリーンアップ方針）
