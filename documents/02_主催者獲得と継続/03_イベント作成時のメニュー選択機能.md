# イベント作成時のメニュー選択機能

## 1. 概要

### 1.1 機能の目的
主催者がイベント作成時に飲食店のメニューを選択し、参加者が注文できるメニューを制限する機能を提供する。

### 1.2 主要な機能
- イベント作成時のメニュー一覧表示
- メニューの選択・非選択の切り替え
- 選択されたメニューのみをイベントメニューとして登録
- 予約申請時のメニュースナップショット機能

### 1.3 対象ユーザー
- イベント主催者（コミュニティ管理者）
- イベント参加者（選択されたメニューのみ注文可能）

## 2. ねらい

### 2.1 ビジネス目標
- 主催者の予算管理の効率化
- 参加者の注文選択の簡素化
- イベント運営の円滑化

### 2.2 ユーザー価値
- **主催者**: 予算内でのメニュー選択によるコスト管理
- **参加者**: 選択肢の絞り込みによる注文の簡素化
- **飲食店**: 事前の注文予測による準備の効率化

### 2.3 成功指標（KPI）
- 主催者請求書払いイベントの増加率
- 参加者の注文完了率向上
- イベント運営の満足度向上

## 3. 前提条件

### 3.1 技術的前提条件
- 既存のイベント作成機能が実装済み
- 既存のメニュー管理機能が実装済み
- PartnerMenuからEventMenuへのスナップショット機能が実装済み

### 3.2 ビジネス的前提条件
- 主催者請求書払い（後日まとめ払い）の利用
- 飲食店のメニューが事前に登録済み

### 3.3 依存関係
- イベント作成機能
- メニュー管理機能
- 予約申請機能
- 注文機能

## 4. 画面仕様

### 4.1 画面遷移
```
イベント作成画面
├── 店舗選択 → メニュー選択画面 → イベント詳細設定画面
              ├── メニュー選択・非選択切り替え
              ├── 次へボタン → イベント詳細設定画面
              └── 戻るボタン → 店舗選択画面
```

### 4.2 UI要素
- **メニュー一覧表示**
  - メニュー画像、名称、価格、説明を表示
  - デフォルト状態はすべて選択済み（ON）
  - 選択状態は視覚的に明確に表示

- **メニュー選択切り替え**
  - クリックで選択・非選択を切り替え
  - 非選択時はグレイアウト表示
  - 選択状態の視覚的フィードバック

- **イベントページ（参加者のメニュー選択ページ）**
  - 主催者が選択したメニューのみが表示される


## 5. 技術仕様・データ構造設計

### 5.1 Firestoreスキーマ
```typescript
// common/src/schemas/EventMenu.ts
import { z } from 'zod'

const EventMenuDbSchema = z.object({
  // 基本情報
  menu_id: z.string(),
  event_id: z.string(),
  partner_id: z.string(),
  
  // メニュー情報
  name: z.string().min(1),
  price: z.number().min(0),
  description: z.string().optional(),
  imageUrl: z.string().url().optional(),
  
  // 選択状態
  is_selected: z.boolean().default(true),
  
  // タイムスタンプ
  created_at: z.date(),
  updated_at: z.date(),
})

export class EventMenu {
  menu_id: string = ''
  event_id: string = ''
  partner_id: string = ''
  name: string = ''
  price: number = 0
  description?: string
  imageUrl?: string
  is_selected: boolean = true
  created_at: Date = new Date()
  updated_at: Date = new Date()
  
  static fromPartnerMenu(partnerMenu: PartnerMenu, eventId: string, partnerId: string): EventMenu {
    const eventMenu = new EventMenu()
    eventMenu.menu_id = partnerMenu.menu_id
    eventMenu.event_id = eventId
    eventMenu.partner_id = partnerId
    eventMenu.name = partnerMenu.menu_name
    eventMenu.price = partnerMenu.menu_price
    eventMenu.description = partnerMenu.menu_description
    eventMenu.imageUrl = partnerMenu.menu_image_url
    eventMenu.is_selected = true
    return eventMenu
  }
}
```

### 5.2 Firestoreフロントエンド処理
- **データ取得処理**: 店舗選択時にPartnerMenuを取得し、EventMenuに変換
- **データ更新処理**: メニュー選択状態の更新（is_selectedフィールド）
- **エラーハンドリング**: メニュー取得失敗時のフォールバック処理

### 5.3 Firestoreセキュリティルール
変更点なし

### 5.4 Functions設計
#### 5.4.1 Callable Functions（フロントエンドから呼び出し）
- `updateEventMenuSelection`: メニュー選択状態の更新
  - **引数**: `eventId: string`, `menuId: string`, `isSelected: boolean`
  - **戻り値**: `{ success: boolean, menu_id: string }`
  - **認証**: コミュニティ管理者のみ

- `createEventMenusFromPartner`: パートナーメニューからイベントメニューを作成
  - **引数**: `eventId: string`, `partnerId: string`
  - **戻り値**: `{ success: boolean, menu_count: number }`
  - **認証**: コミュニティ管理者のみ

#### 5.4.2 Trigger Functions（自動実行）
- `onEventMenuCreated`: イベントメニュー作成時の処理
  - **トリガー**: EventMenuドキュメント作成時
  - **処理内容**: 選択状態の初期化、ログ記録
  - **権限**: システム権限

### 5.5 処理フロー

### 5.5.1 新規イベントの作成
1. 主催者がイベント作成時に、店舗選択画面で店舗を選択
2. 選択された店舗のPartnerMenu一覧を取得
3. メニュー選択画面でPartnerMenu一覧を表示
4. 主催者がメニューの選択・非選択を切り替え（is_selected: trueで初期化）
5. イベントの下書き保存時/予約申請時に選択されたPartnerMenuをEventMenuにスナップショット保存

### 5.5.2 既存イベントの編集・更新
- メニュー選択画面にて、EventMenuとして保存された店舗を選択している場合
  - EventMenuが表示され、is_selected の選択/非選択が反映される。
- メニュー選択画面にて、EventMenuとして保存された店舗とは別のお店を選択し直した場合
  - PartnerMenuが表示され、新たにis_selected: trueで初期化される。

### 5.5.3 イベントページの表示
- イベントページにおいてはEventMenuが表示される。
- is_selected: true だけが表示される。

## 7. 注意事項

### 7.1 既存システムへの影響
- **UI**: 既存のイベント作成フローにメニュー選択画面を挿入
- **注文機能**: 選択されていないメニューは注文不可とする。is_selected:trueのみを表示
- **スナップショット機能**: 選択されたメニューのみをコピーする仕様変更

### 7.2 セキュリティ考慮事項
- **認証**: メニュー選択はコミュニティ管理者のみ許可
- **権限**: イベント作成権限を持つユーザーのみアクセス可能
- **データ整合性**: 予約申請後のメニュー変更は既存の仕様通り制限
- **入力値検証**: メニュー選択状態の適切なバリデーション

### 7.3 運用考慮事項
- **パフォーマンス**: 大量のメニューがある場合の表示最適化
- **ユーザビリティ**: 選択状態の視覚的フィードバック
- **データ管理**: 削除されたメニューの適切な処理
- **拡張性**: 将来的なメニューカテゴリ機能への対応
- **ログ**: メニュー選択変更の適切なログ記録
