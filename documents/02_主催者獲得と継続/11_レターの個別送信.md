# レターの個別送信

## 1. 概要
### 1.1 機能の目的
イベント主催者（コミュニティマネージャー）が、イベント参加者やコミュニティメンバーに対して個別にメッセージを送信できるようにする。

### 1.2 主要な機能
- イベントメンバー一覧・コミュニティメンバー一覧から、個別にメールを送信できる
- メール送信ダイアログ（EmailDialog）で件名・本文を入力して即時送信
- **送信フロー**: フロントエンドでレターを Firestore に保存した上で、`communityId` と `letterId` のみを Cloud Function に渡して送信する（`sendTestLetter` と同様のパターン）
- 送信したメールは `letters` コレクションに `letter_type: 'individual'`, `status: 'sent'` として保存され、レター一覧に履歴として表示される
- 予約送信は行わない（即時送信のみ）

### 1.3 対象ユーザー
- コミュニティマネージャー（イベント主催者）

## 2. ねらい
### 2.1 ビジネス目標
- 主催者と参加者間のコミュニケーションを円滑化し、イベント体験を向上させる
- 個別の問い合わせ対応や連絡をプラットフォーム内で完結できるようにする

### 2.2 ユーザー価値
- 主催者：参加者に対して個別に連絡・フォローアップが可能になる
- 参加者：主催者から直接メールが届くことで信頼感のあるコミュニケーションが取れる

### 2.3 成功指標（KPI）
- 個別メール送信機能の利用率
- 主催者のNPS向上

## 3. 前提条件
### 3.1 技術的前提条件
- SendGrid API が利用可能であること
- コミュニティマネージャーのメールアドレスが設定されていること
- 受信者のメールアドレスが `users_personal_information` コレクションに登録されていること

### 3.2 ビジネス的前提条件
- 送信元は `DEFAULT_FROM`（shokujii@nijuni.jp）を使用し、`replyTo` にコミュニティメールを設定する
- 送信者個人のメールアドレスを `from` に使用しない（SendGrid のドメイン制約対応）

### 3.3 依存関係
- `common/src/schemas/CommunityLetter.ts` - Letter スキーマ（`individual` タイプ追加）
- `common/src/apis/letter.ts` - sendIndividualLetter API の型定義（`communityId`, `letterId` のみ）
- `functions/default/src/individualLetter.ts` - 個別メール送信 Cloud Function（新規作成）
- `base/src/stores/letterList.ts` - `newLetter` の individual 対応（`user_id` 等のオプション追加）
- `base/src/components/EmailDialog.vue` - メール送信ダイアログ（レター保存→送信のフローに変更）
- `user/src/components/manage/event/member.vue` - イベントメンバー一覧（コメント解除 + `communityId` を EmailDialog に渡す）

## 4. 画面仕様
### 4.1 画面遷移
```
メンバー一覧画面（event/member.vue または community/member.vue）
  └→ メンバー行のメールアイコンボタンをクリック
      └→ EmailDialog（メール送信ダイアログ）が表示
          └→ 件名・本文を入力して送信
              └→ 1. フロントエンドでレターを Firestore に保存（status: 'draft'）
              └→ 2. sendIndividualLetter(communityId, letterId) を呼び出し
              └→ 3. Cloud Function がメール送信し、status を 'sent' に更新
              └→ 送信完了通知
                  └→ レター一覧に履歴として表示
```

### 4.3 レター一覧での履歴表示（LetterTable の修正）

#### 4.3.0 一覧画面ごとの表示ルール
individual レターが表示される一覧は、`event_id` の有無によって決まる。

- **イベントレター一覧**（`event/letter.vue`）: `event_id` が一致する individual レターのみ表示される。既存のフィルタ `ls.letter.letter_type == 'community' || ls.letter.event_id !== eventId` により、`event_id` が未設定の individual レターは表示されない
- **コミュニティレター一覧**（`community/letter.vue`）: 全レターが表示されるため、`event_id` の有無にかかわらず individual レターが表示される

つまり、イベントメンバー一覧から送信した individual レターは**イベントレター一覧にもコミュニティレター一覧にも**表示され、コミュニティメンバー一覧から送信した individual レターは**コミュニティレター一覧にのみ**表示される。

#### 4.3.1 individual タイプの表示仕様
| 列 | 表示内容 |
|---|---|
| ステータス | `sent`（常に送信済み） |
| 内容 | 件名・本文の先頭40文字 |
| タイプ | 「個別送信」 |
| 対象人数 | `1` |
| 配信日時 | 送信日時 |
| 更新日時 | 送信日時 |
| 操作 | すべて非表示（編集・削除・コピーいずれも非表示） |

### 5.3 Functions 設計

#### 5.3.1 sendIndividualLetter Cloud Function（新規作成）
```typescript
// functions/default/src/individualLetter.ts

/**
 * 個別メール送信 Cloud Function
 *
 * 1. 入力バリデーション（communityId, letterId）
 * 2. Firestore からレターを取得
 * 3. レターの letter_type が 'individual'、status が 'draft' であることを検証
 * 4. 権限チェック（送信者がコミュニティマネージャーであること）
 * 5. 受信者のメールアドレスを取得（user_id から）
 * 6. SendGrid でメール送信
 * 7. レターの status を 'sent'、sent_at を設定して更新
 */
export const sendIndividualLetter = onCall(
  {
    secrets: ['SENDGRID_API_KEY'],
  },
  async (request) => {
    const uid = request.auth?.uid
    if (uid === undefined) {
      throw new HttpsError('unauthenticated', 'The function must be called while authenticated.')
    }

    const { communityId, letterId } = sendIndividualLetterRequestSchema.parse(request.data)

    // レターを取得
    const letter = await getLetter(communityId, letterId)
    if (!letter) {
      throw new HttpsError('not-found', 'Letter not found.')
    }
    if (letter.letter_type !== 'individual') {
      throw new HttpsError('invalid-argument', 'Letter must be of type individual.')
    }
    if (letter.status !== 'draft') {
      throw new HttpsError('failed-precondition', 'Letter must be in draft status to send.')
    }
    if (letter.user_id == null || letter.user_id === '') {
      throw new HttpsError('invalid-argument', 'User is required.')
    }

    // 権限チェック
    const community = await getCommunity(communityId)
    if (!community) {
      throw new HttpsError('not-found', 'Community not found.')
    }
    const isManager = await community.hasRole(uid, 'manager')
    if (!isManager) {
      throw new HttpsError('permission-denied', 'Only community managers can send direct emails.')
    }

    // 受信者のメールアドレスを取得
    const targetUser = await getUserPersonalInformation(letter.user_id)
    if (!targetUser?.user_email) {
      throw new HttpsError('not-found', 'User email not found.')
    }

    const communityEmail =
      community.community_email !== '' ? community.community_email : DEFAULT_FROM

    await send({
      to: targetUser.user_email,
      from: DEFAULT_FROM,
      replyTo: communityEmail,
      subject: letter.letter_title,
      text: letter.letter_content,
    })

    // status を sent に更新
    const db = getFirestore()
    const now = Timestamp.now()
    const letterRef = db.collection('communities').doc(communityId).collection('letters').doc(letterId)
    await letterRef.update({
      status: 'sent',
      sent_at: now,
      updated_at: now,
    })
  },
)
```

## 7. 処理フロー

### 7.1 個別メール送信フロー
```
1. 主催者がメンバー一覧画面を開く
2. メンバー行のメールアイコンをクリック
3. EmailDialog が表示される
4. 件名・本文を入力して「送信」ボタンをクリック
5. フロントエンドで:
   a. letterListStore.newLetter('individual', eventId) でレターを作成
   b. user_id, letter_title, letter_content を設定し、updateLetter で Firestore に保存（status: 'draft'）
   c. sendIndividualLetter Cloud Function を呼び出し（引数: communityId, letterId のみ）
6. Cloud Function 内で:
   a. Firestore からレターを取得（getLetter）
   b. letter_type === 'individual', status === 'draft' であることを検証
   c. 権限チェック（コミュニティマネージャーか）
   d. 受信者のメールアドレスを取得（user_id から）
   e. SendGrid でメール送信（from: DEFAULT_FROM, replyTo: コミュニティメール）
   f. レターの status を 'sent'、sent_at を設定して更新
7. フロントエンドで送信完了通知を表示
8. ダイアログを閉じる
```

### 7.2 レター一覧での履歴表示フロー
```
1. 主催者がレター一覧画面を開く
2. letterListStore が letters コレクションからデータを取得
3. LetterTable に全レターが表示される（individual タイプ含む）
4. individual タイプのレターは:
   - タイプ列に「個別送信」と表示
   - 宛先ユーザー名を表示
   - 対象人数は 1
   - 「編集」「削除」「コピー」ボタンはすべて非表示
```

## 9. 注意事項

### 9.1 既存システムへの影響
- **letters コレクション**: `letter_type: 'individual'` のドキュメントが追加される。既存のレター一覧クエリに自動的に含まれる
- **polling の `sendLetter` 処理**: individual レターは `status: 'sent'` で保存されるため、`getScheduledLetters`（`status === 'timed'` で取得）に引っかからない。polling による二重送信のリスクはない
- **レガシー `send_email` 関数**: 直接的な影響はない。今回の実装では使用しない。将来的に廃止を検討
- **LetterEdit**: 変更なし。individual レターは EmailDialog から即時送信されるため、LetterEdit を経由しない

### 9.2 セキュリティ考慮事項
- 送信者がコミュニティマネージャーであることを Cloud Function 側で検証する
- 受信者のメールアドレスは `users_personal_information` から取得し、フロントエンドには公開しない
- `from` に個人のメールアドレスを使用しない（SendGrid のドメイン制約対応）

### 9.3 メールの送信元設定
| フィールド | 値 | 説明 |
|---|---|---|
| `from` | `DEFAULT_FROM` (shokujii@nijuni.jp) | SendGrid の認証済みドメインから送信 |
| `replyTo` | コミュニティのメールアドレス | 受信者が返信した場合にコミュニティに届く |

### 9.4 将来の履歴機能拡張への対応
- レターは Firestore に保存されるため、`user_id`, `event_id`, `letter_title`, `letter_content` 等の履歴検索・フィルタリングに必要な情報はすべて保持される
- `letters` コレクションに保存するため、既存のレター一覧基盤をそのまま活用可能
- 後からフィールドを追加する場合も、individual タイプのみの変更で済む

### 9.5 sendTestLetter との一貫性
- `sendIndividualLetter` は `sendTestLetter` と同様に `communityId` と `letterId` のみを受け取る
- レターの内容は Firestore を単一の情報源とし、API は ID のみで参照する設計
