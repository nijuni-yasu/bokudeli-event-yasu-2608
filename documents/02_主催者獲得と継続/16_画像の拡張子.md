# 画像の拡張子

## 1. 概要

### 1.1 機能の目的

ユーザーがアップロードする画像について、**プロジェクト全体で一貫した受け入れ形式**を定める。現状はフロント側の `accept` 属性が `image/*`、サーバー側の `storage.rules` も暫定全許可となっており、SVG（XSS リスク）、HEIC（多くのブラウザで表示不可）、AVIF（一部ブラウザで表示不可）など、表示できない／セキュリティ上望ましくない形式までアップロードを許す状態になっている。本仕様で受け入れ形式を明文化し、フロント・ストレージ・Functions の各レイヤーで揃える。

### 1.2 対象範囲

以下のすべての画像アップロード経路を対象とする。

| 画像種別 | 主な実装 |
| :--- | :--- |
| プロフィール画像 | `user/src/pages/profile.vue`, `base/src/components/UserBioEditDialog.vue` |
| イベントページの画像 | `base/src/components/eventcreate/EventDetailCard.vue` → `base/src/components/ImageInput.vue` |
| コミュニティページの画像 | `base/src/components/CommunityEdit.vue` → `ImageInput` |
| 飲食店の shop 画像（admin） | `admin/src/pages/shop.vue` → `ImageInput` |
| 飲食店の menu 画像（admin） | `admin/src/components/MenuEditCard.vue` → `ImageInput` |
| アルバム画像 | `user/src/components/manage/community/album.vue` |

> Legacy パッケージ（`manager` 等）は新規実装の対象外。本仕様の適用は**現役のアクティブパッケージ**（`user` / `admin` / `base` / `functions/default`）に限る。

### 1.3 対象ユーザー

- 画像をアップロードする全エンドユーザー（一般ユーザー・コミュニティ管理者・飲食店オーナー）
- 仕様・実装のレビューア

## 2. ねらい

### 2.1 ビジネス目標

- アップロードしたが**他の閲覧者には表示できない画像**（HEIC など）が混入することを防ぐ
- SVG 経由の XSS リスクを構造的に排除する
- 受け入れ仕様を共通化し、画像種別ごとのチェックバラつきを解消する

### 2.2 ユーザー価値

- アップロードできた画像は、どの端末・ブラウザでも閲覧者全員に表示される
- 受け入れ不可の形式は、アップロード時点で明確なメッセージとともに弾かれる

## 3. 前提条件

### 3.1 技術的前提条件

- フロントの画像入力は基本的に `base/src/components/ImageInput.vue` に集約されている。`accept` 属性は本仕様に従い**この共通コンポーネントで一元定義**する
- Functions の画像処理は `functions/default` の Sharp ベースで行う（プロフィール画像のサムネイル生成等）
- `storage.rules` は現状「2026-12-31 まで全許可」の暫定状態。本仕様の実装と合わせて `contentType` 制限を入れる方向で見直す

### 3.2 ビジネス的前提条件

- 現状 GIF はアルバム等で実際に利用されており、**アニメーション込みで動作している**ため、本仕様でも変換せず受け入れる
- HEIC（iOS 純正）はブラウザ間互換が取れないため、変換実装が整うまでは受け入れない

## 4. 受け入れ仕様

### 4.1 対応する形式

| 形式 | 拡張子 | MIME タイプ | 備考 |
| :--- | :--- | :--- | :--- |
| JPEG | `.jpg`, `.jpeg` | `image/jpeg` | 写真系のデフォルト |
| PNG | `.png` | `image/png` | 透過対応 |
| GIF | `.gif` | `image/gif` | **アニメ GIF をそのまま許可（変換しない）** |
| APNG | `.apng`, `.png` | `image/apng`, `image/png` | **アニメーション PNG をそのまま許可（変換しない）**。MIME は `image/apng` で来る場合と `image/png` で来る場合の双方を許可する |
| WebP | `.webp` | `image/webp` | 圧縮率に優れ、主要ブラウザで表示可能 |

### 4.2 非対応の形式

| 形式 | 拡張子 | 主な MIME | 理由 |
| :--- | :--- | :--- | :--- |
| SVG | `.svg`, `.svgz` | `image/svg+xml` | 内部にスクリプトを含めうるため、XSS リスク回避の観点で除外 |
| AVIF | `.avif` | `image/avif` | 一部ブラウザで表示できない／実需が薄い |
| JPEG XL | `.jxl` | `image/jxl` | 対応ブラウザが限定的（Safari 17+ 等のみ）。当面非対応 |
| JPEG 2000 | `.jp2`, `.j2k` | `image/jp2` | Safari のみ表示可。他ブラウザで閲覧不可 |
| TIFF | `.tif`, `.tiff` | `image/tiff` | 多くのブラウザで表示不可、ファイルサイズ大 |
| BMP | `.bmp` | `image/bmp` | ファイルサイズ大、Web 用途では非推奨 |
| ICO / CUR | `.ico`, `.cur` | `image/vnd.microsoft.icon`, `image/x-icon` | ファビコン専用。写真・コンテンツ画像用途ではない |
| RAW（カメラ） | `.cr2`, `.nef`, `.arw`, `.dng`, `.orf` 等 | 各種 | ブラウザで表示不可、ファイルサイズ大 |
| PSD / AI / EPS | `.psd`, `.ai`, `.eps` | 各種 | 編集データ。ブラウザで表示不可 |

その他、上記 4.1 / 4.3 に列挙されない形式は**すべて非対応**として扱う。

### 4.3 将来対応

| 形式 | 拡張子 | MIME | 方針 |
| :--- | :--- | :--- | :--- |
| HEIC | `.heic`, `.heics` | `image/heic`, `image/heic-sequence` | 現時点では非対応。将来、サーバー側で JPEG / WebP へ変換する仕組みが整い次第対応する |
| HEIF | `.heif`, `.heifs` | `image/heif`, `image/heif-sequence` | HEIC と同じ将来対応扱い。Android（Google Photos 等）から `.heif` で出力されるケースもあるため、HEIC とセットで扱う |

### 4.4 GIF / APNG の扱い（明示）

- アニメーション GIF・APNG は**変換せず**そのまま受け入れる。閲覧時もアニメーションは保持する
- プロフィール画像のように Sharp でサムネイルを生成する経路では、Sharp の標準動作（先頭フレーム静止画）に依存することを許容する。アニメーション維持はサムネイル側では保証しない
- APNG はブラウザによって MIME が `image/apng` で送られる場合と `image/png` で送られる場合があるため、許可リストには**両方**を含める

## 5. 技術仕様

### 5.1 判定基準

- 受け入れ可否の判定は**ファイルの MIME タイプ**で行う（`image/jpeg` / `image/png` / `image/apng` / `image/gif` / `image/webp`）
- 拡張子文字列はあくまで仕様書・UI 表記用。実装側のチェックは MIME タイプを正とする
- JPEG の別名拡張子（`.jfif`, `.jpe`, `.pjpeg`, `.pjp` 等）は MIME タイプ `image/jpeg` として上がってくるため、本仕様の「対応」に**自動的に含まれる**。仕様書側ではこれらを明示列挙しない
- APNG は `image/apng` と `image/png` の双方の MIME で送られうるため、許可リストには両方を含める

### 5.2 フロント側（必須）

- `base/src/components/ImageInput.vue` の `accept` 属性を、`image/*` から **`image/jpeg, image/png, image/apng, image/gif, image/webp`** に変更する
- プロフィール画像のように `ImageInput` を経由していない `<input type="file">` 直書きの箇所も同じ `accept` に揃える
- 受け入れ可能な MIME タイプ一覧は `common` または `base` に**定数として定義**し、各コンポーネントから参照する形にする（例: `ALLOWED_IMAGE_MIME_TYPES`）
- `accept` は OS のファイル選択ダイアログでの絞り込みに過ぎず、迂回可能なため、**選択直後に MIME タイプを再チェック**してから `uploadImage` 系の関数に渡す

### 5.3 Storage Rules（必須）

- `storage.rules` の暫定全許可ルールを廃止する変更と合わせて、**画像をアップロードするパスでは `request.resource.contentType` を 5.2 の許可リストに含まれる値に限定**する
- 既存の暫定ルールが期限切れになる前に、本仕様の `contentType` 制限を適用する

### 5.4 Functions 側（必須）

- アップロードされた画像を処理する Function（プロフィール画像のサムネ生成 `userImage.ts` 等）は、`object.contentType` が許可リストに含まれない場合は処理をスキップする
- Sharp が読めない形式（SVG / HEIC 等）が万一通過した場合でもクラッシュしないよう、**`contentType` チェック → ホワイトリスト一致のときだけ処理**の順を守る

### 5.5 エラーメッセージ（i18n）

- フロントで非対応形式が選択された場合、**ユーザー向けの明確な文言**を表示する
  - 例: 「対応していない画像形式です。JPEG / PNG / GIF / WebP のいずれかをお選びください。」
- HEIC が選ばれた場合は補助文言を出してもよい（必須ではない）
  - 例: 「iPhone で撮影した HEIC 形式は現在対応していません。お手数ですが JPEG として書き出してから再度アップロードしてください。」
- 文言は `base/src/locales/messages/ja.ts` で管理する

## 6. 実装優先度

### 6.1 Phase 1（必須）

- [ ] `base` または `common` に `ALLOWED_IMAGE_MIME_TYPES` 定数を新設（`['image/jpeg', 'image/png', 'image/apng', 'image/gif', 'image/webp']`）
- [ ] `base/src/components/ImageInput.vue` の `accept` を定数参照に変更
- [ ] `ImageInput` を経由していない画像アップロード入力（プロフィール画像周り、アルバム画像）も同じ定数を参照する形に統一
- [ ] フロント側で選択直後に MIME タイプを再チェックし、不一致なら i18n メッセージで弾く処理を追加
- [ ] 非対応形式エラーの i18n キーを追加（`base/src/locales/messages/ja.ts`）
- [ ] `storage.rules` の暫定全許可ルール置き換え時に、画像パスへ `contentType` 許可リスト制限を組み込む
- [ ] `functions/default` の画像処理 Function に `contentType` ホワイトリストチェックを追加

### 6.2 Phase 2（将来対応）

- [ ] HEIC / HEIF を JPEG または WebP に変換する Functions（`sharp` の libheif 付きビルドまたは `heic-convert` 等）を実装し、受け入れ仕様に追加する
- [ ] Phase 2 の対応に合わせ、フロントの `accept` および `storage.rules` の許可リストに `image/heic`, `image/heic-sequence`, `image/heif`, `image/heif-sequence` を追加する

## 7. 注意事項

### 7.1 既存システムへの影響

- 既にアップロード済みの SVG / HEIC / AVIF などのファイル（もしあれば）はそのまま閲覧可能とする。本仕様は**新規アップロード**にのみ適用する
- `manager`（Legacy）は対象外

### 7.2 セキュリティ考慮事項

- フロントの `accept` 属性は迂回可能なため、**Storage Rules と Functions 側のチェックを正**とする
- SVG を受け入れないことで、`<img src>` 表示時の XSS 経路を構造的に排除する

### 7.3 運用考慮事項

- 受け入れ形式を変更する場合は、本書の §4 と `ALLOWED_IMAGE_MIME_TYPES` 定数、`storage.rules`、`ImageInput.vue` の `accept` を**同時に**更新する
- HEIC を将来対応する場合の変換戦略（フロント変換 / サーバー変換）は別途設計する
