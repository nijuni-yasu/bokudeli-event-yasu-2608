# イベント作成時のメニュー選択機能

## 1. 概要
### 1.1 機能の目的
イベント主催者が、飲食店の登録済みメニューの中から参加者が注文できるメニューを個別に選択・管理できるようにすることで、イベントごとに最適なメニュー構成を実現する。

### 1.2 主要な機能
- イベント編集画面でメニュー一覧を表示し、各メニューの選択/未選択をトグル可能
- 選択されたメニュー（is_selected: true）は緑色で強調表示
- 未選択のメニュー（is_selected: false）は灰色で表示
- クリックで選択/未選択を切り替え
- デフォルトは選択状態（is_selected: true）
- 前回選択したメニューの状態を保持
- 予約承認後もメニューの選択/未選択を変更可能

### 1.3 event_statusによる挙動の違い
イベントのステータスによって、メニュー選択機能の挙動が異なります。

| event_status | メニュー選択可否 | 最新PartnerMenu取得 | 備考 |
|-------------|----------------|-------------------|------|
| in_draft | ○ | ○ | 下書き編集時。最新のPartnerMenuを取得してEventMenuに変換 |
| applying_reservation | ○ | ○ | 申請中も編集可能。最新のPartnerMenuを取得してEventMenuに変換 |
| accepting_order | ○ | × | 承認後の編集。**is_selectedのみ変更可能**。メニュー内容（価格・説明等）は承認時点で固定 |
| finished | × | × | イベント終了後は変更不可 |

**重要な仕様**:
- `accepting_order`状態では、既存EventMenuの`is_selected`フラグのみを更新します
- この状態では最新のPartnerMenuは取得せず、メニューの価格・説明・画像などは承認時点のまま変更されません
- これにより、飲食店が承認した時点のメニュー内容を保持しつつ、主催者が注文可能なメニューの範囲のみを調整できます

**calculatedEventStatusの使用**:
- ステータス判定には`event_status.value`ではなく、`calculatedEventStatus`を使用します
- `calculatedEventStatus`は時刻によって自動的にステータスを判定するゲッターです
- 例：`accepting_order`状態でもイベント終了時刻を過ぎていれば自動的に`finished`を返します
- これにより、データベース上は`accepting_order`のままでも、実際には終了しているイベントでのメニュー編集を防ぎます

### 1.4 対象ユーザー
- イベント主催者（admin画面利用者）

#### 4.2.2 表示するメニューの分岐
表示するメニューは、イベントの`calculatedEventStatus`によって取得元が異なります。

**重要**: ステータス判定には`event_status.value`ではなく、`calculatedEventStatus`を使用します。これにより、時刻による自動的なステータス判定（例：イベント終了時刻を過ぎた場合に`finished`になる）が考慮されます。

**【accepting_order状態（承認後）】**
- 既存のEventMenuをそのまま表示
- PartnerMenuからの取得は行わない
- メニュー内容（価格・説明・画像など）は承認時点で固定
- is_selectedフラグのみ変更可能

**【in_draft, applying_reservation状態（承認前）】**
- `convertFromPartnerMenuToEventMenu`関数を使用してPartnerMenuを取得
  - 選択されたお店をもとにPartnerMenuを取得
  - PartnerMenuの期間限定情報に基づいてフィルタリング
  - イベント開始日時の期間内のメニューのみをEventMenuに変換
  - 変換時に既存EventMenuと同じmenu_idがあれば、is_selected値を引き継ぐ
  - 同じmenu_idがなければ、デフォルトでis_selected: trueを設定

**【finished状態（イベント終了後）】**
- メニューの表示は可能だが、編集は不可
- `calculatedEventStatus`によって自動判定される（データベース上は`accepting_order`でも時刻が過ぎていれば`finished`）

**ユースケース**: 
- 新規作成時: 全メニューがデフォルト選択状態
- 編集時（承認前・お店や日付変更なし）: 前回の選択状態を保持
- 編集時（承認前・お店や日付変更あり）: 期間内メニューを再取得し、同じメニューがあれば選択状態を引き継ぐ
- 編集時（承認後）: 承認時点のEventMenuを表示、is_selectedのみ変更可能

```typescript
// common/src/schemas/EventMenu.ts に追加・変更
import { z } from 'zod'
import { TimestampSchema } from './firebase/index.js'

const EventMenuDbSchema = z.object({
  updatedAt: TimestampSchema,
  menu_description: z.string().nonempty(),
  menu_image_url: z.string().url().nonempty(),
  menu_name: z.string().nonempty(),
  menu_price: z.number().int().positive(),
  is_sold_out: z.boolean(),
  menu_sort_number: z.number().int().nonnegative(),
  is_selected: z.boolean(), // 新規追加
})

const EventMenuAppSchema = z.object({
  // Mandatory
  menu_name: z.string().nonempty(),
  // Default
  menu_price: z.number().int().positive().default(100),
  menu_image_url: z.string().default(''),
  menu_description: z.string().default(''),
  is_sold_out: z.boolean().default(false),
  is_selected: z.boolean().default(true), // 新規追加（デフォルト: true）
  // Mandatory
  menu_sort_number: z.number().int().nonnegative(),
})

const convertToDb = (menu: EventMenu) => {
  return {
    ...menu,
    updatedAt: Date.now(),
  }
}

export class EventMenu {
  // 既存フィールド
  readonly id: string
  readonly menu_id: string
  readonly event_id: string
  updatedAt: number
  menu_description!: string
  menu_image_url!: string
  menu_name!: string
  menu_price!: number
  is_sold_out!: boolean
  menu_sort_number!: number
  
  // 新規追加フィールド
  is_selected!: boolean

  constructor(event_id: string, menu_id: string, src: Partial<EventMenu>) {
    Object.assign(this, EventMenuAppSchema.parse(src))
    this.event_id = event_id
    this.id = menu_id
    this.menu_id = menu_id
    this.updatedAt = Date.now()
  }

  isValidForDatabase(): boolean {
    return EventMenuDbSchema.safeParse(convertToDb(this)).success
  }

  toFirestore(): z.infer<typeof EventMenuDbSchema> {
    return EventMenuDbSchema.parse(convertToDb(this))
  }
}
```

### 5.3 Firestoreフロントエンド処理

#### 5.3.1 メニュー変換関数

PartnerMenuからEventMenuに変換するユーティリティ関数を実装します。

**配置場所**: `common/src/utils/eventMenuConverter.ts`（新規作成）

```typescript
// common/src/utils/eventMenuConverter.ts（新規作成）
import { type BokudeliPartnerMenu } from '@shokujii/base/stores/partner.js'
import { type BokudeliEventMenu } from '@shokujii/base/stores/event.js'

/**
 * PartnerMenuをEventMenuに変換（既存EventMenuのis_selected状態を引き継ぐ）
 * @param partnerMenu - 変換元のPartnerMenu
 * @param eventId - イベントID
 * @param eventStartDatetime - イベント開始日時（期間チェック用）
 * @param existingEventMenus - 既存のEventMenu配列（is_selected状態を引き継ぐため）
 * @returns 変換されたEventMenu、または期間外の場合はnull
 */
export function convertFromPartnerMenuToEventMenu(
  partnerMenu: BokudeliPartnerMenu,
  eventId: string,
  eventStartDatetime: number | null,
  existingEventMenus: BokudeliEventMenu[] = []
): BokudeliEventMenu | null {
  // 期間チェック：イベント開始日時がメニューの有効期間内かチェック
  const menuDateStart = partnerMenu.menu_date_start
  const menuDateEnd = partnerMenu.menu_date_end
  
  if (eventStartDatetime != null && menuDateStart != null && menuDateEnd != null) {
    // 期間外のメニューは変換しない
    if (menuDateStart > eventStartDatetime || eventStartDatetime > menuDateEnd) {
      return null
    }
  }

  // 既存EventMenuから同じmenu_idのis_selected状態を取得
  const existingMenu = existingEventMenus.find(m => m.menu_id === partnerMenu.menu_id)
  const is_selected = existingMenu?.is_selected ?? true // デフォルトはtrue

  // EventMenuに変換（期間情報は含めない）
  return {
    id: partnerMenu.menu_id,
    menu_id: partnerMenu.menu_id,
    event_id: eventId,
    menu_name: partnerMenu.menu_name,
    menu_description: partnerMenu.menu_description,
    menu_image_url: partnerMenu.menu_image_url,
    menu_price: partnerMenu.menu_price,
    is_sold_out: partnerMenu.is_sold_out,
    menu_sort_number: partnerMenu.menu_sort_number,
    is_selected, // 既存の状態を引き継ぐ、なければtrue
    updatedAt: Date.now(),
  }
}

/**
 * PartnerMenuの配列をEventMenuの配列に変換
 * @param partnerMenus - 変換元のPartnerMenu配列
 * @param eventId - イベントID
 * @param eventStartDatetime - イベント開始日時（期間チェック用）
 * @param existingEventMenus - 既存のEventMenu配列（is_selected状態を引き継ぐため）
 * @returns 変換されたEventMenu配列（期間外のメニューは除外）
 */
export function convertPartnerMenusToEventMenus(
  partnerMenus: BokudeliPartnerMenu[],
  eventId: string,
  eventStartDatetime: number | null,
  existingEventMenus: BokudeliEventMenu[] = []
): BokudeliEventMenu[] {
  return partnerMenus
    .map(menu => convertFromPartnerMenuToEventMenu(menu, eventId, eventStartDatetime, existingEventMenus))
    .filter((menu): menu is BokudeliEventMenu => menu !== null)
}
```

#### 5.3.2 EventMenuコンポーネントの拡張
既存の`base/src/components/eventcreate/EventMenu.vue`を拡張してメニュー選択機能を追加します。

**メニューの取得と変換**:
- **新規作成時・編集時共通**: 
  - 選択されたお店のPartnerMenuを取得
  - `convertFromPartnerMenuToEventMenu`関数でEventMenuに変換
  - 編集時は既存EventMenuのis_selected状態を引き継ぐ
  - 期間が重なるメニューのみフィルタリング

**変更点**:
- `EventMenu` オブジェクトの代わりに `selectedMenuIds`（選択されたmenu_idの配列）を管理
- `update:selectedMenuIds` イベントで親コンポーネントに選択されたmenu_idの配列を通知

```vue
<!-- base/src/components/eventcreate/EventMenu.vue -->
<script setup lang="ts">
import { computed, ref, watch } from 'vue'
import { type BokudeliPartnerShop } from '@shokujii/base/stores/partner.js'
import { BokudeliEventMenu } from '@shokujii/base/stores/event.js'
import { priceString } from '@shokujii/base/schemes/converter'
import { mdiChevronLeft, mdiChevronRight, mdiStorefrontOutline } from '@mdi/js'
import { type BokudeliEvent } from '@shokujii/base/stores/event.js'

const props = defineProps<{
  shop: BokudeliPartnerShop | null
  menus: BokudeliEventMenu[]  // EventMenuのみを受け取る
  event: BokudeliEvent
  loading: boolean
}>()

const emit = defineEmits<{
  submit: []
  back: []
  // メニュー配列全体を返す
  'update:menus': [menus: BokudeliEventMenu[]]
}>()

// ローカルのメニュー一覧
const localMenus = ref<BokudeliEventMenu[]>([])

// propsの変更を監視
watch(
  () => props.menus,
  (newValue: BokudeliEventMenu[]) => {
    // 深いコピーを作成
    localMenus.value = newValue.map((menu) => {
      return new BokudeliEventMenu(menu.event_id, menu.menu_id, {
        menu_name: menu.menu_name,
        menu_price: menu.menu_price,
        menu_image_url: menu.menu_image_url,
        menu_description: menu.menu_description,
        is_sold_out: menu.is_sold_out,
        menu_sort_number: menu.menu_sort_number,
        is_selected: menu.is_selected,
      })
    })
  },
  { immediate: true, deep: true },
)

// メニューの選択状態をトグル
const toggleMenuSelection = (menuId: string) => {
  const menu = localMenus.value.find((m) => m.menu_id === menuId)
  if (menu) {
    menu.is_selected = !menu.is_selected
    // 親コンポーネントに通知
    emit('update:menus', localMenus.value)
  }
}

// メニューが選択されているかチェック
const isMenuSelected = (menuId: string): boolean => {
  const menu = localMenus.value.find((m) => m.menu_id === menuId)
  return menu?.is_selected ?? false
}

const submit = () => {
  emit('submit')
}

const back = () => {
  emit('back')
}

// 選択済みカウント
const selectedCount = computed(() => {
  return localMenus.value.filter((menu) => menu.is_selected).length
})
</script>

              {{ event.shop_name }}
```

#### 5.6.1 Trigger Functions（飲食店承認/却下時のメニューコピー）
```typescript
// functions/default/src/eventSnapshot.ts の修正

/**
 * パートナーのメニューをイベントのメニューコレクションにスナップショットとしてコピー
 * @param partnerId - パートナーID
 * @param eventId - イベントID
 * @param startDatetime - イベント開始日時（ミリ秒）
 */
const makeMenuSnapshot = async (partnerId: string, eventId: string, startDatetime: number): Promise<void> =>
  getFirestore().runTransaction(async (transaction) => {
    const partner = await getPartner(partnerId)
    const event = await getEvent(eventId, transaction)
    if (partner == null || event == null) {
      throw new Error(`Partner ${partnerId} or Event ${eventId} not found`)
    }
    const partnerMenus = await partner.getMenus(transaction)
    const eventMenus = await event.getMenus(transaction)
    
    // 既存メニューのis_selected状態を保存
    const previousSelectionState = new Map<string, boolean>()
    eventMenus.forEach((menu) => {
      // is_selectedが未定義の場合はtrueとして扱う（後方互換性）
      previousSelectionState.set(menu.menu_id, menu.is_selected ?? true)
    })
    
    // 既存のメニューを削除
    await Promise.all(
      eventMenus.map(async (menu) => {
        await event.deleteMenu(menu, transaction)
      }),
    )

    // パートナーのメニューをコピー（期間が重なるもののみ）
    await Promise.all(
      partnerMenus.map(async (menu) => {
        const menuDateStart = menu.menu_date_start
        const menuDateEnd = menu.menu_date_end

        // メニューの日付が未設定、またはイベント開始時刻がメニューの期間内の場合はコピー
        if (
          menuDateStart == null ||
          menuDateEnd == null ||
          (menuDateStart <= startDatetime && startDatetime <= menuDateEnd)
        ) {
          // 前回の選択状態を引き継ぐ。新規メニューの場合はデフォルト true
          const is_selected = previousSelectionState.get(menu.menu_id) ?? true
          
          // is_selectedを含めてコピー
          await event.saveMenu({ ...menu, is_selected }, transaction)
        }
      }),
    )
  })

/**
 * イベント作成・更新時に、パートナーのメニューをイベントのメニューコレクションにスナップショットとしてコピー
 * 
 * 実行条件：
 * - 飲食店によるイベント承認時: applying_reservation → accepting_order
 * - 飲食店によるイベント却下時: applying_reservation → in_draft
 * 
 * それ以外（主催者によるイベント保存等）はCallable Function (updateEventMenus)で処理
 */
export const makeShopSnapshotToEvent = onDocumentWritten(
  {
    document: 'communities/{communityId}/events/{eventId}',
    region: 'asia-northeast1',
  },
  async (change) => {
    if (!change.data) {
      console.warn('Change data is undefined')
      return
    }

    const before = change.data.before
    const after = change.data.after

    if (!after?.exists) {
      return
    }

    const beforeStatus = before?.get('event_status')?.value
    const afterStatus = after.get('event_status')?.value

    // 飲食店による承認/却下時のみ実行
    const isShopApproval = 
      beforeStatus === 'applying_reservation' && afterStatus === 'accepting_order'
    const isShopRejection = 
      beforeStatus === 'applying_reservation' && afterStatus === 'in_draft'

    if (!isShopApproval && !isShopRejection) {
      // 飲食店の承認/却下以外の場合はスキップ
      // （主催者によるイベント保存等は Callable Function で処理）
      console.log(
        `Skipping menu snapshot: status change ${beforeStatus} → ${afterStatus} ` +
        `is not shop approval/rejection`
      )
      return
    }

    // 承認から承認への変更は処理しない（念のため）
    if (beforeStatus === 'accepting_order' && afterStatus === 'accepting_order') {
      return
    }

    // 承認状態から他の状態への変更は警告を出して処理を継続
    if (beforeStatus === 'accepting_order' && afterStatus !== 'accepting_order') {
      const communityId = after.get('community_id') as string | undefined
      const eventId = after.id
      console.warn(
        `Event status changed from accepting_order to ${afterStatus}\n` +
          `Community: ${communityId}, Event: ${eventId}`,
      )
    }

    // イベントデータを取得
    const startDatetime = (after.get('event_start_datetime') as Timestamp | undefined)?.toMillis() ?? null
    const partnerId = after.get('partner_id') as string | undefined
    const communityId = after.get('community_id') as string | undefined
    const eventId = after.id
    const eventName = after.get('event_name') as string | undefined

    // 必須パラメータのチェック
    if (!partnerId || !startDatetime) {
      console.warn(
        `Missing required parameters: partnerId=${partnerId}, communityId=${communityId}, eventId=${eventId}, startDatetime=${startDatetime}`,
      )
      return
    }

    try {
      console.log(
        `Executing menu snapshot for shop ${isShopApproval ? 'approval' : 'rejection'}: ` +
        `Community: ${communityId}, Event: ${eventId}, EventName: ${eventName}`
      )
      await makeMenuSnapshot(partnerId, eventId, startDatetime)
    } catch (error) {
      console.error(`Menu snapshot failed - Community: ${communityId}, Event: ${eventId}, EventName: ${eventName}`, error)
    }
  },
)
```

#### 5.6.2 Callable Functions（主催者によるメニュー更新）

**変更点**:
- フロントエンドから `selectedMenuIds`（選択されたmenu_idの配列）を受け取る
- Functions側で最新のPartnerMenuを取得（`accepting_order`状態を除く）
- `accepting_order`状態では既存EventMenuの`is_selected`のみを更新
- `common/src/utils/eventMenuConverter.ts` の `convertPartnerMenusToEventMenus` 関数を使用して全メニューをEventMenuに変換して保存（is_selectedフラグで選択状態を管理）

```typescript
// functions/default/src/updateEventMenus.ts（新規作成）
import { onCall, HttpsError } from 'firebase-functions/v2/https'
import { getFirestore } from 'firebase-admin/firestore'
import { getEvent } from './stores/event.js'
import { EventMenu } from '@shokujii/common/schemas/EventMenu.js'
import { convertPartnerMenusToEventMenus } from '@shokujii/common/utils/eventMenuConverter.js'

interface UpdateEventMenusRequest {
  eventId: string
  communityId: string
  selectedMenuIds: string[]  // 選択されたmenu_idの配列
}

/**
 * イベントのメニューを更新するCallable Function
 * 主催者がイベント保存時に、selectedMenuIdsを受け取り、
 * calculatedEventStatusによって処理を分岐:
 * - accepting_order状態: 既存EventMenuのis_selectedのみ更新
 * - finished状態: 更新不可（エラー）
 * - それ以外: 最新のPartnerMenuからEventMenuを生成して保存
 *
 * 重要: ステータス判定にはcalculatedEventStatusを使用します。
 * これにより、データベース上はaccepting_orderでもイベント終了時刻を過ぎていれば
 * 自動的にfinished判定され、更新が禁止されます。
 *
 * @param request.data.eventId - イベントID
 * @param request.data.communityId - コミュニティID
 * @param request.data.selectedMenuIds - 選択されたmenu_idの配列
 *
 * @throws {HttpsError} unauthenticated - 認証されていない場合
 * @throws {HttpsError} invalid-argument - 必須パラメータが不足している場合
 * @throws {HttpsError} failed-precondition - イベントがfinished状態の場合
 * @throws {HttpsError} not-found - イベントまたはPartnerが見つからない場合
 * @throws {HttpsError} internal - その他のエラー
 */
export const updateEventMenus = onCall<UpdateEventMenusRequest>(
  { region: 'asia-northeast1' },
  async (request) => {
    // 認証チェック
    if (!request.auth) {
      throw new HttpsError('unauthenticated', 'User must be authenticated')
    }

    const { eventId, communityId, selectedMenuIds } = request.data

    // パラメータバリデーション
    if (!eventId || !communityId || !Array.isArray(selectedMenuIds)) {
      throw new HttpsError('invalid-argument', 'eventId, communityId, and selectedMenuIds (array) are required')
    }

    try {
      await getFirestore().runTransaction(async (transaction) => {
        // イベント情報を取得
        const event = await getEvent(eventId, transaction)
        if (event == null) {
          throw new HttpsError('not-found', `Event ${eventId} not found`)
        }

        // イベントの権限チェック
        const userId = request.auth!.uid
        const communityMemberRef = getFirestore()
          .collection('communities')
          .doc(communityId)
          .collection('members')
          .doc(userId)
        const memberDoc = await transaction.get(communityMemberRef)

        if (!memberDoc.exists) {
          throw new HttpsError('permission-denied', 'User is not a member of this community')
        }

        // イベントの権限チェック
        const eventData = event.toFirestore(userId)
        const isCreator = eventData.created_by === userId
        const memberRole = memberDoc.data()?.role

        if (!isCreator && memberRole !== 'manager') {
          throw new HttpsError('permission-denied', 'User does not have permission to update this event')
        }

        // finished状態の場合は更新不可
        // calculatedEventStatusを使用して、時刻による自動判定を考慮
        const calculatedStatus = event.calculatedEventStatus
        if (calculatedStatus === 'finished') {
          throw new HttpsError(
            'failed-precondition',
            'Cannot update menus after event is finished.',
          )
        }

        // イベントステータスによる処理分岐
        const isAcceptingOrder = calculatedStatus === 'accepting_order'

        if (isAcceptingOrder) {
          // accepting_order状態: 既存EventMenuのis_selectedのみ更新
          const existingEventMenus = await event.getMenus(transaction)
          const selectedMenuIdsSet = new Set(selectedMenuIds)

          await Promise.all(
            existingEventMenus.map(async (menu) => {
              // is_selectedフラグのみ更新
              const newIsSelected = selectedMenuIdsSet.has(menu.menu_id)
              if (menu.is_selected !== newIsSelected) {
                menu.is_selected = newIsSelected
                await event.saveMenu(menu, transaction)
              }
            }),
          )

          console.log(
            `Updated is_selected flags for event ${eventId} in accepting_order status. ` +
              `Selected: ${selectedMenuIds.length} menus.`,
          )
        } else {
          // in_draft, applying_reservation状態: 最新のPartnerMenuから再生成
          const partner = await event.getPartner(transaction)
          if (!partner) {
            throw new HttpsError('not-found', `Partner not found for event ${eventId}`)
          }
          
          const partnerMenus = await partner.getMenus(transaction)

          // 最新のPartnerMenusから全EventMenusを生成（is_selectedフラグで管理）
          // common/src/utils/eventMenuConverter.ts の convertPartnerMenusToEventMenus 関数を使用
          // 期間チェックも実行され、期間外のメニューは除外される
          const eventMenusToSave = convertPartnerMenusToEventMenus(
            partnerMenus,
            eventId,
            event.event_start_datetime,
            selectedMenuIds
          )

          // 既存のEventMenuを取得して削除
          const existingEventMenus = await event.getMenus(transaction)
          await Promise.all(
            existingEventMenus.map(async (menu) => {
              await event.deleteMenu(menu, transaction)
            }),
          )

          // 生成したEventMenusを保存
          await Promise.all(
            eventMenusToSave.map(async (menuData) => {
              // EventMenuインスタンスを作成
              const eventMenu = new EventMenu(eventId, menuData.menu_id, {
                menu_name: menuData.menu_name,
                menu_price: menuData.menu_price,
                menu_image_url: menuData.menu_image_url,
                menu_description: menuData.menu_description,
                is_sold_out: menuData.is_sold_out,
                menu_sort_number: menuData.menu_sort_number,
                is_selected: menuData.is_selected,
              })

              await event.saveMenu(eventMenu, transaction)
            }),
          )

          console.log(
            `Updated menus for event ${eventId} in community ${communityId}. ` +
              `Saved ${eventMenusToSave.length} menus from ${selectedMenuIds.length} selected IDs.`,
          )
        }
      })

      return { success: true }
    } catch (error) {
      // HttpsErrorはそのままthrow
      if (error instanceof HttpsError) {
        throw error
      }
      // その他のエラーはinternalとしてwrap
      console.error('Error updating event menus:', error)
      throw new HttpsError('internal', 'Failed to update event menus')
    }
  },
)
```

### 5.7 処理フロー

#### 5.7.1 主催者によるイベント保存とメニュー選択（Callable Function）
```markdown
【対象ステータス遷移】
- in_draft → in_draft（下書き保存）- 最新PartnerMenu取得
- in_draft → applying_to_admin（申請）- 最新PartnerMenu取得
- applying_reservation → applying_reservation（申請中の編集）- 最新PartnerMenu取得
- accepting_order → accepting_order（承認後の編集）- is_selectedのみ更新
- finished: 更新不可

【処理フロー】
1. イベント編集画面の表示時（新規作成時・編集時共通）:
   a. 選択されたお店のPartnerMenuを取得
   b. 編集時は既存のEventMenuも取得
   c. convertFromPartnerMenuToEventMenuでPartnerMenuをEventMenuに変換
      - PartnerMenuの期間情報に基づいてフィルタリング（期間外は除外）
      - 既存EventMenuと同じmenu_idがあれば、is_selected値を引き継ぐ
      - 同じmenu_idがなければ、デフォルトでis_selected: trueを設定
   d. 変換されたEventMenuを eventMenus ref で管理
   e. EventMenuコンポーネントに eventMenus を渡す
2. 主催者がメニューカードをクリックして選択/未選択をトグル
   - EventMenuコンポーネント内でis_selectedを直接更新
   - 選択されたメニューのmenu_idリストを管理
   - update:selectedMenuIds イベントで親コンポーネントに通知
3. 親コンポーネントで selectedMenuIds ref を更新
4. 主催者が「保存」または「申請」ボタンをクリック
5. フロントエンドでイベント情報を更新
6. Callable Function `updateEventMenus` を呼び出し
   - 引数: eventId, communityId, selectedMenuIds[]
   - selectedMenuIds は選択されたmenu_idの配列のみ
7. Functions側で処理:
   a. 認証チェック（イベント作成者またはマネージャー）
   b. イベントステータスチェック（calculatedEventStatusを使用してfinished状態では更新不可）
   c. ステータスによる処理分岐（calculatedEventStatusで判定）:
      【accepting_order状態の場合】
      - 既存EventMenuのis_selectedフラグのみ更新
      - PartnerMenuからの再取得は行わない
      - メニューの価格・説明・画像などは承認時点のまま維持
      【それ以外（in_draft, applying_reservation）の場合】
      - トランザクション開始
      - Partnerの最新のPartnerMenusを取得
      - selectedMenuIdsと最新のPartnerMenusから全EventMenusを生成（is_selectedフラグで選択状態を管理）
        * common/src/utils/eventMenuConverter.ts の convertPartnerMenusToEventMenus 関数を使用
        * 最新のPartnerMenuデータ（価格、説明、画像など）が反映される
        * 期間チェックが実行され、期間外のメニューは自動的に除外される
      - 既存EventMenuを全削除
      - 生成した全EventMenusを保存（選択されたメニューはis_selected=true、それ以外はfalse）
   d. トランザクションコミット
8. フロントエンドで成功通知を表示
9. イベント一覧画面に遷移
```

#### 5.7.2 飲食店による承認/却下時のメニューコピー（Trigger Function）
```markdown
【対象ステータス遷移】
- applying_reservation → accepting_order（承認）
- applying_reservation → in_draft（却下）

【処理フロー】
1. 飲食店がイベント承認または却下を実行
2. Firestoreのevent_statusが更新される
3. onDocumentWritten Trigger `makeShopSnapshotToEvent` が自動実行
4. ステータス遷移をチェック:
   - applying_reservation → accepting_order: 処理継続
   - applying_reservation → in_draft: 処理継続
   - その他: スキップ
5. トランザクション内で処理:
   a. 既存EventMenuの is_selected 状態を Map に保存
   b. 既存EventMenuを全削除
   c. PartnerMenuから期間が重なるメニューをコピー
   d. 各メニューに対して:
      - 前回の is_selected 状態があれば引き継ぐ
      - 新規メニューの場合は is_selected: true をデフォルト設定

   e. EventMenuコレクションに保存
```

## 6. データマイグレーション
### 6.1 マイグレーション対象
既存の EventMenu ドキュメントに `is_selected: true` フィールドを追加する必要があります。

### 6.2 マイグレーション実装
```typescript
// functions/default/src/migrations/addIsSelectedToEventMenus.ts
import { onCall, HttpsError } from 'firebase-functions/v2/https'
import { getFirestore, FieldValue } from 'firebase-admin/firestore'

export const migrateEventMenusAddIsSelected = onCall(async (request) => {
  const uid = request.auth?.uid
  if (uid == null) {
    throw new HttpsError('unauthenticated', '認証が必要です')
  }
  
  // 管理者権限チェック（実装に応じて調整）
  // const user = await getAdminUser(uid)
  // if (!user.is_admin) {
  //   throw new HttpsError('permission-denied', '管理者権限が必要です')
  // }
  
  const db = getFirestore()
  let migratedCount = 0
  
  try {
    // すべてのコミュニティを取得
    const communitiesSnapshot = await db.collection('communities').get()
    
    for (const communityDoc of communitiesSnapshot.docs) {
      const communityId = communityDoc.id
      
      // 各コミュニティのイベントを取得
      const eventsSnapshot = await db.collection(`communities/${communityId}/events`).get()
      
      for (const eventDoc of eventsSnapshot.docs) {
        const eventId = eventDoc.id
        
        // 各イベントのメニューを取得
        const menusSnapshot = await db
          .collection(`communities/${communityId}/events/${eventId}/menus`)
          .get()
        
        // バッチ処理
        const batch = db.batch()
        for (const menuDoc of menusSnapshot.docs) {
          const data = menuDoc.data()
          
          // is_selected フィールドが存在しない場合のみ追加
          if (data.is_selected === undefined) {
            batch.update(menuDoc.ref, {
              is_selected: true,
              updatedAt: FieldValue.serverTimestamp()
            })
            migratedCount++
          }
        }
        
        if (menusSnapshot.docs.length > 0) {
          await batch.commit()
        }
      }
    }
    
    console.log(`Migration completed: ${migratedCount} menus updated`)
    return {
      success: true,
      migrated_count: migratedCount
    }
  } catch (error) {
    console.error('Migration failed:', error)
    throw new HttpsError('internal', 'マイグレーション処理に失敗しました')
  }
})
```

### 6.3 マイグレーション実行手順
1. **事前準備**
   - 本番環境のバックアップを取得
   - 開発環境で実行して動作確認
   - 実行時間の見積もり（イベント数 × 平均メニュー数 を考慮）

2. **実行時**

   - `migrateEventMenusAddIsSelected` を呼び出し

3. **実行後**
   - Firestore Consoleで数件のEventMenuを確認し、is_selectedフィールドが追加されているか確認
   - admin画面とuser画面で正常に動作するか確認

### 6.4 注意事項

### 8.4 予約承認後の動作（accepting_order状態）

#### 8.4.1 基本動作
- **is_selectedフラグの変更**: 承認後も主催者はメニューの選択/未選択を変更可能
- **メニュー内容の固定**: 承認時点でメニューの価格・説明・画像などは固定され、以降変更されない
- **最新PartnerMenuの非取得**: `accepting_order`状態では、主催者がイベントを保存しても最新のPartnerMenuは取得されない

#### 8.4.2 詳細仕様
- **承認後のメニュー追加**: 
  - 飲食店が承認後にPartnerMenuに新しいメニューを追加しても、EventMenuには反映されない
  - 承認時点で存在していたメニューのみがEventMenuとして固定される
- **承認時のメニュー追加**: 
  - 承認タイミングで飲食店がメニューを追加した場合、そのメニューはEventMenuにコピーされる（Trigger Function経由）
  - 承認後は主催者がそのメニューの選択/未選択を変更可能
- **is_selectedのみ変更可能**: 
  - 主催者は`is_selected`フラグのみを変更でき、メニューの表示/非表示を制御できる
  - メニューの価格や説明を変更したい場合は、飲食店に連絡して承認をやり直す必要がある

#### 8.4.3 注文後の変更
- **技術的な制約**: 
  - 参加者がメニューAを注文した後でも、主催者はメニューAを未選択（is_selected: false）にできる
  - システム上は既存の注文をブロックしない
- **運用上の推奨**: 
  - 注文済みのメニューを未選択にすることは運用上避けるべき
  - フロントエンドで注文済みメニューには警告を表示することを推奨（Phase 2で実装予定）

#### 8.4.4 処理の流れ
```
【accepting_order状態でのメニュー編集】
1. 主催者がイベント編集画面を開く
2. calculatedEventStatusで状態を判定
   - イベント終了時刻を過ぎていれば finished となり編集不可
   - 期間内であれば accepting_order として処理を継続
3. 既存のEventMenuが表示される（承認時点のメニュー内容）
4. 主催者がメニューの選択/未選択を変更
5. 保存ボタンをクリック
6. updateEventMenus Function呼び出し
7. Functions側でもcalculatedEventStatusで再度チェック
8. 既存EventMenuのis_selectedフラグのみ更新
9. メニューの価格・説明・画像は変更されない
```

#### 8.4.5 メリット
- **価格の固定**: 承認後に飲食店がPartnerMenuの価格を変更しても、イベントの価格は変わらない
- **内容の保証**: 飲食店が承認した時点のメニュー内容が参加者に提供されることが保証される
- **柔軟な調整**: 承認後も主催者は注文可能なメニューの範囲を調整できる

### 8.5 処理の分岐とステータス管理
#### 8.5.1 Trigger FunctionとCallable Functionの使い分け
- **Trigger Function**: 飲食店による承認/却下時のみ実行
  - メリット: 既存の処理フローを維持、自動実行
  - デメリット: フロントエンドからの制御が難しい
- **Callable Function**: 主催者によるイベント保存時に実行
  - メリット: メニュー選択を明示的に制御可能、エラーハンドリングが容易
  - デメリット: フロントエンドから明示的に呼び出す必要がある

#### 8.5.2 重複実行の防止
- ステータス遷移を厳密にチェックすることで、Trigger FunctionとCallable Functionの重複実行を防止
- `applying_reservation` からの遷移は Trigger Function のみが処理
- それ以外の遷移は Callable Function で処理

#### 8.5.3 エラーハンドリング
- **Callable Function**: HttpsErrorを使用してフロントエンドに詳細なエラーを返却
- **Trigger Function**: console.errorでログ出力、処理は継続（イベント更新をブロックしない）

#### 8.5.4 トランザクション管理
- 両方の処理でFirestore Transactionを使用して原子性を保証
- メニュー削除とコピーを1つのトランザクション内で実行
