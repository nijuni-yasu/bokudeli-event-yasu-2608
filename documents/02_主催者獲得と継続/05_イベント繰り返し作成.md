# イベント繰り返し作成機能

> 関連 Issue: [#1692](https://github.com/nijuniinc/bokudeli-event-new/issues/1692)
> 関連仕様書: [04_イベントコピー.md](./04_イベントコピー.md)

## 1. 概要

### 1.1 機能の目的

既存イベントを起点に、開始日・繰り返し回数と繰り返し条件を指定して **複数イベントを一括コピー** することで、定期開催イベント（週次ランチ会、月次勉強会など）の作成工数を大幅に削減する。

単発コピー機能（[04_イベントコピー.md](./04_イベントコピー.md)）の拡張として、同じ「イベントコピー」モーダル上で「単発／繰り返し」を切り替えて利用できるようにする。

### 1.2 主要な機能

- イベント一覧画面の「イベントコピー」モーダル内に **「単発／繰り返し」のモード切替** を追加
- **繰り返しモード** で次のコピーパターンに対応
  - 日次／週次／月次／年次の繰り返し
  - 月次は **「毎月同じ日付」** と **「毎月同じ曜日（第 N X 曜日）」** の 2 パターン
- コピー元店舗の **営業時間（`shop_time`）に合致しない候補日時はスキップ**（採用件数にカウントしない）
- 開始日・繰り返し条件・繰り返し回数（最大 12）からコピー対象日時を **フロントで計算** し、プレビュー表示
- **最大 12 件** までの一括作成（誤操作による大量作成と、削除困難化を防ぐため意図的に小さく設定）
- 各イベントは独立した `eventId` で保存され、個別に編集・削除可能
- **コピー履歴フィールドは Event スキーマに追加しない**（独立イベントとして扱う）

### 1.3 対象ユーザー

- イベント主催者（コミュニティ管理者）
- 定期開催イベントを運営する主催者

## 2. ねらい

### 2.1 ビジネス目標

- 主催者のイベント作成工数削減
- 定期開催イベント数の増加
- 主催者の継続利用率向上

### 2.2 ユーザー価値

- 過去イベントの設定（カバー画像・店舗・メニュー・主催者情報など）を再利用しつつ、定期開催を数クリックで作成できる
- 営業日のみがカレンダーで選択可能なため、設定ミスが起きにくい
- プレビューで作成対象日時を事前確認できる

### 2.3 成功指標（KPI）

- 繰り返しコピー機能経由で作成されたイベント数 / 月
- コピー機能の利用率（全イベント作成に対する比率）
- コピー後のイベント公開率

## 3. 前提条件

### 3.1 技術的前提条件

- 既存の単発コピー機能（[04_イベントコピー.md](./04_イベントコピー.md)）が動作していること
  - `functions/default/src/eventCopy.ts`（Callable Function `eventCopy`）
  - `user/src/components/manage/community/CopyEventDialog.vue`
- イベント・パートナー店舗・メニューが Firestore に保存されていること
- ユーザーがコミュニティ管理者権限を持っていること

### 3.2 ビジネス的前提条件

- コピー元イベントは `event_status` が「下書き」「公開済み」「終了」いずれでもコピー可能
- コピー先イベントは常に **「下書き（`in_draft`）」** 状態で作成される
- 店舗の営業時間外の日時は **作成不可**（フロントで非表示／無効化、Function 側でも再検証）

#### 5.2.2 新規 Callable Function: `eventCopyRepeat`

**実装ファイル**:
- `common/src/apis/eventCopyRepeat.ts`（型定義）
- `base/src/apis/eventCopyRepeat.ts`（フロント側 `httpsCallable` ラッパー）
- `functions/default/src/eventCopyRepeat.ts`（Function 本体）

**型定義**:

```typescript
// common/src/apis/eventCopyRepeat.ts
export type EventCopyRepeatRequest = {
  srcEventId: string
  startTimes: number[] // フロントで計算済みの開催日時リスト（EpochMillis）
}

export type EventCopyRepeatResultItem =
  | { ok: true; startTime: number; newEventId: string }
  | { ok: false; startTime: number; reason: string }

export type EventCopyRepeatResponse = {
  results: EventCopyRepeatResultItem[]
  successCount: number
  failureCount: number
}
```

**Function 仕様**:

| 項目 | 値 |
| :--- | :--- |
| 関数名 | `eventCopyRepeat` |
| 認証 | 必須（未ログイン時 `unauthenticated`） |
| 権限 | コミュニティ `manager` または `support` |
| タイムアウト | `540` 秒（最大件数 × 画像コピー＋メニュー書き込みを考慮。実際は最大 12 件なので余裕あり） |
| 入力上限 | `startTimes.length` は **1 〜 12** |
| 重複排除 | `startTimes` は昇順／降順問わずだが、重複は事前に排除（同一 `startTime` で 2 件作る用途はない） |

**処理概要**:

1. 認証チェック（`request.auth.uid`）。
2. 入力バリデーション
   - `srcEventId` が非空文字列
   - `startTimes` が配列で、長さ `1〜12`、要素はすべて有限な数値
3. `srcEvent` / `community` / `partner` / `config` を取得（**1 度だけ**）。
4. 権限チェック（`manager` または `support`）。
5. `partner.getShop(srcEvent.shop_id)` で shop を取得。
6. `startTimes` の各要素について並列に `copyEventCore(uid, srcEvent, startTime)` を実行
   - `Promise.allSettled` で集約し、各要素を `EventCopyRepeatResultItem` に変換
   - 個別失敗（営業時間外、画像コピー失敗以外の例外など）は `ok: false` で結果に含める
7. `successCount` / `failureCount` を集計してレスポンスを返却
8. `createModuleLogger('eventCopyRepeat')` で実行 uid・srcEventId・件数・所要時間・失敗理由をログ

**並列度の制御**:
- 入力上限が 12 件なので、初版は単純な `Promise.allSettled` で全件並列実行する。負荷上問題が出た場合のみバッチ化を検討。

### 5.3 日付計算ロジック（フロント実装）

**実装方針**: 日付計算は **フロントで完結** させ、Function 側はフロントが計算した `startTimes` を信頼して処理する（`isInShopTime` の再検証はサーバー側でも実施）。

これにより:
- プレビュー表示と実際の作成結果が完全一致する
- Function の責務が「コピーの実行」のみに限定され、テストしやすい

#### 5.3.1 共通の前提

- `eventStartTimeOffset` = コピー元イベントの開始時刻の「その日 0 時からのオフセット（ms）」
  - 既存 `CopyEventDialog.vue` のロジックを流用
- 各候補日時 = `getStartOfDay(候補日) + eventStartTimeOffset`
- `isInShopTime(候補日時, shop)` が `true` の日時のみ採用
- **採用件数が `repeatCount`（最大 12）に達したら打ち切り**
- **採用件数にカウントしないスキップ条件**（案 A: スキップ＆カウントしない）:
  - `isInShopTime` で `false` を返した候補日時
  - 月次「同じ曜日」で第 N 週が存在しない月
- **無限ループ防止のための探索ステップ上限**: `repeatCount × 12` ステップ進めても採用件数が満たされなければ打ち切り、揃った件数だけプレビューに表示する（UI 側でユーザーに通知）

#### 5.3.2 単位ごとの計算

すべてのパターンに共通する打ち切り条件: **採用件数 ≥ `repeatCount`** または **探索ステップ ≥ `repeatCount × 12`**

**日次 / 週次 / 年次**:
- 開始日からループし、`interval × {1日 | 7日 | 12ヶ月}` ずつ進める
- 各ステップで `isInShopTime` チェック → 通過した日時のみ採用、通過しない場合は **次のステップへ進む（カウントしない）**

**月次（`monthlyPattern: 'date'`）**:
- 開始日の `日（1〜31）` を保持
- `currentDate.setMonth(currentDate.getMonth() + interval)` で月を進める
- 月末日数を超える場合は **当月の月末日に自動調整**（例: 31 日 → 2 月は 28/29 日）
- 各候補日時に `isInShopTime` チェック → 通過しない場合は **次の月へ進む（カウントしない）**

**月次（`monthlyPattern: 'weekday'`）**:
- 開始日の **第 N 週**（`weekNumber: 1〜5`）と **曜日**（`dayOfWeek: 0〜6`）を取得
- 各月で `getNthWeekdayOfMonth(year, month, weekNumber, dayOfWeek)` を計算
- 該当日が存在しない月（例: 第 5 火曜日がない月）は **次の月へスキップ（カウントしない）**
- 該当日があっても `isInShopTime` が `false` なら **次の月へスキップ（カウントしない）**

#### 5.3.3 ヘルパー関数（フロント / `CopyEventDialog.vue` 内に配置）

```typescript
// 月内で何週目か（1〜5）
const getWeekNumberInMonth = (date: Date): number => {
  const firstDayOfMonth = new Date(date.getFullYear(), date.getMonth(), 1)
  return Math.ceil((date.getDate() + firstDayOfMonth.getDay()) / 7)
}

// 指定月の第 N X 曜日（存在しない場合は null）
const getNthWeekdayOfMonth = (
  year: number,
  month: number,
  weekNumber: number, // 1〜5
  dayOfWeek: number, // 0〜6
): Date | null => {
  const firstDayOfWeek = new Date(year, month, 1).getDay()
  const firstOccurrence = 1 + ((dayOfWeek - firstDayOfWeek + 7) % 7)
  const targetDay = firstOccurrence + (weekNumber - 1) * 7
  const lastDay = new Date(year, month + 1, 0).getDate()
  return targetDay > lastDay ? null : new Date(year, month, targetDay)
}
```

> 月次計算が複雑になる場合は `common/src/utils/datetime.ts` への切り出し・ユニットテスト化を検討する（Phase 2）。

### 5.4 処理フロー

#### 5.4.1 単発コピー（既存・変更なし）

[04_イベントコピー.md](./04_イベントコピー.md) を参照。`eventCopy` Callable Function を 1 回呼び出して 1 件作成。

#### 5.4.2 繰り返しコピー（新規）

1. ユーザーが「イベントコピー」ボタンをクリック → モーダルが開く
2. コピー元イベントを選択 → コピー元の `partner_id` から店舗情報（`shop_time`）を取得
3. コピータイプで「繰り返しコピー」を選択
4. 開始日・繰り返し間隔・（月次の場合）月次パターン・繰り返し回数を入力（繰り返し回数は 1〜12、デフォルト 4）
5. フロントで `previewDates: number[]` を計算（営業時間外スキップ・採用件数 `repeatCount` 到達で打ち切り、探索ステップ上限 `repeatCount × 12`）
6. プレビュー表示（件数 + 日時の全件）でユーザーが確認
   - 揃った件数 < `repeatCount` の場合は注意書きを表示
7. 「{n} 個のイベントを作成」ボタンをクリック（指定回数を満たせなくても揃った件数で作成可能）
8. フロントで最終バリデーション（件数 0 件 / 上限 12 件超過）
9. `eventCopyRepeat({ srcEventId, startTimes: previewDates })` を呼び出し
10. Function 側で認証・権限・shop / src 取得 → `Promise.allSettled` で各 startTime を並列コピー
11. レスポンスの `successCount` / `failureCount` を確認
    - `failureCount === 0`: 成功ダイアログ「{n} 個のイベントを作成しました」
    - `successCount > 0 && failureCount > 0`: 部分成功ダイアログ「{success} 個のイベントを作成しました（{failure} 個失敗）」
    - `successCount === 0`: 失敗ダイアログ「イベントの作成に失敗しました」
12. イベント一覧を `eventListStore.reload()` で再読み込み

## 8. 注意事項

### 8.1 既存システムへの影響

- **Firestore スキーマ**: 変更なし（既存 `EventDbSchema` のまま）
- **Firestore セキュリティルール / インデックス**: 変更なし
- **既存 `eventCopy` Function**: 内部リファクタのみ（外部 I/F は維持）
- **イベント一覧画面**: 既存「イベントコピー」ボタンの挙動は単発時に限り従来どおり

### 8.2 セキュリティ考慮事項

- 認証必須（`request.auth` チェック）
- 権限: `community.hasRole(uid, 'manager')` または `config.isSupport(uid)`
- サーバー側で **`startTimes` の各要素を `isInShopTime` で再検証**（フロントからの不正な日時を弾く）
- 入力上限を Function 側でも強制（`startTimes.length` ≤ 12）
- 孤児イベント（`community` が取得できない `srcEventId`）はコピー不可（既存挙動を維持）

### 8.3 運用考慮事項

- 取り消し不可。フロント側の **プレビューで作成対象を必ず明示** する
- 大量コピー時の Function タイムアウト・GCS スループットに注意
  - 初版は `Promise.allSettled` で並列実行。問題が出た場合はバッチ化を検討
- 部分失敗時のロールバックは行わず、`successCount` / `failureCount` を返してユーザーに通知
- ログ（`createModuleLogger('eventCopyRepeat')`）に
  - 実行 uid
  - `srcEventId`
  - `startTimes.length`
  - 各要素の成功／失敗
  - 所要時間
  を記録
