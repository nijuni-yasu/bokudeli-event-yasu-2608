# エンプラ v0.2 ドキュメント索引

v0.2 は「PF 版とエンプラ版の分離（テナント/プロジェクト分離）をどうするか」を検討し、**最終的にパターン A（単一 Firebase Project）＋ Identity Platform マルチテナンシー** を採用したフェーズ。番号順に読むと検討経緯のため方針が揺れて見えるので、**現行の正本と参考（経緯・不採用案）を区別して読むこと**。

---

## 最終結論（1 行）

**Project 分離なし（パターン A 継続）。Auth 境界だけ IdP マルチテナンシーで強化する。** データ/インフラの物理分離（B / B′ / C / D）は採らず、`03` §4 の将来トリガーが発火した時点で段階対応する。詳細は `03` §1。

## パターン早見（`02` / `03` の定義）

| 記号 | 構成 | v0.2 での採否 |
|:--|:--|:--|
