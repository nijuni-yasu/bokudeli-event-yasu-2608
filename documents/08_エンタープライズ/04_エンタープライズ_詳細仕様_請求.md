# 請求 詳細仕様

本ドキュメントは `01_仕様概要`、`02_全体構成・アーキテクチャ`、`04_割引・決済`、`04_ゲスト参加`、`04_ダッシュボード` の決定事項に基づき、企業への請求集計（MVP）および請求書発行（Phase 2）の機能仕様を詳細に定義する。

## 前提とする仕様書

本ドキュメントは EventMemberOrder 設計（`05_EventOrder→EventMemberOrder.md`）を前提とする。集計対象は `members/{userId}/member_orders/{orderId}` および親 `members.is_guest` である。

---

# 1. 概要

## 1.1 対象機能

| 機能 | 概要 |
|:--|:--|
| 企業請求見込額の集計（MVP） | ゲスト無料分・`enterprise_subsidy` 補助分を月別に集計し、ダッシュボード / CSV で表示 |
| 請求書 PDF 発行（Phase 2） | 運営が前月分を確認・承認して PDF 発行 |

## 1.2 決定事項サマリ

| # | 論点 | 決定 |
|:--|:--|:--|
| B-1 | MVP の請求書 PDF 発行 | **MVP では行わない**。集計表示まで。PDF 発行は Phase 2（既存 `common/src/utils/invoice.ts` 流用 or 運用手動） |
| B-2 | 月の帰属 | **イベント開催月**（`event.event_start_datetime` の年月。`04_割引・決済` と同一） |
| B-3 | `community_bill` と全社請求の関係 | **二重計上しない**。`community_bill` はコミュニティ主催者への請求書（PF版と同じ）。全社請求見込額には **ゲスト無料分 + `enterprise_subsidy` 補助分** のみ含める |

# 2. 企業請求見込額（MVP）

## 2.1 背景

エンタープライズ版では以下の費用が shokujii から企業へ後請求される。

| 費用種別 | データソース | 集計式 |
|:--|:--|:--|
| ゲスト無料参加分 | `member_orders`（親 `members.is_guest == true`） | `Σ menu_price` |
| 福利厚生割引（企業補助分） | `member_orders`（`pay_enterprise_subsidy_amount` あり） | `Σ pay_enterprise_subsidy_amount` |
| `community_bill`（主催者請求書払い） | PF版と同じくコミュニティ主催者への請求 | **全社請求見込額には含めない**（別請求フロー） |

> `01_仕様概要` の「請求先は MVP では全社管理者に一本化」は**ゲスト無料参加分および enterprise_subsidy 補助分**の費用負担先を指す。`community_bill` の請求先はコミュニティ主催者（PF版と同じ）である（`04_割引・決済` §4.1 参照）。

## 2.2 集計クエリ

```typescript
// ベースクエリ
collectionGroup('member_orders')
  .where('enterprise_id', '==', enterpriseId)
  .where('status', '==', 'ordered')
```

- 取得後、各 order の `event_id` から events を参照し、`event_start_datetime` の年月でフィルタ（`04_ダッシュボード` と同一ルール）
- ゲスト無料分: 親 `members.is_guest == true` のメンバー配下の `member_orders` を `Σ menu_price` で集計
- 補助分: `pay_enterprise_subsidy_amount ?? 0` の合計（`members.is_guest == false` の EnterpriseMember 分）

## 2.3 表示

| 表示場所 | 内容 |
|:--|:--|
| ダッシュボード（`/admin`） | 月別集計テーブルに「企業請求見込額」列を追加（`04_ダッシュボード` §2 の集計ロジックを拡張） |
| CSV | 月別 CSV に `enterprise_billing_amount` 列を追加 |

請求見込額の集計は既存の `getDashboardMonthlyData`（`04_ダッシュボード` §5.2）を拡張する。専用 Function は新設しない。

# 3. Phase 2: 請求書 PDF 発行

- 既存 [common/src/utils/invoice.ts](../../../common/src/utils/invoice.ts)（PF版 `community_bill` 請求）を参考に、エンプラ向け請求書 PDF 生成 Function を追加
- 運営が月初に前月分を確認 → 承認 → PDF 発行 → 企業へ送付
- ゲスト無料分の `members.is_guest` フィルタ高速化（`04_ゲスト参加` §7.2 Phase 2 案）と連動
