# 監査ログ 詳細仕様

本ドキュメントは `01_仕様概要`、`02_全体構成・アーキテクチャ` の決定事項に基づき、エンタープライズ版の監査ログ機能の仕様を一元化して定義する。

**参照:** 監査ログの記録タイミングは各機能仕様書（04_認証・アカウント管理、04_全社管理者画面、04_割引・決済、04_ゲスト参加、04_イベント管理）に記載。本ドキュメントは action 一覧・スキーマ・実装・閲覧画面を集約する。

## 前提とする仕様書

本ドキュメントは EventMemberOrder 設計（`05_EventOrder→EventMemberOrder.md`）を前提とする。注文系の監査ログは「セッション単位」（`addToCart` ～ `confirmOrder` / `stripeWebhook` ～ `cancelOrders` の単位）で記録する。`member_orders` ドキュメント単位（メニュー単位）での記録は行わない（02 論点 5.1 で決定）。


# 1. 概要

## 1.1 方針

MVP から最低限の監査ログ基盤を構築する。後付けするとログの欠損期間が発生し、大企業への説明で致命的になるため、初期から導入する。

## 1.2 決定事項サマリ

| # | 論点 | 決定 |
|:--|:--|:--|
| A-1 | 出力先 | Firestore + Cloud Logging の二重出力 |
| A-2 | 書き込み | Cloud Functions（Admin SDK）からのみ。クライアント直接書き込み禁止 |
| A-3 | 読み取り | 全社管理者のみ |
| A-4 | ログ保持期間（MVP） | Firestore: 無期限。Cloud Logging: デフォルト30日 |
| A-5 | CSV エクスポート | MVP では不要。Phase 2 |
| A-6 | 注文ログの粒度 | **セッション単位**。`order_ids` 配列を `details` に持つ（02 論点 5.1） |
| A-7 | ゲスト注文ログ | `order_create` に統合し、`details.is_guest = true` で識別。`guest_order_create` は廃止 |
| A-8 | 新規ログ種別 | `monthly_usage_exceeded` / `enterprise_subsidy_recalculated` を MVP に追加（02 論点 5.2） |
| A-9 | `cart_add` / `cart_remove` | MVP では追加しない |
| A-10 | 企業作成ログ | `enterprise_create`（`createEnterprise` 実行時。`04_オンボーディング` 参照） |


# 2. スキーマ・ストレージ

## 2.1 Firestore コレクション

企業ごとのサブコレクションとして格納する。

```
/enterprises/{enterpriseId}/audit_logs/{logId}
```

## 2.2 スキーマ

```typescript
interface AuditLog {
  enterprise_id: string
  user_id: string                 // 操作を行ったユーザーのID。システム実行時は "system"
  action: string                  // ログ種別（3章参照）
  target_id?: string              // 操作対象のドキュメントID（注文系は session 識別子。後述）
  target_type?: string            // 'community' | 'event' | 'order_session' | 'member' | 'settings' | 'enterprise' | 'enterprise_subsidy_settings'
  timestamp: Timestamp
  ip_address?: string             // リクエスト元IPアドレス
  details?: Record<string, unknown>  // 追加情報（変更前後の値、order_ids 配列など）
}
```

### target_type の値

| 値 | 意味 | 備考 |
|:--|:--|:--|
| `community` | コミュニティ | |
| `event` | イベント | |
| `order_session` | **注文セッション**（`addToCart` ～ `confirmOrder` / `stripeWebhook` ～ `cancelOrders` の単位） | 旧 `order` を改名。1 セッション = 複数の `member_orders` ドキュメント（メニュー数分）+ 任意の 1 `stripes` ドキュメント |
| `member` | EnterpriseMember | |
| `enterprise` | 企業（テナント） | createEnterprise 実行時 |
| `settings` | 全社設定 | |
| `enterprise_subsidy_settings` | 企業補助設定 | 全社設定とは別軸で記録するため独立 |

### 注文系ログの target_id / details

| ケース | target_id | details |
|:--|:--|:--|
| Stripe 経由 | `stripes.id`（1 セッション = 1 stripe ドキュメント） | `{ order_ids: string[], event_id, total_payment, pay_enterprise_subsidy_amount, is_guest? }` |
| `confirmOrder` 経由（無料 / 全額補助） | `null`（stripes が存在しない）または「`session-` + 先頭 order_id」 | `{ order_ids: string[], event_id, total_payment: 0, pay_enterprise_subsidy_amount, is_guest? }` |
| キャンセル | キャンセル対象セッションの `stripe_id`（または先頭 order_id） | `{ order_ids: string[], event_id, refund_amount, returned_subsidy_amount }` |

> `target_id` が一意でない（`confirmOrder` 経由で `stripes` がない）ケースに備え、`details.order_ids` を必ず含める方針。検索・トレーサビリティは `details.order_ids` から `member_orders` を逆引きする想定。


# 3. action 一覧

## 3.1 認証・アカウント関連

| action | 日本語ラベル | トリガー | target_type | target_id | details | 記録元 |
|:--|:--|:--|:--|:--|:--|:--|
| login | ログイン | OTP 認証成功時 | — | — | — | confirmEnterpriseEmailLogin |
| logout | ログアウト | 手動ログアウト | — | — | — | logEnterpriseLogout |
| session_timeout | セッションタイムアウト | 60分無操作 | — | — | — | logEnterpriseLogout |
| account_create | アカウント作成 | アカウント作成（CSV/個別） | member | userId | email, role | createEnterpriseMembers |
| account_disable | アカウント停止 | アカウント停止 | member | userId | — | disableEnterpriseMember |
| account_enable | アカウント復活 | アカウント復活 | member | userId | — | enableEnterpriseMember |
| role_change | ロール変更 | ロール変更 | member | userId | old_role, new_role | updateEnterpriseRole |

## 3.2 管理者操作関連

| action | 日本語ラベル | トリガー | target_type | target_id | details | 記録元 |
|:--|:--|:--|:--|:--|:--|:--|
| member_update | メンバー情報更新 | 表示名・部署の編集 | member | userId | — | updateEnterpriseMember |
| community_approve | コミュニティ承認 | 従業員申請の承認 | community | communityId | — | approveCommunity |
| community_reject | コミュニティ却下 | 従業員申請の却下 | community | communityId | rejection_reason | rejectCommunity |
| community_create | コミュニティ作成 | 管理者による一括/個別作成 | community | communityId | — | createEnterpriseCommunities |
| enterprise_create | 企業作成 | 運営による企業 + 初代 admin 作成 | enterprise | enterpriseId | company_name, subdomain, initial_admin_email | createEnterprise |
| settings_update | 全社設定変更 | 会社名・ロゴの変更 | settings | — | 変更前後の key-value | updateEnterpriseSettings |
| discount_update | 補助設定変更 | 企業補助ルールの変更 | enterprise_subsidy_settings | — | 変更前後の `type` / `value` / `monthly_limit_per_user` | updateEnterpriseSubsidySettings |

## 3.3 注文・イベント関連

| action | 日本語ラベル | トリガー | target_type | target_id | details | 記録元 |
|:--|:--|:--|:--|:--|:--|:--|
| order_create | 注文確定 | 注文確定（従業員 / ゲスト、有料 / 無料すべて） | order_session | `stripe_id` または `null` | `order_ids[]`, `event_id`, `total_payment`, `pay_enterprise_subsidy_amount`, `is_guest?` | `confirmOrder`, `stripeWebhook` |
| order_cancel | 注文キャンセル | 注文キャンセル | order_session | キャンセルセッションの `stripe_id` または先頭 `order_id` | `order_ids[]`, `event_id`, `refund_amount`, `returned_subsidy_amount`, `is_guest?` | `cancelOrders` |
| event_auto_cancel | イベント自動中止 | 注文期限3日前の自動中止 | event | eventId | `order_count`, `min_required` | 自動中止 Scheduled Function |

> 旧 `guest_order_create` は廃止。`order_create` の `details.is_guest = true` で識別する（A-7）。これにより、ゲスト分も含めたセッション単位の集計が容易になる。

## 3.4 補助・上限関連（新規追加）

| action | 日本語ラベル | トリガー | target_type | target_id | details | 記録元 |
|:--|:--|:--|:--|:--|:--|:--|
| monthly_usage_exceeded | 月額上限超過 | `addToCart` で残枠を使い切り、補助なしで保存された `member_orders` が発生 | order_session | `null` | `event_id`, `year_month`, `requested_amount`（当該 addToCart 内で算出した補助候補額の合計＝月額上限適用前）, `granted_amount`（実際に `pay_enterprise_subsidy_amount` として保存した合計）, `unfilled_count`（補助フィールドを省略して保存した品数） | `addToCart` |
| enterprise_subsidy_recalculated | 補助額再計算による不整合検知 | `confirmOrder` / `createStripeCheckoutSession` / `stripeWebhook` で `pay_enterprise_subsidy_amount` が再計算値と不一致 | order_session | `null` | `event_id`, `order_ids[]`, `expected[]`, `stored[]` | `confirmOrder`, `createStripeCheckoutSession`, `stripeWebhook` |

## 3.5 システム実行時の user_id

`event_auto_cancel` など、ユーザー操作によらない実行では `user_id: "system"` を設定する。


# 4. 実装

## 4.1 共通ユーティリティ

```typescript
// functions/default/src/utils/auditLog.ts
import { logger } from 'firebase-functions/v2'
import { getFirestore, Timestamp } from 'firebase-admin/firestore'

interface WriteAuditLogParams {
  enterpriseId: string
  userId: string
  action: string
  targetId?: string | null
  targetType?: string
  ipAddress?: string
  details?: Record<string, unknown>
}

export async function writeAuditLog(params: WriteAuditLogParams): Promise<void> {
  const log = {
    enterprise_id: params.enterpriseId,
    user_id: params.userId,
    action: params.action,
    target_id: params.targetId ?? null,
    target_type: params.targetType ?? null,
    timestamp: Timestamp.now(),
    ip_address: params.ipAddress ?? null,
    details: params.details ?? null,
  }

  await getFirestore()
    .collection(`enterprises/${params.enterpriseId}/audit_logs`)
    .add(log)

  logger.info('audit_log', log)
}
```

## 4.2 使用例

```typescript
// アカウント作成時
await writeAuditLog({
  enterpriseId,
  userId: adminUserId,
  action: 'account_create',
  targetId: newUserId,
  targetType: 'member',
  ipAddress: request.rawRequest.headers['x-forwarded-for'] as string,
  details: { email: newUserEmail, role: 'member' },
})

// イベント自動中止時
await writeAuditLog({
  enterpriseId,
  userId: 'system',
  action: 'event_auto_cancel',
  targetId: eventId,
  targetType: 'event',
  details: { order_count: 5, min_required: 10 },
})

// Stripe 経由で注文確定（stripeWebhook 内）
await writeAuditLog({
  enterpriseId,
  userId: customerUserId,
  action: 'order_create',
  targetId: stripeId,                  // stripes ドキュメントの ID
  targetType: 'order_session',
  details: {
    order_ids: orderIds,               // ['oid1', 'oid2', ...]
    event_id: eventId,
    total_payment: totalPayment,
    pay_enterprise_subsidy_amount: subsidyTotal,
  },
})

// confirmOrder 経由で無料確定（stripes なし）
await writeAuditLog({
  enterpriseId,
  userId: customerUserId,
  action: 'order_create',
  targetId: null,
  targetType: 'order_session',
  details: {
    order_ids: orderIds,
    event_id: eventId,
    total_payment: 0,
    pay_enterprise_subsidy_amount: subsidyTotal,
    is_guest: false,
  },
})

// 月額上限超過（addToCart 内。unfilled_count > 0 のときのみ記録）
await writeAuditLog({
  enterpriseId,
  userId: customerUserId,
  action: 'monthly_usage_exceeded',
  targetId: null,
  targetType: 'order_session',
  details: {
    event_id: eventId,
    year_month: eventMonth,              // "2026-07"
    requested_amount: requestedTotal,  // 補助候補額の合計（上限適用前）
    granted_amount: grantedTotal,        // 実際に保存した補助額の合計
    unfilled_count: unfilledCount,       // pay_enterprise_subsidy_amount を省略した品数
  },
})

// 補助額再計算で不整合検知（confirmOrder / createStripeCheckoutSession 内）
await writeAuditLog({
  enterpriseId,
  userId: customerUserId,
  action: 'enterprise_subsidy_recalculated',
  targetId: null,
  targetType: 'order_session',
  details: {
    event_id: eventId,
    order_ids: orderIds,
    expected: [...],   // 各 order の再計算値（null は undefined）
    stored: [...],     // 各 order に保存されていた値（null は undefined）
  },
})
```

# 6. 閲覧画面

## 6.1 画面仕様: /admin/audit-logs

`enterprise/src/pages/admin/audit-logs.vue`。企業内の操作ログを時系列で一覧表示する。

### 一覧テーブル

| カラム | 内容 |
|:--|:--|
| 日時 | timestamp（YYYY/MM/DD HH:mm:ss） |
| アクション | action の日本語ラベル（3章参照） |
| 操作者 | user_id に対応する display_name。system の場合は「システム」。`details.is_guest == true` のときは「ゲスト」表記を併記 |
| 対象 | target_type + target_id の表示名。`order_session` の場合は「注文セッション（N件）」と details.order_ids.length を併記 |
| 詳細 | 「詳細」リンク → ダイアログ表示 |

### フィルタ

| フィルタ | 種類 | 説明 |
|:--|:--|:--|
| アクション種別 | セレクトボックス | 全て / 各種アクション |
| 操作者 | セレクトボックス | 全て / メンバー選択 / システム / ゲスト（`details.is_guest == true`） |
| 期間 | 日付範囲ピッカー | 開始日〜終了日 |

### ページネーション

- Firestore のカーソルベース（`startAfter` + `limit`）
- 「次へ」「前へ」ボタン方式
- 1ページ50件
- `timestamp` 降順

### 詳細ダイアログ

`details` の内容を key-value 形式で表示。`order_ids` 配列はクリックで `member_orders` 詳細画面に遷移可能とする（Phase 2）。

## 6.2 Phase 2 での拡張

- CSV エクスポート
- ログ保持期間の設定（TTL）
- テキスト検索
- `order_ids` から `member_orders` 詳細画面への遷移
- `cart_add` / `cart_remove` の追加（Phase 2 で要件次第）


# 7. ログ保持期間

| 出力先 | MVP | Phase 2 |
|:--|:--|:--|
| Firestore | 無期限 | TTL 設定を検討 |
| Cloud Logging | デフォルト30日 | 長期保存の場合は Cloud Storage へエクスポート |
