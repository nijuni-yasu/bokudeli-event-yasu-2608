# Part 1: 情報セキュリティポリシー


## 1. 基本方針

株式会社〇〇（以下「当社」）は、shokujii サービスの開発・運用において、お客様からお預かりする情報資産を適切に保護し、信頼されるサービスを継続的に提供することを最重要事項と位置づけます。

当社は、以下の原則に基づき、情報セキュリティの確保に取り組みます。

1. お客様のデータを機密性・完全性・可用性の観点から適切に保護します
2. 法令および契約上の要求事項を遵守します
3. 情報セキュリティに関するリスクを継続的に評価し、適切な対策を講じます
4. 全従業員に対して情報セキュリティの重要性を周知し、教育を実施します
5. 情報セキュリティに関する施策を定期的に見直し、改善します


## 2. 適用範囲

- shokujii サービス（プラットフォーム版・エンタープライズ版）の開発・運用に関わる全業務
- 上記に関わる当社の全従業員・業務委託者


## 3. データ保護

### 3.1 暗号化

| 対象 | 方式 |
|:--|:--|
| 保存データ | AES-256 による自動暗号化（Google Cloud 管理鍵） |
| 通信データ | TLS 1.2 以上による暗号化 |
| 決済情報 | Stripe が PCI DSS Level 1 準拠環境で処理。当社にカード情報は保存されない |

### 3.2 データ保管

- すべてのデータは Google Cloud 東京リージョン（asia-northeast1）に保管する
- 日本国外へのデータ転送は原則行わない

### 3.3 テナント分離

- 企業ごとに `enterprise_id` を付与し、論理的にデータを分離する
- Firestore Security Rules により、他社データへのアクセスを技術的に防止する


## 4. アクセス制御

### 4.1 ユーザーアクセス

- 企業メールドメインによるログイン制限
- Firebase Auth の custom claims による権限管理（全社管理者 / 一般従業員）
- 60分無操作でのセッション自動タイムアウト

### 4.2 管理アクセス

- Firebase / GCP コンソールへのアクセスは最小限の担当者に限定する
- 本番環境への直接的なデータ操作は原則禁止し、Cloud Functions 経由で実行する
- GCP の IAM により、開発者・運用者の権限を最小権限の原則で設定する


## 5. 監査・ログ

- ログイン/ログアウト、管理者操作、注文/キャンセル等の操作ログを記録する
- ログは Firestore および Cloud Logging に保存する
- ログへのアクセスは全社管理者（顧客側）および当社の運用担当者に限定する
- クライアントからのログの直接改ざんは Security Rules で技術的に防止する


## 6. 外部委託管理

当社サービスは以下の外部サービスを利用している。各サービスのセキュリティ認証を確認の上、利用を決定している。

| サービス | 提供元 | 用途 | セキュリティ認証 |
|:--|:--|:--|:--|
| Firebase / GCP | Google | インフラ全般 | SOC1/2/3, ISO27001/27017/27018 |
| Stripe | Stripe, Inc. | 決済処理 | PCI DSS Level 1, SOC1/2 |
| SendGrid | Twilio Inc. | メール配信 | SOC2, ISO27001 |


## 7. 継続的改善

- 本ポリシーは年1回以上見直しを行う
- セキュリティインシデント発生時は、再発防止策を講じた上で必要に応じてポリシーを更新する

# Part 2: インシデント対応フロー


## 1. 目的

情報セキュリティインシデントが発生した際に、被害の拡大を防止し、迅速に復旧し、影響を受ける顧客に適切に通知するための手順を定める。


## 2. インシデントの定義

以下の事象をセキュリティインシデントと定義する。

| 分類 | 事象例 |
|:--|:--|
| データ漏洩 | 顧客データへの不正アクセス、意図しないデータ公開 |
| サービス停止 | shokujii サービスの全面または一部停止 |
| 不正アクセス | 第三者によるシステムへの不正侵入 |
| データ改ざん | 顧客データの意図しない変更・削除 |
| 脆弱性の悪用 | 既知または未知の脆弱性を利用した攻撃 |


## 3. 重大度分類

| 重大度 | 定義 | 例 |
|:--|:--|:--|
| **Critical** | データ漏洩またはサービス全面停止 | 顧客の個人情報が外部に流出、Firestore への全アクセス不能 |
| **High** | 一部機能停止または特定企業のデータに影響 | 特定企業のデータが他社から閲覧可能、決済機能の停止 |
| **Medium** | パフォーマンス低下、軽微な不具合 | レスポンスタイムの大幅な悪化、一部画面の表示崩れ |
| **Low** | 潜在的リスク（直接的な影響なし） | 脆弱性の発見（未悪用）、依存パッケージのセキュリティアラート |


## 4. 対応フロー

```
検知 → トリアージ → 初動対応 → 顧客通知 → 原因調査 → 復旧 → 振り返り
```

### 4.1 検知

| 検知方法 | 説明 |
|:--|:--|
| Cloud Logging アラート | エラー率の急増、異常なリクエストパターンを自動検知 |
| 監査ログの異常 | 通常と異なるログインパターン、大量のデータアクセス |
| ユーザーからの報告 | 導入企業の全社管理者からの連絡 |
| 外部からの報告 | セキュリティ研究者等からの脆弱性報告 |
| 依存パッケージのアラート | npm audit、GitHub Dependabot 等 |

### 4.2 トリアージ（重大度判定）

- 検知者は速やかに対応責任者に報告する
- 対応責任者は重大度を判定し、以下のタイムラインに従い対応を開始する

### 4.3 対応タイムライン

| 重大度 | 初動対応 | 顧客通知 | 復旧目標 |
|:--|:--|:--|:--|
| **Critical** | 検知後 **1時間以内** | 検知後 **4時間以内** | 最優先で対応 |
| **High** | 検知後 **4時間以内** | 検知後 **24時間以内** | 24時間以内 |
| **Medium** | 翌営業日まで | 必要に応じて | 計画的に対応 |
| **Low** | 1週間以内に評価 | 通知不要 | 計画的に対応 |

### 4.4 初動対応

1. 被害の拡大防止（影響範囲の特定・隔離）
2. 証拠の保全（ログの保存、スクリーンショット等）
3. 応急措置の実施（アクセス遮断、機能停止等）

### 4.5 顧客通知

- 影響を受ける企業の全社管理者に対してメールで通知する
- 通知内容: 発生事象、影響範囲、対応状況、今後の予定
- Critical / High の場合、第一報は簡潔に速やかに送り、詳細は後続の報告で補完する

**通知テンプレート（第一報）:**

```
件名: 【重要】shokujii セキュリティインシデントのご報告

〇〇株式会社 ご担当者様

平素よりshokujiiをご利用いただきありがとうございます。

下記の事象が発生いたしましたのでご報告いたします。

■ 発生日時: 〇〇年〇〇月〇〇日 〇〇:〇〇
■ 事象概要: （概要を記載）
■ 影響範囲: （影響範囲を記載）
■ 現在の対応状況: （対応状況を記載）
■ 今後の予定: （予定を記載）

詳細が判明次第、改めてご報告いたします。
ご不明点がございましたら、下記までお問い合わせください。

連絡先: 〇〇
```

### 4.6 原因調査・復旧

1. 根本原因の特定
2. 恒久的な修正の実施
3. 修正の検証
4. サービスの復旧確認

### 4.7 振り返り（ポストモーテム）

インシデント収束後、1週間以内にポストモーテムを実施する。

| 項目 | 内容 |
|:--|:--|
| タイムライン | 検知から復旧までの経緯 |
| 根本原因 | なぜ発生したか |
| 影響範囲 | 何が・誰が影響を受けたか |
| 対応の評価 | 対応は適切だったか、改善点はあるか |
| 再発防止策 | 技術的・運用的な再発防止策 |

| 役割 | 担当 | 責務 |
|:--|:--|:--|
| **対応責任者** | 〇〇（要決定） | 重大度判定、対応方針の決定、顧客通知の承認 |

# Part 3: プライバシーポリシー（エンタープライズ版）ドラフト

> **注意:** 本ドラフトは技術的なデータ取扱いの観点からの骨格であり、法務チェックを経て最終化する必要がある。


## 1. 個人情報の取得と利用目的

### 1.1 取得する個人情報

| 情報 | 取得元 | 保管先 |
|:--|:--|:--|
| メールアドレス | ログイン時にユーザーが入力 | Firebase Authentication |
| 氏名 | アカウント作成時に管理者が登録 or ユーザーが入力 | Firestore（`/users`） |
| 所属企業・部署 | アカウント一括作成時に管理者が登録 | Firestore（`/enterprises/{id}/members`） |
| 注文履歴 | サービス利用時に自動記録 | Firestore（`/orders`） |
| 操作ログ | サービス利用時に自動記録 | Firestore（`/audit_logs`）、Cloud Logging |
| IPアドレス | アクセス時に自動取得（監査ログ用） | Firestore（`/audit_logs`）、Cloud Logging |

### 1.2 取得しない情報

| 情報 | 理由 |
|:--|:--|
| クレジットカード番号 | Stripe が PCI DSS 準拠環境で処理。当社システムにカード情報は一切保存されない |
| パスワード | パスワードレス認証（OTP）を採用しているため不要 |


## 2. 利用目的

| 利用目的 | 対象データ |
|:--|:--|
| 本人認証 | メールアドレス |
| サービス提供（注文処理、通知送信） | 氏名、メールアドレス、注文履歴 |
| 利用状況の集計・ダッシュボード表示 | 注文履歴、所属企業・部署 |
| セキュリティ確保（不正アクセス検知） | 操作ログ、IPアドレス |
| カスタマーサポート | 氏名、メールアドレス、注文履歴 |

上記以外の目的で個人情報を利用することはありません。


## 3. 第三者提供・外部委託

当社は、以下のサービスに個人情報の処理を委託しています。

| 委託先 | 委託する情報 | 目的 | 所在国 |
|:--|:--|:--|:--|
| Google LLC（Firebase） | 全ユーザーデータ | データベース保管、認証処理 | 日本（東京リージョン） |
| Stripe, Inc. | 決済に必要な情報 | 決済処理 | 米国（PCI DSS 準拠） |
| Twilio Inc.（SendGrid） | メールアドレス | OTP 送信、通知メール配信 | 米国 |

上記以外の第三者に個人情報を提供することはありません（法令に基づく場合を除く）。


## 4. データの保管

### 4.1 保管場所

すべてのデータは Google Cloud 東京リージョン（asia-northeast1）に保管します。

### 4.2 暗号化

- 保存時: AES-256 による自動暗号化
- 通信時: TLS 1.2 以上による暗号化

### 4.3 アクセス制御

- 企業ごとにデータを論理的に分離し、他社のデータにはアクセスできない設計
- 当社スタッフのデータアクセスは、カスタマーサポートおよび障害対応に必要な場合に限定

### 4.4 保管期間

| データ | 保管期間 |
|:--|:--|
| アカウント情報 | 契約期間中。契約終了後〇〇日以内に削除（**要決定**） |
| 注文履歴 | 契約期間中。契約終了後〇〇日以内に削除（**要決定**） |
| 操作ログ（Firestore） | 契約期間中（Phase 2 で TTL 設定を検討） |
| 操作ログ（Cloud Logging） | 30日間（GCP デフォルト） |

## 5. 個人情報の開示・訂正・削除

### 5.1 ユーザー本人からの請求

ユーザー本人は、当社に対して以下の請求を行うことができます。

| 請求 | 対応方法 |
|:--|:--|
| **開示請求** | 当社が保有する本人の個人情報の内容を開示 |
| **訂正請求** | 個人情報の内容が事実と異なる場合の訂正 |
| **削除請求** | 個人情報の削除 |

### 5.2 企業管理者からの請求

導入企業の全社管理者は、管理者画面から以下の操作を行えます。

| 操作 | 方法 |
|:--|:--|
| メンバー情報の確認 | 管理者画面のメンバー一覧 |
| メンバー情報の変更 | 管理者画面のメンバー編集 |
| アカウント停止（論理削除） | 管理者画面のアカウント管理 |

### 5.3 契約終了時

契約終了時は、当該企業に関するすべてのデータを削除します。

- Firestore: `enterprise_id` でフィルタし一括削除
- Firebase Authentication: 該当ユーザーの一括削除
- Cloud Storage: `/enterprises/{enterpriseId}/` 以下を一括削除
- 削除完了後、企業の求めに応じて**削除証明書**を発行可能
