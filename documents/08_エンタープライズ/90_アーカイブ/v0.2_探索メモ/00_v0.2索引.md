# エンプラ v0.2 ドキュメント索引

v0.2 は「PF 版とエンプラ版の分離（テナント/プロジェクト分離）をどうするか」を検討し、**最終的にパターン A（単一 Firebase Project）＋ Identity Platform マルチテナンシー** を採用したフェーズ。番号順に読むと検討経緯のため方針が揺れて見えるので、**現行の正本と参考（経緯・不採用案）を区別して読むこと**。

> **再編後の所在**: v0.2 ドキュメントは [../../README.md](../../README.md) の構成に従い ADR / リファクタ計画 / アーカイブへ移動済み。本索引は **v0.2 検討経緯の入口** として残す。

---

## 最終結論（1 行）

**Project は分離しない（パターン A 継続）。Auth 境界だけ IdP マルチテナンシーで強化する。** データ/インフラの物理分離（B / B′ / C / D）は採らず、ADR-001 §4 の将来トリガーが発火した時点で段階対応する。詳細は ADR-001 §1。

## パターン早見（再検討 / ADR-001 の定義）

| 記号 | 構成 | v0.2 での採否 |
|:--|:--|:--|
| **A** | 単一 Firebase Project（PF + 全エンプラ同居）＋ `enterprise_id` 論理分離 | **採用**（＋ IdP マルチテナンシー） |
| **B** | PF Project + 1 Enterprise Project（プロダクト分離） | 不採用（パターンB 再設計参照・将来トリガー時） |
| **B′** | 単一 Project + 企業ごと Firestore Database | v0.2 ではやらない（将来トリガー時の中間解） |
| **C** | 企業ごと Project（100 社 = 100 Project） | 不採用（事例調査が示す破綻構造） |
| **D** | 標準は共有、要件企業のみ Silo（Bridge） | 将来の製品方針（03_特定企業だけ分離 参照） |
