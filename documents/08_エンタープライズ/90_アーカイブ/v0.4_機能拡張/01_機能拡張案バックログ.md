## 1. ロゴ設定機能

- 画面左上の shokujii ロゴの部分について、ロゴを表示できるようにしたい
- 現状はログイン画面のみ。左上にも常時表示するようにする

## 2. ログイン画面のサービス訴求（未ログイントップ不採用）

- **未ログイン時はトップ `/` を見せない**（MVP F-2 維持。`/login` へリダイレクト）
- 初版案「トップを未ログイン公開」（#2207 クローズ）は **不採用** → [#2213](https://github.com/nijuniinc/bokudeli-event-new/issues/2213)
- 代わりに **ログイン画面** でサービスイメージを見せる
  - デスクトップ: **左** = サービスイメージ、**右** = 企業ロゴ・社名・ログインフォーム
  - Phase 1: ヒーロー画像は **全社共通の静的アセット**（`enterprise/src/assets/`）
  - `/pass-code` も同一レイアウトに揃える（推奨）
- 社内導入前にサービス内容が伝わるようにする（v0.3「ログイン画面 UI をリッチに」と整合）

> 設計詳細: [02_設計.md §2](./02_設計.md)

## 3. マイページ

- user と enterprise が乖離し始めている
- v-card を base にしていなかったため、UI 表示 user だけアップデートされている

## 4. 利用状況と注文履歴

- 1 つの画面に集約したい
- マイページのタブに表示するのではなく、別画面にしたい
- PF 版の user にも注文履歴画面は必要なので user も別画面に移行する
- PF 版は注文履歴のみ表示。エンプラ版は注文履歴と利用状況両方を表示する
- URL は `/orders` を第一候補とする（`/activity` は不採用方向）

## 5. イベントのテンプレート機能

- エンプラの企業ごとにイベントのテンプレートを作成することができる
- 「カバー画像」「タイトル」「説明文」「人数」のテンプレを作成して、それを元に作成できる
- 「部署定例 MTG」「社長を囲む会」「役員を囲む会」「パパママ会」「部活会」「社内勉強会」など
- どのコミュニティからも、任意のテンプレでイベントを作成できると、別コミュニティなのに、同じ種類のイベントができてしまう 🤔
- コミュニティを運営側で作成して、そこにテンプレとなるようなイベントを作成してそれをコピーしてあげた方が良さそう 🤔
- 「コミュニティの管理者になる」ボタンを押下して承認されたら、そのコミュニティの主催ができるようになる
- そもそも「コミュニティ」の概念が必要なかった？ イベントテンプレだけ用意してあげて、ユーザー個人がイベントを作成することができる状態が良い？（データ構造が変わりすぎてしまうので、全従業員が主催できるコミュニティの箱を用意するのが良い？コミュニティとなると継続利用が前提になり過ぎてしまう。イベント作成のハードルが高まってしまう感がある）
- そもそも PF 版にも全てのユーザーが利用できるデフォルトのテンプレート機能があった方が良い？ 🤔

## 6. コミュニティ承認機能

- 「コミュニティ参加する」を承認する機能
- 部署限定 MTG について、別部署の方が参加できてしまう
- 部活動限定ランチ会について、部員でない方が参加できてしまう
- イベントは**ログイン後の**トップ画面にコミュニティ限定のものも表示するようにしたい

> **注**: コミュニティ承認・限定表示の設計本体は [v0.3_機能拡張/02_設計.md §1](../v0.3_機能拡張/02_設計.md)（3 軸モデル）および [ADR-003](../../20_設計判断_ADR/ADR-003_publish_scope移行.md) を正本とする。本 v0.4 では WS-G（G-5 / G-6）との対応関係を [02_設計.md §5](./02_設計.md) に整理する。
