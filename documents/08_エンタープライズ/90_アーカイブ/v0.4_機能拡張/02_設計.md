## 2. ログイン画面のサービス訴求（未ログイントップ不採用）

### 2-1. 背景

MVP（F-2）ではエンプラ全画面を login 必須とした。社内導入前にサービス内容が伝わりにくくログイン意欲が下がる課題がある。

v0.4 初版案（**未ログインでトップ `/` を peek 表示** / Issue #2207 クローズ）は **不採用** とする（`authGuards` 変更・Firestore Rules 拡張のコスト・セキュリティ面）。代替実装は [#2213](https://github.com/nijuniinc/bokudeli-event-new/issues/2213)。

代わりに **ログイン画面でサービスイメージを見せる** 方針を採用する。v0.3 バックログ「[ログイン画面 UI をリッチにしたい](../v0.3_機能拡張/01_機能拡張案バックログ.md)」の Phase 2 具体化である。

> **G-1（ゲスト参加）との区別**: G-1 は外部ゲスト向けの未認証イベント閲覧。本節は **login 画面の UX 改善** であり、Firestore Rules 変更は不要。

### 2-2. 決定（案）

#### 未ログイン時のルーティング（現状維持）

| ルート | 未ログイン | 備考 |
|:--|:--|:--|
| `/`（トップ） | ❌ login 必須 | `/login` へリダイレクト（**変更なし**） |
| `/login`, `/pass-code`, `/maintenance`, `/404`, `/520` | ✅ | 既存 public |
| `/c/*`, `/e/*`, カート, manage, プロフィール等 | ❌ login 必須 | 既存どおり |

- `authGuards.ts`・Firestore Rules は **変更しない**
- [v0.3 §3-2](../v0.3_機能拡張/02_設計.md) の「全面リダイレクト」を **維持**

#### ログイン画面レイアウト

| 項目 | 内容 |
|:--|:--|
| 背景 | 全画面に共通背景画像（`login_bg.png`）。半透明オーバーレイ（`rgba(0,0,0,0.4)` 程度）で少し暗くする |
| フォーム | 画面中央に `v-card`（企業ロゴ・社名・メール入力 / OTP 導線） |
| ブレークポイント | xs / sm / md 以上とも同一（背景フル + 中央カード） |

| 画面 | 方針 |
|:--|:--|
| `/login` | 主対象 |
| `/pass-code` | 同一レイアウトに揃える（推奨） |

中央 v-card の企業ロゴ・社名は既存 `getEnterpriseByDomain` / `company_logo_url` を流用（§1・#2205 / #2206 と整合）。

### 2-3. 画像ソース（Phase 1）

| 項目 | 内容 |
|:--|:--|
| 背景画像 | **全 enterprise 共通の静的アセット**（`enterprise/src/assets/images/login/login_bg.png`） |
| 企業別カスタム | **Phase 2 見送り**。G-4（`top_banner` 等）と統合検討 |

Phase 1 では admin 設定・アップロード UI・Storage 公開 read の追加は行わない。

### 2-4. 実装要点

- 新規 `LoginBackgroundLayout.vue`（背景 + オーバーレイ + 中央 slot）を `enterprise/src/components/login/` に配置
- `LoginBrandingHeader.vue` で中央 `v-card` に企業ロゴ・社名・フォームを載せる
- `login.vue` / `pass-code.vue` から利用
- 背景画像は build 時バンドル（全社同一）

**不採用（#2207 代替）**

- `PUBLIC_EXACT_PATHS` への `/` 追加
- Firestore Rules 未認証 read 拡張

### 2-5. Phase 2b（G-6 依存）— H-2b

- **ログイン後**のトップに `publish_scope: community` イベントを一覧表示（非メンバー閲覧のみ）
- 未ログイン peek（旧 H-2a）とは **独立**。G-6 / ADR-003 完了後

## 4. 注文履歴・利用状況の専用画面（`/orders`）

### 4-1. 背景

MVP 前倒し（D-10 / EP-24）でマイページ `?tab=usage` / `?tab=orders` を実装したが、マイページと履歴の責務分離・PF/エンプラ共通導線のため **専用画面へ移行**する。

### 4-2. URL 選定

| 候補 | 判定 |
|:--|:--|
| **`/orders`** | **採用（案）**。既存 i18n（`tab_orders`, `orders_link`）と一致 |
| `/activity` | 不採用。PF は「注文履歴」、エンプラは「利用状況+注文」で意味がずれる |
| `/order-history` | 冗長 |
| `/usage` + `/orders`（2 画面） | 不採用。「1 画面集約」の要望と矛盾 |

### 4-3. 決定（案）

| 項目 | PF (user) | Enterprise |
|:--|:--|:--|
| パス | `/orders` | `/orders` |
| 認可 | login 必須 | login 必須 |
| 表示 | 注文履歴のみ | 利用状況（条件付き）+ 注文履歴 |
| 利用状況 | — | `monthly_limit_per_user` 設定あり時のみ（D-10 ロジック流用） |
| タブ（任意） | なし | `/orders?tab=usage` で利用状況セクションへ（enterprise 本人のみ） |

**レイアウト（enterprise）**

```
/orders
├─ [福利厚生利用状況]  ← 上限設定あり時のみ
└─ [注文履歴リスト]
```

### 4-4. 互換 redirect

| 旧 URL | 新 URL |
|:--|:--|
| `/u/:userId?tab=orders` | `/orders` |
| `/u/:userId?tab=usage` | `/orders?tab=usage` |

### 4-5. ナビ・導線

- グローバルメニュー / `UserProfile.vue` の「注文履歴」→ `/orders`
- マイページから `orders` / `usage` タブ削除

### 4-6. 実装配置（案）

- `base/src/pages/orders.vue`（新規）+ app ごと wrapper
- `EnterpriseSubsidyUsagePanel` / `userOrderHistoryStore` を流用

## 6. イベントテンプレート

### 6-1. 方針（案）

| 方式 | 判定 |
|:--|:--|
| 新スキーマ `EventTemplate` | Phase 2 見送り（スキーマ・Rules コスト大） |
| **テンプレイベント + コピー UI** | **採用（案）**。既存 PF イベントコピー機能を拡張 |

### 6-2. 決定（案）

1. **全社デフォルトコミュニティ**を admin が 1 つ用意（全従業員が主催可能な箱）
2. **テンプレ用コミュニティ**（または上記内）にテンプレイベントを admin が事前作成
   - カバー・タイトル・説明・定員を preset
3. ユーザーは「テンプレから作成」→ **イベントコピー** → 対象コミュニティに紐付け
4. 部署別コミュニティは **限定イベント用**（`publish_scope: community`）に使用
5. **PF グローバルテンプレ**（`enterprise_id == null`）は Phase 2 任意（H-8）

### 6-3. 10_仕様 取り込み先

- **新規** `10_仕様/04_詳細_イベントテンプレート.md`（設計確定後）
