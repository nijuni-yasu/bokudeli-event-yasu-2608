# Pマーク・ISO 取得について

エンタープライズ版を大企業に導入する際、第三者認証の取得状況を問われることがある。
本ドキュメントでは、関連する認証制度の整理と shokujii としての取得方針を記載する。


# 1. Pマーク vs ISO 27001 の違い

| | **Pマーク（プライバシーマーク）** | **ISO 27001（ISMS）** |
|:--|:--|:--|
| **対象** | 個人情報の保護 | 情報セキュリティ全般 |
| **規格** | JIS Q 15001（日本独自） | ISO/IEC 27001（国際規格） |
| **通用範囲** | 日本国内のみ | 世界共通 |
| **審査対象** | 会社全体（全部門が対象） | 適用範囲を自分で選べる（例: 開発部門のみ） |
| **取得期間** | 3〜6ヶ月 | 3〜6ヶ月 |
| **初期コスト** | 50〜200万円 | 100〜400万円 |
| **維持コスト** | 2年ごとに更新審査（30〜80万円） | 毎年サーベイランス審査（30〜80万円）、3年ごとに更新 |
| **大企業での認知度** | 日本企業では非常に高い | グローバル企業・IT企業で高い |
| **取得難易度** | やや低い | やや高い |

**核心的な違い:** Pマークは「個人情報を正しく扱っていますか」、ISO 27001 は「情報セキュリティを管理する仕組みがありますか」。守備範囲が異なる。


# 2. エンタープライズ SaaS に関連しうる認証・規格

| 認証・規格 | 概要 | shokujii での必要性 | 推奨時期 |
|:--|:--|:--|:--|
| **ISO 27001（ISMS）** | 情報セキュリティの国際規格 | 大企業導入時に有効 | 中期（大企業展開時） |
| **ISO 27017** | クラウドサービス向けセキュリティ（ISO 27001 の拡張） | SaaS 提供者として有効。27001 と同時取得が効率的 | 27001 と同時 |
| **ISO 27018** | クラウドにおける個人情報保護（ISO 27001 の拡張） | 個人情報を扱う SaaS として有効 | 27001 と同時 |
| **Pマーク** | 日本国内の個人情報保護認証 | 日本の中規模企業への営業に有効 | 中期 |
| **SOC 2** | サービス組織の内部統制報告書（米国基準） | 外資系企業への導入に有効。日本企業では ISO の方が通りが良い | 外資展開時のみ |
| **PCI DSS** | クレジットカード情報のセキュリティ基準 | **不要**。Stripe がカード情報を処理するため shokujii 側は対象外 | 不要 |
| **ISMAP** | 政府情報システムのためのクラウドサービスセキュリティ評価 | 官公庁向けのみ。取得コスト・期間が非常に大きい | 当面不要 |


# 3. ISO 27001 の取得要件

## 3.1 審査で見られる主な領域

| 領域 | 具体例 |
|:--|:--|
| セキュリティポリシー | 情報セキュリティ方針の文書化・経営層の承認 |
| リスクアセスメント | 情報資産の洗い出し、リスクの特定・評価・対応計画 |
| アクセス管理 | 誰がどのシステムにアクセスできるかの管理（社内の話） |
| インシデント管理 | インシデント発生時の対応フロー・連絡体制 |
| 事業継続 | 障害時の復旧計画 |
| 委託先管理 | 外部サービス（GCP, Stripe 等）のセキュリティ評価 |
| 物理セキュリティ | オフィスの入退室管理等 |
| 人的セキュリティ | 従業員教育、NDA、退職時の権限剥奪 |
| 運用管理 | 変更管理、ログ管理、バックアップ |

## 3.2 取得までの流れ

```
1. 準備（3〜6ヶ月）
   - ISMS の適用範囲を決める
   - セキュリティポリシー・手順書の作成
   - リスクアセスメントの実施
   - 内部監査の実施

2. 審査（1〜2ヶ月）
   - ステージ1審査: 文書審査（書類が揃っているか）
   - ステージ2審査: 実地審査（実際に運用されているか）

3. 認証取得
   - 3年間有効、毎年サーベイランス審査（維持審査）
```

## 3.3 コスト感

| 項目 | 目安 |
|:--|:--|
| コンサルティング費用（任意） | 100〜300万円程度 |
| 審査費用（認証機関に支払い） | 50〜150万円程度/初回 |
| 維持審査（毎年） | 30〜80万円程度/年 |
| 社内工数 | 担当者1名が3〜6ヶ月集中（兼務可） |

少人数のスタートアップの場合、総額200〜400万円 + 担当者の工数が初年度の目安。


# 4. shokujii としての方針

## 4.1 結論: MVP 時点では認証取得不要。中期的に検討

| フェーズ | 推奨 | 理由 |
|:--|:--|:--|
| **MVP** | 取得不要 | 取得に3〜6ヶ月かかる。セキュリティチェックシートで「GCP は ISO27001 取得済み」と回答すれば、多くの中規模企業は通る |
| **導入企業5社超** | Pマーク検討 | 日本の中規模企業は ISO より Pマークを重視する傾向がある。ISO より取得が容易 |
| **大企業（1000名〜）への展開時** | ISO 27001 検討 | 大企業の情シスは「ベンダー自身の認証」を求めることがある。「GCP が取得済み」だけでは不十分と判断されるケース |
| **外資系企業への展開時** | SOC 2 検討 | 外資系は SOC 2 Report を求めることが多い |

## 4.2 認証がなくても導入審査を通過する戦略

セキュリティチェックシートで以下のように回答すれば、多くの企業で審査を通過できる。

> **Q: 第三者認証は取得しているか？**
>
> A: サービス基盤である Google Cloud Platform（Firebase）は SOC1/2/3、ISO27001/27017/27018 を取得済みです。
> 決済処理の Stripe は PCI DSS Level 1 を取得済みです。
> 自社の ISMS 認証取得については現在準備中です。

「**準備中**」と回答するためには、セキュリティポリシーやインシデント対応フロー等の運用ドキュメントが整備されている必要がある。

## 4.3 認証が必須となるケース

以下の業界の企業に導入する場合は、認証取得が事実上の必須条件になりうる。

- 金融機関（銀行、証券、保険）
- 医療機関
- 官公庁・自治体
- 一部の大手製造業（独自の厳格な基準を持つ企業）

shokujii のサービス特性（食事注文・社内コミュニケーション）上、扱うデータの機密度は比較的低いため、上記のような厳格な業界でない限り認証がなくても導入審査を通過できる可能性が高い。


# 5. 判断フローチャート

```
MVP リリース
  │
  ├─ まず: ドキュメント整備（認証取得なしでも効果大）
  │        - セキュリティポリシー
  │        - インシデント対応フロー
  │        - プライバシーポリシー（エンプラ版）
  │
  ├─ 導入企業が5社を超えたあたり
  │    └─ Pマーク取得を検討（日本企業メインなら最優先）
  │
  ├─ 大企業（1000名〜）からの引き合いが出てきたら
  │    └─ ISO 27001 取得を検討（27017/27018 も同時取得が効率的）
  │
  └─ 外資系企業からの引き合いが出てきたら
       └─ SOC 2 Report を検討
```


# 6. 今やるべきこと（認証取得の前段階）

以下のドキュメント整備は、認証なしでもセキュリティチェックシートへの回答力を高める。かつ、将来の Pマーク / ISO 取得時にそのまま使える。

| ドキュメント | 内容 | 現状 |
|:--|:--|:--|
| **セキュリティポリシー** | 会社としての情報セキュリティ方針（1〜2ページ） | 未整備 |
| **インシデント対応フロー** | 検知→分析→対応→通知→振り返りの手順 | 未定 |
| **プライバシーポリシー（エンプラ版）** | 個人情報の取扱方針 | 未整備 |
| **サブプロセッサー一覧** | 外部サービスの一覧とセキュリティ評価 | 整備済み（セキュリティチェックシート参照） |
| **データ管理方針** | 保持期間、削除手順、バックアップ | 一部整備済み |
| **SLA 定義** | 稼働率保証の数値 | 未定 |

これらが整備されれば「ISO 取得準備中」と胸を張って回答でき、実際に取得する際の工数も大幅に削減できる。
