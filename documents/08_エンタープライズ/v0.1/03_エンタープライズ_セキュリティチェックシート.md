# セキュリティチェックシート（想定問答）

大企業の導入審査で提出を求められるセキュリティチェックシートへの回答テンプレート。
各回答は現時点の仕様・設計に基づく。未定の項目は方針決定後に更新する。

**準備状況サマリ:**

| 状況 | 質問数 | 説明 |
|:--|:--|:--|
| 回答可能 | 約25問 | 既存ドキュメントから回答可能 |
| 要決定 | 約5問 | 方針だけ決めれば回答可能（SLA 数値等） |
| 未定 | 約8問 | 検討・整備が必要（脆弱性診断、プライバシーポリシー等） |
| 要確認 | 約2問 | 事実ベースの回答が必要（過去のインシデント実績等） |

**参照ドキュメント:**
- `01_エンタープライズ_仕様概要.md` — 仕様概要・決定事項
- `02_エンタープライズ_全体構成・アーキテクチャ.md` — 技術設計（認証、セッション管理、監査ログ、Storage パス設計）
- `03_エンタープライズ_セキュリティ対応_技術詳細.md` — 技術調査済みセキュリティ施策（SSO、IP制限、暗号化、物理分離）
- `03_エンタープライズ_セキュリティ対応_全項目一覧.md` — セキュリティ全項目のステータス管理


# 1. アクセス制御・認証

| # | 質問 | 回答 | 状況 |
|:--|:--|:--|:--|
| 1-1 | 認証方式は何か | 企業メールドメイン制限 + 6桁OTP（ワンタイムパスワード）。Phase 2 で SSO（SAML/OIDC）対応予定 | 回答可能 |
| 1-2 | 多要素認証（MFA）に対応しているか | MVP では OTP 認証のみ。Phase 2 で SMS / 認証アプリによる MFA に対応予定（Identity Platform） | 回答可能 |
| 1-3 | パスワードポリシーはあるか | パスワードレス認証（OTP）を採用しているため、パスワードポリシーは該当しない | 回答可能 |
| 1-4 | アカウントロックアウト機能はあるか | Phase 2 で対応予定（OTP を一定回数間違えたらアカウントをロック） | 要決定 |
| 1-5 | セッションタイムアウトはあるか | 60分無操作で自動ログアウト | 回答可能 |
| 1-6 | 同時ログインの制限はあるか | MVP では制限なし。Phase 2 で対応検討 | 要決定 |
| 1-7 | 管理者によるアカウント停止が即時反映されるか | `revokeRefreshTokens()` によりリフレッシュトークンを即時無効化。最大1時間以内にログアウトされる | 回答可能 |
| 1-8 | 権限管理の仕組みは | Firebase Auth の custom claims で `enterprise_role`（admin / member）を管理。Firestore Security Rules で制御 | 回答可能 |
| 1-9 | 退職者のアカウント削除プロセスは | 全社管理者がアカウント停止（`disableEnterpriseMember`）→ Firebase Auth ユーザー無効化 + セッション即時取消。**従業員による自己削除 UI は提供しない**（`04_認証` §6.3） | 回答可能 |
| 1-10 | SSO に対応しているか | Phase 2 で Identity Platform を使い SAML/OIDC に対応予定。Azure AD、Okta 等に接続可能 | 回答可能 |


# 2. データ保護・暗号化

| # | 質問 | 回答 | 状況 |
|:--|:--|:--|:--|
| 2-1 | 保存データは暗号化されているか | Firestore はすべてのデータを AES-256 で自動暗号化（Google 管理鍵）。追加設定不要 | 回答可能 |
| 2-2 | 暗号鍵の管理方式は | MVP: Google 管理鍵（自動ローテーション）。将来的に CMEK（Cloud KMS による自社管理鍵）へ移行可能 | 回答可能 |
| 2-3 | 通信は暗号化されているか | Firebase Hosting / Cloud Functions はデフォルトで TLS 1.2 以上。追加設定不要 | 回答可能 |
| 2-4 | 個人情報の暗号化は | MVP: Firestore のデフォルト暗号化。必要に応じてフィールドレベル暗号化（Tink + Cloud KMS）を導入可能 | 回答可能 |
| 2-5 | 暗号鍵のローテーションはしているか | Google 管理鍵は自動ローテーション。CMEK 導入後は手動/自動ローテーションを設定可能 | 回答可能 |

# 4. データ保管・管理

| # | 質問 | 回答 | 状況 |
|:--|:--|:--|:--|
| 4-1 | データの保管場所（リージョン）は | Google Cloud 東京リージョン（asia-northeast1）。日本国内に保管 | 回答可能 |
| 4-2 | データのバックアップ体制は | Firestore ポイントインタイムリカバリ（PITR: 7日間）。定期エクスポートの設定を予定 | 要設定確認 |
| 4-3 | データの復旧手順は | PITR により任意の時点にデータ復旧可能。手順書は要整備 | 要決定 |
| 4-4 | テナント間のデータ分離はどうしているか | `enterprise_id` による論理分離。Firestore Security Rules で `request.auth.token.enterprise_id == resource.data.enterprise_id` を強制し、他社データへのアクセスを防止 | 回答可能 |
| 4-5 | データの物理分離は可能か | 対応可能。`enterprise_id` でフィルタし、特定企業のみ別 Firebase Project に移行する手順を整備済み。ただし追加費用が発生 | 回答可能 |
| 4-6 | 契約終了時のデータ削除は | `enterprise_id` で全データを抽出・一括削除可能。Storage も `/enterprises/{enterpriseId}/` 以下に格納しており企業単位で削除可能 | 回答可能 |
| 4-7 | データの持ち出し（エクスポート）は可能か | Phase 2 で管理者画面からの CSV/JSON エクスポート機能を予定 | 要決定 |


# 5. ログ・監査

| # | 質問 | 回答 | 状況 |
|:--|:--|:--|:--|
| 5-1 | 操作ログ（監査ログ）は記録しているか | ログイン/ログアウト、管理者操作（アカウント作成・停止、コミュニティ承認・却下、割引設定変更）、注文/キャンセルを記録。Firestore + Cloud Logging に二重出力 | 回答可能 |
| 5-2 | ログの保持期間は | Firestore: 無期限（MVP）。Cloud Logging: デフォルト30日。Phase 2 で TTL / 長期保存設定を検討 | 回答可能 |
| 5-3 | ログの改ざん防止策は | クライアントからの直接書き込みは Security Rules で禁止（`allow write: if false`）。Cloud Functions（Admin SDK）からのみ書き込み可能 | 回答可能 |
| 5-4 | ログへのアクセス権限は | 全社管理者のみ閲覧可能。Security Rules で `enterprise_role == "admin"` を検証 | 回答可能 |
| 5-5 | 不正アクセスの検知は可能か | 監査ログで異常なログインパターンの確認が可能。自動アラートは Phase 2 で検討 | 要決定 |
