# ゲスト参加 詳細仕様

本ドキュメントは `01_仕様概要`、`02_全体構成・アーキテクチャ`、`04_割引・決済` の決定事項に基づき、ゲスト（プラットフォーム版ユーザー）がエンタープライズ版イベントに参加する際の機能仕様を詳細に定義する。


# 1. 概要

エンタープライズ版では、イベント作成時に「ゲストOK」を設定することで、就活生や外部パートナーなどのプラットフォーム版ユーザーがエンタープライズ版イベントに参加できる。ゲストはイベント単位でのみ参加し、コミュニティメンバーにはならない。

## 1.1 ゲストの定義

| 項目 | 内容 |
|:--|:--|
| 対象 | 就活生、外部パートナーなど、企業外の参加者 |
| 認証 | プラットフォーム版ユーザー（`user_type: "platform"` または未設定） |
| custom claims | `enterprise_id` を持たない |
| 参加単位 | **イベント単位のみ**（コミュニティメンバーにはしない） |
| イベントの members | 注文確定時にイベントの `members` には追加される（参加者として）。event-members トリガーにより自動更新 |
| コミュニティの members | **追加しない**。ゲスト self_pay は `handleEnterpriseStripeWebhook` が処理し、PF版の `addCommunityUser` は呼ばれない |

## 1.2 決定事項サマリ

| # | 論点 | 決定 |
|:--|:--|:--|
| G-1 | イベントの発見方法 | URL共有のみ（PF版トップには表示しない） |
| G-2 | アクセス先 | Enterprise アプリ（企業ドメイン） |
| G-3 | 未認証閲覧 | 認証不要で `allow_guest == true` のイベントを閲覧可能 |
| G-4 | ゲスト認証（注文時） | Enterprise アプリで PF版と同等（メールアドレス+OTP、SNS の両方） |
| G-5 | community_bill + allow_guest | 許可する |
| G-6 | guest_payment | free / self_pay 両方許容。allow_guest 時は必須、デフォルトは free |
| G-7 | ゲスト無料時の monthly_usage | 加算しない |
| G-8 | ゲスト無料時の決済 | Stripe スキップで直接注文確定 |
| G-9 | ゲスト無料時の請求 | 請求書に含め、企業が shokujii に支払う。Stripe は使わない |
| G-10 | ゲスト self_pay の Functions | event_payment に関係なく `createStripeCheckoutSession` に統一 |
| G-11 | 参加者一覧 | 「ゲスト」であることを明示する表示 |
| G-12 | Security Rules（イベント閲覧） | 認証不要で allow_guest イベントを読める |


# 2. 参加フロー

## 2.1 イベントの発見

| 項目 | 仕様 |
|:--|:--|
| 発見方法 | **URL共有のみ** |
| PF版トップ表示 | しない（エンプライベントは PF版のイベント一覧に表示しない） |
| 共有URL形式 | `{企業ドメイン}/c/{communityAccount}/e/{eventId}`（例: `company-a.shokujii.com/c/foo/e/bar`） |

主催者（従業員）がイベント詳細画面のURLをコピーし、ゲストに共有する。ゲストはそのURLを開いてイベントにアクセスする。

## 2.2 アクセス先

| 項目 | 仕様 |
|:--|:--|
| アプリ | **Enterprise アプリ**（企業ドメイン） |
| 理由 | 主催者が共有するURLはブラウザのURLをそのままコピーするため、企業ドメインのURLになる。企業ブランディング（ロゴ・テーマカラー）で「A社の食事会」と文脈が明確になる。 |

## 2.3 未認証閲覧

| 項目 | 仕様 |
|:--|:--|
| 閲覧 | `allow_guest == true` のイベントは**認証不要**で閲覧可能 |
| 対象 | イベント詳細（メニュー、日時、場所など） |
| 制限 | 注文・カート操作は認証必須 |

URLを知っていれば誰でもイベント内容を閲覧できる。注文する場合はログインが必要となる。

## 2.4 ゲスト認証（注文時）

ゲストが注文するには認証が必要。Enterprise アプリのログイン画面に「ゲストの方はこちら」を追加し、**PF版と同等の認証方式**（メールアドレス+OTP、SNS ログイン）のいずれかでサインインする。

### ログイン画面の構成

```
┌─────────────────────────────────────┐
│         [企業ロゴ]                    │
│                                      │
│  ─────── 従業員の方はこちら ───────   │
│  メールアドレス [______________]      │
│  ※ 企業メールドメインのみ             │
│  [ログイン]  ← OTP 認証               │
│                                      │
│  ─────── ゲストの方はこちら ───────   │
│  メールアドレス [______________]      │
│  [ログイン]  ← OTP 認証（PF版と同様）  │
│  [Googleでログイン] [Appleでログイン]  │
└─────────────────────────────────────┘
```

ゲスト向けのメールアドレス+OTP は PF版と同じく**メールドメイン制限なし**。SNS ログインも PF版と同様に利用可能。

**認証 Functions の扱い:** ゲスト向けは PF版の `requestEmailLogin` / `confirmEmailLogin` を流用する。custom claims は設定せず、通常の Firebase Auth でログインする。

### 認証後の扱い

| ユーザー種別 | custom claims | アクセス範囲 |
|:--|:--|:--|
| 従業員 | `enterprise_id` あり | 全機能（コミュニティ、イベント、注文など） |
| ゲスト | `enterprise_id` なし | `allow_guest == true` のイベントのみ（閲覧・注文） |

### ナビゲーションガード

- `enterprise_id` を持たないユーザーが `allow_guest` 以外のページにアクセスした場合 → ログイン画面またはエラー表示
- ゲストは `allow_guest == true` のイベント詳細・注文フローにのみ遷移可能


# 3. event_payment と guest_payment の組み合わせ

## 3.1 全組み合わせ

| event_payment | 従業員の支払い | allow_guest | guest_payment | ゲストの支払い | 成立 |
|:--|:--|:--|:--|:--|:--|
| enterprise_subsidy | 割引後クレカ | true | free | 0円（企業負担） | ✓ |
| enterprise_subsidy | 割引後クレカ | true | self_pay | 全額クレカ | ✓ |
| user_advance | 全額クレカ | true | free | 0円（企業負担） | ✓ |
| user_advance | 全額クレカ | true | self_pay | 全額クレカ | ✓ |
| community_bill | 0円（請求書） | true | free | 0円（企業負担） | ✓ |
| community_bill | 0円（請求書） | true | self_pay | 全額クレカ | ✓ |

**すべての event_payment で allow_guest = true を許可する。** community_bill のイベントでもゲスト参加は可能である。

## 3.2 guest_payment の扱い

| 項目 | 仕様 |
|:--|:--|
| 選択肢 | `free`（無料参加・企業負担）/ `self_pay`（自己負担・全額クレカ） |
| 必須条件 | `allow_guest == true` のとき **必須** |
| デフォルト値 | `free` |
| バリデーション | allow_guest を true にしたら、guest_payment を必ず選択させる |

# 5. 注文・決済フロー

## 5.1 カート追加（addOrder の流用・拡張）

メニュー選択・カート追加は PF版の `addOrder` を流用する。ゲストがエンプライベントに注文する場合、注文Doc に以下をセットする必要がある。

| フィールド | 設定タイミング |
|:--|:--|
| enterprise_id | イベントに enterprise_id がある場合、addOrder または注文確定時にセット |
| is_guest_order | 注文確定時（confirmGuestOrderFree / createStripeCheckoutSession 呼び出し時）に判定。custom claims に enterprise_id がないユーザー = ゲスト |

addOrder の拡張として、イベントに `enterprise_id` がある場合は注文Doc に `enterprise_id` をセットする。

## 5.2 フロー分岐の全体像

| 参加者 | guest_payment | 呼び出す Function | 決済 |
|:--|:--|:--|:--|
| ゲスト | free | `confirmGuestOrderFree`（新規） | Stripe スキップで直接確定 |
| ゲスト | self_pay | `createStripeCheckoutSession`（PF版） | Stripe 決済 |
| 従業員 | — | `createEnterpriseCheckout` または PF版既存 | 割引・決済仕様に従う |

## 5.3 ゲスト無料参加（guest_payment == 'free'）

### confirmGuestOrderFree のリクエスト

```typescript
interface ConfirmGuestOrderFreeRequest {
  community_id: string
  event_id: string
  order_id: string
}
```

### 処理フロー（事前条件）

- 認証チェック: 認証済みであること
- ゲスト判定: custom claims に `enterprise_id` がないこと（従業員の誤呼び出しを防ぐ）
- 注文Doc: status が 'in_cart' であること。user_id が一致すること
- イベントDoc: allow_guest == true, guest_payment == 'free' であること
- 注文期限・定員チェック: PF版と同様

### 処理フロー

```
[フロントエンド]                      [Functions]
   │                                    │
   │  1. メニュー選択・カート追加        │
   │     （addOrder を流用）             │
   │                                    │
   │  2. 注文確認画面                   │
   │     「全額会社負担」を表示         │
   │                                    │
   │  3. confirmGuestOrderFree          │
   │ ──────────────────────────────────>│
   │                                    │  4. 注文Doc更新
   │                                    │     status → ordered
   │                                    │     ordered_at をセット
   │                                    │     enterprise_id（イベントから取得）
   │                                    │     is_guest_order = true
   │                                    │     discount_amount = 0
   │                                    │     user_paid_amount = 0
   │                                    │  5. monthly_usage は加算しない
   │                                    │  6. 監査ログ記録（action: 'guest_order_create'）
   │                                    │  7. success_url = getEnterpriseUrl(enterpriseId)
   │  8. 完了画面にリダイレクト         │
   │<──────────────────────────────────│
```

### enterprise_id の取得

success_url は `getEnterpriseUrl(enterpriseId)` で生成する。ゲストは custom claims に `enterprise_id` を持たないため、**イベントDocから `enterprise_id` を取得**する。

### レスポンス

```typescript
interface ConfirmGuestOrderFreeResponse {
  success_url: string   // 完了画面の URL
}
```

- Stripe は使用しない
- `monthly_usage` は加算しない（ゲストは EnterpriseMember ではないため）
- 企業負担分は後から請求書で回収する

## 5.4 ゲスト自己負担（guest_payment == 'self_pay'）

**event_payment に関係なく**、PF版の `createStripeCheckoutSession` に統一する。

```
[フロントエンド]                      [Functions]                    [Stripe]
   │                                    │                              │
   │  1. メニュー選択・カート追加        │                              │
   │  2. 注文確認画面                   │                              │
   │     「全額自己負担」を表示         │                              │
   │                                    │                              │
   │  3. createStripeCheckoutSession    │                              │
   │     （order に enterprise_id,      │                              │
   │      is_guest_order を含める）     │                              │
   │ ──────────────────────────────────>│                              │
   │                                    │  4. metadata に enterpriseId, │
   │                                    │     isGuestOrder を追加      │
   │                                    │  5. success_url を           │
   │                                    │     getEnterpriseUrl に      │
   │                                    │  6. Stripe Checkout 作成     │
   │                                    │ ─────────────────────────────>│
   │  7. Stripe Checkout ページへ       │<─────────────────────────────│
   │<──────────────────────────────────│                              │
   │                                    │                              │
   │  8. ユーザーが決済                 │                              │
   │ ─────────────────────────────────────────────────────────────────>│
   │                                    │  9. Webhook 受信             │
   │                                    │<─────────────────────────────│
   │                                    │  10. metadata.isGuestOrder   │
   │                                    │      → monthly_usage スキップ │
   │                                    │  11. 注文確定、監査ログ       │
```

### createStripeCheckoutSession の拡張

PF版の `createStripeCheckoutSession` を拡張し、エンプラ・ゲスト注文に対応する。

| 条件 | 追加処理 |
|:--|:--|
| イベントに enterprise_id あり | metadata に `enterpriseId` を追加。`isGuestOrder` は custom claims に enterprise_id がない場合に true |
| イベントに enterprise_id あり | success_url を `getEnterpriseUrl(enterpriseId)` に変更 |

フロントエンドは order に `enterprise_id` を含めて渡すか、Functions 側でイベントから `enterprise_id` を取得する。

### Webhook のルーティング

metadata に `enterpriseId` がある Checkout Session は `handleEnterpriseStripeWebhook` が処理する。`isGuestOrder` がある場合は `monthly_usage` の加算をスキップする。

## 5.5 注文Docのフィールド（ゲストの場合）

| フィールド | ゲスト free | ゲスト self_pay |
|:--|:--|:--|
| enterprise_id | セット | セット |
| is_guest_order | true | true |
| discount_amount | 0 | 0 |
| user_paid_amount | 0 | total_amount |
| ordered_at | セット（確定時） | セット（Webhook 到着時） |


# 6. 割引・決済との関係

## 6.1 monthly_usage

| ケース | monthly_usage |
|:--|:--|
| ゲスト無料参加 | **加算しない** |
| ゲスト self_pay | **加算しない** |

ゲストは EnterpriseMember ではないため、`monthly_usage` には一切加算しない。

## 6.2 キャンセル時

ゲストのキャンセルは **cancelEnterpriseOrder は使用しない**（custom claims に `enterprise_id` を持たないため）。PF版の Functions を使用する。

| ケース | 呼び出す Function | 処理内容 |
|:--|:--|:--|
| ゲスト無料参加のキャンセル | `updateOrderStatus`（PF版） | status を 'canceled' に変更。Stripe 返金なし。`monthly_usage` の戻しは不要 |
| ゲスト self_pay のキャンセル | `stripe_refunds`（PF版）+ `updateOrderStatus`（PF版） | PF版と同様に Stripe Refund を実行後、status を 'canceled' に変更 |


# 7. 無料参加時の課金・請求

## 7.1 決定事項

| 項目 | 仕様 |
|:--|:--|
| ゲスト無料参加分の扱い | 企業の福利厚生費として**請求書に含める** |
| 支払いフロー | 企業が **shokujii に請求書払い**で支払う |
| Stripe の利用 | ゲスト無料参加分については **Stripe は使わない** |
| 請求タイミング | **後から企業に請求書を発行**する |

## 7.2 他パターンとの関係

| ケース | Stripe | 請求書 |
|:--|:--|:--|
| 従業員（enterprise_subsidy 自己負担分） | shokujii の Stripe で即時決済 | 割引分のみ請求書に含む |
| 従業員（community_bill） | 使わない | 請求書に含む |
| ゲスト無料参加 | **使わない** | **請求書に含む** |
| ゲスト self_pay | shokujii の Stripe で即時決済 | 含まない |


# 8. Security Rules

## 8.1 イベントの読み取り

`allow_guest == true` のイベントは**認証不要**で読み取り可能とする。

```javascript
// events の読み取りルール
match /communities/{communityId}/events/{eventId} {
  allow read: if resource.data.allow_guest == true
              || (request.auth != null && resource.data.enterprise_id == request.auth.token.enterprise_id)
              || (resource.data.enterprise_id == null);  // PF版コミュニティ
  // write は既存ルールに従う
}
```

- 未認証（`request.auth` が null）でも、`allow_guest == true` のイベントは読める
- 認証済みの従業員は `enterprise_id` が一致するイベントを読める
- PF版コミュニティ（`enterprise_id` が null）は既存ルールのまま

## 8.2 未認証閲覧時のデータ取得

未認証でイベント詳細を表示する場合、`/c/{communityAccount}/e/{eventId}` のようなルートでは、`collectionGroup('events')` で `community_account` と `event_id` を指定してイベントを直接取得する方式を推奨する。これにより、community ドキュメントの読み取りルールを緩和せずに済む。

## 8.3 注文のアクセス

ゲストが自分の注文のみ read/write できるようにする。詳細は Firestore Rules 設計時に `04_割引・決済` の Security Rules と整合させる。

# 11. メール配信

ゲストへの注文確認メール・リマインダーは `04_メール配信` で定義する。基本的に PF版と同じ内容・送信条件とするが、エンプライベントである旨をメールに含めるかは要検討。
