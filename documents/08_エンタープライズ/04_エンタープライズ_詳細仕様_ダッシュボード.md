# ダッシュボード 詳細仕様

本ドキュメントは `01_仕様概要`、`02_全体構成・アーキテクチャ`、`04_割引・決済`、`04_全社管理者画面` の決定事項に基づき、全社管理者向けダッシュボードの機能仕様を詳細に定義する。


# 1. 概要

## 1.1 位置づけ

- 全社管理者画面のトップページ（`/admin`）として実装
- 対象ロール: `enterprise_role == "admin"` のユーザーのみ
- 月別集計とメンバー別集計の2セクションで構成

## 1.2 決定事項サマリ

| # | 論点 | 決定 |
|:--|:--|:--|
| D-1 | 「利用金額」の定義 | 注文合計額・企業負担額・自己負担額の3つ全てを表示 |
| D-2 | user_advance / community_bill の扱い | 月別・メンバー別集計に含める |
| D-3 | ゲスト注文の扱い | 利用人数・利用回数に含めない（EnterpriseMember のみ） |
| D-4 | メンバー別 CSV の期間 | 期間指定（開始月・終了月） |
| D-5 | MVP のグラフ | 棒グラフ + テーブル |
| D-6 | 集計実行場所 | Cloud Functions |
| D-7 | 期間のデフォルト | 直近12ヶ月（月別・メンバー別・CSV で統一） |
| D-8 | メンバー一覧の表示条件 | 対象期間に注文が1件以上あるメンバーのみ（画面・CSV で統一） |


# 2. 集計ロジック

## 2.1 データソース

MVP では **ハイブリッド方式** を採用する。D-2（user_advance / community_bill を含める）を満たすため、利用回数・利用人数も orders から集計する。

| 集計項目 | データソース | 理由 |
|:--|:--|:--|
| 利用回数・利用人数・注文合計額・自己負担額 | orders コレクション | 全支払い方式を含む。同一データソースで一貫性を確保 |
| 企業負担額（割引） | EnterpriseMember の `monthly_usage` | enterprise_subsidy のみ（他は 0）。決済完了時にリアルタイム更新済み |

### データソースの選択肢（参考）

| 方式 | データソース | メリット | デメリット |
|:--|:--|:--|:--|
| EnterpriseMember のみ | `monthly_usage`, `monthly_order_count` | 軽量・高速 | enterprise_subsidy のみ。user_advance / community_bill が含まれない |
| orders のみ | 後述の Collection Group クエリ | 全項目を正確に集計可能 | 企業内全 orders のスキャンが必要 |
| monthly_usage コレクション | `/enterprises/{id}/monthly_usage/{yearMonth}` | 月別集計が高速 | **Phase 2**。MVP では未実装 |

### orders のクエリ方法

orders は `communities/{communityId}/events/{eventId}/orders/{orderId}` のサブコレクションのため、**Firestore Collection Group クエリ** を使用する。

```
collectionGroup('orders')
  .where('enterprise_id', '==', enterpriseId)
  .where('status', '==', 'ordered')
```

- `enterprise_id` に対する複合インデックスを Firestore に設定する
- イベント開催月で絞る場合: orders 取得後、各 order の `event_id` から events を参照し、`event_start_datetime` の年月でフィルタする（`04_割引・決済` と同様に、orders に `event_month` は持たせない方針）

## 2.2 集計タイミング

| 項目 | タイミング |
|:--|:--|
| EnterpriseMember の更新 | 決済完了時（Webhook or 直接確定時）にリアルタイム更新（`04_割引・決済` で定義済み） |
| ダッシュボード表示 | 画面表示時に Functions を呼び出し、集計結果を取得 |
| monthly_usage コレクション | Phase 2 で Scheduled Function による月初バッチ更新を検討 |

## 2.3 集計対象の注文

| 条件 | 含める |
|:--|:--|
| 支払い方式 | `enterprise_subsidy`, `user_advance`, `community_bill` すべて |
| ステータス | `ordered` のみ（`in_cart`, `canceled` は除外） |
| ゲスト注文 | 含めない（EnterpriseMember に紐づく注文のみ） |

ゲスト注文は `monthly_usage` に加算されないため、利用回数・利用人数・企業負担額には自動的に含まれない。注文合計額・自己負担額の集計時も `is_guest_order == true` の注文は除外する。

### user_advance / community_bill の注文フィールド

`04_割引・決済` では、user_advance / community_bill の注文には `discount_amount` と `user_paid_amount` をセットしないと定義されている。集計時の扱い:

| 支払い方式 | discount_amount | user_paid_amount | 注文合計額 | 自己負担額 |
|:--|:--|:--|:--|:--|
| enterprise_subsidy | 設定あり | 設定あり | menus の合計 | `user_paid_amount` の値 |
| user_advance | 未設定（0扱い） | 未設定 | menus の合計 | 未設定時は注文合計額と同額 |
| community_bill | 未設定（0扱い） | 未設定 | menus の合計 | 0（参加者負担なし） |


# 3. 表示項目

## 3.1 月別集計

| 項目 | 定義 | データソース |
|:--|:--|:--|
| 利用回数 | 注文数（ordered） | orders から集計 |
| 利用人数 | ユニークユーザー数 | orders から集計（user_id のユニーク数） |
| 注文合計額（税込） | 割引前の税込合計 | orders から集計 |
| 企業負担額（割引） | 割引適用額の合計 | EnterpriseMember の `monthly_usage` 合計 |
| 自己負担額 | ユーザー支払額の合計 | orders から集計 |

### 月の定義

イベント開催月（`event.event_start_datetime` の年月）に紐づける。`04_割引・決済` の月額利用実績と同一のルール。

## 3.2 メンバー別集計

| 項目 | 定義 | データソース |
|:--|:--|:--|
| 利用回数 | 注文数 | orders から集計（対象期間の合計） |
| 注文合計額（税込） | 割引前の税込合計 | orders から集計 |
| 企業負担額（割引） | 割引適用額の合計 | `monthly_usage`（対象期間の合計） |
| 自己負担額 | ユーザー支払額の合計 | orders から集計 |

メンバー一覧は**対象期間に注文が1件以上あるメンバーのみ**表示する。画面表示と CSV 出力で同一の条件とする。

## 3.3 グラフの種類

| 用途 | グラフ | 備考 |
|:--|:--|:--|
| 月別トレンド | 棒グラフ | 月ごとの利用回数・金額の推移 |
| 月別内訳 | 積み上げ棒グラフ | 企業負担 vs 自己負担の比率（Phase 2 で検討） |
| メンバー別 | テーブル | 一覧表示。上位 N 名のランキング表示は Phase 2 で検討 |

MVP では棒グラフ（月別）+ テーブル（月別・メンバー別）を実装する。棒グラフは**利用回数**と**注文合計額**の2系列を表示する（タブまたは切り替えで選択可能）。


# 4. CSV 出力

## 4.1 フォーマット

| 項目 | 仕様 |
|:--|:--|
| 文字コード | UTF-8（BOM 付き） |
| 区切り文字 | カンマ |
| 囲み文字 | ダブルクォート（フィールド内にカンマ・改行・クォートがある場合） |
| ヘッダー | 日本語 |

`base/src/utils/downloadCsv.ts` と同様に BOM 付き UTF-8 で出力し、Windows 環境での文字化けを防ぐ。

## 4.2 月別 CSV

### 出力項目

| 日本語ヘッダー | 英フィールド | 説明 |
|:--|:--|:--|
| 年月 | year_month | YYYY-MM |
| 利用回数 | order_count | 注文数 |
| 利用人数 | unique_users | ユニークユーザー数 |
| 注文合計額（税込） | total_amount | 割引前の合計（円） |
| 企業負担額（割引） | discount_amount | 割引適用額の合計（円） |
| 自己負担額 | user_paid_amount | ユーザー支払額の合計（円） |

### 期間指定

画面上で選択した期間（開始月・終了月）をそのまま出力する。期間未選択時は直近12ヶ月をデフォルトとする。

### ファイル名

`dashboard_monthly_YYYYMMDD_HHmmss.csv`（ダウンロード日時を含む。例: `dashboard_monthly_20260311_143052.csv`）

## 4.3 メンバー別 CSV

### 出力項目

| 日本語ヘッダー | 英フィールド | 説明 |
|:--|:--|:--|
| 表示名 | display_name | EnterpriseMember.display_name |
| メールアドレス | email | users_personal_information.user_email |
| 部署 | department | EnterpriseMember.department |
| 利用回数 | order_count | 対象期間の注文数 |
| 注文合計額（税込） | total_amount | 割引前の合計（円） |
| 企業負担額（割引） | discount_amount | 割引適用額の合計（円） |
| 自己負担額 | user_paid_amount | ユーザー支払額の合計（円） |

### 期間指定

開始月・終了月を指定してダウンロードする。指定しない場合は直近12ヶ月をデフォルトとする。

### ファイル名

`dashboard_members_YYYYMM_YYYYMM_YYYYMMDD_HHmmss.csv`（期間 + ダウンロード日時。例: `dashboard_members_202401_202412_20260311_143052.csv`）


# 5. パフォーマンス・実装方針

## 5.1 集計の実行場所

`01_仕様概要` の技術方針に従い、**集計は Cloud Functions で行う**。フロントエンドからの直接集計は行わない。

### 理由

| 観点 | Functions | フロント |
|:--|:--|:--|
| データ量 | 企業内全 orders をスキャン可能 | クライアントに大量データを送るのは非現実的 |
| セキュリティ | enterprise_id でテナント分離を厳密に制御 | クライアントに生データを渡すリスク |
| 読み取りコスト | サーバー側で制御可能 | クライアント数 × 読み取り回数で増加 |
| キャッシュ | 集計結果のキャッシュが可能（Phase 2） | 難しい |

## 5.2 API 設計

### 認証・検証

- 呼び出し元は認証済みユーザーであること（Firebase Auth）
- `request.auth.token.enterprise_id` とパラメータの `enterpriseId` を照合し、**一致しない場合はエラー**とする
- または、`enterpriseId` をパラメータで受け取らず、`request.auth.token.enterprise_id` のみを使用する方式も可（クライアント改ざんのリスクを排除）

### getDashboardMonthlyData

| 項目 | 内容 |
|:--|:--|
| 種別 | onCall |
| パラメータ | `enterpriseId`, `startYearMonth`, `endYearMonth` |
| 戻り値 | 月別集計の配列 |

### getDashboardMemberData

| 項目 | 内容 |
|:--|:--|
| 種別 | onCall |
| パラメータ | `enterpriseId`, `startYearMonth`, `endYearMonth` |
| 戻り値 | メンバー別集計の配列 |

### getDashboardCsvMonthly / getDashboardCsvMembers

CSV 用の集計データを返す。フロントエンドで `downloadCsv` を呼び出してダウンロードする。または、Functions で CSV 文字列を生成して返す方式も検討可能。

## 5.3 負荷対策

| 規模 | 対策 |
|:--|:--|
| EnterpriseMember | 100〜300人規模。全件取得は問題なし |
| orders | `enterprise_id` インデックス + 期間絞りでクエリ最適化 |
| Phase 2 | `monthly_usage` コレクションを導入し、月別集計を事前計算に移行 |


# 6. 画面構成

## 6.1 レイアウト

```
/admin (ダッシュボード)
├── 月別集計セクション
│   ├── 期間選択（開始月・終了月、デフォルト: 直近12ヶ月）
│   ├── 棒グラフ（利用回数 / 注文合計額を切り替え表示）
│   ├── テーブル（月別一覧）
│   └── CSV ダウンロードボタン
└── メンバー別集計セクション
    ├── 期間選択（開始月・終了月、デフォルト: 直近12ヶ月）
    ├── テーブル（メンバー一覧、注文1件以上のメンバーのみ）
    └── CSV ダウンロードボタン
```

### 期間のデフォルト

月別集計・メンバー別集計・CSV 出力のいずれも、期間未指定時は**直近12ヶ月**をデフォルトとする。

## 6.2 他ドキュメントとの整合

- **02_全体構成:** `monthly_usage` コレクションは Phase 2 のまま。MVP では使用しない
- **04_割引・決済:** EnterpriseMember の `monthly_usage` / `monthly_order_count` の更新タイミングは既存仕様どおり。user_advance / community_bill の注文フィールドは本ドキュメント 2.3 で定義
- **04_ゲスト参加:** ゲスト注文（`is_guest_order == true`）は集計対象外。D-3 で決定
- **04_全社管理者画面:** ダッシュボードは本ドキュメントで詳細化
