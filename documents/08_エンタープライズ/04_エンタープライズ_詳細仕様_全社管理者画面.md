# 全社管理者画面 詳細仕様

本ドキュメントは `01_仕様概要`、`02_全体構成・アーキテクチャ`、および `04_認証・アカウント管理` の決定事項に基づき、全社管理者画面の機能仕様を詳細に定義する。

**注意:** アカウント管理（CSV一括作成、停止・復活、ロール変更）の Functions・処理フローは `04_認証・アカウント管理` に定義済み。本ドキュメントでは画面UI・操作フローを中心に記載する。割引設定・ダッシュボードは別仕様書で詳細化する。

## 前提とする仕様書

本ドキュメントは EventMemberOrder 設計（`05_EventOrder→EventMemberOrder.md`）を前提とする。注文集計の参照先は `members/{userId}/member_orders/{orderId}` および `stripes/{stripeId}` となる。


# 1. 概要

## 1.1 全社管理者画面の位置づけ

- `enterprise` パッケージ内の `/admin/*` ルートとして実装
- 一般従業員画面と同一パッケージに含め、ナビゲーションガードでアクセス制御
- 対象ロール: `enterprise_role == "admin"` のユーザーのみ

## 1.2 決定事項サマリ

| # | 論点 | 決定 |
|:--|:--|:--|
| 1-1 | テーマカラー設定 | MVPでは管理者による編集不可。Firestoreフィールドのみ設け、運営が設定 |
| 1-4 | allowed_email_domains の編集 | MVPでは設定不可。運営がFirestoreに設定 |
| 2-1 | メンバー一覧のページネーション | ページ番号方式（1ページ50件） |
| 2-2 | メンバーの個別追加 | できる |
| 2-3 | メンバーの削除 | MVPでは不可。停止のみ |
| 2-4 | メンバー情報の編集 | 管理者が表示名・部署を変更可能 |
| 3-2 | コミュニティ承認フロー | **Phase 2**（MVP: **作成は全従業員可**、**更新は manager 限定**。補足 E 参照） |
| 3-3 | 却下理由の入力 | Phase 2（承認フロー導入時） |
| 3-4 | 却下後の再申請 | Phase 2 |
| 3-5 | 管理者による直接作成 | MVP: CSV 一括作成（`createEnterpriseCommunities`）。承認フローは Phase 2 |
| 4-2 | コミュニティ一括作成の初期メンバー | manager のみ指定 |
| 5-6 | 監査ログの CSV エクスポート | MVPでは不要。Phase 2 |

## 2.3 ナビゲーションガード

| ガード条件 | 対象 | 動作 |
|:--|:--|:--|
| 未認証 | `/admin/*` 全体 | `/login` にリダイレクト |
| `enterprise_role != "admin"` | `/admin/*` 全体 | `/`（トップページ）にリダイレクト + 「管理者権限が必要です」トースト表示 |

### 実装イメージ

```typescript
router.beforeEach(async (to) => {
  if (!to.path.startsWith('/admin')) return

  const user = getAuth().currentUser
  if (!user) return { path: '/login' }

  const tokenResult = await user.getIdTokenResult()
  if (tokenResult.claims.enterprise_role !== 'admin') {
    notification.show('管理者権限が必要です', 'error')
    return { path: '/' }
  }
})
```

# 3. 全社設定画面

## 3.1 画面仕様: /admin/settings

会社の基本情報を表示・編集する画面。MVPでは一部フィールドは表示のみ（運営が設定）。

### 画面構成

| セクション | フィールド | 編集 | 説明 |
|:--|:--|:--|:--|
| **基本情報** | 会社名 | 可 | テキスト入力。空文字不可 |
| | 企業ロゴ | 可 | 画像アップロード。2MB以下、PNG/JPG/SVG。推奨 200x200px |
| **外観設定** | テーマカラー | 表示のみ | 現在のテーマカラーを色見本で表示。「変更する場合はお問い合わせください」 |
| **ドメイン設定** | サブドメイン | 表示のみ | 例: company-a.shokujii.com |
| | カスタムドメイン | 表示のみ | 設定されている場合のみ表示 |
| **認証設定** | 許可メールドメイン | 表示のみ | 例: company-a.com, company-a.co.jp |
| **支払い設定** | デフォルト支払い方式 | 表示のみ | 「福利厚生割引」（enterprise_subsidy）。イベント作成時に他の方式も選択可能 |

> **企業作成・初代 admin**: MVP では運営が `createEnterprise` Callable を実行して企業と初代 admin を一括作成する（`04_オンボーディング` 参照）。企業作成 UI は Phase 2。

### バリデーション

| フィールド | ルール |
|:--|:--|
| 会社名 | 必須。1〜100文字 |
| 企業ロゴ | 2MB以下。PNG / JPG / SVG のみ。アップロード時にプレビュー表示 |

### 保存処理

- **すべて Callable `updateEnterpriseSettings` 経由**（クライアントから `/enterprises` への直接 write は禁止。`02` §5.2 参照）
- 会社名: `updateEnterpriseSettings({ company_name })`
- 企業ロゴ: Storage `/enterprises/{enterpriseId}/logo/company-logo.png` にアップロード → 取得 URL を `updateEnterpriseSettings({ company_logo_url })` で反映
- 保存成功時: 「設定を保存しました」トースト表示
- 監査ログ: `updateEnterpriseSettings` 内で変更前後の値を `details` に記録（action: `settings_update`）

## 3.2 ロゴアップロードの仕様

```
1. ファイル選択
2. フロントエンドでバリデーション（サイズ、形式）
3. プレビュー表示（ログイン画面での見え方を模擬）
4. 「保存」ボタン押下
5. Storage にアップロード → download URL を取得
6. updateEnterpriseSettings で company_logo_url を更新（監査ログ記録）
```

## 3.3 Phase 2 での拡張

- テーマカラーをプリセットから選択可能にする
- allowed_email_domains の管理者による編集
- セッションタイムアウト時間のカスタマイズ


# 4. アカウント管理画面

## 4.1 画面仕様: /admin/members

メンバー一覧を表示し、停止・復活・ロール変更・個別追加を行う。

### 一覧テーブル

| カラム | 内容 | ソート |
|:--|:--|:--|
| 表示名 | display_name | 可 |
| メールアドレス | `getEnterpriseMembers` レスポンスの `email` | 不可 |
| 部署 | department | 可 |
| ロール | admin / member | 可 |
| ステータス | 有効 / 停止 | 可 |
| 当月利用額 | `monthly_usage[現在月]`（円表示。辞書方式。詳細は `04_割引・決済` 3.2） | 可 |
| 作成日 | created_at | 可 |
| アクション | 停止/復活、ロール変更、編集ボタン | - |

### データ取得

- メンバー一覧は Callable `getEnterpriseMembers`（admin 限定）を呼び出す（`04_認証・アカウント管理` §9.1 参照）
- `/users_personal_information` への Firestore 直接 read は行わない

### ページネーション

- **ページ番号方式**: 1ページ50件
- Firestore のカーソルベース（`startAfter` + `limit`）で実装
- 「全 XX 件中 1〜50 件を表示」の総件数表示

### 検索・フィルタ

| フィルタ | 種類 | 説明 |
|:--|:--|:--|
| テキスト検索 | テキスト入力 | 表示名前方一致 + メール部分一致（`getEnterpriseMembers` の `search` パラメータ） |
| ロール | セレクトボックス | 全て / admin / member（API の `role` パラメータ） |
| ステータス | セレクトボックス | 全て / 有効 / 停止（API の `is_active` パラメータ） |

検索・フィルタ・ソートはすべて `getEnterpriseMembers` 経由。クライアント側での追加フィルタは行わない。

### アクション

| 操作 | 対象 | 確認ダイアログ | Functions |
|:--|:--|:--|:--|
| 停止 | 有効なメンバー | あり（「このアカウントを停止しますか？」） | disableEnterpriseMember |
| 復活 | 停止中メンバー | あり（「このアカウントを復活しますか？」） | enableEnterpriseMember |
| ロール変更 | 全メンバー | あり（「ロールを admin / member に変更しますか？」） | updateEnterpriseRole |
| 編集 | 全メンバー | なし（編集ダイアログを表示） | updateEnterpriseMember |

## 4.2 メンバー個別追加

CSV一括作成とは別に、1人ずつメンバーを追加できる。

### UIフロー

```
1. 「メンバーを追加」ボタン押下
2. ダイアログ表示
   - メールアドレス（必須）
   - 表示名（必須）
   - 部署（任意）
   - ロール（admin / member、デフォルト: member）
3. バリデーション（メール形式、ドメインチェック、重複チェック）
4. 「追加」ボタン押下
5. Functions: createEnterpriseMember（単一メンバー作成）
6. 成功 → 一覧に追加 + トースト表示
```

### Functions: createEnterpriseMember

`createEnterpriseMembers`（複数形）の単一版。内部的には同じロジックで `members` 配列の要素が1件のケース。

## 4.3 メンバー情報編集

### 編集可能フィールド

| フィールド | 編集可能 |
|:--|:--|
| display_name | 可 |
| department | 可 |
| email | 不可（変更する場合はアカウント停止→新規作成） |
| role | ロール変更アクションで対応 |

### UIフロー

```
1. 一覧のアクションから「編集」ボタン押下
2. ダイアログ表示（表示名、部署を入力）
3. 「保存」ボタン押下
4. Callable `updateEnterpriseMember` を呼び出す（Functions が Admin SDK で
   /enterprises/{enterpriseId}/members/{userId} を更新し、/users/{userId} の display_name を同期）
   ※ Security Rules では EnterpriseMember に対し allow write: if false（02_全体構成 5.2）。
     クライアントからの Firestore 直接更新は行わない。
5. 監査ログは `updateEnterpriseMember` 内で記録（action: 'member_update'）
```

## 4.4 画面仕様: /admin/members/import

CSV一括作成画面。詳細な処理フロー・CSVフォーマット・エラーハンドリングは `04_認証・アカウント管理` を参照。

### 画面構成

| 要素 | 仕様 |
|:--|:--|
| CSVフォーマット説明 | email, display_name, department, role の説明を表示 |
| CSVテンプレートダウンロード | 空のCSVテンプレートファイルをダウンロード |
| ファイルアップロード | .csv ファイルのみ受付。ドラッグ&ドロップ対応 |
| プレビューテーブル | アップロード後、パース結果をテーブルで表示。エラー行を赤ハイライト |
| エラー詳細 | エラー行ごとにエラーメッセージを表示 |
| 実行ボタン | プレビュー確認後に一括作成を実行。エラー行がある場合も実行可能（スキップされる旨を表示） |
| 結果表示 | 実行後、行ごとの成功/失敗をテーブルで表示 |

# 6. コミュニティ一括作成（CSV）

## 6.1 画面仕様: /admin/communities/import

管理者がCSVで事業部ごとのコミュニティを一括作成する。

### CSV フォーマット

```csv
community_name,community_account,description,manager_email
開発部ランチ会,dev-lunch,開発部の毎週ランチ会です,tanaka@company-a.com
営業部ランチ会,sales-lunch,営業部の定例ランチ,suzuki@company-a.com
```

| 列 | 必須 | 説明 | バリデーション |
|:--|:--|:--|:--|
| community_name | 必須 | コミュニティ名 | 空文字不可。1〜100文字 |
| community_account | 必須 | アカウント名（URL用） | 半角英数字 + ハイフン。重複不可 |
| description | 任意 | コミュニティ説明文 | |
| manager_email | 必須 | 管理者のメールアドレス | `/enterprises/{id}/members` に存在する必要がある |

### 処理フロー

```
1. CSV アップロード → パース → プレビュー表示
2. バリデーション
   a. community_name が空でないか
   b. community_account が半角英数字 + ハイフンか
   c. community_account が既存コミュニティと重複しないか
   d. manager_email が企業メンバーに存在するか
   e. 同一CSV内での community_account 重複チェック
3. エラー行はスキップ（アカウント管理と同じ方式）
4. コミュニティ作成（`enterprise_id` をセット。`approval_status` はセットしない — MVP）
5. manager を community の managers に設定
6. 監査ログ記録
```

### Functions: createEnterpriseCommunities

```typescript
interface CreateEnterpriseCommunitiesRequest {
  enterprise_id: string
  communities: {
    community_name: string
    community_account: string
    description?: string
    manager_email: string
  }[]
}

interface CreateEnterpriseCommunitiesResponse {
  total: number
  success_count: number
  error_count: number
  results: {
    row: number
    community_name: string
    status: 'success' | 'error'
    error_message?: string
  }[]
}
```

### 画面構成

アカウント一括作成画面（/admin/members/import）と同じパターン:
- CSVフォーマット説明 + テンプレートダウンロード
- ファイルアップロード（ドラッグ&ドロップ対応）
- プレビューテーブル（エラー行ハイライト）
- 実行ボタン → 結果表示

企業内の操作ログを時系列で一覧表示する。

### 一覧テーブル

### アクション種別の日本語ラベル

| action | ラベル |
|:--|:--|
| login | ログイン |
| logout | ログアウト |
| session_timeout | セッションタイムアウト |
| account_create | アカウント作成 |
| account_disable | アカウント停止 |
| account_enable | アカウント復活 |
| member_update | メンバー情報更新 |
| role_change | ロール変更 |
| community_approve | コミュニティ承認 |
| community_reject | コミュニティ却下 |
| community_create | コミュニティ作成 |
| discount_update | 補助設定変更（`discount_type` / `discount_value` / `monthly_limit_per_user`） |
| enterprise_create | 企業作成 |

| order_create | 注文確定（セッション単位） |
| order_cancel | 注文キャンセル（セッション単位） |
| monthly_usage_exceeded | 月額上限超過（addToCart） |
| enterprise_subsidy_recalculated | 補助額再計算による不整合検知 |
| event_auto_cancel | イベント自動中止 |

> 注文系ログはセッション単位で記録される（02 論点 5.1）。詳細は `04_監査ログ` 3 章を参照。

### フィルタ

| フィルタ | 種類 | 説明 |
|:--|:--|:--|
| アクション種別 | セレクトボックス | 全て / 各種アクション |
| 操作者 | セレクトボックス | 全て / メンバー選択 |
| 期間 | 日付範囲ピッカー | 開始日〜終了日 |

### ページネーション

- Firestore のカーソルベース（`startAfter` + `limit`）
- 「次へ」「前へ」ボタン方式
- 1ページ50件
- 新しいログが上に来るよう `timestamp` 降順

```
対象:     全社設定

詳細:
  変更前 割引タイプ: 固定金額
  変更後 割引タイプ: 割合
  変更前 割引値: 500
  変更後 割引値: 50
```

# 9. Firestore アクセスパターン

# 10. Security Rules（全社管理者画面に関連する部分）

注文系（`member_orders` / `stripes` / `members`）の Rules は `02_全体構成・アーキテクチャ` 5.2 を正本とする。本章では本画面に直接関係する設定系・コミュニティ系のみ記載。

```javascript
// 全社設定・補助設定: 同一企業メンバーは read、write は Functions のみ
match /enterprises/{enterpriseId} {
  allow read: if request.auth.token.enterprise_id == enterpriseId;
  allow write: if false;
}

// EnterpriseMember (monthly_usage 等): 同一企業のメンバー read、書き込みは Functions のみ
match /enterprises/{enterpriseId}/members/{userId} {
  allow read: if request.auth.token.enterprise_id == enterpriseId;
  allow write: if false;
}

// isEnterpriseCommunityManager の定義は 02_全体構成・アーキテクチャ §5.2 参照
// コミュニティ: PF 版 create 維持 + エンプラは同一 enterprise の全従業員可。update は PF 同等（community manager 限定）
match /communities/{communityId} {
  allow read: if resource.data.enterprise_id == null
              || resource.data.enterprise_id == request.auth.token.enterprise_id;
  allow create: if (request.auth != null && request.resource.data.enterprise_id == null)
              || (request.auth.token.enterprise_id != null
                  && request.resource.data.enterprise_id == request.auth.token.enterprise_id);
  allow update: if isSupport() || isEnterpriseCommunityManager(communityId);
}

// EventMember / EventMemberOrder / EventStripe（注文系）は 02 全体構成 5.2 参照
// PF版もエンプラ版も以下のパターンで運用する（ダッシュボード集計はすべて Functions 経由）:
//   members         : enterprise_id == null || enterprise_id == request.auth.token.enterprise_id で read
//   member_orders   : 同上
//   stripes         : 本人（user_id）のみ read（MVP）
```


# 補足資料: Phase 2 仕様概要

## A. テーマカラーの管理者編集

- プリセット 8〜10色から選択可能にする
- `/enterprises/{enterpriseId}` の `theme_color` を管理者が更新可能
- カラーピッカーによる自由選択は Phase 3 以降

## B. allowed_email_domains の管理者編集

- ドメインの追加・削除を管理者が行えるようにする
- 誤設定防止のため、ドメイン追加時にメールによる所有確認を検討
- 既存メンバーのドメインを削除する場合の影響チェック（該当メンバーがログインできなくなる旨の警告）

## C. メンバーの完全削除

- 停止だけでなく完全削除を可能にする
- Firebase Auth ユーザーの削除 + Firestore ドキュメントの削除
- 個人情報の取扱いポリシー（保持期間、削除義務）との整合性を事前に整理する必要がある

## D. 監査ログの CSV エクスポート

- フィルタ条件を適用した状態で「CSVダウンロード」ボタンを表示
- CSV カラム: 日時、アクション種別、操作者、対象、詳細
- 件数が多い場合: 直近1万件までをフロントエンド側で生成
- 1万件超の場合は Functions 側での生成を検討

## E. コミュニティ承認フロー（Phase 2）

MVP では **作成は全従業員可**、**更新は manager 限定**（承認なし）。Phase 2 で以下を導入する。

### 画面

- `/admin/communities` に未承認 / 承認済み / 却下タブを追加
- サイドナビに未承認件数バッジ
- 承認・却下ダイアログ、却下理由入力、再申請フロー

### フロー概要

```
一般従業員: コミュニティ作成 → approval_status: "pending" → 管理者へメール通知
管理者: 承認 / 却下（Functions 経由）→ 作成者へメール通知 → 監査ログ
作成者（却下後）: 再申請 → pending 復帰 → 管理者へメール通知
```

### Functions（Phase 2）

| 関数名 | 概要 |
|:--|:--|
| approveCommunity | 承認 + メール + 監査ログ |
| rejectCommunity | 却下 + メール + 監査ログ |
| notifyCommunityApplied | 新規申請時の管理者通知（`onDocumentCreated`） |
| resubmitCommunity | 再申請時の管理者通知（Phase 2 で新設。update トリガーでも可） |

### Firestore 追加フィールド

`approval_status`, `rejection_reason`, `approved_by`, `approved_at`（`02` §3.3 参照）

### 画面内通知（Phase 2 以降）

- メール通知に加え、管理者画面内でもリアルタイム通知（ベルアイコン + ドロップダウン）を追加
- Firestore のリアルタイムリスナーで新規申請を検知
