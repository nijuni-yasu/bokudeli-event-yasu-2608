# 請求 詳細仕様

> **原典**: `90_アーカイブ/v0.1原典/` の 04_請求 を現行化。

本ドキュメントは `01_仕様概要`、`02_アーキテクチャ`、`02_課金設計`、`04_割引・決済`、`04_ゲスト参加`、`04_ダッシュボード` の決定事項に基づき、企業への**食事関連従量**の請求集計および**月次請求書 PDF**（MVP）の機能仕様を詳細に定義する。

> **プラットフォーム利用料**（有効アカウント月額 500円等）は `02_課金設計` が正本。本ドキュメントの「企業請求見込額」は**食事従量（実費）のみ**を指す。shokujii のマージンは載せず、収益の③（飲食店送客手数料）は別途実施予定（`02_課金設計` §4）。

## 前提とする仕様書

本ドキュメントは EventMemberOrder 設計（`05_EventOrder→EventMemberOrder.md`）を前提とする。集計対象は `members/{userId}/member_orders/{orderId}` および親 `members.is_guest` である。

# 1. 概要

## 1.1 対象機能

| 機能 | 概要 |
|:--|:--|
| 企業請求見込額の集計（MVP） | ゲスト無料分・`enterprise_subsidy` 補助分を月別に集計し、ダッシュボード / CSV で表示 |
| 月次請求書 PDF ダウンロード（MVP） | 全社管理者が `/admin/invoices` から、**確定済み暦月**の請求書 PDF を取得（①プラットフォーム利用料 + ②食事従量の合算） |

## 1.2 決定事項サマリ

| # | 論点 | 決定 |
|:--|:--|:--|
| B-1 | MVP の請求書 PDF | **MVP で実装**。全社管理者が月次 PDF をダウンロード。根拠は `billing_snapshots`（`billing_status: final`）。PF版 `community_bill` のイベント単位請求書とは**別 Function・別テンプレート** |
| B-2 | 月の帰属（食事従量） | **イベント開催月**（`event.event_start_datetime` の年月。`04_割引・決済` と同一） |
| B-3 | `community_bill` | **エンプラ版では選択不可**（`04_割引・決済` D-13、`02_課金設計` P-13）。企業請求見込額は **ゲスト無料分 + `enterprise_subsidy` 補助分** のみ |
| B-4 | 請求書の対象月 | **暦月**（`YYYY-MM`）。1 枚の PDF に①②を**2 行明細**で記載。帰属ルールの差異は注記で明示（`02_課金設計` §5.2） |
| B-5 | PDF 生成の参照実装 | PF版 `functions/default/src/eventBillInvoice.ts`（`onRequest` + JWT + GCS キャッシュ + Adobe PDF Services）。**10% 請求書手数料行は載せない**（P-11） |
| B-6 | ダウンロード可能条件 | `billing_snapshots/{YYYY-MM}` が存在し `billing_status == 'final'` の月のみ。当月・未スナップショット月は DL 不可（見込みはダッシュボード参照） |
| B-7 | 請求先表示 | MVP 最小: `Enterprise.company_name` のみ。住所・担当者は Phase 2 で `billing_profile` 拡張を検討 |

# 2. 企業請求見込額（MVP）

## 2.1 背景

エンタープライズ版では以下の費用が shokujii から企業へ後請求される。

| 費用種別 | データソース | 集計式 |
|:--|:--|:--|
| ゲスト無料参加分 | `member_orders`（親 `members.is_guest == true` **かつ** イベント `guest_payment == 'free'`） | `Σ menu_price` |
| 福利厚生割引（企業補助分） | `member_orders`（`pay_enterprise_subsidy_amount` あり） | `Σ pay_enterprise_subsidy_amount` |

> `community_bill`（主催者請求書払い）はエンプラ版では選択不可（D-13）。企業請求は上記 2 種のみ。

## 2.2 集計クエリ

```typescript
// ベースクエリ
collectionGroup('member_orders')
  .where('enterprise_id', '==', enterpriseId)
  .where('status', '==', 'ordered')
```

- 取得後、各 order の `event_id` から events を参照し、`event_start_datetime` の年月でフィルタ（`04_ダッシュボード` と同一ルール）
- ゲスト無料分: 親 `members.is_guest == true` **かつ** 当該イベント `guest_payment == 'free'` の `member_orders` を `Σ menu_price` で集計（`04_ゲスト参加` §7.1 — **self_pay は含めない**）
- 補助分: `pay_enterprise_subsidy_amount ?? 0` の合計（`members.is_guest == false` の EnterpriseMember 分）

## 2.3 表示

| 表示場所 | 内容 |
|:--|:--|
| ダッシュボード（`/admin`） | 月別集計テーブルに「企業請求見込額（食事）」列（`enterprise_billing_amount`）。プラットフォーム利用料・合計は `02_課金設計` / `04_ダッシュボード` §3.1 |
| 請求書画面（`/admin/invoices`） | 月別の有効アカウント数・①②・合計・確定状態・PDF ダウンロード（§3.3） |
| CSV | 月別 CSV に `enterprise_billing_amount` 列を追加。`platform_fee_amount` / `total_billing_amount` は `04_ダッシュボード` §4.2 |

請求見込額の集計は既存の `getDashboardMonthlyData`（`04_ダッシュボード` §5.2）を拡張する。集計専用 Callable は新設しない。

# 3. MVP: 月次請求書 PDF

## 3.1 PF版 `community_bill` との区別

| 観点 | PF版 `eventBillInvoice` | エンプラ版 `enterpriseBillInvoice`（本節） |
|:--|:--|:--|
| 請求単位 | **イベント**（`community_bill` 1 件） | **企業 × 暦月** |
| 請求先 | コミュニティ主催者 | 企業（全社管理者） |
| 明細 | メニュー行 + 10% 手数料（カットオフ後） | **2 行サマリ**（①プラットフォーム利用料、②食事従量） |
| 画面 | コミュニティ manage「請求書」タブ | **`/admin/invoices`**（全社管理者専用） |
| エンプラ UI | **非表示**（D-13） | **こちらが正** |

> PF版の `getEventBillInvoicePdf` / `createEventBillInvoice` はエンプラ UI から呼び出さない。

## 3.2 請求書の金額内訳

1 枚の PDF に載せる合計は `billing_snapshots.total_billing_amount` と一致させる。

| 明細行 | フィールド | 内容 |
|:--|:--|:--|
| ① プラットフォーム利用料 | `platform_fee_amount` | `{active_account_count} アカウント × {unit_price}円`（お試し期間・企業停止時は 0） |
| ② 食事関連従量 | `meal_billing_amount` | 福利厚生補助分 + ゲスト無料分（G-1 前は補助分のみ。`dashboardAggregation` と同一） |
| **合計** | `total_billing_amount` | ① + ② |

税表示:

- ① は**税込**サービス料（`02_課金設計` §2.4）
- ② は**実費取次**（メニュー税込価格ベース）。PF版 `calculateInvoiceFee`（10% 手数料）は**適用しない**

MVP の PDF 明細は**イベント別・メニュー別の内訳を載せない**。詳細はダッシュボード / CSV を参照する。

## 3.3 画面: `/admin/invoices`

| 項目 | 仕様 |
|:--|:--|
| 対象ロール | `enterprise_role == "admin"` のみ（`/admin/*` 共通ガード） |
| ナビ | `04_詳細_全社管理者画面` §2.2 — ダッシュボードの次に配置 |
| データ取得 | `getDashboardMonthlyData` の返却を流用（新 Callable 不要） |
| 表示列 | `year_month`、有効アカウント数、プラットフォーム利用料、食事従量、合計、確定状態、操作 |
| DL ボタン | `billing_status == 'final'` かつ `total_billing_amount > 0` の行のみ有効 |
| DL 操作 | 新規タブで PDF 表示（PF版 `EventBillInvoicePdf` と同様の iframe ページ、または `fetch` + blob URL） |
| 期間変更 | 期間ピッカー変更時は**最新リクエストのみ**一覧に反映（古い応答は破棄） |
| 注記 | `02_課金設計` §5.2 の「集計の見方」文案を画面下部に表示 |

## 3.4 バックエンド: `enterpriseBillInvoice`

PF版 `eventBillInvoice.ts` のパターンを踏襲する。

### HTTP エンドポイント

```
GET /enterpriseBillInvoice/{enterpriseId}?year_month=2026-06
GET /enterpriseBillInvoice/{enterpriseId}?year_month=2026-06&id={invoiceId}
```

| パラメータ | 認証 | 動作 |
|:--|:--|:--|
| `id` あり | **不要** | GCS から既存 PDF を返却（経理担当者への URL 共有可能。PF版と同趣旨） |
| `id` なし | `Authorization: JWT {token}` | 全社管理者権限を検証後、PDF 生成またはキャッシュ返却 |

### 認可

- JWT 検証後 `assertEnterpriseAdmin(enterpriseId)`（`enterpriseAuthHelpers`）
- トークンの `enterprise_id` とパスの `{enterpriseId}` が一致すること

### 生成フロー

1. `billing_snapshots/{year_month}` を取得。無い、または `billing_status != 'final'` なら `failed-precondition`
2. `invoice_files/{year_month}.gcs_id` を参照。あれば GCS から返却（冪等）
3. なければ docx テンプレート `enterpriseBillInvoice.docx` にマージデータを投入
4. Adobe PDF Services（`PdfGenerator`）で PDF 生成
5. GCS 保存: `gs://{project}-invoice/enterprises/{enterpriseId}/{yearMonth}/{gcs_id}`（`gcs_id` はランダム base64url。PF 同趣旨）
6. `invoice_files/{year_month}` に `gcs_id` を記録（`create` による一意性。並行生成時は先着 1 件に収束）
7. レスポンス: `Content-Type: application/pdf`

> **キャッシュ無効化**: `recaptureEnterpriseBillingSnapshot` または月次バッチ再確定時に `invoice_files/{yearMonth}` を削除する。スナップショット更新後は次回 DL で PDF を再生成する。

### テンプレート項目（例）

| プレースホルダ | 内容 |
|:--|:--|
| `number` | 請求書番号（`{enterpriseId 短縮}-{yearMonth}` 等） |
| `date` | 請求書発行日 |
| `companyName` | `Enterprise.company_name` |
| `items` | 2 行明細 + 空行パディング（PF版と同様の行数上限） |
| `subTotal` / `tax` / `total` | 税計算結果 |
| `deadline` | 支払期限（発行月の翌月末等。運営ポリシーに合わせて Functions 内で算出） |
| `billingNote` | ①②の帰属ルール注記 |

税計算ロジックは `common/src/utils/enterpriseInvoice.ts`（新規）に純粋関数として切り出し、vitest でテストする。

## 3.5 依存関係

| 依存 | 理由 |
|:--|:--|
| **D-4** `captureEnterpriseBillingSnapshots` | 確定値（`final`）が PDF の唯一の根拠。D-4 未完了時は請求書 DL を出荷しない |
| **D-2** ダッシュボード集計 | `/admin/invoices` の一覧データ源 |
| MVP-A `billing_settings` / `last_activated_at` | ① の算出前提（`02_課金設計` §2.3） |

実装順: **D-2 ∥ D-4 → B-1（Function + テンプレート）→ `/admin/invoices` UI**

## 3.6 入金フローとの関係

- MVP の請求**入金**は引き続き振込等の**手動**（`02_課金設計` §7.1 MVP-C）
- PDF は全社管理者が自己取得。運営による「承認 → 送付」は必須としない（運営はスナップショットを監視可能）
- Stripe Subscription 自動課金は Phase 2（`02_課金設計` §7.2）
