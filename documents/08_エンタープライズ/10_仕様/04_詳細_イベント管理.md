# イベント管理 詳細仕様

> **原典**: v0.1 `04_イベント管理` + v0.3 §1（3 軸モデル）。`publish_scope` 移行は [ADR-003](../20_設計判断_ADR/ADR-003_publish_scope移行.md) を正本とする。

本ドキュメントは [01_仕様概要.md](./01_仕様概要.md)、[02_アーキテクチャ.md](./02_アーキテクチャ.md)、[04_詳細_全社管理者画面.md](./04_詳細_全社管理者画面.md) の決定事項に基づき、エンタープライズ版のイベント関連機能の仕様を詳細に定義する。

## 前提とする仕様書

本ドキュメントは EventMemberOrder 設計（`05_EventOrder→EventMemberOrder.md`）を前提とする。注文集計の参照先は `members/{userId}/member_orders/{orderId}` に変更される（旧 `orders` コレクションは廃止）。

**PF 版共通機能**（イベントコピー・繰り返し作成、最小催行人数・自動中止、イベント一括中止コア・将来の主催者手動中止）はエンプラ MVP のスコープ外。PF 版の `base` / `user` 実装をそのまま利用し、正本は `documents/02_主催者獲得と継続/` 配下を参照する。

### 2.3.1 非表示の実装方針

- `enterprise` パッケージでは、base の `EventDetailsCard`、`UserSuccessJoinEventDialog`、`EventDetailCard`、`CommunitySetupForm` 等をラップし、SNS・ハッシュタグ関連の UI を出さない
- または base に `hideSnsFeatures?: boolean` のような props を追加し、エンプラ版から `true` で渡す
- 既存データの `event_sns_hash_tag` は DB 上は残すが、エンプラ版 UI では表示・編集しない
- **`community_bill` 関連**: base に `hideCommunityBillFeatures?: boolean`（または enterprise 側で tabs / コンポーネントを omit）を設け、次を出さない
  - コミュニティ manage の `tabs` 配列から `'invoice'` を除外（PF版は `events`, `member`, `letter`, `album`, `invoice`, `slackSetting`, `settings`）
  - イベント overview の `EventCommunityBillAlert`
  - イベントルートの `invoice` タブ（存在する場合）および `EventBillInvoicePdf` ページ
  - コミュニティ編集フォームの請求書用氏名・メール欄

### 2.3.2 主催者請求書 UI と企業請求の区別

| 対象 | PF版 `CommunityInvoice` | エンプラ版 企業請求（`04_請求` / 全社管理者画面） |
|:--|:--|:--|
| 請求先 | コミュニティ主催者（`community_bill` イベント単位） | 企業（全社管理者）。食事補助・ゲスト無料分 + プラットフォーム利用料 |
| 画面 | コミュニティ manage「請求書」タブ | `/admin/invoices` 月次請求書（MVP）。集計・CSV は `/admin` ダッシュボード |
| エンプラ版 | **非表示**（D-13） | **こちらが正** |

> PF版の `getEventBillInvoicePdf` / `createEventBillInvoice`（`community_bill` 向け）は、エンプラ版 UI からは呼び出さない。エンプラ向け企業請求 PDF は `enterpriseBillInvoice` + `04_請求` §3 で定義する。

## 4.1 軸2: `event.publish_scope`（PF / エンプラ共通）

詳細・移行手順は [ADR-003](../20_設計判断_ADR/ADR-003_publish_scope移行.md) を正本とする。

```ts
publish_scope: 'public' | 'community' | 'url'
allow_guest?: boolean  // エンプラ。既存どおり直交
```

| `publish_scope` | エンプラ一覧表示 | 注文 | PF版（エンプラゲスト掲載） | 移行期 `is_public` |
|:--|:--|:--|:--|:--|
| `public` | 表示（エンプラ: 同社全員） | 全員可 | `allow_guest == true` なら**出うる**（G-1） | `true` |
| `community` | 表示（非メンバー閲覧のみ） | `CommunityMember` のみ | 出ない | — |
| `url` | 非表示 | URL を知る人のみ | 出ない | `false` |

- **`access_password`**: Phase 2（ADR-003 §4）。MVP では未実装。
- PF版（エンプラゲスト掲載）列は将来 G-1 の話。MVP マージ時点では PF 一覧はクエリ A（`enterprise_id == null`）のみ。

### エンプラ版一覧クエリ（確定）

```typescript
// エンプラ版イベント一覧 — publish_scope 必須
collectionGroup('events')
  .where('enterprise_id', '==', myEnterpriseId)
  .where('publish_scope', 'in', ['public', 'community'])
```

### 4.1c PF 版一覧クエリ（確定）

```typescript
// クエリ A: PF ネイティブ（MVP マージ必須 — 02 §T2）
collectionGroup('events')
  .where('enterprise_id', '==', null)
  .where('is_public', '==', true)  // Phase 2 G-6 後: publish_scope 参照へ

// クエリ B: エンプラゲストの PF 掲載（将来 G-1 — 04_詳細_ゲスト参加 §2.1）
collectionGroup('events')
  .where('allow_guest', '==', true)
  .where('publish_scope', '==', 'public')
// PF トップは A + B をクライアントマージ。B のカードリンクは Enterprise URL（新タブ）
```

### Security Rules

events の read Rules は [02_アーキテクチャ](./02_アーキテクチャ.md) 5.2 / [04_詳細_ゲスト参加](./04_詳細_ゲスト参加.md) §8.1 と同一:

```javascript
allow read: if data.get('enterprise_id', null) == null
            || resource.data.allow_guest == true
            || (request.auth != null
                && resource.data.enterprise_id == request.auth.token.enterprise_id);
```

> Rules では `data.get('enterprise_id', null)` を推奨（フィールド欠落の既存 PF doc 対応）。Firestore クエリでは materialize 済み `where('enterprise_id', '==', null)` を使う（02 §PF 版データ露出フィルタ）。

- `publish_scope: url` でも URL 直アクセスは Rules 上可能（一覧に出ないだけ）
- ゲスト未認証閲覧は `allow_guest == true` のイベントのみ

### 移行期: `is_public` 互換（Phase 2 G-6）

[ADR-003 §3](../20_設計判断_ADR/ADR-003_publish_scope移行.md): **MVP では `is_public` が正本**。Phase 2 expand 中は `is_public = (publish_scope === 'public')` を自動同期。Migrate 完了後は `publish_scope` を正とする。

## 4.1d MVP: 参加者トップページ一覧（#2138）

> **Phase 2 正本**は §4.1 の `publish_scope` クエリ。MVP のトップ実装正本は本節 + [04_詳細_参加者画面](./04_詳細_参加者画面.md) §2。

`enterprise/src/pages/index.vue` — `collectionGroup('events')` 相当（`useEventListStore` 経由）:

```typescript
// 共通（人気・開催予定・終了の3クエリ）
.where('enterprise_id', '==', myEnterpriseId)
.where('is_public', '==', true)
.where('event_status.value', '==', 'accepting_order')
.where('event_num_members', '>=', 0) // 0 人表示と Firestore inequality / orderBy 制約の両立
```

| セクション | 追加 where / orderBy |
|:--|:--|
| 人気 | `event_deadline_datetime > now`、`orderBy('event_num_members', 'desc')` |
| 開催予定 | `event_end_datetime > now`、`orderBy('event_start_datetime', 'asc')` |
| 終了 | `event_end_datetime <= now`、`orderBy('event_start_datetime', 'desc')` |

**PF 版との差分**: `user/src/pages/index.vue` も同3クエリで `where('event_num_members', '>=', 0)` を用いる（#2288。enterprise は `enterprise_id`、PF は `enterprise_id == null` でテナント分離）。

## 4.1b `is_public` — MVP 正本 / Phase 2 で `publish_scope` へ移行

v0.1 原典の boolean モデル。**MVP では引き続き正本**（`true` = 公開一覧、`false` = URL 限定）。Phase 2（G-6）で `publish_scope` へ移行後、contract で削除予定。
