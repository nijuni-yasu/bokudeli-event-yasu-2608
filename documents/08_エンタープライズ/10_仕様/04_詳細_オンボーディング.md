# オンボーディング 詳細仕様

> **原典**: `90_アーカイブ/v0.1原典/` の 04_オンボーディング を現行化。

本ドキュメントは `01_仕様概要`、`02_アーキテクチャ`、`05_認証・テナント`、`04_監査ログ` の決定事項に基づき、企業オンボーディング（初代 admin ブートストラップ）の機能仕様を詳細に定義する。

---

# 1. 概要

## 1.1 対象機能

| 機能 | 概要 |
|:--|:--|
| 企業オンボーディング | 運営が `createEnterprise` で `/enterprises/{id}` と初代 admin を一括作成 |

## 1.2 決定事項サマリ

| # | 論点 | 決定 |
|:--|:--|:--|
| O-1 | 初代 admin の作成 | 運営専用 Callable `createEnterprise` で同時作成（CSV 一括作成の鶏卵問題を解消） |
| O-2 | 企業作成 UI | MVP は運営 / スクリプト運用。管理画面 UI は Phase 2 |
| O-3 | テーマカラー / allowed_email_domains | MVP では運営が `createEnterprise` で設定。管理者による編集は Phase 2（`04_全社管理者画面` 補足 A/B 参照） |
| O-4 | 初期割引設定の保存形式 | リクエストはネスト DTO 可。Firestore は **フラット** `discount_type` / `discount_value` / `monthly_limit_per_user`（`02` §3.2 / §3.5 参照） |
| O-5 | IdP tenant onboarding | `createEnterprise` で Identity Platform tenant 作成 + `tenant_id` 保存 + 初代 admin を `authForTenant` 経由（`05_認証・テナント` §0、`04_WS-B` B-3） |

# 2. 背景

エンタープライズ版の利用開始には以下が必要だが、従来は「運営が Firestore に手動設定」止まりで、**初代 admin が存在しないと CSV 一括作成もできない**鶏卵問題があった。

# 3. Functions: createEnterprise

運営（サポートアカウント）専用の Callable Function。企業ドキュメントと初代 admin を一括作成する。

## 3.1 実行権限

- `isSupport()`（サポートアカウント）のみ実行可能
- 一般ユーザー・企業 admin からは呼び出せない

## 3.2 リクエスト

```typescript
interface CreateEnterpriseRequest {
  enterprise_id: string              // ドキュメント ID（例: "company-a"）
  company_name: string
  subdomain: string                  // 例: "company-a" → company-a.shokujii.com
  custom_domain?: string             // 任意
  allowed_email_domains: string[]    // 例: ["company-a.com", "company-a.co.jp"]
  theme_color: string                // 例: "#1976D2"
  // 初期割引設定（API はネスト DTO。Firestore 保存時にフラット3フィールドへ展開）
  initial_subsidy_settings: {
    type: 'fixed' | 'percentage'
    value: number
    monthly_limit_per_user: number
  }
  initial_admin: {                   // 初代 admin（1名必須）
    email: string
    display_name: string
    department?: string
  }
}
```

## 3.3 処理フロー

```
1. isSupport() チェック
2. subdomain の形式・予約語バリデーション
   - 形式: ^[a-z0-9](?:[a-z0-9-]{0,61}[a-z0-9])?$（DNS ラベル準拠）
   - 予約語: www / user / partner / enterprise / admin / api / mail / app 等
   - 違反時: `invalid-argument` エラー
3. enterprise_id / subdomain / custom_domain（指定時）の重複チェック
   - 重複時: `already-exists` エラー
4. Identity Platform tenant を作成（tenantManager().createTenant）
   - tenantId は PoC で enterprise_id 同値可否を確認（不可なら Firebase 発行 ID）
5. /enterprises/{enterpriseId} ドキュメントを作成
   - company_name, subdomain, custom_domain, allowed_email_domains, tenant_id
   - theme_color, is_active: true
   - discount_type, discount_value, monthly_limit_per_user（initial_subsidy_settings から展開）
   - billing_settings: unit_price=500, trial_months=3, billing_trial_ends_at
6. initial_admin を tenant 内 Auth user として作成（createEnterpriseMembers と同等ロジック）
   a. 同一 enterprise 内で initial_admin.email の重複チェック（EnterpriseMember.user_email）
   b. authForTenant(tenantId).createUser({ email, emailVerified: true, displayName })
   c. authForTenant(tenantId).setCustomUserClaims({ enterprise_id, enterprise_role: 'admin', user_type: 'enterprise' })
   d. /enterprises/{id}/members/{userId}（user_email 含む）, /users/{userId}, /users_personal_information/{userId}
7. 失敗時ロールバック（RC-19/25）
   - Auth 作成後 Firestore 失敗 → tenant user 削除（可能なら tenant も削除）
   - saveEnterprise 後 tenant 作成失敗 → enterprise doc 削除
8. 監査ログ記録（action: 'enterprise_create'）
9. レスポンス返却
```

> **移行**: sandbox では既存 project-level Enterprise Auth user を作り直し可（`07_デプロイ・運用` §12）。本番は Enterprise 従業員蓄積前に WS-B を完了する。

## 3.4 レスポンス

```typescript
interface CreateEnterpriseResponse {
  enterprise_id: string
  initial_admin_user_id: string
}
```

## 3.5 オンボーディング完了条件（テナント URL・インフラ）

`createEnterprise` の Callable 成功は **Firestore / IdP tenant 作成完了**を意味する。**ブラウザからテナント URL で利用開始**までがオンボーディング完了とする。

| # | 項目 | 必須条件 |
|:--|:--|:--|
| 1 | Firestore / IdP | §3.3 どおり `createEnterprise` 成功 |
| 2 | Hosting + DNS | テナント FQDN 方式の場合 [08_カスタムドメイン.md](./08_カスタムドメイン.md) §6.1b |
| 3 | Terraform | テナント FQDN を `auth_authorized_domains_extra` に追加 → **`terraform plan`**（Auth: `multi_tenant` 削除なし）→ **`terraform apply`**（Auth + **Storage CORS**。CORS のみ急ぐ場合は [terraform/README.md](../../../terraform/README.md) の targeted apply）。チャット画像 [#2241](https://github.com/nijuniinc/bokudeli-event-new/issues/2241) |
| 4 | 受け入れ | テナント URL で OTP ログイン、**チャットで画像送受信**（DevTools に `firebasestorage` の CORS エラーなし） |

FQDN 行の出力: [terraform/scripts/print-enterprise-tenant-fqdns.sh](../../../terraform/scripts/print-enterprise-tenant-fqdns.sh)

```bash
cd terraform
./scripts/print-enterprise-tenant-fqdns.sh --subdomain company-a --base-domain test.tabete.co
```

`ENTERPRISE_BASE_DOMAIN` 未設定で `custom_domain` のみ（§6.2）の場合は `--custom-domain <PROJECT>-enterprise.web.app` 等。`<PROJECT>-enterprise.web.app` は Terraform 既定の Auth/CORS に含まれる。
