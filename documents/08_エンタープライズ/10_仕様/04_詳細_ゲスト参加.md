# ゲスト参加 詳細仕様

> **原典**: `90_アーカイブ/v0.1原典/` の 04_ゲスト参加 + ADR-002 を現行化。

> **将来実装（MVP スコープ外）**: 本ドキュメントの機能・フィールド（`allow_guest` / `guest_payment` / `members.is_guest` 等）は MVP に含めない。実装時期・優先度は [01_MVP全体計画](../00_計画/01_MVP全体計画.md) **WS-G**（G-1 以降）および [ADR-002](../20_設計判断_ADR/ADR-002_IdP採用とゲスト方針.md) を参照。現行コードには当該スキーマ・Rules 例外は未実装。

本ドキュメントは `01_仕様概要`、`02_アーキテクチャ`、`04_割引・決済` の決定事項に基づき、ゲスト（プラットフォーム版ユーザー）がエンタープライズ版イベントに参加する際の機能仕様を詳細に定義する。

## 前提とする仕様書

本ドキュメントは EventMemberOrder 設計（`05_EventOrder→EventMemberOrder.md`）を前提とする。注文関連のデータは `members/{userId}/member_orders/{orderId}` および `stripes/{stripeId}` に格納される。ゲスト判定は **`members.is_guest`** に配置する（02 論点 1.4 で決定）。


# 1. 概要

エンタープライズ版では、イベント作成時に「ゲストOK」を設定することで、就活生や外部パートナーなどのプラットフォーム版ユーザーがエンタープライズ版イベントに参加できる。ゲストはイベント単位でのみ参加し、コミュニティメンバーにはならない。

## 1.1 ゲストの定義

| 項目 | 内容 |
|:--|:--|
| 対象 | 就活生、外部パートナーなど、企業外の参加者 |
| 認証 | プラットフォーム版ユーザー（`user_type: "platform"` または未設定） |
| custom claims | `enterprise_id` を持たない |
| 参加単位 | **イベント単位のみ**（コミュニティメンバーにはしない） |
| イベントの `members` 配列 | 注文確定時にイベントの `members` 配列に追加される（`eventMembers.ts` トリガーが自動更新。02 論点 8.2 でゲストも含める） |
| イベントの `members` サブコレクション | `members/{userId}` ドキュメントが作成される。`is_guest = true` をセット |
| コミュニティの `members` | **追加しない**。`stripeWebhook` / `confirmOrder` の `enterprise_subsidy` ゲスト分岐では PF版の `addCommunityUser` を呼ばない |

# 2. 参加フロー

## 2.1 イベントの発見

PF版トップ・イベント一覧に掲載するエンプラゲストイベントの条件は、`allow_guest == true` かつ `publish_scope === 'public'` とする。それ以外のエンプライベントは PF版には掲載しない。

| パターン | `allow_guest` | `publish_scope` | PF版一覧表示 | 詳細・注文URL |
|:--|:--|:--|:--|:--|
| 従業員のみ | `false` | `public` / `community` / `url` | しない | Enterprise URL |
| ゲストOK・URL共有のみ | `true` | `community` / `url` | しない | Enterprise URL |
| ゲストOK・PFにも掲載 | `true` | `public` | する | Enterprise URL |

`allow_guest` はゲスト参加可否、`publish_scope` はイベント公開区分、`guest_payment` はゲスト支払い方法、`enterprise_id` はテナント分離を担い、互いに責務を混ぜない。

主催者（従業員）がイベント詳細画面のURLをコピーし、ゲストに共有する。PF版に掲載する場合も、PF版は発見面としてのみ使い、PF版トップ・イベント一覧では通常のPFイベントカードと同列に表示する。一覧カードのリンク先は Enterprise URL とする。

**PF 一覧クエリ（2 本立て）**

```typescript
// クエリ A: PF ネイティブ（MVP マージ必須 — 02 §T2）
collectionGroup('events')
  .where('enterprise_id', '==', null)
  .where('is_public', '==', true)  // C-3 後: publish_scope 参照へ

// クエリ B: エンプラゲストの PF 掲載（将来 G-1 — 本ドキュメント）
collectionGroup('events')
  .where('allow_guest', '==', true)
  .where('publish_scope', '==', 'public')
// PF トップは A + B をクライアントマージ。B のカードリンクは Enterprise URL（新タブ）
```

MVP マージ時点（WS-M）ではクエリ A のみ実装し、エンプラ doc は PF 一覧から除外する。クエリ B は [01_MVP全体計画](../00_計画/01_MVP全体計画.md) WS-G G-1 で実装する。

## 2.2 アクセス先

| 項目 | 仕様 |
|:--|:--|
| アプリ | **Enterprise アプリ**（企業ドメイン） |
| URL形式 | `{企業ドメイン}/c/{communityAccount}/e/{eventId}`（例: `company-a.shokujii.com/c/foo/e/bar`） |
| 理由 | 主催者が共有するURLはブラウザのURLをそのままコピーするため、企業ドメインのURLになる。PF版一覧から遷移する場合も企業ドメインに寄せることで、同一イベントに複数の正規URLを持たせない。企業ブランディング（ロゴ・テーマカラー）で「A社の食事会」と文脈が明確になる。 |

PF版に掲載する場合も、PFアプリ内にエンプライベント詳細ページは作らない。PF一覧カードのリンク先は `enterprises/{enterpriseId}` の `subdomain` または `custom_domain` から生成した Enterprise URL とし、`target="_blank"` 相当で新しいタブで開く。

## 2.3 URL名前空間

`community_account` は企業内で一意とする。Enterprise URL ではホスト名から `enterprise_id` を解決できるため、`/c/{communityAccount}/e/{eventId}` は企業スコープ内で一意に解決できる。

PF版はエンプライベント詳細を `/c/{communityAccount}/e/{eventId}` として解決しない。PF版に掲載されたエンプライベントは、PF版トップ・イベント一覧から、一覧カードのリンク先である Enterprise URL へ遷移する（新タブ）。

## 2.4 未認証閲覧

| 項目 | 仕様 |
|:--|:--|
| 閲覧 | `allow_guest == true` のイベントは**認証不要**で閲覧可能 |
| 対象 | イベント詳細（メニュー、日時、場所など） |
| 制限 | 注文・カート操作は認証必須 |

URLを知っていれば誰でもイベント内容を閲覧できる。注文する場合はログインが必要となる。

## 2.5 ゲスト認証（注文時）

ゲストが注文するには認証が必要。Enterprise アプリのログイン画面に「ゲストの方はこちら」を追加し、**PF版と同等の認証方式**（メールアドレス+OTP、SNS ログイン）のいずれかでサインインする。

### ログイン画面の構成

```
┌─────────────────────────────────────┐
│         [企業ロゴ]                    │
│                                      │
│  ─────── 従業員の方はこちら ───────   │
│  メールアドレス [______________]      │
│  ※ 企業メールドメインのみ             │
│  [ログイン]  ← OTP 認証               │
│                                      │
│  ─────── ゲストの方はこちら ───────   │
│  メールアドレス [______________]      │
│  [ログイン]  ← OTP 認証（PF版と同様）  │
│  [Googleでログイン] [Appleでログイン]  │
└─────────────────────────────────────┘
```

ゲスト向けのメールアドレス+OTP は PF版と同じく**メールドメイン制限なし**。SNS ログインも PF版と同様に利用可能。

**認証 Functions の扱い:** ゲスト向けは PF版の `requestEmailLogin` / `confirmEmailLogin` を流用する。custom claims は設定せず、通常の Firebase Auth でログインする。

### 認証後の扱い

| ユーザー種別 | custom claims | アクセス範囲 |
|:--|:--|:--|
| 従業員 | `enterprise_id` あり | 全機能（コミュニティ、イベント、注文など） |
| ゲスト | `enterprise_id` なし | `allow_guest == true` のイベントのみ（閲覧・注文） |

### ナビゲーションガード

- `enterprise_id` を持たないユーザーが `allow_guest` 以外のページにアクセスした場合 → ログイン画面またはエラー表示
- ゲストは `allow_guest == true` のイベント詳細・注文フローにのみ遷移可能


# 3. event_payment と guest_payment の組み合わせ

## 3.1 全組み合わせ

| event_payment | 従業員の支払い | allow_guest | guest_payment | ゲストの支払い | 成立 |
|:--|:--|:--|:--|:--|:--|
| enterprise_subsidy | 補助後クレカ | true | free | 0円（企業負担） | OK |
| enterprise_subsidy | 補助後クレカ | true | self_pay | 全額クレカ | OK |
| user_advance | 全額クレカ | true | free | 0円（企業負担） | OK |
| user_advance | 全額クレカ | true | self_pay | 全額クレカ | OK |

**`enterprise_subsidy` および `user_advance` の event_payment で allow_guest = true を許可する。**

## 3.2 guest_payment の扱い

| 項目 | 仕様 |
|:--|:--|
| 選択肢 | `free`（無料参加・企業負担）/ `self_pay`（自己負担・全額クレカ） |
| 必須条件 | `allow_guest == true` のとき **必須** |
| デフォルト値 | `free` |
| バリデーション | allow_guest を true にしたら、guest_payment を必ず選択させる |

# 5. 注文・決済フロー

## 5.1 カート追加（addToCart の流用・拡張）

メニュー選択・カート追加は PF版の `addToCart` Callable を使用する。`event_payment` および呼び出し元の認証状態（custom claims に `enterprise_id` があるか）で分岐し、以下のフィールドをセットする。

| フィールド | 配置先 | 設定タイミング |
|:--|:--|:--|
| `enterprise_id` | `members` / `member_orders` 両方 | イベントに `enterprise_id` がある場合、`addToCart` 内で必ずセット |
| `is_guest` | **`members`** | `addToCart` 内で判定。custom claims に `enterprise_id` がないユーザー（≒ PF版ユーザー）が `enterprise_id` を持つイベントに参加する場合 = ゲスト |
| `pay_enterprise_subsidy_amount` | `member_orders` | ゲストの場合は `undefined`（フィールド省略）。EnterpriseMember を持たないため `monthly_usage` ベースの補助計算は行わない |

> エンプラ版では `community_bill` は選択不可（D-13）のため、`pay_community_bill_off_amount` は設定されない。

> ゲストが `enterprise_subsidy` イベントに参加する場合、企業補助は適用されない（G-7）。`pay_enterprise_subsidy_amount` フィールドは保存しない。請求書には別途「ゲスト無料参加分」として企業に請求する（7. 参照）。

## 5.2 フロー分岐の全体像

| 参加者 | guest_payment | 呼び出す Function | 決済 |
|:--|:--|:--|:--|
| ゲスト | free | `confirmOrder`（PF版） | Stripe スキップで直接確定 |
| ゲスト | self_pay | `createStripeCheckoutSession`（PF版） | Stripe 決済 |
| 従業員 | — | `addToCart` → `confirmOrder` or `createStripeCheckoutSession`（`04_割引・決済` 参照） | 補助あり / なしで分岐 |

## 5.3 ゲスト無料参加（guest_payment == 'free'）

PF版の `confirmOrder` Callable に「ゲスト無料分岐」を追加する。専用 Function は新設しない。

### 事前条件

- 認証チェック: 認証済みであること
- ゲスト判定: 親 `members.is_guest == true` であること（`addToCart` で設定済み）
- イベント: `allow_guest == true` && `guest_payment == 'free'` であること
- 注文期限・定員チェック: PF版と同様

### 処理フロー

```
[フロントエンド]                      [Functions]
   │                                    │
   │  1. メニュー選択 → addToCart        │
   │ ──────────────────────────────────>│  - members.is_guest = true をセット
   │                                    │  - member_orders 作成（pay_*amount は無し）
   │                                    │
   │  2. 注文確認画面                   │
   │     「全額会社負担」を表示         │
   │                                    │
   │  3. confirmOrder(order_ids)        │
   │ ──────────────────────────────────>│
   │                                    │  4. ゲスト分岐:
   │                                    │     - members.is_guest を確認
   │                                    │     - guest_payment === 'free' を確認
   │                                    │     - total_payment === 0 を確認
   │                                    │  5. Transaction 内で:
   │                                    │     - 各 order の status → ordered
   │                                    │     - ordered_at をセット
   │                                    │     - members.monthly_usage は加算しない
   │                                    │     - PF版 addCommunityUser は呼ばない
   │                                    │  6. 監査ログ（action: 'order_create',
   │                                    │     details.is_guest = true）
   │  7. 完了画面にリダイレクト         │
   │<──────────────────────────────────│
```

### enterprise_id の取得

success_url は `getEnterpriseUrl(enterpriseId)` で生成する。ゲストは custom claims に `enterprise_id` を持たないため、**イベントDocから `enterprise_id` を取得**する。`addToCart` 時点で `members.enterprise_id` にもセットされているため、こちらから取得してもよい。

### `member_orders` の状態

- Stripe は使用しない
- `members.monthly_usage` は加算しない（ゲストは EnterpriseMember ではないため）
- `member_orders.stripe_id` は設定されない（`stripes` ドキュメントは作成されない）
- 企業負担分は後から請求書で回収する（7. 参照）

### createStripeCheckoutSession の拡張

PF版の `createStripeCheckoutSession` に以下の分岐を追加する。

| 条件 | 追加処理 |
|:--|:--|
| イベントに `enterprise_id` あり | metadata に `enterpriseId` を追加 |
| 親 `members.is_guest == true` | 補助額計算スキップ。line_items は `Σ menu_price` ベース。`success_url` を `getEnterpriseUrl(enterpriseId)` に変更 |
| 通常の従業員（`enterprise_subsidy`） | 補助計算（`04_割引・決済` 5.3 参照） |

### Webhook のルーティング

`stripeWebhook` は metadata の `orderIds` から `member_orders` を取得し、親 `members.is_guest` を確認して分岐する。

| ゲスト判定 | 処理 |
|:--|:--|
| `members.is_guest == true` | `monthly_usage` 加算をスキップ。`stripes` ドキュメントには `enterprise_id` をセットするが `pay_enterprise_subsidy_amount` は 0 |
| `members.is_guest == false`（従業員） | `04_割引・決済` 5.4 のフローを実行 |

## 5.5 注文系ドキュメントのフィールド（ゲストの場合）

| フィールド | 配置先 | ゲスト free | ゲスト self_pay |
|:--|:--|:--|:--|
| `enterprise_id` | members / member_orders / stripes | セット | セット |
| `is_guest` | **members のみ** | true | true |
| `pay_enterprise_subsidy_amount` | member_orders / stripes | 未設定（補助なし） | 未設定 |
| `stripe_id` | member_orders | 未設定（stripes 作成しない） | セット |
| `ordered_at` | member_orders | セット（confirmOrder 確定時） | セット（Webhook 到着時） |


# 6. 割引・決済との関係

## 6.1 monthly_usage

| ケース | monthly_usage |
|:--|:--|
| ゲスト無料参加 | **加算しない** |
| ゲスト self_pay | **加算しない** |

ゲストは EnterpriseMember ではないため、`monthly_usage` には一切加算しない。

## 6.2 キャンセル時

ゲストのキャンセルは PF版と同じ `cancelOrders` を使用する。エンプラ専用 Function は新設しない（02 論点 6.1）。

| ケース | 呼び出す Function | 処理内容 |
|:--|:--|:--|
| ゲスト無料参加のキャンセル | `cancelOrders`（PF版） | status を 'canceled' に変更。Stripe 返金なし。`monthly_usage` の戻しは不要（`members.is_guest == true` でスキップ） |
| ゲスト self_pay のキャンセル | `cancelOrders`（PF版） | `stripe_id` でグルーピングして Stripe Refund を実行後、status を 'canceled' に変更。`monthly_usage` の戻しは不要 |

`cancelOrders` 内で `members.is_guest == true` の場合は `monthly_usage` 操作をスキップする分岐を追加する。


# 7. 無料参加時の課金・請求

## 7.1 決定事項

| 項目 | 仕様 |
|:--|:--|
| ゲスト無料参加分の扱い | 企業の福利厚生費として**請求書に含める** |
| 支払いフロー | 企業が **shokujii に請求書払い**で支払う |
| Stripe の利用 | ゲスト無料参加分については **Stripe は使わない** |
| 請求タイミング | **後から企業に請求書を発行**する |

## 7.2 請求対象の集計方法

`collectionGroup('member_orders')` でゲスト分のみ抽出する：

```
collectionGroup('member_orders')
  .where('enterprise_id', '==', enterpriseId)
  .where('status', '==', 'ordered')
  // 親 members.is_guest == true でフィルタ（クライアント側 or 別クエリで）
```

> `member_orders` に `is_guest` を持たせない方針（02 論点 1.4）のため、ゲストフィルタは「親 `members` ドキュメント側を確認」または「`stripes` 側で判定」のいずれかで行う。Phase 2 で `monthly_usage` コレクションに「ゲスト負担合計」を保持する案も検討。

## 7.3 他パターンとの関係

| ケース | Stripe | 請求書 |
|:--|:--|:--|
| 従業員（enterprise_subsidy 自己負担分） | shokujii の Stripe で即時決済 | 補助分のみ請求書に含む |
| ゲスト無料参加 | **使わない** | **請求書に含む**（`Σ menu_price`） |
| ゲスト self_pay | shokujii の Stripe で即時決済 | 含まない |


# 8. Security Rules

## 8.1 イベントの読み取り

`allow_guest == true` のイベントは、Enterprise URL で**認証不要**で読み取り可能とする。PF 版への一覧掲載は `allow_guest == true` かつ `publish_scope === 'public'` で制御し、イベント詳細の read 許可とは分けて扱う。

```javascript
// events の読み取りルール（02 全体構成 5.2 と同一）
match /communities/{communityId}/events/{eventId} {
  allow read: if data.get('enterprise_id', null) == null     // PF版は従来公開
              || resource.data.allow_guest == true            // ゲスト未認証閲覧
              || (request.auth != null
                  && resource.data.enterprise_id == request.auth.token.enterprise_id);
  // write は既存ルールに従う
}
```

- 未認証（`request.auth` が null）でも、`allow_guest == true` のイベントは読める
- 認証済みの従業員は `enterprise_id` が一致するイベントを読める
- PF版コミュニティ（`enterprise_id` が null）は従来どおり公開
- PF版一覧掲載（将来 G-1）はクエリ B: `where('allow_guest', '==', true)` と `where('publish_scope', '==', 'public')` を使用する。PF ネイティブ除外（MVP 必須）はクエリ A: `where('enterprise_id', '==', null)` と併用し、クライアントでマージする。リンク先は Enterprise URL とする

## 8.2 未認証閲覧時のデータ取得

未認証で Enterprise URL のイベント詳細を表示する場合、ホスト名から `enterprise_id` を解決したうえで、`collectionGroup('events')` で `enterprise_id` / `community_account` / `event_id` を指定してイベントを直接取得する方式を推奨する。これにより、community ドキュメントの読み取りルールを緩和せずに済む。

> `community_account` はイベント側のフィールドとして残る（`05_EventOrder→EventMemberOrder.md` で `community_account` を削除する対象は `members` / `member_orders` / `stripes` のみ。`event` には残る）。

PF版はエンプライベント詳細を直接表示しないため、PF版側で community doc を解決しない。PF版一覧に必要な表示情報（イベント名、企業名、開催日時、カバー画像等）は、一覧クエリで取得できる event / enterprise の範囲に限定する。

## 8.3 注文・members のアクセス

`02_アーキテクチャ` 5.2 で定義した Rules に従う。**ゲスト本人**（`enterprise_id` claim なし）も `request.auth.uid == resource.data.user_id`（または members ネストでは `request.auth.uid == uid`）により自分の注文を read できる。

```javascript
// EventMember (members コレクション)
match /communities/{cid}/events/{eid}/members/{uid} {
  allow read: if resource.data.enterprise_id == null
              || (request.auth != null && (
                   resource.data.enterprise_id == request.auth.token.enterprise_id
                   || request.auth.uid == uid
                   || request.auth.uid == resource.data.user_id
                 ));
  allow write: if false;   // Functions のみ

  match /member_orders/{oid} {
    allow read: if resource.data.enterprise_id == null
                || (request.auth != null && (
                     resource.data.enterprise_id == request.auth.token.enterprise_id
                     || request.auth.uid == resource.data.user_id
                   ));
    allow write: if false;
  }
}

// EventStripe (stripes コレクション): 本人 user_id 一致（ゲストも可）
match /communities/{cid}/events/{eid}/stripes/{sid} {
  allow read: if request.auth != null && request.auth.uid == resource.data.user_id;
  allow write: if false;
}
```

> collectionGroup（`/{path=**}/member_orders/{oid}`）も上記と同一条件とする（02 全体構成 5.2 参照）。PF版（`enterprise_id == null`）は従来どおり公開のため影響なし。
