# エンタープライズ_PF版_共通新機能

## 概要
- エンタープライズ開発において、プラットフォーム版との共通タスクを洗い出す
- どちらにも実装が必要なものについて、先にプラットフォーム版開発として進める
- **エンプラ MVP スコープ外**の項目は PF 版で先行実装し、エンプラ Phase 2 でマージする（`08_実装計画` Phase 0-4 参照）

## 共通タスク
- イベント中止機能（予約申請時・予約承認後参加者内・予約承諾後の参加者ありで返金処理付き）— **エンプラ Phase 2**
- イベントの最小催行人数・自動中止機能 — **エンプラ Phase 2**（PF 正本: `02_主催者獲得と継続/09_...`）
- アカウントの作成機能（明示的サインアップ画面）— **エンプラ Phase 2**
- 割引参加機能（community_bill）— **PF 版のみ**（エンプラは `enterprise_subsidy` で代替。0-2 実装済み）
- イベントの繰り返し作成機能 — **PF 実装済み**（`eventCopyRepeat`、上限 12）。エンプラ固有仕様なし

---

## 共通タスク（詳細）

### 1. イベント中止機能
- 参照: `documents/02_主催者獲得と継続/08_イベントキャンセル_参加者あり_返金.md`
- パターン: 予約申請時（返金不要） / 承認後参加者あり（返金あり）
- 依存: Stripe Refund、community_bill 請求書キャンセル、enterprise_subsidy の monthly_usage 戻し

### 2. イベントの最小催行人数・自動中止機能
- 参照: `documents/02_主催者獲得と継続/09_イベントの最小催行人数設定・自動中止.md`（PF 正本）
- 依存: イベント中止機能（返金処理）、EventMemberOrder 設計
- エンプラ: MVP 外。PF 版実装後に `enterprise` へマージ

### 3. アカウントの作成機能
- 現状: PF版はメール+OTP初回ログインで自動作成
- 課題: 明示的な新規作成画面がない
- エンプラ: 管理者一括作成が前提（別タスク）

### 4. 割引参加機能（community_bill）— PF版のみ
- 参照: `documents/01_マネタイズと決済/03_無料参加・割引参加・クーポン.md`
- 内容: community_bill_settings.type: 'discount'（一部請求書・一部クレカ）
- **エンプラ版では `community_bill` 自体が選択不可**（D-13）。企業補助は `enterprise_subsidy` で代替する

### 5. イベントの繰り返し作成機能
- **PF 実装済み**: `eventCopyRepeat`（`CopyEventDialog`、上限 **12** 件）
- 参照: `documents/02_主催者獲得と継続/05_イベント繰り返し作成.md`
- エンプラ: 固有仕様なし。PF の `base` / `user` 実装をそのまま利用
