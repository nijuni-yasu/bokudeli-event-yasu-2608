本ドキュメントは `01_仕様概要`、`02_全体構成・アーキテクチャ` の決定事項に基づき、エンタープライズ版の**ビジネスモデル・課金ルール・集計方針**を定義する。

食事補助・ゲスト無料分などの**企業向け利用従量請求**の技術詳細は `04_請求` が正本。飲食店向け**送客手数料**は別途実施予定（`01_マネタイズと決済` を参照予定）。本ドキュメントはエンタープライズ版の**マネタイズ全体像**と**企業向け課金（①②）**を定義する。

> **注意（`01_仕様概要` との差分）**  
> `01_仕様概要` には旧来「導入費用（数十万円〜）、月額費用（5万円〜）」の記載があった。本ドキュメントの決定事項が**優先**する。

> **注意（営業・契約の検討案）**  
> 導入費・コミット席数・契約メタデータ等の詳細は `10_競合調査・営業資料/03_課金設計案.md` を参照。  
> **単価体系（定価1,200円・期間別単価）は本書 §2.1 に反映済み。** 本書の P-1〜P-12 が**実装・集計の優先**。

# 1. 概要

## 1.1 ポジショニング

エンタープライズ版は**福利厚生**として導入されることを前提とする。

- 食事費用は企業が半額・全額などのルールで負担する（`enterprise_subsidy`）
- **全従業員が利用する権利を持つ**前提でアカウントを付与する
- 「使っていないから勿体無い」ではなく、「権利はあるが利用は本人の選択」という説明で運用する
- 企業への食事請求は**実費の取次**とし、shokujii のマージンは載せない（収益は ① 席課金と ③ 飲食店手数料で確保）

## 1.2 マネタイズの3系統（ハイブリッド）

エンタープライズ版の shokujii 収益は、**企業向け席課金**と**飲食店向け送客手数料**のハイブリッドとする。

```
企業 ──① 席課金（unit_price/有効アカウント/月）──→ shokujii
企業 ──② 食事実費（補助分・ゲスト分・取次）──→ shokujii ──→ 飲食店（③差引後）
飲食店 ──③ 送客手数料 ──────────────────────→ shokujii
```


| #   | 名称              | 支払者          | 内容                                             | 正本                        |
| --- | --------------- | ------------ | ---------------------------------------------- | ------------------------- |
| ①   | **プラットフォーム利用料** | 企業           | 有効アカウント数に基づく月額固定課金                             | **本ドキュメント** §2            |
| ②   | **食事関連従量（実費）**  | 企業           | `enterprise_subsidy` 補助分、ゲスト無料参加分など。**マージンなし** | `04_請求`                   |
| ③   | **送客手数料**       | 飲食店（partner） | エンプラ経由注文に対する手数料。**別途実施予定**                     | `01_マネタイズと決済`（新規ドキュメント予定） |


### 企業向け請求の分離

企業への請求・ダッシュボード表示は **① と ② のみ**。**③ は企業請求に含めない**（メニュー単価・企業への食事請求額に上乗せしない）。

**`community_bill`（主催者請求書払い）はエンプラ版では選択不可**（P-13）。PF版ではコミュニティ主催者への別請求フローだが、エンプラ版は企業請求（①②）に一本化する。

### PF版との関係


| 収益             | PF版                                        | エンプラ版                                 |
| -------------- | ------------------------------------------ | ------------------------------------- |
| 主催者・企業への手数料上乗せ | `community_bill` 請求書に **10%**（`01_請求書手数料`） | **該当なし**（`community_bill` 非対応。②は実費のみ） |
| 参加者クレカ手数料      | 注文額の約10%（`02_ユーザー決済手数料`）                   | 自己負担分に同様適用可（PF版と同じ Functions 分岐）      |
| 飲食店への手数料       | **別途実施予定**                                 | **別途実施予定**（③。エンプラ経由注文を対象に含める）         |

# 2. プラットフォーム利用料

## 2.1 料金表

### 営業料金（契約期間別）

**定価（list）: 1,200円 / 有効アカウント / 月（税込）**。割引は**契約期間のみ**（人数ボリューム割引なし）。


| 契約期間       | unit_price | 定価比    | 備考                         |
| ---------- | ---------- | ------ | -------------------------- |
| **年間（標準）** | **800円**   | 33%OFF | 推奨。コミットあり                  |
| **6ヶ月**    | **1,000円** | 17%OFF | 年度途中導入                     |
| **3ヶ月**    | **1,200円** | 定価     | 短期 PoC                     |
| **月次**     | **1,200円** | 定価     | 解約柔軟・コミットなし                |
| **早期導入**   | **500円**   | —      | 初回契約期間中のみ（`03_課金設計案` §4.1） |


契約ごとの最終適用単価は `billing_settings.unit_price` に **1本化** して保持する。早期500円と年間800円は**併用しない**（有利な方のみ。`03_課金設計案` §4.1）。

### MVP・実装（現行）


| 項目                       | 金額                                 |
| ------------------------ | ---------------------------------- |
| 初期費用                     | 0円（P-1。導入費30万は `03_課金設計案` §5 で検討中） |
| お試し期間                    | 3ヶ月（プラットフォーム利用料 0円）                |
| `createEnterprise` デフォルト | `unit_price: 500`（早期導入）            |
| 月額（4ヶ月目以降）               | 有効アカウント数 × **`unit_price`**        |


### 計算式

```
platform_fee(YM) =
  if YM がお試し期間内: 0
  else if /enterprises/{id}.is_active == false: 0
  else: billable_account_count(YM) × unit_price

billable_account_count(YM) =
  count(members where billable_in(YM) == true)   // §2.3

unit_price = /enterprises/{id}.billing_settings.unit_price  // 円。デフォルト 500（早期導入）。営業契約は §2.1 の期間別単価
```

> **Phase 2（検討中）:** 年間契約でコミット席数を設ける場合、請求人数を `max(billable_account_count(YM), commit_seats)` とする拡張を検討する（詳細・試算は `03_課金設計案` §7）。MVP は上記の **実数のみ**。

### 計算例


| 条件                               | プラットフォーム利用料（月）                      |
| -------------------------------- | ----------------------------------- |
| お試し2ヶ月目、有効200件                   | 0円                                  |
| 4ヶ月目、有効200件（unit_price 800）      | 200 × 800 = **160,000円**            |
| 4ヶ月目、有効50件・当月停止10件（unit_price 500） | **60 × 500 = 30,000円**（当月に一度でも有効だった60件。先月以前から停止のみの10件は課金しない） |

## 2.3 課金対象アカウントの定義（月内 ever active）

課金対象は **`/enterprises/{enterpriseId}/members/{userId}`** の `EnterpriseMember` のうち、当該暦月 `YM` で **`billable_in(YM) == true`** となるレコード。`admin` / `member` **いずれも課金対象**（全社管理者も1アカウントとしてカウント）。

### 方針（P-8）

| 採用 | 不採用 |
|:--|:--|
| `last_activated_at` / `last_deactivated_at` による月次判定 | 日次 `billing_daily_snapshots` |
| 月次バッチの主ソース = `EnterpriseMember` フィールド | 月次バッチの主ソース = `audit_logs` replay |
| dispute 時 = `audit_logs` replay で検証・手動訂正 | — |

### フィールド更新ルール（MVP 必須）

| 操作 | `last_activated_at` | `last_deactivated_at` | `is_active` |
|:--|:--|:--|:--|
| 作成（`createEnterpriseMembers`） | 現在時刻 | `null` | `true` |
| `enableEnterpriseMember` | 現在時刻 | **変更しない（消さない）** | `true` |
| `disableEnterpriseMember` | 変更しない | 現在時刻 | `false` |

> `is_active` は**現在のログイン可否**、`billable_in(YM)` は**当該月の課金対象**を表す。`enable` 時に `last_deactivated_at` を `null` に戻すと月末ゲーミング（6/30 停止 → 7/1 復活で6月非課金）が可能になるため**禁止**。

### 判定式 `billable_in(YM)`

`YM` の暦月範囲を JST で `[monthStart, monthEnd]`（`monthEnd` = 当該月 23:59:59.999 JST）とする。

```
billable_in(YM) =
  (last_activated_at が YM 内) OR
  (last_deactivated_at が YM 内) OR
  (last_activated_at <= monthEnd
   AND (last_deactivated_at == null OR last_deactivated_at > monthEnd)) OR
  (is_active == true
   AND last_activated_at <= monthEnd
   AND (last_deactivated_at == null OR last_deactivated_at < last_activated_at))
```

- **3行目**: その月をまたいで active だった stint（月初から toggle なしで active、当該月以降に停止、など）。`last_deactivated_at == null` または `last_deactivated_at > monthEnd` のケース。
- **4行目**: **現 stint の継続**。`enable` 時に `last_deactivated_at` を消さないため、再有効化後に当該月内の toggle がなくても、現在有効（`is_active == true`）かつ直近の activate が deactivate より新しければ課金対象。6月停止 → 7/15 復活 → 8月 toggle なし、など。

### 判定例（6月 `YM = 2026-06`）

| ケース | 課金 | 理由 |
|:--|:--|:--|
| 1月からずっと active（toggle なし） | 対象 | 3行目（stint が6月を跨ぐ） |
| 6/20 退職停止 | 対象 | `last_deactivated_at` が6月 |
| 5月まで inactive のまま | 対象外 | いずれの条件にも該当しない |
| 6/1〜6/10 のみ active | 対象 | activate/deactivate が6月 |
| 6月ずっと active、7/1 停止 | 対象 | 3行目（deact が7月 > 6月末） |
| 6/30 停止 → 7/1 復活（deact 保持） | 対象 | `last_deactivated_at` が6月 |
| 6月停止 → 7/15 復活、8月 toggle なしで active 継続 | 対象 | 4行目（現 stint 継続。3行目は `last_deactivated_at` が6月のため非該当） |

月次バッチは **毎月 1 日 00:05 JST** に走る。確定月 `YM` については上記式の **1〜3行目はタイムスタンプのみ**、**4行目は `is_active` を含む**が、いずれも当該月の ever active を表す。バッチ実行時点の `is_active` **だけ**では判定しない（§5.4）。

### 課金対象外（企業・ゲスト）

| 対象 | 理由 |
|:--|:--|
| 当該月に `billable_in(YM) == false` のメンバー | 当該月に一度も active でなかった |
| ゲスト（PF版ユーザー） | `EnterpriseMember` に存在しない（`04_ゲスト参加`） |
| 企業全体停止 | `/enterprises/{id}.is_active == false` の間はプラットフォーム利用料も **0円** |

**ログイン・注文の有無は課金に影響しない**（P-6）。対外名称は「利用料」ではなく **「プラットフォーム利用料（有効アカウント月額）」** を推奨する。

## 2.4 税区分


| 論点                  | 方針                                                                                           |
| ------------------- | -------------------------------------------------------------------------------------------- |
| プラットフォーム利用料         | **税込**で表示・請求（営業標準: 定価1,200円、年間800円等）                                                         |
| `unit_price` の企業別設定 | MVP デフォルト 500 円。営業契約では §2.1 の期間別単価を `billing_settings.unit_price` に設定（MVP は運営が Firestore 更新） |
| 福利厚生費（非課税）との関係      | ① は**システム利用料**であり、食事補助の非課税枠（月7,500円等）とは**別物**として説明・経理処理する                                    |


## 2.5 停止アカウントの運用ガイド

`billable_in(YM)` により、**退職月はその月分まで課金**される（月内 ever active）。先月以前から停止のみのメンバーは当該月非課金。福利厚生の趣旨とコスト最適化のバランスに注意する。


| 推奨用途    | 非推奨用途                  |
| ------- | ---------------------- |
| 退職・契約終了 | 未ログインユーザーの一括停止によるコスト削減 |
| 長期休職    | 部署単位の一時停止（要社内ルール）      |


全社管理者画面のメンバー一覧に **有効件数 / 登録件数** を常時表示し、停止判断の透明性を確保する（`04_全社管理者画面` と連動）。

# 3. 食事関連従量（企業向け・実費）

プラットフォーム利用料（①）とは独立し、**実際の食事イベント利用**に応じて企業へ請求する。**shokujii のマージンは載せない**（P-11）。


| 費用種別          | 集計                                | 月の帰属        |
| ------------- | --------------------------------- | ----------- |
| 福利厚生割引（企業補助分） | `Σ pay_enterprise_subsidy_amount` | **イベント開催月** |
| ゲスト無料参加分      | `Σ menu_price`（`is_guest`）        | **イベント開催月** |


詳細は `04_請求` §2、`04_割引・決済`、`04_ゲスト参加` §7 を参照。

企業向け説明の例:

> プラットフォーム利用料は、社内専用サイトの運用に対する月額です（定価1,200円/人/月、年間契約800円/人/月等）。  
> 食事の会社負担分は、イベント参加・注文に応じた**実費（補助分）**として別途ご請求します。食事代に shokujii の手数料は上乗せしません。当社は飲食店側から送客手数料をいただくモデルです。

# 4. 送客手数料（飲食店向け・別途実施予定）

③ は **PF版と同様の飲食店向けマネタイズ**をエンプラ経由注文にも適用する。**実装・料率の詳細は別ドキュメントで定義**する（本節は方針のみ）。

## 4.1 方針


| 項目       | 方針                                                                                  |
| -------- | ----------------------------------------------------------------------------------- |
| 支払者      | 飲食店（partner）。企業・従業員は③の負担者ではない                                                       |
| 企業請求との関係 | ②の金額に手数料を**上乗せしない**。メニュー表示価格＝企業・従業員が認識する価格                                          |
| PF版との整合  | PF版 `01_請求書手数料`（主催者請求書10%）とは請求先が異なる。エンプラでは主催者手数料の代わりに **店舗側手数料** で shokujii 収益を確保する |
| 収益の役割    | ①が予測可能な MRR、③が GMV 連動のアップサイド。イベント活性化が双方の利益になる                                       |


## 4.2 未定義（別ドキュメントで決定）


| 論点      | 候補                                                  |
| ------- | --------------------------------------------------- |
| 手数料率    | PF版と同一（例: 10%）を初期案とし、エンプラ大口で優遇は Phase 2             |
| 算定基準    | `member_orders` の `menu_price` 合計（税込）を想定            |
| 対象注文    | エンプライベントの `ordered` な全 `member_orders`（支払い方式問わず）を想定 |
| 徴収タイミング | 店舗への振込・精算時に差し引き（PF版の partner 精算フローに合わせる）            |
| 運営向け集計  | 企業ダッシュボードには**表示しない**。運営・partner 向けレポートで別管理          |


## 4.3 収益構造の例（200名・利用率40%・手数料8%仮）


| 収益源                     | 月額（概算）                |
| ----------------------- | --------------------- |
| ① 席課金（200 × 800円・年間契約例） | 160,000円              |
| ③ 送客手数料（流通32万円 × 8%）    | 25,600円               |
| ② 企業食事実費                | shokujii 収益には含めない（取次） |

# 5. 集計・表示

## 5.1 集計タイミング


| 課金種別          | 集計単位        | タイミング                                           | 表示先                        |
| ------------- | ----------- | ----------------------------------------------- | -------------------------- |
| ① プラットフォーム利用料 | 暦月          | **毎月 1 日 00:05 JST** バッチで直前暦月の `billable_in(YM)` 件数を `billing_snapshots` に確定 | 企業ダッシュボード                  |
| ② 食事関連従量      | イベント開催月     | `getDashboardMonthlyData` 既存ロジック（`04_ダッシュボード`）  | 企業ダッシュボード                  |
| ③ 送客手数料       | イベント開催月（想定） | 別途実施予定                                          | **運営・partner のみ**（企業には非表示） |


## 5.2 ダッシュボード表示（MVP）

全社管理者画面（`/admin`）の月別テーブルに列を追加する。


| 列名          | フィールド例                      | 内容                                                |
| ----------- | --------------------------- | ------------------------------------------------- |
| 有効アカウント数    | `active_account_count`      | 当該**暦月**の `billable_in(YM)` 件数（確定月はスナップショット、当月は見込み）              |
| プラットフォーム利用料 | `platform_fee_amount`       | 円。お試し期間内は 0                                       |
| 企業請求見込額（食事） | `enterprise_billing_amount` | 既存（`04_請求`）。**イベント開催月**で帰属                        |
| **合計請求見込額** | `total_billing_amount`      | `platform_fee_amount + enterprise_billing_amount` |
| 確定状態（内部）    | `billing_status`            | `final`（確定月）/ `provisional`（当月見込み）。CSV には任意       |


> 月別テーブルの `year_month` 行には、プラットフォーム利用料（暦月）と食事従量（開催月）が同じキーで並ぶ。帰属ルールが異なる点を画面注記またはヘルプで明示する。

**画面注記（推奨文案）**

> **集計の見方**  
>
> - **プラットフォーム利用料**・**有効アカウント数**: 各**暦月**の **月内 ever active** 件数（当月は見込み。§2.3 `billable_in`）  
> - **企業請求見込額（食事）**: **イベント開催月**の利用実績  
> 同じ「年月」行に、請求サイクルが異なる2種類の金額が並びます。

当月行には **「見込み」** ラベルを表示する。当月の ① は手動請求（MVP-C）の根拠に使わない。

CSV エクスポートにも同列を追加する。

## 5.3 集計実装方針（MVP）


| 項目          | 方針                                                                    |
| ----------- | --------------------------------------------------------------------- |
| 請求根拠        | **月次スナップショット**（`billing_snapshots`）。手動請求（MVP-C）の確定値とする                |
| 有効アカウント数    | `billable_in(YM)` 件数（§2.3）。確定バッチは直前暦月を対象。当月のみライブ集計（見込み） |
| 判定実装        | `common` または `functions` に `isEnterpriseMemberBillableInYearMonth(member, ym)` を共通化 |
| ダッシュボード API | **新設しない**。`getDashboardMonthlyData` を拡張（`04_請求` B-1 と同様）              |
| スナップショット保存  | **`/enterprises/{id}/billing_snapshots/{YYYY-MM}`（MVP-B で実装）**        |


### 参照ルール（`getDashboardMonthlyData`）


| 対象月                 | ① 有効人数・プラットフォーム利用料                                         | ② 食事従量                                      |
| ------------------- | ---------------------------------------------------------- | ------------------------------------------- |
| **過去月**（スナップショットあり） | `billing_snapshots` を表示（**請求確定値**、`billing_status: final`） | スナップショットの `meal_billing_amount` 優先。なければ都度集計 |
| **当月**              | ライブ集計（`billing_status: provisional`）                       | ライブ集計                                       |
| **スナップショット未作成の過去月** | 都度集計 + UI に「未確定」表示                                         | 都度集計                                        |


### billing_snapshots スキーマ

```typescript
interface EnterpriseBillingSnapshot {
  year_month: string              // "2026-07"（暦月）
  active_account_count: number    // billable_in(YM) 件数（§2.3）
  unit_price: number              // 確定時点の billing_settings.unit_price
  platform_fee_amount: number     // count × unit_price（お試し中は 0）
  is_trial: boolean
  meal_billing_amount: number     // enterprise_billing_amount（食事従量・開催月ベース）
  total_billing_amount: number
  snapshot_at: Timestamp          // 集計実行日時
  billing_status: 'final' | 'provisional' // 当月のみ provisional（通常は final）
}
```

> API / CSV では `billing_status` として返却する（Firestore フィールド名と同一）。

## 5.4 月次スナップショットバッチ（MVP-B）


| 項目         | 仕様                                                                        |
| ---------- | ------------------------------------------------------------------------- |
| Function 名 | `captureEnterpriseBillingSnapshots`（Scheduled Function）                   |
| スケジュール     | **毎月 1 日 00:05 JST** に **直前暦月**（例: 7/1 00:05 → `2026-06`）を確定              |
| cron 例     | `5 0 1 * *` + `timeZone: Asia/Tokyo`                                      |
| 確定基準       | 直前暦月 `YM` について全 `EnterpriseMember` に §2.3 **`billable_in(YM)`** を適用（バッチ実行時点の `is_active` のみでは判定しない）             |
| タイムゾーン     | `Asia/Tokyo`（`onSchedule` の `timeZone`）                                   |
| 対象         | **全 `Enterprise`**（`is_active == false` 含む。停止企業も ② の未確定請求を残す）             |
| ① の集計      | `billable_in(YM)` 件数 × `unit_price`（お試し・**企業停止時は 0**） |
| ② の集計      | `getDashboardMonthlyData` と同一ロジックで `meal_billing_amount` を算出              |
| 保存         | `/enterprises/{id}/billing_snapshots/{YYYY-MM}` に upsert                  |
| 再実行        | 運営向け手動 Callable（障害復旧・ dispute 用）。`snapshot_at` を更新                        |


> 月中にメンバーを停止・復活しても、**確定済み過去月のスナップショットは自動では書き換えない**。訂正は運営が手動 Callable または Firestore 更新（監査ログ必須）。

### dispute 時の監査ログ replay（補助）

月次バッチの**主ソースは `EnterpriseMember` のタイムスタンプ**とする。企業から異議申し立てがあった場合、運営は当該 `userId` について `audit_logs` の `account_create` / `account_disable` / `account_enable`（`target_type == 'member'`）を `timestamp` 昇順に replay し、§2.3 と整合するか検証する。不一致時は replay 結果を正として手動 Callable で `billing_snapshots` を訂正する。

> 監査ログは `04_監査ログ` のとおり書き込み欠損しうるため、**毎月の自動集計の唯一の根拠にはしない**。日次スナップショットは採用しない。

# 6. データモデル拡張

`02_全体構成・アーキテクチャ` の `Enterprise` に以下を追加する。

```typescript
interface EnterpriseBillingSettings {
  unit_price: number              // デフォルト 500（円/有効アカウント/月）
  trial_months: number            // デフォルト 3
  billing_trial_ends_at: Timestamp // お試し終了日時（createEnterprise 時に自動設定）
}

// Enterprise に追加
billing_settings: EnterpriseBillingSettings
```


| フィールド                   | 設定タイミング                                                       |
| ----------------------- | ------------------------------------------------------------- |
| `billing_settings`      | `createEnterprise` で初期化（`unit_price: 500`, `trial_months: 3`） |
| `billing_trial_ends_at` | 同上。営業上の個別調整は運営が Firestore 更新（MVP）                             |


`EnterpriseMember.is_active` の意味は変更しない（`04_認証・アカウント管理`）。課金判定用に以下を **MVP 必須**で追加する。

```typescript
// EnterpriseMember に追加（MVP）
last_activated_at: Timestamp | null    // 直近の有効化（作成時・enable 時に更新）
last_deactivated_at: Timestamp | null  // 直近の停止（disable 時に更新。enable では消さない）
```

| フィールド | 設定タイミング |
|:--|:--|
| `last_activated_at` | `createEnterpriseMembers`（active 作成時）、`enableEnterpriseMember` |
| `last_deactivated_at` | `disableEnterpriseMember` のみ。`enable` では **null に戻さない** |

### Phase 2 で追加検討するフィールド（`03_課金設計案` 参照）

```typescript
interface EnterpriseBillingSettings {
  unit_price: number
  trial_months: number
  billing_trial_ends_at: Timestamp
  // --- 以下 Phase 2（契約プラン確定後）---
  commit_seats?: number           // コミット席数。未設定時は MVP と同様に実数のみ
  contract_term_months?: number // 12 / 6 / 3 / 1
  contract_ends_at?: Timestamp
  billing_cycle?: 'monthly'       // MVP は monthly 固定
}
```

> 更新料は廃止し、短期契約のコストは **unit_price に織り込む**（`03_課金設計案` §6.0）。`renewal_fee` フィールドは追加しない。

# 7. 請求・入金フロー

## 7.1 MVP（企業向け）


| ステップ | 担当   | 内容                                                               |
| ---- | ---- | ---------------------------------------------------------------- |
| 1    | システム | **毎月 1 日 00:05 JST** バッチで**直前暦月**を `billing_snapshots` に確定（§5.4） |
| 2    | 運営   | 翌月 2〜5 営業日にスナップショット・ダッシュボードを確認・承認                                |
| 3    | 運営   | 請求書送付（プラットフォーム利用料 + 食事従量を**明細分離**）。根拠は `billing_snapshots`       |
| 4    | 企業   | 請求書払い（振込等。`Enterprise.payment_method` はイベント決済用。企業向け①②請求は契約書＋振込）  |


**契約期間と請求サイクル**

- MVP では **契約期間の縛りは契約書・営業運用** で管理し、システム請求は **毎月後払い**（①＋②）とする。
- 年間契約でも **一括前払いは不要**。①は暦月ごと、②は利用実績ごとに請求する（`03_課金設計案` §6.2）。

PDF 自動発行は `04_請求` Phase 2 と合わせて検討する。

③ 送客手数料の店舗精算は、PF版 partner 向けフローと合わせて別途定義する（本書の MVP スコープ外）。

## 7.2 Phase 2（自動課金）


| 項目          | 方針案                                            |
| ----------- | ---------------------------------------------- |
| プラットフォーム利用料 | Stripe Subscription（企業単位）+ quantity（有効アカウント数）  |
| 食事従量        | 従来どおり後請求・請求書                                   |
| 失敗時         | リトライ → 全社管理者通知 → 企業 `is_active` 停止は最終手段（要ポリシー） |

# 8. 対外メッセージ（たたき）

契約書・営業資料・ヘルプで共通利用する。

### 企業向け

> **shokujii エンタープライズの料金（企業様）**  
>
> - 初期費用: 無料（導入費の定価・キャンペーンは営業資料参照）  
> - お試し: ご契約から3ヶ月間、プラットフォーム利用料は無料  
> - 月額（① プラットフォーム利用料）: 有効アカウント 1 件あたり **定価1,200円**（税込）  
>   - **年間契約（標準）: 800円/人/月**（33%OFF）  
>   - 6ヶ月: 1,000円 / 3ヶ月・月次: 1,200円（定価）  
>   - 早期導入キャンペーン: 500円/人/月（初回契約期間中）  
>   - 人数によるボリューム割引はありません  
>   - 当該月に一度でも有効だったアカウント（月内 ever active）が課金対象。退職月はその月分まで課金  
>   - ログインや注文の有無にかかわらず、有効アカウント数に基づきます
> - 食事の会社負担分（福利厚生補助・ゲスト無料分等）: ご利用に応じた**実費**として別途ご請求（shokujii の手数料は上乗せしません）
