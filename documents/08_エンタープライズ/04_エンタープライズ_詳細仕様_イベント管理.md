# イベント管理 詳細仕様

本ドキュメントは `01_エンタープライズ_仕様概要`、`02_エンタープライズ_全体構成・アーキテクチャ`、`04_エンタープライズ_詳細仕様_全社管理者画面` の決定事項に基づき、エンタープライズ版のイベント関連機能（PF版との差分・コミュニティ作成）の仕様を詳細に定義する。

## 前提とする仕様書

本ドキュメントは EventMemberOrder 設計（`05_EventOrder→EventMemberOrder.md`）を前提とする。注文集計の参照先は `members/{userId}/member_orders/{orderId}` に変更される（旧 `orders` コレクションは廃止）。

**PF 版共通機能**（イベントコピー・繰り返し作成、最小催行人数・自動中止、参加者ありイベント中止・返金）はエンプラ MVP のスコープ外。PF 版の `base` / `user` 実装をそのまま利用し、正本は `documents/02_主催者獲得と継続/` 配下を参照する。

# 2. プラットフォーム版との差分

## 2.1 エンプラ版で追加する機能

| 機能 | 概要 |
|:--|:--|
| ゲスト参加 | `allow_guest`, `guest_payment`（`04_ゲスト参加` 参照） |
| 福利厚生割引 | `event_payment: 'enterprise_subsidy'`（`04_割引・決済` 参照） |

## 2.2 エンプラ版で変更する機能

| 機能 | PF版 | エンプラ版 |
|:--|:--|:--|
| 支払い方式 | user_advance, user_on_day, community_bill | enterprise_subsidy（デフォルト）, user_advance。**community_bill / user_on_day は選択不可** |
| コミュニティ作成 | 即時公開（**作成: 全従業員**） | **MVP も即時公開**。**更新: manager 限定**（PF 同等）。Phase 2 で承認フロー |

## 2.3 エンプラ版で非表示にする機能

| 機能 | 非表示箇所 | 理由 |
|:--|:--|:--|
| SNS投稿ボタン | イベントページ（`EventDetailsCard.vue` の shareSnsButton） | 社内利用のため不要 |
| 注文完了時のSNSシェア | `UserSuccessJoinEventDialog.vue` の「参加することをSNSで友だちにも知らせよう」 | 同上 |
| ハッシュタグ入力 | イベント編集の `event_sns_hash_tag`、コミュニティ編集の `community_sns_hash_tag` | SNS投稿機能を使わないため |
| 当日払い | `user_on_day` 選択肢 | deprecated。PF版でも利用実績なし |
| 主催者請求書払い（イベント作成） | `community_bill` 選択肢・`community_bill_settings` UI（`EventDetailCard.vue`） | エンプラ版では企業請求一本化のため非対応（D-13） |
| コミュニティ manage「請求書」タブ | `/manage/community/{account}/invoice`（`CommunityInvoice.vue`）。tabs から `invoice` を omit | `community_bill` イベントが作れないため常に空。D-13 |
| イベント manage の請求書案内 | `EventCommunityBillAlert.vue`（overview タブ） | 同上 |
| 主催者請求書 PDF ページ | `/manage/event/{eventId}/invoice`（`EventBillInvoicePdf.vue`） | 同上。URL 直打ち時は 404 または overview へリダイレクト |
| コミュニティ設定の請求書用氏名・メール | `CommunityEdit.vue` の `community_bill_fullname` / `community_bill_email` | `community_bill` 非対応のため入力不要 |

### 2.3.1 非表示の実装方針

- `enterprise` パッケージでは、base の `EventDetailsCard`、`UserSuccessJoinEventDialog`、`EventDetailCard`、`CommunitySetupForm` 等をラップし、SNS・ハッシュタグ関連の UI を出さない
- または base に `hideSnsFeatures?: boolean` のような props を追加し、エンプラ版から `true` で渡す
- 既存データの `event_sns_hash_tag` は DB 上は残すが、エンプラ版 UI では表示・編集しない
- **`community_bill` 関連**: base に `hideCommunityBillFeatures?: boolean`（または enterprise 側で tabs / コンポーネントを omit）を設け、次を出さない
  - コミュニティ manage の `tabs` 配列から `'invoice'` を除外（PF版は `events`, `member`, `letter`, `album`, `invoice`, `slackSetting`, `settings`）
  - イベント overview の `EventCommunityBillAlert`
  - イベントルートの `invoice` タブ（存在する場合）および `EventBillInvoicePdf` ページ
  - コミュニティ編集フォームの請求書用氏名・メール欄

### 2.3.2 主催者請求書 UI と企業請求の区別

| 対象 | PF版 `CommunityInvoice` | エンプラ版 企業請求（`04_請求` / 全社管理者ダッシュボード） |
|:--|:--|:--|
| 請求先 | コミュニティ主催者（`community_bill` イベント単位） | 企業（全社管理者）。食事補助・ゲスト無料分 |
| 画面 | コミュニティ manage「請求書」タブ | `/admin` ダッシュボード・CSV（MVP）。PDF は Phase 2 |
| エンプラ版 | **非表示**（D-13） | **こちらが正** |

> PF版の `getEventBillInvoicePdf` / `createEventBillInvoice`（`community_bill` 向け）は、エンプラ版 UI からは呼び出さない。エンプラ向け企業請求 PDF は `04_請求` Phase 2 で別途定義する。

# 4. その他検討事項

## 4.1 イベント公開設定（`is_public` / URL 限定公開）

PF版の既存 `is_public` 概念をそのまま流用し、エンプラ版では**テナント内での出し分け**に意味を限定する。

| `is_public` | 一覧表示 | アクセス |
|:--|:--|:--|
| `true` | 同一 enterprise 従業員のイベント / コミュニティ一覧に表示 | 同社従業員 + （`allow_guest == true` ならゲストも URL から） |
| `false`（URL 限定） | 一覧に出さない | URL を知る人のみ |

### 一覧クエリ

```typescript
// エンプラ版イベント一覧
collectionGroup('events')
  .where('enterprise_id', '==', myEnterpriseId)
  .where('is_public', '==', true)
```

### Security Rules

events の read Rules は `02_全体構成 5.2` / `04_ゲスト参加` §8.1 と同一:

```javascript
allow read: if resource.data.enterprise_id == null
            || resource.data.allow_guest == true
            || (request.auth != null
                && resource.data.enterprise_id == request.auth.token.enterprise_id);
```

- `is_public == false` でも、上記 Rules により URL 直アクセスは可能（一覧に出ないだけ）
- ゲスト未認証閲覧は `allow_guest == true` のイベントのみ
