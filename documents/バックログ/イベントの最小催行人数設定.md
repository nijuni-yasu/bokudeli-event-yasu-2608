# イベントの最小催行人数設定

## 1. 概要
### 1.1 機能の目的
イベント主催者が最小催行人数を設定し、参加人数が不足した場合にイベントを自動的に中止する機能を提供する。

### 1.2 主要な機能
- 最小催行人数の設定・解除
- 判断タイミングの設定
- 自動的なイベント中止処理
- 参加者への返金処理

### 1.3 対象ユーザー
- イベント主催者（コミュニティ管理者）
- イベント参加者

## 2. ねらい
### 2.1 ビジネス目標
- 主催者のリスク軽減（参加人数不足による損失回避）
- イベント品質の維持（適切な規模での開催）

### 2.2 ユーザー価値
- **主催者**: 参加人数不足による損失リスクの軽減
- **参加者**: 適切な規模のイベントへの参加

### 2.3 成功指標（KPI）
- 最小催行人数設定イベントの開催率向上
- 主催者と参加者の満足度向上

## 3. 前提条件
### 3.1 技術的前提条件
- イベント作成・編集機能が実装済み
- 決済・返金システムが実装済み（`12_イベント中止と返金.md`）

### 3.2 ビジネス的前提条件
- イベントに注文期限（`event_deadline_datetime`）が設定されている
- 参加者の決済が完了している

### 3.3 依存関係
- イベント管理機能
- 決済・返金機能
- 通知機能（メール）

## 4. 画面仕様
### 4.1 画面遷移
イベント作成・編集画面 → 最小催行人数設定セクション

### 4.2 UI要素
- **最小催行人数設定トグル**: 設定する/設定しない
- **最小催行人数入力**: 1-10名の数値入力
- **判断タイミング選択**: 注文期限のX日前（1-7日前）
- **設定説明**: 機能の動作説明

## 5. 技術仕様・データ構造設計
### 5.1 Firestoreスキーマ
```typescript
// Eventスキーマに追加するフィールド
interface Event {
  // 既存フィールド...
  event_id: string;
  event_name: string;
  event_deadline_datetime: Timestamp;
  event_max_people: number;
  event_num_members: number;
  // ... その他の既存フィールド
  
  // 最小催行人数設定（新規追加）
  minimum_participants?: {
    enabled: boolean;           // 最小催行人数設定の有効/無効
    count: number;              // 最小催行人数（1-10）
    judgment_days_before: number; // 判断日（注文期限のX日前、1-7）
    judgment_datetime: Timestamp; // 判断日時（注文期限から算出。判断日が注文期限から1日前なら、注文期限の24時間前。
  };
}
```

### 5.2 Zodスキーマ定義
```typescript
// common/src/schemas/event.ts に追加
export const MinimumParticipantsSchema = z.object({
  enabled: z.boolean(),
  count: z.number().min(1).max(10),
  judgment_days_before: z.number().min(1).max(7),
  judgment_datetime: z.instanceof(Timestamp) // 判断日時（Firestoreに保存済み）
});

export const EventDbSchema = z.object({
  // 既存フィールド...
  
  // 最小催行人数設定（オプショナル）
  minimum_participants: MinimumParticipantsSchema.optional(),
});
```

### 5.3 Firestoreフロントエンド処理
- **データ取得処理**: イベント作成・編集時に最小催行人数設定を取得
- **データ更新処理**: イベント保存時に最小催行人数設定を更新
- **リアルタイム監視**: 参加者数の変更を監視（`event_num_members`）

### 5.4 Firestoreセキュリティルール
更新なし

### 5.5 Functions設計
#### 5.5.1 Trigger Functions（自動実行）
- `checkMinimumParticipants`: 最小催行人数の判定
  - **トリガー**: Firestoreの`judgment_datetime`に基づくCloud Scheduler（定期実行）
  - **処理内容**: 
    - 現在時刻が`judgment_datetime`に達したイベントを検索
    - 参加者数をチェック（`event_num_members`）
    - 不足時はイベント中止処理を実行
    - 参加者全員に返金処理と通知を実行
  - **権限**: システム権限

#### 5.5.2 定期実行処理
- `processMinimumParticipantsChecks`: 最小催行人数チェックの定期実行
  - **トリガー**: Cloud Scheduler（毎分実行）
  - **処理内容**: 
    - `judgment_datetime`が現在時刻に達したイベントを検索
    - 該当イベントに対して最小催行人数チェックを実行

### 5.6 処理フロー
1. イベント作成・編集時に最小催行人数設定を保存
2. 設定保存時に注文期限から判断日時を計算し、`judgment_datetime`に保存
3. Cloud Schedulerが定期実行（毎分）で`judgment_datetime`をチェック
4. 判断日時に達したイベントの参加者数をチェック
5. 参加者数が不足している場合、イベント中止処理を実行
6. 参加者全員に返金処理と通知を実行

## 7. 注意事項
### 7.1 既存システムへの影響
- イベント作成・編集画面のUI変更が必要
- イベントスキーマの拡張が必要
- 既存のイベントには影響なし（オプショナル機能）

### 7.2 運用考慮事項
- 判断日時のタイムゾーン考慮が必要（Asia/Tokyo）
- 返金処理の失敗時の再試行機能
- Cloud Schedulerの定期実行管理（毎分実行）
- 通知配信の失敗時の再試行機能
- イベント削除時の処理（`judgment_datetime`の削除は不要）
- 定期実行処理の負荷管理（大量のイベントがある場合の考慮）

### 7.3 セキュリティ考慮事項
- 最小催行人数設定の権限チェック
- 返金処理のセキュリティ
- 通知配信の認証・認可
