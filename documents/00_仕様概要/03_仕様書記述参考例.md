## 1. TypeScriptスキーマ定義の参考例

### 1.1 基本的なスキーマ定義
```typescript
// common/src/schemas/NewFeature.ts
import { z } from 'zod'

// データベーススキーマ
const NewFeatureDbSchema = z.object({
  // 必須フィールド
  feature_id: z.string(),
  feature_name: z.string().min(1),
  
  // オプションフィールド
  feature_description: z.string().optional(),
  
  // タイムスタンプ
  created_at: z.date(),
  updated_at: z.date(),
})

// クラス定義
export class NewFeature {
  feature_id: string = ''
  feature_name: string = ''
  feature_description?: string
  created_at: Date = new Date()
  updated_at: Date = new Date()
  
  // バリデーション
  validate(): boolean {
    return this.feature_name.length > 0
  }
  
  // ファクトリメソッド
  static fromDb(data: any): NewFeature {
    const feature = new NewFeature()
    feature.feature_id = data.feature_id
    feature.feature_name = data.feature_name
    feature.feature_description = data.feature_description
    feature.created_at = data.created_at.toDate()
    feature.updated_at = data.updated_at.toDate()
    return feature
  }
}
```

## 2. Functions設計の参考例

### 2.1 Callable Function（フロントエンドから呼び出し）
```typescript
// functions/default/src/apis/newFeature.ts
import { onCall, HttpsError } from 'firebase-functions/https'
import { getNewFeature } from '../stores/newFeature.js'

export const createNewFeature = onCall(async (request) => {
  // 認証チェック
  const uid = request.auth?.uid
  if (uid == null) {
    throw new HttpsError('unauthenticated', '認証が必要です')
  }
  
  // 引数の取得とバリデーション
  const { featureName, description } = request.data
  if (!featureName || featureName.length === 0) {
    throw new HttpsError('invalid-argument', '機能名は必須です')
  }
  
  // ビジネスロジック実行
  const feature = await createNewFeatureInDb(uid, featureName, description)
  
  // レスポンス返却
  return {
    success: true,
    feature_id: feature.feature_id,
    feature_name: feature.feature_name
  }
})

export const getNewFeatureById = onCall(async (request) => {
  const uid = request.auth?.uid
  if (uid == null) {
    throw new HttpsError('unauthenticated', '認証が必要です')
  }
  
  const { featureId } = request.data
  if (!featureId) {
    throw new HttpsError('invalid-argument', '機能IDは必須です')
  }
  
  const feature = await getNewFeature(featureId)
  if (!feature) {
    throw new HttpsError('not-found', '機能が見つかりません')
  }
  
  return feature
})
```

### 2.2 Trigger Function（自動実行）
```typescript
// functions/default/src/triggers/newFeature.ts
import { onDocumentCreated, onDocumentUpdated } from 'firebase-functions/firestore'
import { sendNotification } from '../utils/notification.js'

// 新機能作成時の自動処理
export const onNewFeatureCreated = onDocumentCreated(
  'features/{featureId}',
  async (event) => {
    const featureData = event.data?.data()
    if (!featureData) return
    
    // 管理者に通知
    await sendNotification({
      type: 'new_feature_created',
      title: '新機能が作成されました',
      body: `機能名: ${featureData.feature_name}`,
      target_users: ['admin']
    })
    
    // ログ記録
    console.log(`New feature created: ${featureData.feature_id}`)
  }
)

// 機能更新時の自動処理
export const onNewFeatureUpdated = onDocumentUpdated(
  'features/{featureId}',
  async (event) => {
    const beforeData = event.data?.before.data()
    const afterData = event.data?.after.data()
    
    if (beforeData?.feature_name !== afterData?.feature_name) {
      // 機能名が変更された場合の処理
      await updateRelatedDocuments(afterData?.feature_id, afterData?.feature_name)
    }
  }
)
```

### 2.3 Scheduled Function（定期実行）
```typescript
// functions/default/src/scheduled/newFeature.ts
import { onSchedule } from 'firebase-functions/scheduler'
import { cleanupOldFeatures } from '../utils/cleanup.js'

// 毎日午前2時に実行
export const scheduledFeatureCleanup = onSchedule(
  '0 2 * * *',
  async () => {
    console.log('Starting scheduled feature cleanup...')
    
    try {
      const deletedCount = await cleanupOldFeatures()
      console.log(`Cleaned up ${deletedCount} old features`)
    } catch (error) {
      console.error('Feature cleanup failed:', error)
    }
  }
)

// 毎週月曜日の午前9時に実行
export const weeklyFeatureReport = onSchedule(
  '0 9 * * 1',
  async () => {
    console.log('Generating weekly feature report...')
    
    try {
      const report = await generateFeatureReport()
      await sendWeeklyReport(report)
      console.log('Weekly report sent successfully')
    } catch (error) {
      console.error('Weekly report generation failed:', error)
    }
  }
```

## 3. 処理フローの参考例

### 3.1 基本的な処理フロー
```markdown
### 新機能作成の処理フロー
1. ユーザーが新機能作成画面で情報を入力
2. フロントエンドでバリデーション（機能名の必須チェック等）
3. Callable Function `createNewFeature`を呼び出し
4. Firebase Functionで認証チェック
5. 引数のバリデーション
6. Firestoreに新機能データを保存
7. Trigger Function `onNewFeatureCreated`が自動実行
8. 管理者に通知送信
9. レスポンスをフロントエンドに返却
10. フロントエンドで成功メッセージを表示
```

### 3.2 エラーハンドリングを含む処理フロー
```markdown
### 注文処理の処理フロー
1. ユーザーがカート画面で注文確定ボタンをクリック
2. フロントエンドで在庫チェック
3. Callable Function `createOrder`を呼び出し
4. Firebase Functionで認証チェック
5. 注文データのバリデーション
6. 在庫の再確認（同時注文対策）
7. 決済処理実行
   - 成功: 注文データをFirestoreに保存
   - 失敗: エラーメッセージを返却
8. Trigger Function `onOrderCreated`が自動実行
9. 店舗に注文通知送信
10. ユーザーに注文完了メール送信
11. レスポンスをフロントエンドに返却
12. フロントエンドで結果表示
    - 成功: 注文完了画面
    - 失敗: エラーメッセージ表示
```

## 6. 注意事項の参考例

### 6.1 既存システムへの影響
```markdown
### 既存システムへの影響
- **データベース**: 新しいコレクション`features`を追加
- **認証**: 既存の認証システムを利用
- **通知**: 既存の通知システムに新機能作成通知を追加
- **UI**: 既存のナビゲーションに新機能管理メニューを追加
```

### 6.2 セキュリティ考慮事項
```markdown
### セキュリティ考慮事項
- **認証**: すべてのFunctionsで認証チェックを必須とする
- **権限**: 機能の作成・編集・削除は管理者のみ許可
- **入力値検証**: すべての入力値に対して適切なバリデーションを実装
- **SQLインジェクション対策**: Firestoreのクエリビルダーを使用
- **XSS対策**: フロントエンドでの適切なエスケープ処理
```

### 6.3 運用考慮事項
```markdown
### 運用考慮事項
- **ログ**: 機能の作成・編集・削除時に適切なログを記録
- **バックアップ**: 機能データの定期バックアップを設定
- **監視**: 機能作成の異常な増加を監視
- **パフォーマンス**: 機能一覧のページネーション実装
``` 
