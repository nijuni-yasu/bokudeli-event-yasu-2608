# メニューの並べ変え

## 1. 概要
### 1.1 機能の目的
admin画面でメニューの表示順序を動的に変更できるようにし、主催者がイベントページやイベント作成画面でメニューを希望する順序で表示できるようにする。

### 1.2 主要な機能
- admin画面（admin/src/pages/menu.vue）でのメニュー並び順変更機能（ドラッグ&ドロップ等のUI実装）
- メニューに`sort_number`フィールド（number型）を追加し、並び順を保存
- イベントスナップショット作成時に`sort_number`をコピー
- イベントスナップショット作成時に`updatedAt`を現在時刻に設定
- イベントページのメニュー一覧表示で`sort_number`順にソート
- イベント作成画面のメニュー一覧表示で`sort_number`順にソート

### 1.3 対象ユーザー
- 飲食店・パートナー（admin画面利用者）

## 2. ねらい
### 2.1 ビジネス目標
- メニュー表示順の最適化による注文数の向上
- 人気メニューを上位に表示することで売上向上

### 2.2 ユーザー価値
- メニューの表示順を自由にカスタマイズできる
- 人気メニューやおすすめメニューを目立つ位置に配置できる

### 2.3 成功指標（KPI）
- メニュー並び順変更機能の利用率
- 並び順変更後の注文数・売上の変化

## 3. 前提条件
### 3.1 技術的前提条件
- Firestoreにメニュー情報が正しく保存されていること
- ユーザーがメニュー編集権限を持っていること
- admin画面が正常に動作していること

### 3.2 ビジネス的前提条件
- メニューが既に作成されていること

### 3.3 依存関係
- admin画面（admin/src/pages/menu.vue）
- パートナーメニュースキーマ（common/src/schemas/PartnerMenu.ts）
- イベントメニュースキーマ（common/src/schemas/EventMenu.ts）
- イベントスナップショット機能（functions/default/src/eventSnapshot.ts）
- イベントページのメニュー表示（base/src/components/EventMenuList.vue）
- イベント作成画面のメニュー表示（base/src/components/eventcreate/EventMenu.vue）

## 4. 画面仕様
### 4.1 画面遷移
```
admin画面
  └─ メニュー管理画面（menu.vue）
       └─ メニュー並び順変更UI（ドラッグ&ドロップ等）
            └─ 並び順保存 → メニュー一覧に反映
```

### 4.2 UI要素
#### 4.2.1 メニュー並び順変更UI
- **ドラッグ&ドロップ機能**
  - メニューカードをドラッグして順序を変更
  - または上下矢印ボタンで順序を変更
  - リアルタイムで順序変更を反映
- **保存ボタン**
  - カラー: プライマリ
  - 状態: 順序変更時のみ有効
  - アクション: `sort_number`を保存してFirestoreを更新

#### 4.2.2 メニュー一覧表示
- **admin画面（menu.vue）**
  - 表示内容: メニューカード一覧
  - ソート: `sort_number`の昇順（未設定の場合は`updatedAt`の降順）
- **イベントページ（EventMenuList.vue）**
  - 表示内容: イベントメニュー一覧
  - ソート: `sort_number`の昇順（未設定の場合は`updatedAt`の降順）
- **イベント作成画面（EventMenu.vue）**
  - 表示内容: パートナーメニュー一覧
  - ソート: `sort_number`の昇順（未設定の場合は`updatedAt`の降順）

### 5.2 Firestoreフロントエンド処理
- **データ取得処理**: メニュー一覧を取得し、`sort_number`でソート
  ```typescript
  // admin/src/pages/menu.vue
  const menus = computed(() => {
    const sortedMenus = partnerStore.menus?.sort((a, b) => {
      // sort_numberが設定されている場合はそれでソート、未設定の場合はupdatedAtでソート
      if (a.sort_number != null && b.sort_number != null) {
        return a.sort_number - b.sort_number
      }
      if (a.sort_number != null) return -1
      if (b.sort_number != null) return 1
      return (b.updatedAt?.valueOf() ?? 0) - (a.updatedAt?.valueOf() ?? 0)
    }) ?? []
    return sortedMenus
  })
  ```
- **データ更新処理**: 並び順変更時に`sort_number`を更新
  ```typescript
  // admin/src/pages/menu.vue
  const updateMenuSortOrder = async (menuIds: string[]) => {
    const batch = writeBatch(db)
    menuIds.forEach((menuId, index) => {
      const menuRef = doc(db, `partners/${partnerId}/menus/${menuId}`)
      batch.update(menuRef, { sort_number: index })
    })
    await batch.commit()
  }
  ```
- **リアルタイム監視**: メニュー一覧の変更を監視

  ```typescript
  const makeMenuSnapshot = async (partnerId: string, eventId: string, startDatetime: number): Promise<void> =>
    getFirestore().runTransaction(async (transaction) => {
      const partner = await getPartner(partnerId)
      const event = await getEvent(eventId, transaction)
      if (partner == null || event == null) {
        throw new Error(`Partner ${partnerId} or Event ${eventId} not found`)
      }
      const partnerMenus = await partner.getMenus(transaction)
      const eventMenus = await event.getMenus(transaction)
      // 既存のメニューを削除
      await Promise.all(
        eventMenus.map(async (menu) => {
          await event.deleteMenu(menu, transaction)
        }),
      )

      // パートナーのメニューをコピー（期間が重なるもののみ）
      const now = Date.now() // 現在時刻を取得
      await Promise.all(
        partnerMenus.map(async (menu) => {
          const menuDateStart = menu.menu_date_start
          const menuDateEnd = menu.menu_date_end

          // メニューの日付が未設定、またはイベント開始時刻がメニューの期間内の場合はコピー
          if (
            menuDateStart == null ||
            menuDateEnd == null ||
            (menuDateStart <= startDatetime && startDatetime <= menuDateEnd)
          ) {
            // sort_numberもコピー
            const eventMenu = new EventMenu(eventId, menu.menu_id, {
              ...menu,
              sort_number: menu.sort_number, // sort_numberをコピー
            })
            eventMenu.updatedAt = now // updatedAtを現在時刻に設定
            await event.saveMenu(eventMenu, transaction)
          }
        }),
      )
    })
  ```

### 5.6 処理フロー
#### 5.6.1 メニュー並び順変更の処理フロー
1. ユーザーがadmin画面（menu.vue）でメニューの並び順を変更（ドラッグ&ドロップ等）
2. フロントエンドでバリデーション（並び順が正しく設定されているか）
3. 各メニューの`sort_number`を更新（Firestoreに直接書き込み）
4. 更新成功後、メニュー一覧を再取得して表示を更新
5. エラー時はエラーメッセージを表示

#### 5.6.2 イベントスナップショット作成時の処理フロー
1. イベント作成・更新時にTrigger Function `makeShopSnapshotToEvent`が自動実行
2. パートナーのメニューを取得
3. イベントの既存メニューを削除
4. パートナーのメニューをイベントメニューにコピー
   - `sort_number`もコピー
   - `updatedAt`を現在時刻に設定
5. イベントメニューを保存

#### 5.6.3 メニュー表示時の処理フロー
1. メニュー一覧を取得
2. `sort_number`でソート（昇順）
   - `sort_number`が未設定の場合は`updatedAt`でソート（降順）
3. ソート済みメニュー一覧を表示

## 6. データマイグレーション（必要な場合）
### 6.1 マイグレーション対象
- **既存のPartnerMenu**: `sort_number`フィールドが未設定の場合は、`updatedAt`の降順で自動的に番号を付与
- **既存のEventMenu**: `sort_number`フィールドが未設定の場合は、`updatedAt`の降順で自動的に番号を付与

### 6.2 マイグレーション実装
```typescript
// functions/default/src/migrations/migrateMenuSortNumber.ts
export const migrateMenuSortNumber = onCall(async (request) => {
  const uid = request.auth?.uid
  if (uid == null) {
    throw new HttpsError('unauthenticated', '認証が必要です')
  }
  
  // 管理者権限チェック（必要に応じて）
  
  try {
    const db = getFirestore()
    const partnersSnapshot = await db.collection('partners').get()
    
    for (const partnerDoc of partnersSnapshot.docs) {
      const partnerId = partnerDoc.id
      const menusSnapshot = await db.collection(`partners/${partnerId}/menus`).get()
      
      // updatedAtでソートしてsort_numberを付与
      const menus = menusSnapshot.docs
        .map(doc => ({ id: doc.id, data: doc.data(), updatedAt: doc.data().updatedAt?.toMillis() ?? 0 }))
        .sort((a, b) => b.updatedAt - a.updatedAt)
      
      const batch = db.batch()
      menus.forEach((menu, index) => {
        const menuRef = db.doc(`partners/${partnerId}/menus/${menu.id}`)
        if (menu.data.sort_number == null) {
          batch.update(menuRef, { sort_number: index })
        }
      })
      
      await batch.commit()
    }
    
    return {
      success: true,
      migrated_count: partnersSnapshot.docs.length
    }
  } catch (error) {
    console.error('Migration failed:', error)
    throw new HttpsError('internal', 'マイグレーション処理に失敗しました')
  }
})
```

## 8. 注意事項
### 8.1 既存システムへの影響
#### 8.1.1 データベース構造への影響
- **既存コレクションの変更**: `partners/{partnerId}/menus`と`communities/{communityId}/events/{eventId}/menus`に`sort_number`フィールドを追加
- **既存データへの影響**: `sort_number`が未設定のメニューは`updatedAt`でソートされるため、既存の動作に影響なし

#### 8.1.2 アプリケーションへの影響
- **フロントエンド**: 
  - admin画面（menu.vue）: メニュー並び順変更UIの追加
  - イベントページ（EventMenuList.vue）: ソートロジックの変更
  - イベント作成画面（EventMenu.vue）: ソートロジックの変更
- **バックエンド**: 
  - イベントスナップショット機能（eventSnapshot.ts）: `sort_number`のコピー処理を追加
- **既存機能**: メニュー表示順序が変更される可能性があるが、後方互換性は保たれる

#### 8.1.3 運用への影響
- **パフォーマンス**: メニュー数が少ないため、パフォーマンスへの影響は軽微
- **ストレージ**: `sort_number`フィールド追加によるストレージ使用量の増加は軽微

### 8.2 セキュリティ考慮事項
- メニュー並び順変更はパートナー本人のみが実行可能（Firestoreセキュリティルールで制御）
- イベントメニューの更新はFunctions経由のみ可能（セキュリティルールで制御）

### 8.3 運用考慮事項
- **ログ**: メニュー並び順変更時のログ記録
- **バックアップ**: 通常のFirestoreバックアップで対応
- **監視**: メニュー並び順変更のエラー率を監視
- **パフォーマンス**: メニュー数が増えた場合のソート処理のパフォーマンスを監視
- **拡張性**: 将来的にメニュー並び順のテンプレート機能を追加する可能性を考慮
