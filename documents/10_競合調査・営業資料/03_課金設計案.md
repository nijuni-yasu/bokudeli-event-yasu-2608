## 3. 料金の3層（変更なし）

```
企業 ──① プラットフォーム利用料（席課金）──→ shokujii
企業 ──② 食事実費（補助・ゲスト・取次）──────→ shokujii → 飲食店
飲食店 ──③ 送客手数料 ─────────────────────→ shokujii
```

| 層 | 名称 | 課金タイミング | 本案の方針 |
|:--|:--|:--|:--|
| C | **導入費用** | 契約時（一度） | 定価30万円、キャンペーン0円 |
| A | **① プラットフォーム利用料** | **毎月**（年間契約でも月次請求） | 席課金・企業別単価 |
| B | **② 食事実費** | **毎月**（利用実績） | 常に従量。前払い不可 |

### ② マージン0 と ③ の関係

② 食事実費は **マージン0の取次** とするが、当該注文について shokujii は **③ 飲食店からの送客手数料** を受け取る（料率・精算は別途定義）。

- 企業・従業員が認識する価格には手数料を上乗せしない（メニュー表示価格のまま）
- shokujii の収益は ①（席課金）と ③（店舗手数料）で確保し、② は収益源としない
- 営業説明: 「食事代に当社の手数料は上乗せしません。当社は飲食店側から送客手数料をいただくモデルです」

## 4. ① プラットフォーム利用料（案）

### 4.1 単価

単価は次の **3種に整理** し、契約ごとの最終適用単価は `billing_settings.unit_price` に **1本化** して保持する。

| 種別 | 単価（税込） | 適用条件 | 備考 |
|:--|:--|:--|:--|
| **定価（list）** | **1,200円** / 有効アカウント / 月 | 標準（見積・契約書に必ず記載） | 3ヶ月・月次の基準単価 |
| **早期導入（founding）** | **500円** / 有効アカウント / 月 | 先着N社 or 2026年内等 | **初回契約期間中のみ**（永久500円は避ける） |
| **企業別（custom）** | 営業交渉で決定 | 期間別単価（§6.0）、個別見積を含む | `billing_settings.unit_price` に保持 |

> **割引は契約期間のみ**。人数によるボリューム割引は設けない。  
> 年間・6ヶ月等の期間別単価（§6.0）は定価からの調整として **企業別 unit_price に反映** する。

- 課金対象: 月末時点の `EnterpriseMember.is_active == true`（現行 P-4〜P-6 と同じ）
- 停止中・ゲストは課金対象外（現行維持）

### 割引の併用ルール

早期導入 500円 と 年間契約 800円（定価1,200円の33%OFF）は **併用しない**。**いずれか一方（顧客に有利な方）のみ** を適用する。

| ケース | 適用単価 |
|:--|:--|
| 早期 + 年間契約 | 500円（早期を適用。年間OFFは適用しない） |
| 早期終了後 + 年間契約 | 800円（年間OFFを適用） |
| 早期終了後 + 6ヶ月 | 1,000円 |
| 早期終了後 + 3ヶ月/月次 | 1,200円（定価） |

早期500円の契約が更新を迎えた場合は、年間契約なら 800円 への移行を標準とする。

### 4.2 企業ごとの単価変更

| 方針 | 内容 |
|:--|:--|
| 技術 | 既存設計の `EnterpriseBillingSettings.unit_price` を利用 |
| 運用 | 営業が契約時に設定。変更は更新時 or 役員承認 |
| ガードレール | 最低単価フロア（例: 400円）、割引理由の記録（早期 / 期間 / 事例提供 等）。**人数による割引は不可** |

## 6. 契約プラン（案）

### 6.0 契約期間プラン

**年間契約を標準（前提）** とし、短期契約は **オプション** として提供する。  
契約期間が短いほど **① シート単価が高い**。短期契約のコストは **更新料ではなく単価に織り込む**。

| プラン | 契約期間 | ① unit_price（定価1,200円比） | 更新料 | コミット | 位置づけ |
|:--|:--|:--|:--|:--|:--|
| **年間（標準）** | 12ヶ月 | **800円/人/月**（33%OFF） | なし | あり | **推奨・前提** |
| **6ヶ月** | 6ヶ月 | **1,000円/人/月**（17%OFF） | なし（単価に織り込み） | あり（要検討） | 年度途中導入・試行 |
| **3ヶ月** | 3ヶ月 | **1,200円/人/月**（定価） | なし（単価に織り込み） | なし or 最低席数 | 短期 PoC・小規模 |
| **月次（解約柔軟）** | 1ヶ月ごと | **1,200円/人/月**（定価） | なし（毎月更新） | なし | お試し・小規模・PLG |

> **更新料を廃止し単価に織り込む理由**: 請求実装が単純になり、営業説明も「期間が短いほど単価が高い」の一言で済む。  
> **人数によるボリューム割引は設けない**。人数増加は True-up（同 unit_price × 実数）のみ。

**短期契約を高くする理由（営業説明用）**

- 解約・更新サイクルが短く、収益予測とサポートコストが不利
- 福利厚生制度として **定着・本格運用** には年間契約を推奨
- 短期は **PoC・年度途中の予算消化** 向けのオプション

**契約期間別試算（100名・①のみ）**

| プラン | 月額① | 契約期間の①合計 |
|:--|--:|--:|
| 年間（800円） | 80,000円 | 960,000円 |
| 6ヶ月（1,000円） | 100,000円 | 600,000円 |
| 3ヶ月（1,200円） | 120,000円 | 360,000円 |
| 月次（1,200円）×12 | 120,000円 | 1,440,000円 |

**短期を繰り返した場合の総コスト（100名・1年換算・案）**

| パターン | 計算 | **総額** |
|:--|--:|--:|
| 年間1本 | 960,000円 | **960,000円** |
| 6ヶ月×2回 | 600,000×2 | **1,200,000円** |
| 3ヶ月×4回 | 360,000×4 | **1,440,000円** |
| 月次×12 | 120,000×12 | **1,440,000円** |

→ 短期を繰り返すほど **総コストが上振れ** し、年間契約の経済合理性を示す。

### 6.1 年間 vs 月次（解約柔軟）の比較

| 項目 | 年間プラン（標準） | 月次プラン（オプション） |
|:--|:--|:--|
| ① 単価 | 800円/人/月（33%OFF） | 1,200円/人/月（定価） |
| 契約期間 | 12ヶ月 | 1ヶ月ごと自動更新 |
| 解約 | 期間満了まで原則不可（D-7） | **1〜3ヶ月前通知**で解約可（要決定） |
| コミット | あり | なし（実数のみ） |
| 更新料 | なし | なし |
| ② 食事実費 | 毎月従量 | 毎月従量（同じ） |
| 請求 | **毎月**（①＋②） | **毎月**（①＋②） |

→ 「年間契約」と「毎月払い」は両立する。差は **契約期間の縛り** と **単価**。

### 6.2 「年間契約」と「支払いサイクル」は別

| 概念 | 意味 |
|:--|:--|
| **年間契約** | 1年間の**契約期間・単価・コミット**を縛る |
| **支払いサイクル** | その代金を**いつ払うか**（一括 / 四半期 / 毎月） |

**推奨（本案）: 年間基本契約 ＋ 月次請求**

- ① プラットフォーム料: 年間単価で契約し、**毎月後払い**
- ② 食事実費: **毎月従量**（変動のため前払い不可）
- 請求書は **①＋②を1通にまとめる** 運用を想定

→ 「年間契約だけど毎月払い」は矛盾しない（Slack 等でも一般的）。

### 6.3 支払いパターン（①のみ）

| パターン | 内容 | 優先度 |
|:--|:--|:--|
| **C. 月次後払い** | 毎月 max(実数, コミット) × unit_price | **MVP推奨** |
| B. 四半期前払い | 3ヶ月分×4回 | Phase 2 |
| A. 年間一括前払い | 12ヶ月分を契約開始時（追加割引可） | Phase 2 |
| D. ①一括＋②月次 | ①だけ前払い | 要望があれば |

### 6.4 年間契約で固定するもの

| 固定 | 例 |
|:--|:--|
| 契約期間 | 2026/4/1〜2027/3/31 |
| unit_price | 800円/人/月（定価1,200円から年間33%OFF） |
| コミット席数 | 見積時点120席 |
| 中途解約 | 残期分請求 or 違約金（要法務確認） |

### 6.5 導入パターン: 部署PoC → 全社年間（Land & Expand）

**最初3ヶ月は部署単位で実験し、その後1年契約で全社導入** するパターンを想定する。

| 段階 | 目的 | 契約イメージ |
|:--|:--|:--|
| **お試し（正本 P-2）** | プロダクト検証 | ①無料・3ヶ月（テナント作成時） |
| **部署PoC** | 制度・運用の実験 | **3ヶ月契約**（部署30〜50名・1,200円・更新料なし） |
| **全社本番** | 福利厚生として定着 | **年間契約**（全社100〜200名・800円） |

**契約の持ち方（推奨: 同一 `enterprise_id` で拡張）**

- Phase 1 から同じ社内専用サイトを使い、アカウントを **部署→全社** に増やす
- PoC 終了時に **新しい年間契約** に切り替え（コミット・単価・期間を更新）
- メリット: イベント履歴・コミュニティが残る、導入の連続性

**タイムライン例**

```
4〜6月  部署PoC（3ヶ月契約・50名・1,200円）
        ①: 50 × 1,200 × 3 = 180,000円
        ②: 利用実績分

7月     年間契約開始（全社・コミット100・800円）
        実際のアカウント: 120名 → 7月請求 max(120,100)×800 = 96,000円 ＋ ②

10月    全社展開で active 180名
        10月請求 max(180,100)×800 = 144,000円 ＋ ②

翌7月   更新時にコミット180へ改定
```

> お試し（P-2・①無料）と部署PoC（有償3ヶ月）は **別枠**。混同しないよう営業資料で区別する。

## 7. 人数帯（ティア）と月次変動（True-up）

### 7.1 人数帯の役割

**見積規模・コミット交渉の目安** のみ。単価は契約期間で決まり、**人数によるボリューム割引はない**。

| ティア | 人数帯 | 用途 |
|:--|:--|:--|
| XS | 1〜50 | 見積規模の目安 |
| S | 51〜100 | 同上 |
| M | 101〜200 | 同上 |
| L | 201〜300 | 同上 |
| XL | 301〜400 | 同上 |
| XXL | 401〜500 | 同上 |
| Enterprise | 501〜 | 個別見積・個別交渉 |

### 7.2 2種類の「人数」

| 概念 | 説明 |
|:--|:--|
| **契約人数（コミット）** | 年間契約で「最低この席数を買う」と約束した数 |
| **課金人数（実数）** | 毎月末の `is_active == true` 件数 |

### 7.3 推奨: コミット最低 ＋ 超過請求（パターンB）

**月次請求式**

```
platform_fee(月) = max(月末 active 人数, コミット人数) × unit_price
```

| ケース | 処理 |
|:--|:--|
| 実数 < コミット（退職多発） | コミット人数分を請求（返金なし） |
| 実数 > コミット（採用） | 実数分を請求（**同 unit_price**。人数割引なし） |

**例（コミット120席・unit_price 800円）**

| 月 | 月末 active | 請求人数 | ① 請求額 |
|:--|--:|--:|--:|
| 4月 | 118 | 120（コミット適用） | 96,000円 |
| 5月 | 125 | 125 | 100,000円 |
| 6月 | 108 | 120（コミット適用） | 96,000円 |

### 7.4 コミット超過の具体例（100名契約 → 150名・200名）

**年間100名コミット・800円/人** で契約し、途中から人数が増えた場合。

```
platform_fee(月) = max(月末 active 人数, コミット100) × 800円
```

| 月 | 月末 active | 請求人数 | ① 請求額 | 説明 |
|:--|--:|--:|--:|--|
| 1月 | 98 | **100** | 80,000円 | 98 < 100 → コミット適用 |
| 2月 | 105 | **105** | 84,000円 | 採用で超過 → 105人分 |
| 3月 | 150 | **150** | 120,000円 | 150人分 |
| 4月 | 200 | **200** | 160,000円 | 200人分 |
| 5月 | 185 | **185** | 148,000円 | 退職で減っても100超なら実数 |

| 論点 | 回答 |
|:--|:--|
| 100名契約なのに150人になったら？ | **150人分を請求**（同 unit_price）。追加契約書は不要（True-up） |
| 100人未満に減ったら？ | **最低100人分**（コミット床）。返金なし |
| 101〜200人帯をまたいだら？ | **単価は変わらない**。更新時にコミット150等へ改定を交渉 |
| 大幅増員（100→300） | 任意で **契約変更（コミット改定）**。なければ実数×同単価で月次請求 |

### 7.5 代替案（参考）

| パターン | 概要 | 採用 |
|:--|:--|:--|
| A. 帯内定額＋超過のみ | 101〜200人帯＝年192万固定、201人超で追加 | 参考 |
| C. 帯＝完全定額（True-upなし） | 採用ブームで赤字リスク | 非推奨 |
