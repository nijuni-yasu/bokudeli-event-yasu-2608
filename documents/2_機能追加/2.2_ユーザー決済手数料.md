# ユーザー決済手数料機能仕様書

## 1. 概要
- ユーザー決済手数料を動的に計算してクレジットカード決済に上乗せする。
- 手数料は決済処理のコストをカバーするための変動料金として設定
- 手数料は返金対象外とする

## 2. 手数料設定
### 2.1 手数料計算式
- **計算式**: `ユーザー手数料 = MAX(110, FLOOR(注文金額 × 0.1, 100) × 1.1)`
- **計算手順**:
  1. 注文金額に10%をかける
  2. 100の位で切り捨てる
  3. 1.1（消費税）をかける
  4. 最低でも110円とする
- **適用条件**: すべてのクレジットカード決済

### 2.2 手数料計算例
| 注文金額 | 計算過程 | 手数料 |
|---------|---------|--------|
| 1,000円 | MAX(110, FLOOR(1000×0.1, 100)×1.1) = MAX(110, 100×1.1) = 110円 | 110円 |
| 2,000円 | MAX(110, FLOOR(2000×0.1, 100)×1.1) = MAX(110, 200×1.1) = 220円 | 220円 |
| 3,500円 | MAX(110, FLOOR(3500×0.1, 100)×1.1) = MAX(110, 300×1.1) = 330円 | 330円 |
| 10,000円 | MAX(110, FLOOR(10000×0.1, 100)×1.1) = MAX(110, 1000×1.1) = 1,100円 | 1,100円 |

### 2.3 手数料の変動要因
- 注文金額に応じて手数料が変動
- 将来的な手数料変更に対応するため、設定可能な仕組みを構築
- イベント単位での手数料設定は現時点では対応しない

## 3. 画面仕様

### 3.1 カート画面
- **表示内容**:
  - 商品小計: 1,000円
  - 決済手数料: 110円
  - 合計金額: 1,110円
- **表示位置**: 小計の下、合計金額の上
- **デザイン**: 手数料項目は明確に区別して表示

### 3.2 Stripe決済画面
- **表示内容**: カート画面と同様の内訳表示
- **決済金額**: 合計金額（商品小計 + 手数料）で決済
- **手数料の明示**: 決済前に手数料を含むことを明確に表示

### 3.3 マイページ（注文履歴）
- **表示内容**:
  - 商品金額: 1,000円
  - 決済手数料: 110円
  - 合計金額: 1,110円
- **表示形式**: 内訳を明確に分けて表示
- **注文詳細**: 各注文の詳細画面でも同様の表示

### 3.4 店舗管理画面
- **表示制限**: 手数料を含まない商品金額のみ表示
- **店舗メール**: 手数料を含まない商品金額で通知
- **店舗支払い金額**: 手数料を除いた商品金額のみ
- **理由**: 店舗は手数料を受け取らないため

### 3.5 イベントページ
- **キャンセルポリシー**: 手数料の返金不可を明記
- **表示例**: 「決済手数料は返金されません」

## 4. 返金・キャンセル仕様

### 4.1 返金ルール
- **返金対象**: 商品金額のみ
- **返金対象外**: 決済手数料
- **返金計算**: 合計金額 - 決済手数料 = 返金金額

### 4.2 キャンセル時の表示
- **マイページ**: キャンセル実行時に手数料返金不可を明記
- **確認ダイアログ**: 「決済手数料は返金されません」を表示
- **キャンセルポリシー**: イベントページに事前に明記

### 4.3 部分キャンセル
- **対応**: 部分キャンセルは現時点では対応しない
- **理由**: 手数料の按分計算が複雑になるため

## 5. 技術仕様

### 5.1 Firestoreスキーマ

```typescript
orderDoc: {
  orderId: string; // FirestoreのドキュメントID
  eventId: string; // 紐づくイベント
  userId: string;  // 注文者
  
  // 注文されたメニュー（複数対応）
  menus: Array<{
    menu_id: string; // メニューID
    name: string; // メニュー名
    price: number; // 単価（税込）
    count: number; // 注文数
  }>;
  
  // 金額関連フィールド
  payment_subtotal_amount: number; // 商品小計（税込）
  payment_user_fee_amount: number; // ユーザー決済手数料（動的計算）
  payment_user_total_amount: number; // 小計 + 手数料 = 合計金額
  payment_user_refund_amount?: number; // 返金金額（合計金額 - 手数料）
  payment_community_bill_off_amount?: number; //コミュニティ割引金額
  
  // 注文ステータス
  status: 'ordered' | 'in_cart' | 'canceled';
  
  // タイムスタンプ
  canceled_at?: Timestamp; // キャンセル日時
  ordered_at: Timestamp;
  created_at: Timestamp;
  updated_at: Timestamp;
}
```

### 5.2 計算ロジック
```typescript
// 商品小計の計算
payment_subtotal_amount = menus.reduce((sum, menu) => sum + (menu.price * menu.count), 0);

// 手数料の計算
function calculateUserFee(subtotal: number): number {
  const feeBase = Math.floor(subtotal * 0.1 / 100) * 100; // 100の位で切り捨て
  const feeWithTax = feeBase * 1.1; // 消費税をかける
  return Math.max(110, feeWithTax); // 最低110円
}

payment_user_fee_amount = calculateUserFee(payment_subtotal_amount);

// 合計金額の計算
payment_user_total_amount = subtotal_amount + user_payment_fee;

// 返金金額の計算
payment_user_refund_amount = user_total_amount - user_payment_fee;
```

### 5.3 Stripe決済
- **決済金額**: `payment_user_total_amount`を使用
- **メタデータ**: 手数料情報を含める
- **返金処理**: `payment_user_refund_amount`で返金実行

## 7. 注意事項

### 7.1 既存データへの影響
- 既存の注文データには手数料フィールドが存在しない
- マイグレーション処理が必要
- 表示時は手数料0円として扱う

### 7.2 表示の一貫性
- すべての画面で手数料の表示方法を統一
- 店舗向けとユーザー向けで表示内容を明確に分ける

### 7.3 エラーハンドリング
- 手数料計算エラー時の適切な処理
- 決済失敗時の手数料扱いの明確化

### 7.4 手数料計算の精度
- 小数点以下の処理を適切に行う
- 計算結果の検証機能を実装
