# イベント中止と返金

## 1. 概要
### 1.1 機能の目的
主催者がイベントを中止した際に、参加者への返金処理と関係者への通知を自動化し、円滑なイベント中止プロセスを提供する。

### 1.2 主要な機能
- 主催者によるイベント中止申請
- イベント中止理由の入力（50文字以上必須）
- イベント中止確定前の確認ダイアログ
- 参加者への自動返金処理
- 飲食店へのメール・電話通知
- イベントステータスの自動更新

### 1.3 対象ユーザー
- **主催者**: イベントを中止する権限を持つユーザー
- **参加者**: 事前決済で参加申込をしたユーザー
- **飲食店**: イベントに関連する店舗

## 2. ねらい
### 2.1 ビジネス目標
- イベント中止時の運営負荷を軽減
- 参加者への返金処理を自動化し、信頼性向上
- 飲食店への迅速な通知による関係性維持

### 2.2 ユーザー価値
- 主催者: イベント中止の手続き簡素化
- 参加者: 確実で迅速な返金処理
- 飲食店: 早期の情報共有による対応準備

### 2.3 成功指標（KPI）
- イベント中止処理の完了率: 95%以上
- 返金処理の完了率: 100%
- 飲食店通知の到達率: 100%

## 3. 前提条件
### 3.1 技術的前提条件
- イベント管理システムが稼働していること
- 決済システム（Stripe等）との連携が確立されていること
- メール送信機能が利用可能であること
- Twilio電話通知機能が利用可能であること

### 3.2 ビジネス的前提条件
- イベント注文期限の前日までに中止申請を行うこと
- 主催者がイベント中止の権限を持っていること
- 参加者の事前決済が完了していること

### 3.3 依存関係
- イベント管理機能
- 決済処理機能
- メール通知機能
- Twilio電話通知機能
- ユーザー認証機能

#### 5.1.3 Eventクラスの拡張
既存の`Event`クラスにキャンセル関連フィールドとメソッドを追加します。

```typescript
export class Event {
  // ... 既存フィールド ...
  
  // キャンセル関連フィールド
  cancel_reason?: string
  cancel_status?: 'pending' | 'processing' | 'completed' | 'failed'
  refund_status?: 'pending' | 'processing' | 'completed' | 'failed'
  refund_count?: number
  refund_total_amount?: number
  notification_status?: 'pending' | 'sent' | 'failed'
  canceled_at?: number
  canceled_by?: string
  
  // キャンセル関連メソッド
  isCanceled(): boolean {
    return this.event_status.value === 'event_canceled'
  }
  
  canBeCanceled(): boolean {
    // 注文期限の前日までキャンセル可能
    const deadline = new Date(this.event_deadline_datetime)
    const dayBeforeDeadline = new Date(deadline.getTime() - 24 * 60 * 60 * 1000)
    return new Date() <= dayBeforeDeadline && 
           this.event_status.value !== 'event_canceled' &&
           this.event_status.value !== 'finished'
  }
  
  validateCancelReason(reason: string): boolean {
    return reason.length >= 50 && reason.length <= 1000
  }
  
  // キャンセル処理の開始
  startCancelProcess(reason: string, canceledBy: string): void {
    if (!this.validateCancelReason(reason)) {
      throw new Error('キャンセル理由は50文字以上1000文字以下で入力してください')
    }
    
    this.cancel_reason = reason
    this.cancel_status = 'pending'
    this.refund_status = 'pending'
    this.notification_status = 'pending'
    this.canceled_at = Date.now()
    this.canceled_by = canceledBy
    this.event_status.value = 'event_canceled'
  }
  
  // 返金処理の更新
  updateRefundStatus(status: 'pending' | 'processing' | 'completed' | 'failed', count?: number, amount?: number): void {
    this.refund_status = status
    if (count !== undefined) this.refund_count = count
    if (amount !== undefined) this.refund_total_amount = amount
  }
  
  // 通知状態の更新
  updateNotificationStatus(status: 'pending' | 'sent' | 'failed'): void {
    this.notification_status = status
  }
  
  // キャンセル処理の完了
  completeCancelProcess(): void {
    this.cancel_status = 'completed'
  }
}
```

match /communities/{communityId}/events/{eventId} {
  allow read: if request.auth != null &&

  allow update: if request.auth != null &&

}

### 5.4 Functions設計
#### 5.4.1 Callable Functions（フロントエンドから呼び出し）
- `cancelEvent`: イベント中止処理の開始
  - **引数**: `{ communityId: string, eventId: string, cancelReason: string }`
  - **戻り値**: `{ success: boolean, event_id: string }`
  - **認証**: イベント主催者のみ

#### 5.4.2 Trigger Functions（自動実行）
- `onEventCanceled`: イベント中止時の自動処理
  - **トリガー**: `/communities/{communityId}/events/{eventId}` ドキュメント更新（event_status = 'event_canceled'）
  - **処理内容**: 返金処理と通知送信の開始
  - **権限**: システム権限

- `onRefundCompleted`: 返金完了時の処理
  - **トリガー**: `/communities/{communityId}/events/{eventId}` ドキュメント更新（refund_status = 'completed'）
  - **処理内容**: 参加者への通知送信
  - **権限**: システム権限

#### 5.4.3 Scheduled Functions（定期実行）
- `checkPendingRefunds`: 未完了返金の確認
  - **スケジュール**: 毎時0分に実行
  - **処理内容**: 返金処理の再試行

### 5.5 処理フロー
1. 主催者がイベント管理画面で「イベントを中止する」を押下
2. イベント中止入力フォーム画面に遷移
3. 主催者が中止理由を50文字以上で入力
4. 「イベント中止を確定する」を押下
5. 確認ダイアログが表示され、「はい」で確定
6. Callable Function `cancelEvent`を呼び出し
7. イベントドキュメント（`/communities/{communityId}/events/{eventId}`）を更新
   - `event_status`を`event_canceled`に更新
   - キャンセル関連フィールドを設定
8. 参加者の注文ステータスを`event_canceled`に更新
9. Trigger Function `onEventCanceled`が自動実行
10. 事前決済参加者への返金処理を開始
11. 飲食店へのメール通知を送信
12. 飲食店へのTwilio電話通知を送信
13. 返金処理完了後、参加者への通知を送信
