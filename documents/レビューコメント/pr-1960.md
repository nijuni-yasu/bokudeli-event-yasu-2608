````
### 🔴 必須修正

#### 1. `isReserveDataMissing` に `currentUserStore.user` の null チェックが欠落している（`EventEdit.vue`）

`submitReservation` 内では `user == null` のガードが入っているのに、ボタンの `disabled` 条件に使う `isReserveDataMissing` には含まれていません。`user` が null のままボタンが有効になり、押下時にアラートダイアログが表示されます。

```typescript
// 現状
const isReserveDataMissing = computed(() => {
  return (
    partnerShopListStore.totalCount == null || currentUserStore.personalInformation == null || location.value == null
  )
})

// 修正案
const isReserveDataMissing = computed(() => {
  return (
    partnerShopListStore.totalCount == null ||
    currentUserStore.user == null ||
    currentUserStore.personalInformation == null ||
    location.value == null
  )
})
```

#### 2. `role="alertdialog"` を `v-card` に付与している（`ConfirmDialog.vue`）

ARIA 仕様では `alertdialog` ロールはダイアログの**コンテナ要素**に付けるべきです。現在は `v-card` に付与されていますが、支援技術は `v-dialog` が生成する `role="dialog"` の要素を先に読み取るため、`v-card` の `role="alertdialog"` は正しく機能しません。

Vuetify の `v-dialog` に `role` を直接渡すか、`aria-live="assertive"` 等の代替手段の利用を検討してください。

### 🟡 提案

#### 3. `REASON_CODE_ORDER` 構築時の `as` キャスト（`validateReservationRequest.ts`）

```typescript
const map = {} as Record<ReservationRequestReasonCode, number>
```

`as` キャストはプロジェクトルールで原則禁止です。以下のように `Partial` を使えばキャストなしで型安全に書けます。

```typescript
const REASON_CODE_ORDER: Partial<Record<ReservationRequestReasonCode, number>> = Object.fromEntries(
  RESERVATION_REQUEST_REASON_CODES.map((c, i) => [c, i]),
)
// ソート時のアクセス
.sort((a, b) => (REASON_CODE_ORDER[a] ?? 0) - (REASON_CODE_ORDER[b] ?? 0))
```

#### 4. `validateEventDbAndOrganizer` 内の `ORGANIZER_PATH_TO_REASON` が実質デッドコード（`validateReservationRequest.ts`）

主催者フィールドは `NonEmptyStringSchema.optional()` で定義されているため、`EventDbSchema.safeParse` 時に空文字は `FieldValue.delete()` に変換されてパースが成功します。`dbResult.error.issues` に主催者フィールドのエラーが入ることはなく、`ORGANIZER_PATH_TO_REASON` の `dbResult` 側ループは到達しません。

`ReservationRequiredSchema.safeParse` の結果でのみ使われる設計であれば、`dbResult.error.issues` 側の主催者ルックアップを削除してコードの意図を明確にしてください。

#### 5. `allowedStartDates` で `Date` を直接操作している（`EventBasicInfoCard.vue`）

```typescript
// 現状（Date を直接操作）
const y = value.getFullYear()
const m = String(value.getMonth() + 1).padStart(2, '0')
const d = String(value.getDate()).padStart(2, '0')
return `${y}-${m}-${d}` >= min

// 修正案（luxon を使用）
import { DateTime } from 'luxon'
return DateTime.fromJSDate(value).toFormat('yyyy-MM-dd') >= min
```

プロジェクトでは `Date` の直接使用は禁止で、luxon で代替する規約です。

#### 6. `Date.now()` の使用（`EventEdit.vue` L629）

```typescript
// 現状
nowMillis: Date.now(),

// 修正案（DateTime はすでに import 済み）
````
