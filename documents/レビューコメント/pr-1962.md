### ✅ 問題なし

**TypeScript・型安全性**
- `disabled?: boolean` の型宣言と `false` のデフォルト値は適切。既存の `readonly` prop と同じパターンで統一されており後方互換も保たれている。

**比較・falsy チェック**
- `:disabled="selectedEvent === null"` は厳密な `=== null` を使っており正しい（`selectedEvent` は `ref<BokudeliEvent | null>(null)` のため `undefined` は入らないが、strict comparison は適切）

**Vue リアクティビティ**
- `menu` computed の `props.readonly || props.disabled ? false : _menu.value` は既存ロジックの自然な拡張。問題なし。

**副作用として既存の不具合も修正**
- `LetterEdit.vue` ではすでに `:disabled="!isScheduled"` を `DateInput` に渡していたが、従来は `$attrs` 経由でのスプレッドだったため `menu` computed が `disabled` を考慮しておらず、カレンダーが開ける状態だった可能性がある。今回の `disabled` prop 追加により、`LetterEdit.vue` でも calendar が正しく抑制されるようになる。

---

### 🟡 提案

**`disabled` のとき close アイコンが表示されうる**

```html
<!-- 現在 -->
:append-inner-icon="clearable && modelValue != null ? mdiClose : undefined"

<!-- 提案: disabled のとき close アイコンも非表示に -->
:append-inner-icon="clearable && !disabled && modelValue != null ? mdiClose : undefined"
```

Vuetify は `disabled` の `v-text-field` でのクリックイベントをブロックするため実害はないが、`disabled=true` のときに close アイコンが見えていると UX 的に紛らわしい可能性がある。

---

### 🟢 任意

**`readonly` は常に `true` なのに、`readonly` prop が存在する点**

`DateInput` 内で `:readonly="true"` はハードコードされており、`props.readonly` はカレンダーメニューの制御にのみ使われている。今回の変更範囲外だが、将来的に `readonly` と `disabled` の責務が混在しないよう整理できると良い。

---

### 総評

変更は最小限かつ意図が明確で、既存の `readonly` prop と対称に設計されている。バグ修正の範囲は適切で、他の利用箇所（`MenuEditCard.vue`, `EventBasicInfoCard.vue`）への影響もデフォルト値 `false` により後方互換が保たれている。🟡 の提案は任意対応で構わない。LGTM 🎉
