**レビュワー**: Copilot

**レビュワーのコメント（原文）**:

[nits] `markFoodMenuImageFailed` — Set 再生成が不要**
`user/src/components/profile/UserProfilePage.vue` L524–526

```ts
const markFoodMenuImageFailed = (orderId: string) => {
  if (failedFoodMenuImageIds.value.has(orderId)) return
  failedFoodMenuImageIds.value = new Set([...failedFoodMenuImageIds.value, orderId])
}
```

Vue 3 の `ref(new Set())` は内部的に Proxy でラップされるため、`.add()` を呼ぶだけで reactivity が発火します。毎回スプレッドで新しい Set を生成する必要がなく、以下に簡略化できます。

```ts
const markFoodMenuImageFailed = (orderId: string) => {
  failedFoodMenuImageIds.value.add(orderId)
}
```

**コメント要約**: `failedFoodMenuImageIds` 更新時に Set を毎回再生成している。Vue 3 では reactive Set への `.add()` で十分なため簡略化できる。

**判断結果**: ✅ 対応済み

**PRスコープ**: 📌 スコープ内

**ラベル**: 📏 規約

**変更種別**: 📐 リファクタ

**想定工数**: S

**判断理由**: 指摘は技術的に正しい。Vue 3 の reactive コレクションは mutation で更新可能。早期 return の `has` チェックは `.add()` 版でも維持可能。Issue #2093 の同一ファイル変更内で数行の整理として自然。

**対応内容**: `failedFoodMenuImageIds.value.add(orderId)` に簡略化済み。
