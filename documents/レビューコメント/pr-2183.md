### 🚨 必須修正

RC-1 対応で `pageDocs` に有効行が無いとき `sentinelDoc(docs[limit])` を `nextCursor` に採用しているが、この cursor で次ページを `startAfter` すると sentinel 自身（最初の有効候補）を未返却のままスキップする。有効な友人を欠落させるため、ページング整合性が壊れる。`nextCursor` は「このレスポンスで返した最後の行」を基準にするか、sentinel を使う場合は同一レスポンスに含めて欠落しないようロジックを修正し、欠落再現テストを追加すること。

**Codex インライン（原文抜粋）**: sentinel を cursor にして有効な友人を飛ばさないで。追加テストの「page 末尾が不正でも sentinel doc...」ケースでも `friend2` が返却されないまま cursor だけ進む。

**判断理由**: 指摘は妥当。RC-1 の sentinel フォールバックは `hasMore`/`nextCursor` 不整合は解消するが、sentinel が有効友人 doc のとき `startAfter(sentinel)` で当該友人が永久スキップされる。現行テストも `friends` が空のまま `nextCursor=friend2` を期待しており、欠落を再現している。sentinel を `friends` に含める、または cursor を返却済み末尾に限定する修正が必要。
