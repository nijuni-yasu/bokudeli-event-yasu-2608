**識別子**: RC-19（セルフレビュー）

**レビュワー**: セルフレビュー（`shokujii-code-review` チェックリスト「Firestore / Store パターン」）

**指摘内容**:

`functions/default/src/memberOrders.ts` `confirmOrder` および `functions/default/src/stripeWebhook.ts` で、`runTransaction` の外で `community.addMember(uid)` を呼び出している。`addMember` は内部で「既存 `members` 配列の取得（read）」→「`members` 配列への追加（write）」を行うメソッドのため、orders 確定トランザクションとメンバー追加が分離されていると以下のリスクがある:

- orders 確定後に `addMember` が失敗すると、`members` に未追加のまま注文だけ確定状態で残る
- 同時に複数の confirmOrder が走った場合、`addMember` 内の read+write がトランザクション保護を受けないため楽観ロックが効かない

```text
functions/default/src/memberOrders.ts:264-268
    const community = await getCommunity(community_id)
    if (community != null) {
      await community.addMember(uid)
    }
```

**判断結果**: ⚠️ 要対応（必須修正）

**対応方針候補**:
1. `community.addMember` を `runTransaction` 内で実行し、read を write より前に集約する設計に変更
2. もしくは orders 確定と `addMember` を分離する場合、冪等な再試行ジョブ（onDocumentWritten トリガ等）で整合させる
3. 現状の挙動（先勝ち + ベストエフォート）を許容するなら、最低限「addMember 失敗時のリトライキュー」を入れる

`stripeWebhook.ts` も同パターンのため同時修正が必要。
