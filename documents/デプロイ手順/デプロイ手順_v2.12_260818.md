## 実行順序の要点

```text
[0 ゲート] development の Deploy functions 復旧（backupFirestore 削除 → 再実行）
  → Node 24 ネイティブ実走検証 → チャット v2 / エンプラ / SEO の E2E

[A 事前] terraform plan（Destroy 0・allow_tenants 削除なし）
  → production Variables 差分確認 → 本番 orphan 関数の棚卸し

[B 当日]
  Analytics → メンテ ON → Firestore バックアップ
  → terraform apply
  → ⚠️ 本番 backupFirestore を明示削除          ← push 前必須（残すと Deploy functions が abort）
  → ⚠️ batch 0046 本実行                        ← push 前必須（メンテ中なので新規注文は発生しない）
  → release PR マージ → tag → push main production
  → CI: firestore(index → rules) → functions → user / partner / enterprise / terms
  → ⚠️ onChatReactionWritten を --force で手動 1 回デプロイ（retry: true）→ functions re-run
  → ⚠️ Deploy user が sitemap で 400 になったら functions 完了後に re-run

[C 後]
  疎通・E2E（PF 回帰 最優先）→ SEO 本番検証 → バックアップ疎通 → メンテ OFF
```

| バッチ | 実行タイミング |
| --- | --- |
| `0046` member_orders の `enterprise_id` materialize | **メンテ ON 後・`production` push 前**（B-5） |
| `0047` stripes の `enterprise_id` materialize | **本リリースでは不要**（エンプラダッシュボード go-live 前に実施） |
| `0045` Google 画像移行 | 任意（v2.11 未実施のまま） |
| `0043` / `0044` | **v2.11 で本番実行済み。再実行不要** |

> **`0046` の重要性**: #2120 で PF のプロフィール・注文履歴・カートの collectionGroup クエリに `where('enterprise_id', '==', null)` が入る。Firestore の `== null` は**フィールド欠落と区別される**ため、`0046` 未完了のまま user をデプロイすると **既存の注文が PF プロフィールから消える**（[#2198](https://github.com/nijuniinc/bokudeli-event-new/issues/2198)、[02_developmentマージ.md](../08_エンタープライズ/00_計画/02_developmentマージ.md) §2.3.1）。
>
> **なぜ push 前に実行するか**: 順序の正本（[01_MVP全体計画.md](../08_エンタープライズ/00_計画/01_MVP全体計画.md) F-1 メモ）は **Functions（`enterprise_id: null` の明示書き込み）→ `0046` → index → クライアント**だが、これは**無停止前提**の順序で、backfill 中に作られる新規注文の欠落を防ぐためのもの。本リリースは**メンテナンスモード中に実施し新規注文が発生しない**ため、Functions デプロイ前に `0046` を完了させても欠落は起きない。
> 一方、`deploy_*.yml` は `push` で**同時発火し順序を制御できない**ため、「Deploy user だけ後回しにする」ことは実質できない。**push 前に `0046` を終わらせるのが唯一確実な回避策**。

## トラブルシュート

### `Deploy functions` が `Command aborted` で失敗する

**症状**: `The following functions are found in your project but do not exist in your local source` に続いて `Command aborted.`。

**原因**: `--force` 廃止後（#2260）、`index.ts` に export の無い関数が GCP 上に残っていると CLI が削除確認を求め、非対話の Actions では abort する。**abort 時点では何もデプロイされていない**。

**対処**: A-3 / B-4 の手順で残存関数を削除して再実行する。

### `Pass the --force option to deploy functions with a failure policy`

**原因**: `retry: true` の新規エンドポイント（本リリースでは `onChatReactionWritten`）。

**対処**: B-8 の手動デプロイを 1 回実行してから CI を再実行する。

### `Deploy user` が Cloud Run service does not exist で失敗する

**症状**: `Cloud Run service handlesitemaprequest does not exist in region asia-northeast1`（HTTP 400）で hosting:user の finalize が失敗。

**原因**: `firebase.json` の user Hosting rewrite に `/sitemap.xml → handleSitemapRequest` が追加されたが、Hosting rewrite で Gen2 Function を参照する場合は **先に Function がデプロイ済み**である必要がある。workflow は独立発火するため順序が保証されない（[#2202](https://github.com/nijuniinc/bokudeli-event-new/issues/2202)、development 実績あり）。

**対処**: `Deploy functions` の完了を待ってから `Deploy user` を re-run する。

### PF プロフィールから注文履歴・参加イベントが消える

**原因**: `0046` 未実行または未完了のまま user をデプロイした。`where('enterprise_id', '==', null)` はフィールド欠落に一致しない。

**対処**: メンテナンス ON → `0046` 本実行 → 再確認。コードのロールバックだけでは解消しない。

### Functions デプロイが 30 分 timeout / quota 429

**原因**: Node 24 化により 87 関数すべてが再デプロイ対象になる（差分スキップが効かない）。

**対処**: Firebase CLI は 429 をリトライする。timeout で落ちた場合は re-run（成功済み関数は次回 Skipped になり収束する）。個別に確認するときは `gcloud functions describe <name> --gen2 --region=asia-northeast1` の `updateTime` を見る。

### `Deploy functions` は緑だがログがすべて `Skipped (No changes detected)`

**原因**: CLI がソース・設定・`.env` に差分なしと判断した。**Node 24 リリースでは起こらないはず**なので、全件 Skipped なら Node 24 の変更が反映されていない疑いがある。

**対処**: [functionsのCIデプロイ.md](../実装メモ/functionsのCIデプロイ.md) §デプロイ成功時の注意 を参照。

### リアクションが付かない / pill が空のまま

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| 書き込みが permission-denied | Rules 未デプロイ | `Deploy firestore` を先に完了させる |
| 書き込めるが数が出ない | `onChatReactionWritten` 未デプロイ | B-8 を実施（`messages` は `update: false` のため summary は必ず Functions 経由） |

### iOS Safari で一括ダウンロードが `unavailable` になる

**原因**: Blob の fetch 待ちで user activation が失効する（既知・未対応）。単枚 DL は成功する。

### Firestore index 構築中の PF ClientError

**症状**: デプロイ直後に `The query requires an index. That index is currently building` が報告される。

**対処**: Console で **Enabled** になるまで待つ（通常数分〜）。`0046` 未実施の欠落問題とは別。
