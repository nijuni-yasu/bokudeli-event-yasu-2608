## フェーズ C：デプロイ後

### C-1. 旧 `backupFirestore` の明示削除（初回切替時必須）

コードから `backupFirestore` を削除しても **GCP 上の旧 Function は自動では消えない**。新 7 関数デプロイ成功後、対象プロジェクトごとに 1 回実施する。

**対象プロジェクト例**

| 環境 | プロジェクト ID |
| --- | --- |
| 本番 | `bokudeli-event-dev` |
| development | `bokudeli-event-test` |

**削除前確認**

```bash
PROJECT_ID=bokudeli-event-dev   # 環境に合わせて変更

firebase --project "${PROJECT_ID}" functions:list \
  | grep -E 'backupFirestore|firestoreExport|storageBackup|backupRetention'

# 新 7 関数が存在し、手動 export / copy が 1 回成功していること
```

**削除**

```bash
firebase --project "${PROJECT_ID}" functions:delete \
  backupFirestore \
  --region asia-northeast1 \
  --force
```

**削除後確認**

```bash
# backupFirestore が一覧に無いこと
firebase --project "${PROJECT_ID}" functions:list | grep backupFirestore
# → 出力なし

# 孤立 Scheduler（旧 backupFirestore 用）が残っていれば削除
gcloud scheduler jobs list --project="${PROJECT_ID}" --location=asia-northeast1 \
  | grep -i backupFirestore

# 存在する場合のみ（ジョブ名は環境により異なる）
# gcloud scheduler jobs delete firebase-schedule-backupFirestore-asia-northeast1 \
#   --project="${PROJECT_ID}" --location=asia-northeast1 --quiet
```

- [ ] `backupFirestore` 不在
- [ ] 旧 Scheduler 不在（または削除済み）
- [ ] 翌日 2:00 JST 以降、Cloud Logging で **新関数のみ**が export / copy している（二重実行なし）

> Firebase 公式: 関数名変更時は新関数デプロイ後に旧名を `functions:delete` する。  
> 参考: [21_bot_legacy移行.md §5.10](../07_リファクタリング/21_bot_legacy移行.md)（Gen1 削除手順と同型）

## トラブルシュート

### 旧 `backupFirestore` が残り二重 export される

**症状**: 毎日 2:00 前後に export フォルダが 2 系統できる / Scheduler に旧ジョブが残る。

**対処**: §C-1 を実施。新関数デプロイ**後**に delete する（先に delete すると一時的に export 停止）。

### Storage バックアップに `_SUCCESS` が無い

**症状**: `daily/YYYY-MM-DD/_inprogress/` のみ存在。

**原因**: `storageBackup*` がタイムアウトまたは copy 失敗で途中終了。

**対処**: Cloud Logging でエラー確認。`backupRetentionCleanup` が incomplete run を削除する。容量・時間は [仕様 §5.6.3](../09_運営向け機能/02_firestoreとstorageの自動バックアップ.md) を参照。
