## トラブルシュート

### PF トップが全件ゼロ表示

**症状**: リリース後、PF トップ・コミュニティ一覧にイベント / コミュニティが 1 件も出ない。

**原因**: `0043` 未実行または未完了のまま、`where('enterprise_id', '==', null)` 付き user をデプロイした。

**対処**: メンテナンス ON → `0043` 本実行 → 再確認。コードのロールバックだけでは解消しない。

### `0044` 実行後も既存参加者にチャットルームが見えない

**症状**: リリース前から注文済みのユーザーが `/chat` にルームを表示できない。

**原因**: `0044` 未実行・check 失敗・対象イベント条件外。

**対処**: check 0044 の `events_target` と task dry-run を照合。必要なら batch ログを確認して再実行（冪等）。

### v2.11 実績: Functions デプロイ時の Cloud Run / Cloud Functions クォータ 429

**症状**: `Deploy functions` 実行中、Cloud Audit または Firebase CLI に `Quota exceeded`（Write requests / mutation requests）が多数出る。一部 Function で `UpdateFunction` 失敗ログが残る。

**原因**: 旧構成では hybrid / pf / enterprise の 3 ジョブ並行 + `--force` による全 Function 強制更新で **1 分あたりの Cloud Run / Cloud Functions API 書き込み上限**に到達しやすかった。

**対処**（[#2260](https://github.com/nijuniinc/bokudeli-event-new/issues/2260) 以降）:

- `deploy_functions.yml` を **1 ジョブ + `--only functions`（`--force` なし）** に統一（[functions の CI デプロイ](../実装メモ/functionsのCIデプロイ.md)）
- 関数名を明示しない `--only functions` では差分なし Function がスキップされ、quota 負荷が軽減される
- **ログ確認**: 全件 `Skipped (No changes detected)` のみなら実装差分なし（CI yml / doc のみの PR 等）。**CI 緑 = 全 Function 再デプロイ済みではない** — 詳細は [functions の CI デプロイ §デプロイ成功時の注意](../実装メモ/functionsのCIデプロイ.md#デプロイ成功時の注意スキップとci-緑)

**429 発生時**（旧構成・大量変更時）:

- Firebase CLI は **429 時にリトライ**する。Actions ジョブ全体が `success` なら最終的には反映済みのことが多い（v2.11 実績: [run #29510999085](https://github.com/nijuniinc/bokudeli-event-new/actions/runs/29510999085)）
- 失敗 Function が疑わしい場合は `gcloud functions describe <name> --gen2 --region=asia-northeast1` で `updateTime` を確認
- enterprise Callable の IAM は `SetIamPolicy` 429 が出ても **リトライ後に `allUsers` + `roles/run.invoker` になることがある**（v2.11: 19/19 OK）

### `Deploy functions` が成功だがログがすべて `Skipped (No changes detected)` になる

**症状**: Actions は緑、`Deploy complete!` だが、各 Function が `Skipped (No changes detected)` のみ（更新行なし）。

**原因**: Firebase CLI がソース・設定・deploy 時 `.env` に差分がないと判断した。**`functions/default` の実装を変えていない PR**（CI 設定・verify・ドキュメントのみ）では正常。

**対処**: 実装を反映したい場合は **functions コード（または `common/` 等、デプロイバンドルに入る変更）を含むコミット**のあと再デプロイする。GCP 側だけ直したい場合は該当 Function を `--only functions:<name>` で手動デプロイ。詳細は [functions の CI デプロイ §デプロイ成功時の注意](../実装メモ/functionsのCIデプロイ.md#デプロイ成功時の注意スキップとci-緑)。

### `Deploy functions` が `Command aborted` で失敗する（`--force` 廃止後）

**症状**: `Deploy functions` が `The following functions are found in your project but do not exist in your local source` に続いて `Command aborted.` で exit 非 0 になる。

**原因**: [#2260](https://github.com/nijuniinc/bokudeli-event-new/issues/2260) 以降、CI は `--force` を使わない（[functions の CI デプロイ](../実装メモ/functionsのCIデプロイ.md)）。`index.ts` に export が無い `default` codebase の関数が GCP 上に残っていると、CLI が削除確認を求め、非対話の Actions では abort する（誤削除を防ぐ安全側の挙動）。abort 時点では**何もデプロイされていない**ため、残存関数を削除して再実行すればよい。

**対処**: 残存関数を確認し、明示削除してから再実行する。

```bash
PROJECT_ID=bokudeli-event-test   # 環境に合わせて変更

firebase --project "${PROJECT_ID}" functions:list
firebase --project "${PROJECT_ID}" functions:delete <関数名> \
  --region asia-northeast1 \
  --force
```

残存候補: 旧 Gen1 8 件・旧 Gen2 名 `eventNotification` / `orderNotification`（[21_bot_legacy移行.md §5.10 / §5.12](../07_リファクタリング/21_bot_legacy移行.md)）、旧 `backupFirestore`（[デプロイ手順_v2.12 §C-1](./デプロイ手順_v2.12_260719.md)）。

### `Deploy functions` が failure policy で `--force` を要求する

**症状**: `Pass the --force option to deploy functions with a failure policy` で exit 非 0（例: `retry: true` の Function を環境に初デプロイする場合）。

**原因**: Firebase CLI が retry 付き Function の初回デプロイ確認を求める。orphan 削除用の `--force` とは別用途だが、フラグは共通のため CI では自動承認しない。

**対処**: 該当 Function のみ**手動で 1 回**デプロイしてから CI を再実行する。関数名を絞った `--only` は他の関数を削除候補にしないため、`--force` を付けても安全。以降は同じ環境で再発しない。

```bash
firebase --project "${PROJECT_ID}" deploy --only functions:onChatReactionWritten --force
```

### `Deploy functions` が成功しているのにトリガーが更新されない（`--force` 廃止後）

**症状**: Actions は緑だが、対象 Function のトリガーが旧設定のまま。ログに `Skipping updates for functions that may be unsafe to update` が出ている。

**原因**: Firebase CLI は `--force` なしの非対話デプロイで、**イベント種別を変える危険な更新をスキップ**して成功扱いにする（データロス防止）。旧 CI は常に `--force` だったため無条件に適用されていた。

**対処**: 上記警告が出た Function を [manage-functions の手順](https://firebase.google.com/docs/functions/manage-functions?gen=2nd#modify-trigger)に従って個別に更新する（新トリガー名で作成 → 旧関数を明示削除、または `--force` 付き手動デプロイ）。

### `Deploy functions` がデプロイ後に cleanup policy エラーで失敗する（`--force` 廃止後）

**症状**: Function 自体はデプロイ済みだが、`could not set up cleanup policy` で exit 非 0。

**原因**: Artifact Registry に **cleanup policy が未設定のリージョン**があると、CLI が `--force`（自動設定）を要求する。

**対処**: 一度だけポリシーを設定してから再実行する。

```bash
firebase --project "${PROJECT_ID}" functions:artifacts:setpolicy
```

### v2.11 実績: Firestore index 構築中の PF ClientError

**症状**: デプロイ直後、`reportClientError` に `The query requires an index. That index is currently building` が PF トップ（`/`）等から報告される。

**原因**: `Deploy firestore` 直後、複合 index が **building → enabled** の遷移中。

**対処**: Console で index が **Enabled** になるまで待つ（通常数分〜）。0043 未実施の PF 全件ゼロ表示とは別問題（[上記](#pf-トップが全件ゼロ表示)）。
